# Phase 2.1 Design — Typed evaluation

**Date:** 2026-09-27
**Phase:** 2.1
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

> Milestone 2 design: `docs/superpowers/specs/2026-09-27-milestone-2-design.md`. Issues in scope: #22 (a non-breaking `IJevClient` shape), #12 (record equality), #13 (ProbabilityMap boxing).
>
> Decided in the brainstorm on 2026-09-27:
> - the typed methods are default interface methods, and `JevClient` overrides them;
> - `[JevQuestions(State = typeof(...))]` links a question set to its state type;
> - the model comes from `JevClientOptions.Model`.

## Goal

A `[JevQuestions]` question set is evaluated in one call and comes back as its typed result. With `JevClient` this needs no reflection, no intermediate `SystemOneResponse`, and fewer allocations than the untyped call. Any other `IJevClient` implementation keeps compiling and still returns typed results.

## Approach

**Public API.**
- `IJevClient` gains four default interface methods:
  - `EvaluateAsync<T>(string state, CancellationToken ct = default)`;
  - `EvaluateAsync<T>(JsonElement state, CancellationToken ct = default)`;
  - `EvaluateUtf8Async<T>(ReadOnlyMemory<byte> utf8JsonState, CancellationToken ct = default)`;
  - `EvaluateAsync<T, TState>(TState state, JsonTypeInfo<TState> stateTypeInfo, CancellationToken ct = default)`.
- The first three are constrained `where T : IJevQuestionSet<T>`, and the last `where T : IJevQuestionSet<T, TState>`. All four return `ValueTask<Result<T, JevError>>`.
- The UTF-8 overload has its own name, so it is never confused with the `string` overload (compare #21).
- A new marker interface, `IJevQuestionSet<TSelf, TState> : IJevQuestionSet<TSelf>`, links a set to its state type.
- `JevQuestionsAttribute` gains `Type? State { get; set; }`.
- `JevClientOptions` gains `string Model { get; set; } = JevDefaults.Model`, validated as non-blank in `JevClientSettings`. Typed calls send it; the untyped call keeps using `SystemOneRequest.Model`.

**Errors.**
- Transport and HTTP failures keep their existing `JevError` kinds, and retries apply unchanged.
- A response whose answers `T.Parse` rejects becomes `JevErrorKind.InvalidResponse`, with the `JsonException` as `Exception` and a message that names the failing question where the parser reports it.
- A response without `answers` is also `InvalidResponse`.
- Caller cancellation throws `OperationCanceledException`.

**The zero-allocation path in `JevClient`.**
- **Raw endpoint.** `IJevApi` gets `EvaluateRawAsync([Body] RawJson body, [Header("Authorization")] string authorization, [Header("X-TypeSafe-Retry-Count")] [RetryAttempt] int? retryCount, CancellationToken ct)`, returning `ValueTask<Result<RawJson, JevError>>`, with a method-level `[Serializer(typeof(JevRawSerializer))]`.
  - `RawJson` is internal and owns a pooled UTF-8 buffer.
  - `JevRawSerializer` is an internal `IRestSerializer` that supports only `RawJson` and throws for anything else. It copies bytes between the stream and the buffer, with no JSON model in between.
- **Retries** go through the same generated proxy, so `Retry-After`, `RethrowDeclined` and the retry-count header behave exactly as they do for the untyped call.
- **Writing the request.** A `Utf8JsonWriter` over a pooled `IBufferWriter<byte>` writes:
  - `state`, from the string, the `JsonElement`, the raw UTF-8 validated as a single JSON value, or `TState` through its `JsonTypeInfo`;
  - `model`;
  - `questions`, as `T.QuestionsUtf8` written raw.
- **Reading the response.** A `Utf8JsonReader` over the response buffer walks the top-level object to `answers`, calls `T.Parse(ref reader)`, and skips every other property.
- **Buffers.** They are returned to the pool on every path, including errors and exceptions.
- **Spike first.** At the start of the plan, confirm that ZeroAlloc.Rest 2.2.0 and ZeroAlloc.Resilience 3.3.0 support the method-level `[Serializer]` together with `[ErrorMapper]` and `[Retry]` on the same interface, with a `RawJson` body and return type. If they don't, the fallback is a hand-written `HttpClient` call inside `JevClient` that reuses `JevErrorMapper` and the retry policy. That fallback would be a workaround: file the upstream gap as an issue before taking it.

**The default interface method fallback.**
- It deserializes `T.QuestionsUtf8` into `Dictionary<string, JevQuestion>` through `JevJsonContext`, and builds a `SystemOneRequest` with the given state and `JevDefaults.Model`, because the interface cannot see options.
- It calls `EvaluateAsync(SystemOneRequest)`, serializes `response.Answers` back to UTF-8 through `JevJsonContext`, and runs `T.Parse`.
- It allocates more but is correct, and it is documented as the path test doubles take.
- `TState` state is serialized to a `JsonElement` first, through its `JsonTypeInfo`.

**Generator.**
- With `State` set, the generator emits `IJevQuestionSet<TSelf, TState>` instead of `IJevQuestionSet<TSelf>`.
- A new error, **JEV107**, fires when `State` is not a class, struct or record type, for example an interface, an open generic or `void`. Phase 2.2 moves it to the analyzer project with the rest of the series.
- `QuestionsUtf8` and `Parse` are unchanged.

**#12.** `ProbabilityMap<T>` implements `IEquatable<ProbabilityMap<T>>`, with `Equals` and `GetHashCode` computed over the option set and the probability values, not the buffer reference. `Choice<T>` and `Score<T>` equality then follows from their fields, so record equality of `[JevQuestions]` records compares by value. A test proves that two separate parses of the same JSON are equal.

**#13.** The indexer's error path calls a `[DoesNotReturn]` throw helper that formats the option without boxing it; the message names the option index. The throw path still allocates the exception, as every throw does. The success path stays allocation-free, and a gate asserts that.

**Budgets and benchmarks.**
- The AOT smoke app gains:
  - a typed round-trip check for `EvaluateAsync<T>(string)`;
  - a typed-state check for `EvaluateAsync<T, TState>` with a source-generated `JsonSerializerContext` for `TState`;
  - a `TypedEvaluateRoundTrip` `AllocationGate`.
- The gate budget is measured and follows the Phase 1.8 rule: about 10% headroom, because the path goes through HTTP. It is expected to be below `EvaluateRoundTrip`'s 5120 B, and the measurement is recorded.
- The benchmarks gain typed against untyped `EvaluateAsync`, over the same canned handler.

**Live tests.** `GeneratedQuestionSet_ParsesTypedAnswers` switches to `EvaluateAsync<LiveTriage>`, which drops the reflection-based JSON options.

## Tests

- **Unit:**
  - The request each overload writes is JSON-equal to the matching `SystemOneRequest` serialization.
  - `T.Parse` runs on response answers, including answers that arrive out of order and extra top-level fields.
  - A response with no `answers`, or an answer of the wrong type, gives `InvalidResponse`.
  - Retries and `Retry-After` behave identically on the typed path.
  - The default interface method, through a minimal test double implementing only the two abstract members, returns the same typed result.
  - `JevClientOptions.Model` is validated and sent.
  - Pooled buffers are returned on errors, checked with a counting `ArrayPool` or the tests' pool hook.
- **Equality and boxing:** two parses of the same JSON give equal records with equal hash codes (#12). The indexer's success path doesn't allocate (#13).
- **Generator:** with and without `State`, snapshots show the generic interface; JEV107 fires for invalid `State` types.
- **Integration:** a typed round trip over WireMock, with a 503 then a 200, showing the retry-count header and the typed result.
- **AOT:** the typed and typed-state checks plus the `TypedEvaluateRoundTrip` gate pass under Native AOT with zero warnings.
- **Regression:** every existing test stays green.

## Open Questions

None. Decided in the brainstorm: default interface methods, `State` on the attribute, the model from `JevClientOptions`, the raw endpoint behind a method-level serializer, a separate name for the UTF-8 overload, and content equality for `ProbabilityMap<T>`.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| ZeroAlloc.Rest or Resilience doesn't support a method-level `[Serializer]` together with the error mapper and retry on one interface | The raw path can't use the generated client | Spike first; if it fails, file the upstream issue and use a documented hand-written call that reuses the mapper and retry policy |
| Default interface methods and trimming or AOT | Warnings or missing code | The AOT smoke app exercises the default path through a small test double too |
| The pooled-buffer lifetime crosses the retry proxy | Use-after-return or leaks | `RawJson` owns its buffer; the writer and reader dispose deterministically; a counting-pool test covers it |
| Raw UTF-8 state that isn't a single JSON value is written unchecked | A malformed request | Validate with `Utf8JsonReader` before writing; throw `ArgumentException` |
| Content equality on `ProbabilityMap<T>` makes hashing cost more | Slower hashing of records | Computed only on demand; documented |
