# Phase 1.8 Design — CI and release pipeline

**Date:** 2026-09-27
**Phase:** 1.8
**Surface:** Infra
**Stage:** phase (one phase, implementation-ready)

> Already in place from phase 1.5: CI `build` (restore, build, test, pack) and `aot-smoke` jobs, release-please without a publish job, and ruleset "Main" requiring `build` and `aot-smoke`. Org precedent:
> - ZeroAlloc.Resilience and ZeroAlloc.Rest have `benchmarks.yml`, which calls `ZeroAlloc-Net/.github`'s shared `benchmark-smoke.yml`.
> - Resilience has a `PackTests` project and a `trigger-website.yml` copied from the org template.
> - ZeroAlloc.Mediator and ZeroAlloc.Authorization run `AllocationGate`, from ZeroAlloc.TestHelpers, in their AOT smoke apps.

## Goal

CI proves that the package is zero-allocation where it claims to be, that its benchmarks still run, and that the `.nupkg` ships the generator correctly. It also proves that the AOT smoke app is free of every trim and AOT warning. Separately, docs changes reach the org website. NuGet publishing stays off.

## Approach

**Allocation gates.**
- **Where:** the AOT smoke app gains `AllocationGate` checks. The helper comes from ZeroAlloc.TestHelpers (source-only, `PrivateAssets="all"`, already in `Directory.Packages.props`), and the checks run under Native AOT in the `aot-smoke` job.
- **Paths gated:**
  - The generated `Parse` of a `[JevQuestions]` set, from UTF-8 answer bytes.
  - `JevAnswerReader.ReadNoul`, `ReadChoice` and `ReadScore`, into a caller-supplied buffer.
  - Serializing a `SystemOneRequest` and deserializing a `SystemOneResponse` through the source-generated context.
- **Budgets:** each gate has a byte budget over a fixed iteration count.
  - Zero where the path truly allocates nothing.
  - Otherwise the measured value, rounded up a little, with a comment naming what the bytes are, for example "the result record and its probability buffer".
  - A budget is a regression gate, not a target. Lowering one is welcome; raising one needs a stated reason.

**Benchmarks.**
- **Project:** `benchmarks/ZeroAlloc.Jev.Benchmarks`, using BenchmarkDotNet with `[MemoryDiagnoser]` and the same org layout as the siblings.
- **What it measures:** the gated paths, plus `EvaluateAsync` end to end against an in-memory `HttpMessageHandler`, so client overhead is visible without network time.
- **Workflow:** `.github/workflows/benchmarks.yml`, mirroring ZeroAlloc.Resilience's.
  - The `smoke` job calls the org's `benchmark-smoke.yml@main` on pull requests and pushes to main.
  - The `full` job measures for real on `workflow_dispatch` and uploads `BenchmarkDotNet.Artifacts`.
- **Baseline:** no numbers are committed, because they depend on the machine. The maintainer records the first full run's summary in `docs/performance.md`, which is created with an explanatory stub.

**Package checks.**
- **Generator packing (#14):** `ZeroAlloc.Jev.csproj` stops hard-coding `bin/$(Configuration)/netstandard2.0`. A target that runs before `_GetPackageFiles` calls `MSBuild` with `Targets="GetTargetPath"` on the generator project reference, and packs the returned path under `analyzers/dotnet/cs`.
- **Org issue:** every sibling hard-codes the same path, so one issue on `ZeroAlloc-Net/.github` records the pattern and the fix.
- **Pack tests:** a new `tests/ZeroAlloc.Jev.PackTests` project runs `dotnet pack` for `src/ZeroAlloc.Jev` into a temporary directory, then opens the `.nupkg` as a zip. It asserts that:
  - `analyzers/dotnet/cs/ZeroAlloc.Jev.Generator.dll` is present;
  - `lib/net10.0/ZeroAlloc.Jev.dll` and `ZeroAlloc.Jev.xml` are present;
  - there are no other analyzer or lib assemblies;
  - the nuspec dependencies are exactly the runtime packages, never the generator or an analyzer package.
- **Where it runs:** the existing CI `build` job picks the project up through the solution test run.

**IL warnings (#30).** The AOT smoke csproj swaps its six-code `WarningsAsErrors` for `TreatWarningsAsErrors=true`, and the `aot-smoke` comment in `ci.yml` is updated. Any warning this reveals is fixed at its root.

**Toolchain (#15).** The README states the minimum toolchain: the .NET 10 SDK, 10.0.100 or later, because the generator compiles against Roslyn 5.0. An IDE must host Roslyn 5.0 or later. Name specific IDE versions only where they can be verified.

**Website.**
- `.github/workflows/trigger-website.yml` is copied from the org template. It dispatches `submodule-update` to `ZeroAlloc-Net/.website` on pushes to `docs/**`, using the org secret `WEBSITE_DISPATCH_TOKEN`, which this repository can already see.
- ROADMAP Phase 4.3 is re-pointed from "Docusaurus on GitHub Pages" to the org website:
  - user docs in `docs/`;
  - a `repos/jev` submodule and an `apps/docs-jev` app in `.website`;
  - served at jev.zeroalloc.net, the address `PackageProjectUrl` already uses.
- Until then each dispatch is a harmless no-op.

**Deferred:**
- api-compat (#28), which needs a released baseline.
- NuGet publishing (#29), until the maintainer declares the package mature.

GitVersion, which the roadmap goal names, is dropped: the org versions with release-please.

## Tests

- **Allocation:** the AOT smoke app fails, with a non-zero exit and `aot-smoke` red, when a gated path exceeds its budget. Check this once locally by temporarily lowering a budget below the measured value, and record it in the task report.
- **Benchmarks:** every benchmark runs in the smoke gate locally, using the same `--job Dry` style run the org workflow uses. The project builds in the solution.
- **Pack:** the pack tests pass. Check once that they fail when the generator is removed from the package, by temporarily breaking the target.
- **AOT:** the smoke app publishes with `TreatWarningsAsErrors` and passes every check on linux-x64 in CI and on win-x64 locally.
- **Regression:** the unit (231), generator (57) and integration (15) tests stay green. Live tests stay skipped without `JEV_LIVE=1`. The solution build has 0 warnings.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Allocation differs between JIT and Native AOT, or between runtime patch versions | Flaky `aot-smoke` | Gates run only under AOT in CI; budgets are measured values rounded up; zero budgets only where the code truly allocates nothing |
| `TreatWarningsAsErrors` in the smoke app surfaces warnings from dependencies such as ZeroAlloc.Rest and ZeroAlloc.Resilience | `aot-smoke` fails | Fix in this repo when the warning is ours; if it is upstream, file an upstream issue and suppress only that code in the smoke csproj, with the issue link, telling the maintainer |
| The pack test is slow or collides with the solution's own pack step | Slow or flaky CI | Pack into a unique temporary directory with `--no-build` against the already-built output where possible; one test class |
| The benchmark smoke gate needs the org workflow's project layout | Workflow fails | Mirror ZeroAlloc.Resilience's `benchmarks.yml` and project exactly |
| The website dispatch fails because `.website` has no Jev submodule yet | A red workflow on docs pushes | `repository-dispatch` only sends the event, so it succeeds whatever `.website` does with it; check after the first docs push |
