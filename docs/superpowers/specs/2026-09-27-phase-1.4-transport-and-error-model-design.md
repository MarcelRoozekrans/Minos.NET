# Phase 1.4 Design — Transport and error model

**Date:** 2026-09-27
**Phase:** 1.4
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

> Merges the former phases 1.4 (Transport) and 1.5 (Error model): ZeroAlloc.Rest 2.1.0's `[ErrorMapper]` makes the public client signature depend directly on `JevError`, so both are designed together. The later Milestone 1 phases renumber: Resilience 1.5, Test harness 1.6, CI and release 1.7.

## Goal

A public, AOT-safe `JevClient` that calls `POST /v1/systemone` and `GET /v1/models` on TypeSafe or OpenRouter and returns `Result<T, JevError>` for every outcome — success, HTTP error status, network failure, time-out and unreadable response — without throwing for anything but programming errors and caller cancellation.

## Approach

**Public surface.** `IJevClient` declares `ValueTask<Result<SystemOneResponse, JevError>> EvaluateAsync(SystemOneRequest request, CancellationToken ct = default)` and `ValueTask<Result<ModelList, JevError>> ListModelsAsync(CancellationToken ct = default)`. `JevClient : IJevClient, IDisposable` has two constructors: `JevClient(JevClientOptions? options = null)`, which creates and owns its `HttpClient`, and `JevClient(HttpClient httpClient, JevClientOptions? options = null)`, where the caller owns the `HttpClient`. `EvaluateAsync` is the raw form; Phase 2.1's typed `EvaluateAsync<T>` joins the same family. `Result<T, E>` is ZeroAlloc.Results', which becomes a package dependency.

**Configuration.** `JevClientOptions` has `set` properties (so Milestone 3's `services.Configure<JevClientOptions>(...)` can populate them): `Provider` (`JevProvider.TypeSafe` default, or `JevProvider.OpenRouter`), `ApiKey`, `BaseAddress` and `Timeout` (default 60 s). Resolution, first match wins:
- API key: `ApiKey`, then `TYPESAFE_API_KEY` for TypeSafe or `OPENROUTER_API_KEY` for OpenRouter. None found → `InvalidOperationException` at construction naming the variable to set. The resolved key is trimmed; a key that still contains a control character throws `ArgumentException` (an option key) or `InvalidOperationException` naming the variable (an environment key), without echoing the key in the message.
- Base address: `BaseAddress`, then — for `JevProvider.TypeSafe` only — `TYPESAFE_BASE_URL`, then the provider default: `https://api.typesafe.ai/` for TypeSafe, `https://openrouter.ai/api/` for OpenRouter (both on `JevDefaults`). `TYPESAFE_BASE_URL` never applies to `JevProvider.OpenRouter`, so an OpenRouter key is never sent to a TypeSafe proxy. The result is normalised to end with `/` so relative routes `v1/...` resolve under OpenRouter's `/api/`.
- Invalid values (non-absolute base address, a base address with a query or fragment, a base address whose scheme is not http or https, non-positive time-out, unknown provider) throw `ArgumentException` at construction for an option, or `InvalidOperationException` naming `TYPESAFE_BASE_URL` for the environment variable.
- A caller-supplied `HttpClient` with its own `BaseAddress` already set is validated with the same rules (absolute, http or https, no query or fragment, path ending in `/`); an invalid one throws `ArgumentException` with parameter name `httpClient`, and the caller's client is never modified.
Environment variables are read through an internal seam so tests never touch the process environment. `JevDefaults.Model` becomes a `static` property instead of a `const`, so a changed default is not compiled into callers.

**Transport.** An internal `[ZeroAllocRestClient(MaxErrorBodyBytes = 16384)] [ErrorMapper(typeof(JevErrorMapper))] interface IJevApi` declares `[Post("v1/systemone")]` with a `[Body] SystemOneRequest` and `[Get("v1/models")]`, each with an internal `[Header("Authorization")] string authorization` parameter carrying `Bearer {key}` on every request — a caller-supplied `HttpClient` is never mutated for auth, and the key never appears in public API. The generated client (internal) is constructed directly with the `HttpClient`, a per-client `new SystemTextJsonSerializer(JevJson.Options)` and the mapper; no DI (Milestone 3). For an owned `HttpClient`: base address, `Timeout`, and `User-Agent: Jev.Net/{informational version}`. For a caller-supplied `HttpClient`: its `BaseAddress` wins when set (validated with the same rules as a configured address, plus a required trailing `/`, since the caller's client is never modified), otherwise ours is assigned; its time-out is left alone. `Dispose` disposes only an owned `HttpClient`. `ListModelsAsync` with `Provider = OpenRouter` returns `JevError` of kind `Unsupported` without sending a request — OpenRouter's `/api/v1/models` is its own Models API with a different shape.

**Error model.** `public sealed class JevError` exposes `JevErrorKind Kind`, `int? StatusCode`, `string Message`, `TimeSpan? RetryAfter`, `JsonElement? Detail` and `Exception? Exception`. `JevErrorKind`: `Unauthorized`, `Validation`, `RateLimited`, `Overloaded`, `Server`, `Http`, `Network`, `Timeout`, `InvalidResponse`, `Unsupported`. The internal `JevErrorMapper : IHttpErrorMapper<JevError>` maps ZeroAlloc.Rest's `HttpError`:
- `Status` kind: 401/403 → `Unauthorized`; 400/422 → `Validation`; 429 → `RateLimited`; 529/503 → `Overloaded`; other 5xx → `Server`; any other status → `Http`.
- `Transport` → `Network`; `Timeout` → `Timeout`; `Deserialization` → `InvalidResponse`; each carries the exception.
- `RetryAfter` from the `Retry-After` header in either form (delta-seconds or HTTP date, relative to now; past dates → zero); absent or unparseable → `null`.
- `Detail`: when the body is non-empty, not truncated and has a JSON content type (`application/json` or `+json`), parsed and cloned so it outlives the buffer; otherwise `null`. `Message` is a short human-readable summary (status and reason, or the exception message).
Caller-requested cancellation still throws `OperationCanceledException` (ZeroAlloc.Rest behaviour). A 2xx response whose `answers` object contains a `null` entry (which `RespectNullableAnnotations` does not reject for dictionary values — Phase 1.2 follow-up) is returned as `InvalidResponse` by `EvaluateAsync`, so callers never see a null answer. Writing an uninitialised `default(JevContent)` in a request still throws: it is a programming error, not a call outcome.

**Wire-model additions (OpenRouter).** Optional `string? Id` and `string? Provider` on `SystemOneResponse`, and `double? Cost` on `JevUsage`. They are absent from TypeSafe responses and present on OpenRouter's.

## Tests

- **Request shape:** method, absolute URL for both providers (`https://api.typesafe.ai/v1/systemone`, `https://openrouter.ai/api/v1/systemone`, `https://api.typesafe.ai/v1/models`), `Authorization: Bearer <key>`, and the JSON body equal to the Phase 1.2 request fixture.
- **Success:** `response-noul/choice/score.json` and new `response-openrouter.json` (with `id`, `provider`, `usage.cost`) parse through the client; `models.json` through `ListModelsAsync`.
- **Error mapping:** every status → kind row above; `Retry-After` delta-seconds, HTTP date, past date, absent and garbage; 422 with JSON detail, non-JSON body, truncated body; network failure (handler throws `HttpRequestException`); time-out (handler outlasts `Timeout`); invalid 2xx JSON → `InvalidResponse`.
- **Null answers:** a response with `"answers": {"x": null}` → `InvalidResponse`.
- **Cancellation:** a cancelled caller token throws `OperationCanceledException`.
- **OpenRouter models:** `ListModelsAsync` → `Unsupported` with zero requests sent.
- **Configuration:** explicit key, each environment fallback, missing key throws naming the variable; base address precedence and `/` normalisation; invalid options throw.
- **Ownership:** disposing a client disposes an owned `HttpClient` and leaves a caller-supplied one usable; a caller-supplied `BaseAddress` is respected.
- **Regression:** existing 149 tests stay green; build warning-free under `IsAotCompatible` analyzers.
- WireMock.Net component tests and key-gated live smoke tests are Phase 1.7.

## Open Questions

None blocking. Decided in the brainstorm: phases merged; OpenRouter model listing fails fast with `Unsupported`; `Provider` enum plus options; one `JevError` type with a `Kind` enum (plus an `Http` catch-all kind); raw method named `EvaluateAsync`.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| ZeroAlloc.Rest 2.1.0 generated constructor or `[Header]` usage differs from the docs | Client wiring needs rework | Plan task inspects the generated source first; fallback is `Create`-style construction the docs describe |
| STJ serializer through ZeroAlloc.Rest raises IL2026/IL3050 under `IsAotCompatible` | Breaks the zero-warning DoD | The gap analysis found 1.3.5 clean with generated suppressions; verify on 2.1.0 in the first task and fix at the source (upstream issue) if not |
| TypeSafe's real 422 body shape and `Retry-After` usage are unknown | `Detail`/`RetryAfter` untested against reality | Raw JSON `Detail` avoids guessing a schema; the live smoke suite in 1.6 confirms |
| Time-out tests are slow or flaky | CI noise | Use a tiny `Timeout` with a handler that awaits the cancellation token, not wall-clock sleeps |
