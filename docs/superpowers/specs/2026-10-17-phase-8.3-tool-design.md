# Phase 8.3 Design — `The minos tool`

**Date:** 2026-10-17
**Phase:** `8.3`
**Surface:** `Infra`
**Stage:** phase (one phase, implementation-ready)

## Goal

A .NET user runs `dotnet tool install -g Minos.NET.Tool`, and then:
- `minos calibrate` against any configured System One provider, to get a results file and a calibration report;
- `minos report`, to rebuild a report from saved results without calling the provider;
- `minos conformance`, to check an endpoint.

`Minos.NET.Evaluation` and `Minos.NET.Tool` are published to nuget.org through the release path, as 1.2.0.

## Decisions

By the maintainer:
- **Milestone design, 2026-10-17:**
  - The package is `Minos.NET.Tool` and the command is `minos`.
  - It runs `calibrate` and `conformance` against any System One provider.
  - Providers are configured with the provider-switch layout, plus a model override.
  - The conformance suite ships inside the tool, not as its own package.
  - Prices come from a dated table.
- **This phase, 2026-10-17:**
  - **#228:** when a client exception stops a run, the runner throws a `DatasetRunException` that carries the partial `EvaluationResults` of the finished items. The tool saves them as `results.partial.jsonl` and exits non-zero, so a report can still be built from what was paid for.
  - **The command-line parser is System.CommandLine 2.0** (2.0.13). Only the tool depends on it.

My calls:
- **Commands and options:**
  - `minos calibrate --dataset <file.jsonl> [--config <file>] [--provider <name>] [--model <id>] [--parallel <n>] [--prices <file>] [--out <dir>]`
  - `minos report --results <file.jsonl> --dataset <file.jsonl> [--prices <file>] [--out <dir>]`
  - `minos conformance [--config <file>] [--provider <name>] [--model <id>] [--out <dir>]`
- **Defaults:**
  - `--config` defaults to `minos.json` in the current directory.
  - `--provider` defaults to the configuration's `Minos:Active`.
  - `--parallel` defaults to 1.
  - `--out` defaults to `./minos-out/<provider>-<UTC yyyyMMdd-HHmmss>/`.
- **Output files:**
  - `calibrate` writes `results.jsonl`, `report.json` and `report.md`.
  - `report` writes `report.json` and `report.md`.
  - `conformance` writes `conformance.json` and `conformance.md`.
  - Each command prints the paths it wrote and a short summary to stdout.
- **Configuration is the provider-switch layout:** `Minos:Active` and `Minos:Providers:<name>`, each section bound as `SystemOneDecisionClientOptions`.
  - API keys come from the environment exactly as the client already reads them.
  - Environment variables override the file, through the standard .NET configuration chain: the file, then unprefixed environment variables with `__` as the separator (see Settled item 3).
  - `--model` overrides the section's `Model`.
  - An unknown provider name, or a section that fails options validation, is a clear error, and the exit code is 2.
- **The prices file:** JSON, `{"prices":[{"model":"…","inputPerMillion":…,"outputPerMillion":…,"date":"yyyy-MM-dd","source":"…"}]}`. It is read into a `PriceTable`. Without one, cost uses reported costs only.
- **Exit codes:**
  - 0: done.
  - 1: the run or the check finished, but a `DatasetRunException` stopped it partway, or conformance has a failed check.
  - 2: usage, configuration or input problems, such as dataset problems or results problems. These are printed with their line numbers.
- **The tool has no public API.** Everything in it is `internal`, and `Program` is the entry point. It is framework-dependent, not AOT. It targets net10.0 like the libraries.
- **Packing:**
  - `Minos.NET.Evaluation` becomes packable.
  - `Minos.NET.Tool` is a `PackAsTool` package with `ToolCommandName` `minos`. The conformance code is linked in, as a project reference that is not packed separately.
  - **Package validation baseline:** both new ids have no 1.0.1 to compare with, so the 1.0.1 baseline is turned off for them. A comment in `Directory.Build.targets` or the csproj says to turn it on once they have published.
- **Release:** a `feat:` commit releases 1.2.0. All 8 packages version together, as now.
  - Trusted Publishing's glob is `*`, so the two new ids publish under the same policy.
  - `Minos.NET.Tool` is a new id under the reserved prefix.

## `DatasetRunException` (#228)

A new type in `Minos.Evaluation`: `public sealed class DatasetRunException : Exception`.
- **`PartialResults`:** an `EvaluationResults` holding the items that finished, in dataset order. It contains only finished items, so `ItemCount` equals the number of finished items. The header's `Finished` is the time of the stop.
- **`InnerException`:** the original exception.
- **What triggers it:** `DatasetRunner.RunAsync` throws it when a client or progress exception stops the run.
- **What does not change:**
  - Cancellation still throws `OperationCanceledException`.
  - A `DecisionError` is still recorded on its item, as now.
- **Breaking change:** callers that caught the raw client exception now catch `DatasetRunException` instead. The package is unreleased, so this is acceptable.

## Settled after the builder check (my calls)

1. **Partial results feed `minos report`.**
   - `RunHeader` gains `bool Partial`, written in the results file as `"partial": true` and absent or `false` otherwise. The format is unreleased, so it stays version 1.
   - `DatasetRunException.PartialResults` has `Partial = true`.
   - With a partial header, `CalibrationReport.Create` matches the results against the dataset by id. The result items must be a subset of the dataset's ids, in dataset order, and that order holds even when there are gaps.
   - The report labels itself partial, as "Partial run: N of M items". The JSON gets `header.partial` and `datasetItemCount`.
   - Without a partial header, the match stays exact, as now.
   - The tool needs no extra flag.
2. **`minos conformance` targets:**
   - The provider section is bound into `SystemOneDecisionClientOptions`.
   - The `ModelRule` is the TypeSafe rule for `SystemOneProvider.TypeSafe` and the OpenRouter rule for `OpenRouter`. Every other provider has no rule, so the model check is reported as skipped.
   - The model is `--model`, then the section's `Model`, then the preset's default. A Custom section with no model already fails options validation, which exits 2. `conformance` therefore gains `--model`.
   - The live probes run without asking for confirmation. Running the command is the request. The tool prints the provider and model before it starts. Record and replay are not exposed.
3. **Configuration binding:**
   - The tool reads the `Minos` section of a chain made of the `--config` file and then unprefixed environment variables, the same as the provider-switch sample. An example override is `Minos__Providers__OpenRouter__Model`.
   - There is no `MINOS_` prefix; this replaces the earlier wording.
4. **Validating the tool package:**
   - `inspect_packages.py` checks that `Minos.NET.Tool` has the `DotnetTool` package type and no `Minos.NET*` nuspec dependencies.
   - It also checks the bundled `tools/net10.0/any/Minos.NET*.dll` files, including the tool's own DLL. Each must carry the release version as its informational version, which catches a stale `-local` build.
   - A `.snupkg` for the tool is checked only if the SDK produces one.
   - Evaluation's Minos dependency list is `("Minos.NET",)`. `ZeroAlloc.Results` is external and is not listed.
5. **Exit codes:**
   - 0: success. A skipped conformance check counts as a pass.
   - 1: a run-time failure. That covers:
     - a `DatasetRunException`;
     - a failed conformance check;
     - a network or unexpected exception;
     - an output directory that cannot be written.
   - 2: input or configuration problems.
   - 130: cancelled with Ctrl+C.
   - Every failure prints one clear line on stderr.

**Facts confirmed:**
- **CI:** the pack-validate consumer loop cannot `dotnet add package` a tool. A separate step installs `Minos.NET.Tool` from the local feed with `dotnet tool install --tool-path … --add-source …`, and then runs `minos --help`.
- **Stale text:** remove every place that still says "six packages" or "Evaluation is not packed yet". That includes:
  - the `ci.yml` comments and step names;
  - `RELEASING.md`;
  - the comments in the Evaluation, Conformance and AotSurface csproj files.
- **READMEs:** `Directory.Build.props` packs the root `README.md` into every packable project. The Evaluation and Tool projects replace that item with their own README.

## Tests

- **Tool, end to end in-process:**
  - **Fake setup:** a temporary config with a provider whose `BaseAddress` points at a fake handler or in-memory server, plus a small dataset.
  - **`calibrate`:**
    - writes the three files;
    - `report.json` has `kind` `minos-report`;
    - the exit code is 0;
    - `--model` reaches the request body;
    - `--parallel` is honoured;
    - `--prices` gives a priced cost;
    - a dataset with problems exits 2 and prints them with line numbers;
    - an unknown provider exits 2;
    - a client that throws mid-run exits 1 and writes `results.partial.jsonl`.
  - **`report`:** rebuilds an identical `report.json` from saved results; a dataset mismatch exits 2.
  - **`conformance`:** writes both files against a conforming fake. A failing fake exits 1.
  - **`--help`:** each command has help text, pinned by a snapshot.
- **`DatasetRunException`:**
  - its partial results contain the finished items in dataset order, they save and load, and `ItemCount` matches;
  - the inner exception is the original;
  - cancellation is unchanged.
- **Packaging:**
  - the pack tests cover the Evaluation package's content and dependencies, and the tool package's type, command name and entry point;
  - the inspection script takes 8 packages;
  - CI installs the tool from the local feed and runs `minos --help`.
- **Docs:** the configuration and prices examples parse and bind.
- **Regression:** the full suite, plus the AOT smoke app and the gates. The tool is not in the AOT checks.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The tool package bundles assemblies that conflict with a user's global tools | Install problems | Tools are isolated per tool, so this cannot happen. |
| The first publish of two new ids fails, for example on the policy or the prefix | 1.2.0 is published partly | Same mitigation as 1.0.1: `resume=true` and `--skip-duplicate`. The glob `*` and the reserved prefix cover both ids. |
| Package validation fails for new ids with no baseline | CI is red | The baseline is turned off for those two ids until their first release, as Decisions says. |
| System.CommandLine 2.x API differences from older samples | Wasted time | Pin 2.0.13 and follow its current API. |
| Real billed runs happen through the tool by accident in tests | Cost | The tests use fake handlers only. Live runs belong to Phase 8.4 and need approval. |
