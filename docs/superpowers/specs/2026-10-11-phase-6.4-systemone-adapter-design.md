# Phase 6.4 Design — `/v1/systemone adapter`

**Date:** 2026-10-11
**Phase:** `6.4`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)

## Goal

The `/v1/systemone` protocol moves out of the core into its own `Minos.NET.SystemOne` package. That package adds presets for TypeSafe, OpenRouter, Cloudflare Workers AI (Clef), vLLM Semantic Router and custom servers, capability flags checked before a request is sent, optional auth and `AddSystemOneClient` DI registrations, default or keyed. The core becomes abstraction-only, so Phase 6.5's OpenAI package sits beside it as an equal (#115).

## Decisions (maintainer, 2026-10-11)

- **Full split now.** Phase 6.1 decided on "an abstraction-only core, plus one package per protocol", and 6.2 and 6.3 left the split to this phase. This phase moves the concrete client, its options, the protocol, the transport and the raw System One calls into `Minos.NET.SystemOne`. It is a breaking change, made before 1.0.
- **Presets are an enum, with capability overrides.** `SystemOneProvider` names a closed set of presets. Each one resolves internally to a base address, a request path, an auth rule and default capabilities. The options can override the capabilities and the path, so a server that supports Noul only says so. It binds from configuration as `"Provider": "OpenRouter"`. Two alternatives were rejected:
  - public preset objects, which are open-ended but need a separate name string to bind from configuration, and widen the API;
  - documentation-only values, which make every user re-type the vendor details.
- **Cloudflare is built and verified live.** Cloudflare's Clef endpoint is account-scoped and does not serve `/v1/systemone`. The maintainer adds `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` to the `live-api` environment. A live test records the real response, and the envelope reader is built against that fixture, not against the docs alone.
- **The local test server is ollajev, run in CI.** The first task spikes it on a GitHub-hosted runner. If it works, a non-required `local-systemone` job runs the Custom preset against it. If it does not, the result and a documented manual run are recorded instead, and the recorded fixtures carry the proof.
- **DI is provider-neutral, plus `AddSystemOneClient`.** `Minos.NET.DependencyInjection` keeps the default and keyed registration, the pipeline builder and a factory overload. `Minos.NET.SystemOne` depends on it and adds `AddSystemOneClient`. Phase 6.5's OpenAI package follows the same pattern. Two alternatives were rejected:
  - a separate `Minos.NET.SystemOne.DependencyInjection` package, which gives a leaner graph at the cost of two packages per protocol;
  - a DI package that references SystemOne, which 6.5 would have to undo.

## Research (2026-10-11)

These facts come from vendor pages unless marked otherwise. Each one that the code depends on is verified by a live call or a recorded fixture before code is built on it.

| Provider | Endpoint | Auth | Notes |
|---|---|---|---|
| TypeSafe | `https://api.typesafe.ai/v1/systemone` | Bearer, `TYPESAFE_API_KEY` | Noul, Choice with up to 255 options, Score with 2–10 levels. Errors 401, 422, 429, 529. `GET /v1/models` is used by today's client. |
| OpenRouter | `https://openrouter.ai/api/v1/systemone` | Bearer, OpenRouter key | Model ids such as `typesafe/jev-1.13`. Its `/api/v1/models` returns OpenRouter's own shape, not System One's. |
| Cloudflare Workers AI | `https://api.cloudflare.com/client/v4/accounts/{account}/ai/run/@cf/cloudflare/{model}` | Bearer, Cloudflare API token | Models `clef` and `clef-flash`. The body is `model`, `state` and `questions` (1–64), with optional `images` (6.5). All three kinds. The clef-flash context is 24,576 tokens. The response envelope is not documented on the model page. |
| vLLM Semantic Router | `{base}/v1/systemone` | Optional Bearer | All three kinds. Kai and Lex allow 1,024 tokens per question, larger models 16,384. 422 `max_length_exceeded` and `invalid_question`. No default port is documented. Apache-2.0. |
| jevos (local) | `http://localhost:8080/v1/systemone` | Optional | Noul only; Choice and Score return 422. The case the capability flags exist for. |
| ollajev (local) | `http://127.0.0.1:8000/v1/systemone` | None on localhost | All three kinds, `GET /v1/models`, Apache-2.0, pip-installable on Python 3.12. How to choose a model non-interactively, and its RAM use, are unverified. |

## Approach

### Packages

- **`Minos.NET` (core)** keeps:
  - `IDecisionClient`, `DelegatingDecisionClient`, `DecisionClientBuilder` and the retry, logging and OpenTelemetry stages;
  - the question model, the generator contract, `DecisionRequest`, `DecisionResponse` and `DecisionContent`;
  - `DecisionError`, `DecisionErrorKind` and `QuestionFailure`, `DecisionClientMetadata` and the telemetry types.

  `DecisionClient`, `DecisionClientOptions`, `DecisionProvider`, the provider-specific parts of `DecisionDefaults`, `Transport/`, `Protocols/`, `SystemOneRequest` and the raw response types all leave the core. Internal helpers that both packages need are shared through `InternalsVisibleTo` only where an internal type must cross, never by making it public. The plan lists each one.
- **`Minos.NET.SystemOne`**, namespace `Minos.SystemOne`:
  - `SystemOneClient : IDecisionClient`, renamed from `DecisionClient`. It keeps the raw `EvaluateAsync(SystemOneRequest)` and `ListModelsAsync`, the constructors, `ConfigureHttpClient` and the standard pipeline.
  - `SystemOneClientOptions`, renamed from `DecisionClientOptions`.
  - `SystemOneProvider` and `SystemOneCapabilities`.
  - `SystemOneDefaults`, which holds the environment variable names, base addresses and default model that leave `DecisionDefaults`.
  - The protocol, transport, request and response types.
  - `AddSystemOneClient` extensions in the `Microsoft.Extensions.DependencyInjection` namespace.
- **`Minos.NET.DependencyInjection`** becomes provider-neutral. It keeps `DecisionClientServiceBuilder` and the default and keyed registration logic. The public entry point is `AddDecisionClient(this IServiceCollection, Func<IServiceProvider, IDecisionClient>)` and its keyed overload with a `string name`. Each returns the registration's builder. The SystemOne-specific overloads, options binding, validator and named `HttpClient` move to `Minos.NET.SystemOne`, built on internal helpers that the DI package exposes to it.

### Presets

`SystemOneProvider` values:

| Preset | Base address | Path | Key | Key from environment |
|---|---|---|---|---|
| `TypeSafe` (default) | `https://api.typesafe.ai/`, or `TYPESAFE_BASE_URL` | `v1/systemone` | required | `TYPESAFE_API_KEY` |
| `OpenRouter` | `https://openrouter.ai/api/` | `v1/systemone` | required | `OPENROUTER_API_KEY` |
| `CloudflareWorkersAi` | `https://api.cloudflare.com/client/v4/` | `accounts/{AccountId}/ai/run/@cf/cloudflare/{model}` | required | `CLOUDFLARE_API_TOKEN` |
| `VllmSemanticRouter` | `BaseAddress` required | `v1/systemone` | optional | none |
| `Custom` | `BaseAddress` required | `v1/systemone`, or `Path` | optional | none |

The rules:
- `BaseAddress` always overrides a preset's address, with today's checks: absolute, http or https, no query or fragment.
- `TYPESAFE_BASE_URL` applies to `TypeSafe` only, as today.
- `CloudflareWorkersAi` needs `AccountId`, from the option or `CLOUDFLARE_ACCOUNT_ID`. It must match `[A-Za-z0-9]+`, so it cannot change the path. The model goes into the path escaped as a single segment, and into the body as well.
- `Custom` and `VllmSemanticRouter` never read a key from the environment, so a vendor key is never sent to an arbitrary server. An explicit `ApiKey` is sent as a Bearer token. With no key, no `Authorization` header is sent.
- `Path` is a relative path without a query. It overrides the preset's path for `Custom` and `VllmSemanticRouter` only; on the hosted presets it is a validation error.
- The default model stays `jev-latest` for `TypeSafe` and `OpenRouter`. The other presets have no default model, so `Model` must be set; a blank model fails validation, as today.

### Capabilities

`SystemOneCapabilities` is a class in the options, bindable from configuration:
- `QuestionKinds`, a `[Flags]` enum of Noul, Choice and Score;
- `MaxQuestions`, an `int?`;
- `MaxChoiceOptions`, an `int?`;
- `Images`, a `bool?`, declared now and enforced in 6.5;
- `ModelListing`, a `bool?`.

Each property left unset takes the preset's default:

| Preset | Kinds | MaxQuestions | MaxChoiceOptions | Images | ModelListing |
|---|---|---|---|---|---|
| `TypeSafe` | all | unset | 255 | false | true |
| `OpenRouter` | all | unset | 255 | false | false |
| `CloudflareWorkersAi` | all | 64 | 255 | true | false |
| `VllmSemanticRouter` | all | unset | unset | false | false |
| `Custom` | all | unset | unset | false | true |

A preset default is a claim about the vendor. The plan verifies each one against the vendor's docs or a live call, and records any it cannot verify. The client resolves the capabilities once, when it is constructed, and `GetService(typeof(SystemOneCapabilities))` returns them.

### The capability check

Before sending a typed or neutral call, `SystemOneClient` checks the request's question set:
- each question's kind is in `QuestionKinds`;
- the question count is within `MaxQuestions`;
- each Choice question's option count is within `MaxChoiceOptions`.

A failure returns `DecisionError` with `Kind = Unsupported` and sends no request. Its message names the provider and the first problem, for example "VllmSemanticRouter does not support Choice questions". `Failures` holds one `QuestionFailure` for each offending question, by key.

The check runs in the transport, the innermost layer, so the telemetry and logging stages record the failure like any other. The retry stage does not retry `Unsupported`, and retrying could not change the result anyway. It walks the definition array once and allocates nothing when the set passes, and an AOT gate holds it to 0 B.

The raw calls behave differently:
- `EvaluateAsync(SystemOneRequest)` is not checked, because it is the raw pass-through.
- `ListModelsAsync` returns `Unsupported` on a provider without `ModelListing`, without sending a request.

Context size is not checked on the client, because tokens cannot be counted there. A server's 422 still maps to `Validation`, with `Detail`, as today. A server whose capabilities are declared too generously returns its own error; the client does not guess from the body.

### Cloudflare's envelope

The request is today's System One body, sent to the account path. The response reader is built against the recorded live fixture. The expected shape, Cloudflare's usual `{ "result": …, "success": …, "errors": […] }`, is confirmed or corrected by that fixture before the reader is written. The reader takes the System One answers from `result`. A `success: false` body maps `errors[]` into `DecisionError.Detail`, with the kind taken from the HTTP status, as for other errors. The envelope handling lives in the protocol, so the transport stays unaware of it.

### Telemetry and logging

`DecisionClientMetadata.ProviderName` becomes `typesafe`, `openrouter`, `cloudflare`, `vllm-sr` or `custom`. The span's `server.address` is the resolved base address host, as now. No new attributes are added.

### Out of scope

- Image state and the analyzer that warns about a capability mismatch are Phase 6.5, where images arrive. The analyzer in #115 is mostly about images.
- The Providers page with the capability matrix is Phase 6.7. This phase updates the existing pages for the package rename only.
- vLLM-SR's `/v1/systemone/batches` extension.

- `benchmarks/`: new references.
- `.github/workflows/`: a scratch spike workflow, deleted after the spike; a `local-systemone` job if the spike works; and the Cloudflare secrets in the live workflow.

## Tests

- **Unit:**
  - preset resolution for each provider: addresses, paths, required and optional keys, environment variables, `AccountId` rules, and `Path` allowed only on custom presets;
  - capability defaults and overrides;
  - the capability check: each kind, the counts, the message and `Failures`, and no request sent;
  - `ListModelsAsync` returning `Unsupported`;
  - no `Authorization` header without a key;
  - the Cloudflare envelope reader, both success and failure.
- **Integration (WireMock):** recorded fixtures for each preset's success path, a jevos-style Noul-only server returning 422, and a Cloudflare envelope.
- **DI:**
  - the `AddSystemOneClient` overloads, default and keyed;
  - two keyed providers in one container;
  - configuration binding of `Provider`, `AccountId`, `Path` and `Capabilities`;
  - validate-on-start;
  - the neutral `AddDecisionClient` factory overload.
- **AOT:** every existing gate keeps its budget unchanged, and a capability-check gate is added at 0 B on success.
- **Live:** the 13 existing tests run against the new package, and a Cloudflare test records and checks the envelope.
- **Local server:** if the spike works, a `local-systemone` job runs the Custom preset against ollajev for Noul, Choice and Score. It runs on `main` and on dispatch, and is not required.
- **Regression:** the full suite, the AOT surface and entry-point coverage, the docs tests, the pack tests and the benchmarks smoke.

## Open Questions

None blocking the plan. Two items are settled by tasks, not by the maintainer:
- whether ollajev runs on a GitHub runner, settled by the spike;
- Cloudflare's actual envelope, settled by the live recording, which needs the maintainer to add the two `live-api` secrets.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The split breaks an internal seam that both packages need | Types forced public, or duplicated code | The plan inventories every cross-package internal first and decides each one: move it, keep it in core, or share it through `InternalsVisibleTo`. Nothing goes public only to bridge packages. |
| The split costs allocations | Budgets loosen | Every gate's budget stays unchanged; the move is mechanical before any behaviour changes. |
| Cloudflare's envelope or path differs from the docs | Adapter rework | The live recording comes before the reader is written. |
| ollajev does not run on a runner | No CI proof of a local server | The documented manual run plus recorded fixtures, as the milestone allows. |
| A preset's capability default is wrong | False `Unsupported` errors, or raw 422s | Each default is checked against vendor docs or a live call, and any default that cannot be checked is listed as unverified in the code comment and in the Providers page in 6.7. Users can override every one. |
| Release-please mis-credits a multi-package breaking change | Wrong changelog | The PR override nests every commit after the first, and the release PR is checked after the merge. |

## Amendments while planning (2026-10-11)

The boundary inventory, `docs/plans/2026-10-11-phase-6.4-split-inventory.md`, and the vendor research, `docs/plans/2026-10-11-phase-6.4-provider-research.md`, settled these. The plan carries the details.

- **DI builder (maintainer):** `DecisionClientServiceBuilder` becomes a non-sealed class with an internal constructor, and loses `HttpClient`. `AddSystemOneClient` returns `SystemOneClientServiceBuilder`, which derives from it and adds `HttpClient`. The neutral DI package depends only on `Microsoft.Extensions.DependencyInjection.Abstractions` and the core.
- **Tests stay in `Minos.NET.Tests`,** which references the new package and is granted `InternalsVisibleTo` by both libraries. No `Minos.NET.SystemOne.Tests` project is created.
- **Capability failures use rule ids MIN201–MIN203** in `QuestionFailure.Rule`: an unsupported kind, too many questions, too many Choice options. MIN2xx is reserved for provider-capability rules, which Phase 6.5's analyzer reuses. `DecisionError` gains an internal constructor taking a kind and failures. No public constructor is added until a third-party protocol package needs one.
- **`SystemOneClientOptions.Model` becomes nullable.** Null resolves to the preset's default model, `jev-latest` for TypeSafe and OpenRouter. The other presets require one.
- **Cloudflare's address:** the base address is `https://api.cloudflare.com/client/v4/accounts/{AccountId}/ai/run/@cf/cloudflare/`, and the request path is the model name. The `@` is never escaped. A Cloudflare model must be a single name matching `[A-Za-z0-9._-]+`.
- **The raw `EvaluateAsync(SystemOneRequest)` route becomes `{**path}`,** so Cloudflare and `Path` reach it. `IDecisionProtocol.EndpointPath` is removed, because the resolved settings own the path.
- **Observability:** the raw-call and model-list logs name the provider by its telemetry name, `typesafe`, where they used the enum name. The logger category stays `Minos.DecisionClient`. The model-list `Unsupported` message becomes "Model listing is not available on {provider}."
- **No new allocation budget.** The capability check is proven allocation-free on success by every existing typed and built-set gate keeping its measurement. The `Unsupported` path gets a functional AOT smoke check.
- **Left for 6.5:** whether `IDecisionProtocol`, `RequestStates` and `StateWriter` come back to core, and widening `QuestionSetDefinition`'s single protocol-cache slot.

## Amendment during execution (2026-10-11): Cloudflare taken out

There is no Cloudflare account to record Clef's real response with, so the maintainer chose to take the `CloudflareWorkersAi` preset out of this phase instead of building its envelope reader on an unverified shape. #151 tracks adding it back, with everything learned here. 6.4 ships the TypeSafe, OpenRouter, VllmSemanticRouter and Custom presets. The `AccountId` option, the Cloudflare defaults and environment variables, the per-model path, and the envelope reader are removed. `SystemOneClientSettings.PathFor` keeps its shape, because `Custom.Path` still uses it. `Images` stays declared for 6.5.
