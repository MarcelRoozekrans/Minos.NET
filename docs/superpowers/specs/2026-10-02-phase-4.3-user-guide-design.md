# Phase 4.3 Design — User guide

**Date:** 2026-10-02
**Phase:** 4.3
**Surface:** Docs
**Stage:** phase (one phase, implementation-ready)

## Goal

Write ZeroAlloc.Jev's user guide in `docs/`, in the org's Docusaurus layout, so jev.zeroalloc.net can serve it in Phase 4.4.

The guide becomes the single source of user documentation. Phase 4.4 then cuts the README down to an overview.

The guide covers:

- getting started;
- every question type;
- typed evaluation and builders;
- the client and its errors;
- DI and configuration;
- logging and telemetry;
- Native AOT;
- diagnostics;
- testing your own code;
- the patterns and samples.

Every C# block in the guide compiles, and each page's main example runs as a test. Closing this phase also closes issue #16.

This is the third phase of Milestone 4 (`docs/superpowers/specs/2026-10-02-milestone-4-design.md`).

## Decisions

The maintainer took these decisions during the brainstorm on 2026-10-02.

| Question | Decision | Why |
|---|---|---|
| How the guide relates to the README | **The guide becomes the source.** The README's reference content moves into guide pages, rewritten where needed. Phase 4.4 cuts the README down to an overview: what Jev is, the disclaimer, install, one example and links. | Each fact lives in one place, and the README's hand-written C# is replaced by compiled snippets. |
| Page structure | **The 13 entries below.** | They follow the org layout, sidebar and front matter that ZeroAlloc.Rest uses, and they cover the milestone's Definition of Done. |
| Code in the guide | **Every C# block is a compiled snippet**, through MarkdownSnippets from `tests/ZeroAlloc.Jev.Docs.Tests`. Each page's main example also runs as a test. | This is the same rule Phase 4.1 set for the pattern guides. |
| Keeping the guide correct | **New docs tests check front matter and every internal link and anchor**, over published pages only. | Docusaurus and GitHub both render the pages, so a broken link or a missing front-matter field would only surface when the site is built. |

## Context

- **How the org site serves docs.** It serves each library's `docs/` folder through a Docusaurus app at `apps/docs-<name>`, with `path: ../../repos/<name>/docs`, an autogenerated sidebar and `routeBasePath: '/'`.
  - ZeroAlloc.Rest excludes `**/README.md`, `**/pre-push-review*.md` and `**/plans/**`.
  - Jev's app must also exclude `planning/**` and `superpowers/**`. That is Phase 4.4's job.
- **Front matter.** ZeroAlloc.Rest's pages carry `id`, `title`, `slug` (only the first page, set to `/`), `sidebar_position` and `description`.
- **The README's "Testing" section** is for contributors: it covers running this repository's own suites. It stays in the README and is not part of the guide.

## Section 2 — Writing and verification

**Content**
- Each page is adapted from the README section it replaces, in plain language. Nothing is copied from TypeSafe.
- Statements of behaviour match the code and its tests. Pages link the API or page that pins a rule down, for example threshold boundaries, startup validation and allocation figures.
- Each page ends with "Next" links that walk a newcomer through the guide.

**Code**
- Every C# block is a `#region` in `tests/ZeroAlloc.Jev.Docs.Tests`, written into the Markdown by MarkdownSnippets.
- Each page's main example runs as a test against canned answers.
- Illustration-only snippets compile but don't run, for example the `appsettings.json` binding call.
- Shell, JSON and XML blocks may be hand-written.

**New docs tests**, in the same project:
- **Front matter.** Every published page has `id`, `title`, `sidebar_position` and `description`. Ids are unique. Positions are unique within a folder. Only `getting-started.md` has `slug: /`.
- **Internal links.** Every relative link in a published page points to an existing file. Every `#anchor` matches a heading in the target page under Docusaurus's heading-id rules.
- **Published scope.** `docs/planning`, `docs/plans` and `docs/superpowers` are unpublished, which matches Phase 4.4's site exclusions.

**Fix-ups from Phase 4.1**
- The fan-out page links to the README's run-time question sets section. Repoint that link to `question-sets-at-run-time.md`.
- Give the pattern pages front matter and a `_category_.json`.

**Not in this phase**
- Building the Docusaurus site and the `.website` PR (Phase 4.4).
- Cutting the README down (Phase 4.4).
- The site's exclusion list (Phase 4.4).

Until Phase 4.4, the README and the guide overlap.

## Tests

See Section 2. Every C# block compiles, each page's main example runs, and the front-matter and link tests guard the site build. The docs drift check in CI runs `dotnet mdsnippets` and then `git diff --exit-code`, and it covers the new pages.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A page states behaviour the code doesn't have | Users are misled | Examples run as tests, and pages link the API that pins each rule. Reviewers check claims against the code. |
| The Docusaurus heading-id rules differ from the link test's | Anchors pass the test but break on the site | Implement the same slug rule Docusaurus uses (lower case, spaces become `-`, punctuation dropped), and verify it on the existing pattern pages. Phase 4.4's site build is the final check. |
| The README and the guide drift before Phase 4.4 | Two versions for a short time | Phase 4.4 follows directly and cuts the README down. |
| The guide is long, so some pages end up thin or duplicated | A weak guide | Each page owns one topic. Reviewers check for overlap across pages. |
