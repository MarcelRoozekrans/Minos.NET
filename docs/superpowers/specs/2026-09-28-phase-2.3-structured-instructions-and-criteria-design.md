# Phase 2.3 Design — Structured instructions and criteria

**Date:** 2026-09-28
**Phase:** 2.3
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

## Goal

`[JevQuestions]` sets can send structured criteria (`Examples` / `NotFor`) and JSON object or array instructions and descriptions, checked at compile time, and callers can build `JevContent` from typed values or UTF-8 JSON through public factories.

## Approach

**Public surface.** `[Noul]`, `[Choice]` and `[Score]` gain `bool Json { get; set; }`: when set, the constructor's instructions text is a JSON object or array. `[Criteria]` and `[Level]` gain `bool Json`, `string[]? Examples` and `string[]? NotFor`. Noul `True` / `False` stay plain text. `JevContent` gains two public factories, the `state` helpers:

```csharp
public static JevContent FromValue<T>(T value, JsonTypeInfo<T> typeInfo);
public static JevContent FromUtf8Json(ReadOnlySpan<byte> utf8Json);
```

Both throw `ArgumentException` when the value is not a string, object or array, or when the bytes are not exactly one JSON value, reusing the checks in `TypedEvaluation`. `EvaluateAsync<T, TState>` switches to `FromValue` internally, so there is one path. Both are AOT-safe: `JsonTypeInfo<T>` only, no reflection overload. Both go into `PublicAPI.Unshipped.txt`.

**Wire shape of a Criteria or Level description.**
- Neither `Examples` nor `NotFor` set, or both empty: a plain string, exactly as today. Existing sets produce byte-identical `QuestionsUtf8`.
- `Examples` or `NotFor` set: a criterion object, with empty arrays omitted:
  ```json
  { "description": "Payments, invoicing, refunds",
    "examples": ["I was charged twice"],
    "not_for": ["How much is Pro?"] }
  ```
  `description` / `examples` / `not_for` are a ZeroAlloc.Jev convention the model reads, not an API field; the XML docs say so.
- `Json = true`: the description is the minified JSON value itself. Combining it with `Examples` / `NotFor` is JEV109, never a silent merge.
- A Choice member without `[Criteria]` still sends `null`.

**Generator.** A new `JsonMinifier` parses text in one strict RFC 8259 pass: no comments, trailing commas or single quotes; the top level must be an object or array; lone surrogates are rejected. On success it returns the minified JSON, with every character outside printable ASCII escaped as `\uXXXX` exactly as `JsonText.AppendJsonString` does, so `QuestionsUtf8` stays a pure-ASCII u8 literal, plus the string values it read. On failure it returns a message and the offset. It has no dependencies, since the generator runs inside the compiler host; System.Text.Json is not bundled. `ModelBuilder` computes each text's wire fragment (a JSON string, a criterion object or minified JSON) and `Models.cs` carries fragments: `QuestionModel.InstructionsJson` and `OptionModel.DescriptionJson` (`null` sends `null`). They are plain strings, so incremental-cache equality holds. `SourceEmitter` appends the fragments verbatim. `Parse` is unchanged. An invalid set (JEV108, JEV109) gets the throwing stubs, as JEV101–107 do.

**Analyzers.** `ZeroAlloc.Jev.Analyzers` links `JsonMinifier.cs` as it links `ModelBuilder.cs`.

| Rule | Severity | When |
|---|---|---|
| JEV108 (new) | Error | Text marked `Json = true` is not a JSON object or array. The message carries the parser's reason and offset; reported on the attribute argument. |
| JEV109 (new) | Error | `Json = true` is combined with `Examples` or `NotFor`; reported on the `Json` argument. |
| JEV003 (extended) | Warning | Also a blank or `null` entry in `Examples` / `NotFor`, and JSON instructions that are exactly `{}` or `[]`. An object without string values, such as `{"threshold":5}`, is not flagged. |
| JEV004 (extended) | Warning | For `Json = true` instructions, scans backticks in every string value the minifier returns. Keys are not scanned; descriptions stay unchecked, as today. |

`DiagnosticIds` gains `InvalidJson` (JEV108) and `JsonWithExamples` (JEV109); `IsAdvisory` is unchanged. `AnalyzerReleases.Unshipped.md` gains both rules. No new code fixes: adding `Json = true` because text looks like JSON would be a guess.

**Lone surrogates in plain text.** `AppendJsonString` today writes a lone surrogate as `\uD800`. The plan verifies whether System.Text.Json or the API rejects that; if either does, the fix lands in this phase, in `JsonText.cs`, which this phase touches.

## Tests

- Unit (`JsonMinifier`): one test per grammar rule — every string escape, surrogate pairs, lone surrogates rejected, number forms (`-0`, `1e+5`, leading zeros rejected), nesting, whitespace; rejections for comments, trailing commas, single quotes, a scalar top level and trailing content.
- Unit (differential): a corpus of valid and invalid inputs run through both `JsonMinifier` and System.Text.Json; accept/reject agrees on every input, and accepted outputs are `JsonNode.DeepEquals` to STJ's parse.
- Generator: snapshots for a criterion object, JSON instructions, a JSON description, and both array syntaxes (`new[] { … }` and `[ … ]`); for each, `QuestionsUtf8` is `JsonNode.DeepEquals` to an expected fixture. All existing snapshots stay unchanged.
- Analyzer: JEV108, JEV109 and the JEV003 / JEV004 extensions, each with positive and negative cases; the generator emits throwing stubs for invalid sets.
- Unit (runtime): `FromValue` and `FromUtf8Json` for each accepted kind, rejected scalars, rejected multiple values, and a BOM handled as the existing state path does.
- Integration (WireMock): the request body carries the criterion object and the JSON instructions.
- Regression: pack tests unchanged (no new assembly); the full existing suite passes.
- Budgets: `AllocationGate` budgets and benchmarks for `FromValue` and `FromUtf8Json`, recorded in `docs/performance.md`; the AOT smoke app gains a set using `Examples`, `NotFor` and `Json = true`. Evaluating a set allocates nothing new, since `QuestionsUtf8` stays a static literal.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| `JsonMinifier` gets an RFC 8259 edge case wrong | Invalid JSON reaches the API as a 422, or valid JSON is rejected | Rule-by-rule tests plus the STJ differential test |
| A lone surrogate in plain text is sent as `\uD800` | The API or STJ rejects the request | Verify in the plan; if rejected, fix `AppendJsonString` in this phase |
| Attribute array syntax in attribute arguments | A declaration form fails to bind | net10 means C# 14; both `new[] { … }` and `[ … ]` are tested |
| The model misreads the `examples` / `not_for` convention | Structured criteria do not improve answers | Run the live suite once, before merge, with a Choice set using them |
