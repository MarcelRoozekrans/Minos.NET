# Phase 1.7 Design — Test harness

**Date:** 2026-09-27
**Phase:** 1.7
**Surface:** Infra
**Stage:** phase (one phase, implementation-ready)

> Precedent: ZeroAlloc.Rest tests its generated clients over real HTTP in `tests/ZeroAlloc.Rest.Integration.Tests` with WireMock.Net 2.18.0. Unit coverage already exists: 229 tests in `ZeroAlloc.Jev.Tests`, driven through the in-process `StubHandler`, and 55 in `ZeroAlloc.Jev.Generator.Tests`.

## Goal

Prove `JevClient` over real sockets against a WireMock server, and against the live TypeSafe and OpenRouter APIs on demand, and close the unit-test gaps in #17.

## Approach

**Component tests.** A new project, `tests/ZeroAlloc.Jev.Integration.Tests`, references WireMock.Net 2.18.0 through `Directory.Packages.props` and uses the same xUnit v2 stack and analyzers as the other test projects.
- **Setup.** Each test class shares one WireMock server through a class fixture, and resets its mappings and request log per test.
- **Construction.** Tests use the public `new JevClient(new JevClientOptions { ApiKey = …, BaseAddress = server URL, … })` constructor. The client therefore runs its real owned `SocketsHttpHandler` and User-Agent. A few tests use a borrowed `HttpClient` instead. Every option is set explicitly, so the environment cannot leak in.
- **Fixtures.** The existing request and response fixtures in `tests/ZeroAlloc.Jev.Tests/Fixtures` are linked in, not copied.
- **Speed.** Tests use small time-outs and backoffs. Timing assertions are lower bounds only.
- **CI.** The project runs in the existing `build` job, because the job's solution-wide `dotnet test` picks it up.

**Live smoke tests.** A new project, `tests/ZeroAlloc.Jev.Live.Tests`, calls the real APIs.
- **Skipping.** A repo-local `LiveFactAttribute(JevProvider provider)`, a `FactAttribute` subclass with no new dependency, sets `Skip` with a clear reason unless `JEV_LIVE=1` **and** that provider's key variable are set: `TYPESAFE_API_KEY` or `OPENROUTER_API_KEY`. The explicit opt-in was decided on 2026-09-27 after the final review. The keys are the same variables the library reads, so without it a configured machine would bill on every solution-wide `dotnet test`. Without the opt-in the suite reports skipped, never failed, including in the CI solution run.
- **Model.** The model is `JevDefaults.Model` unless `JEV_LIVE_MODEL` is set. For OpenRouter, `JEV_LIVE_OPENROUTER_MODEL` overrides it separately, because OpenRouter model ids may differ.
- **Probe output.** The error probes write the raw status, headers and body to `ITestOutputHelper`.

**Manual workflow.** `.github/workflows/live-smoke.yml` is triggered only by `workflow_dispatch`, never by a pull request or push.
- It runs on ubuntu with a 10-minute timeout and uses the org's `actions/setup-dotnet` setup from `ci.yml`.
- It runs `dotnet test tests/ZeroAlloc.Jev.Live.Tests -c Release --logger "console;verbosity=detailed"`.
- It sets `JEV_LIVE=1` and reads `TYPESAFE_API_KEY` and `OPENROUTER_API_KEY` from a GitHub environment named `live-api`, so only this workflow sees them. The maintainer creates the environment, restricts its deployment branches to `main`, adds the secrets and optionally a required reviewer.
- Without the secrets, the run passes with every test skipped.

**Unit-test gaps (#17).** Four tests close #17:
- `ReadChoice` with `probabilities` before `choice`.
- A keyword-named question property and enum member, for example `@class`, through the generator.
- `CSharpLiteral` with non-ASCII input.
- A borrowed `BaseAddress` with a fragment but no query.

If one of them finds a defect, it is fixed in this phase.

## Tests

**Integration (WireMock)**
- **Wire format:**
  - `POST v1/systemone` and `GET v1/models` carry `Authorization: Bearer <key>`, `User-Agent: ZeroAlloc.Jev/<version>` and `Content-Type: application/json`.
  - The request body is JSON-equal to the matching `request-*.json` fixture.
- **Providers and base paths:**
  - A TypeSafe response fixture parses.
  - An OpenRouter response fixture parses, including `Id`, `Provider` and `Cost`.
  - A base address with a path prefix (`…/api/`) reaches `/api/v1/systemone`.
  - A borrowed `HttpClient` with its own base address works.
- **Errors:**
  - 401 maps to `Unauthorized` and 422 to `Validation`, with the body kept.
  - An error body over 16 KiB comes back truncated, with `BodyTruncated` set.
  - A malformed 200 maps to `InvalidResponse`.
- **Retries:**
  - 429 with `Retry-After: 1`, then 200: success, with at least about 1 s between the two requests. This is the spec case phase 1.6 deferred.
  - 503 on every attempt makes exactly `MaxRetries + 1` requests in WireMock's log and returns `Overloaded`.
  - 400 is requested exactly once.
- **Time-outs and network:**
  - A response delayed beyond `Timeout` maps to `Timeout` after `MaxRetries + 1` attempts.
  - A refused connection, on a stopped server's port, maps to `Network`.
  - Caller cancellation mid-request throws `OperationCanceledException`.

**Live** — each test skips unless `JEV_LIVE=1` and its key are set.
- **TypeSafe evaluation** (1 billed call), with Noul, Choice and Score questions: success, each answer valid, usage present.
- **OpenRouter evaluation** (1 billed call), with the same questions: success, plus `Id`, `Provider` and `Cost`.
- **Generated question set** (1 billed call on TypeSafe): a `[JevQuestions]` record parses into typed answers.
- **TypeSafe model list** (free): non-empty, and includes `JevDefaults.Model`.
- **Bad key:** `Unauthorized`.
- **Invalid request:** `Validation`, where 400 and 422 both count. Both probes log the raw response.

**Unit:** the four #17 cases.

**Regression:** the existing 229 + 55 tests stay green, and CI `build` and `aot-smoke` stay green with the new projects in the solution.

## Open Questions

None. Decided in the brainstorm:

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Timing tests over real sockets flake on CI | Red builds | Lower-bound timing assertions only; small delays; retry counts come from WireMock's request log, not from timing |
| WireMock.Net's dependency tree clashes with a pinned package, such as `Microsoft.CodeAnalysis.CSharp` 5.0.0 | Restore fails with NU1605 | Test-only project; resolve with central version management and check the pin still holds; if not, raise it with the maintainer rather than overriding it silently |
| The live model id differs per provider | OpenRouter evaluation fails | `JEV_LIVE_OPENROUTER_MODEL` override; the first live run reveals the id |
| An invalid-request probe is billed or accepted by the API | Cost, or a probe that asserts the wrong thing | Use a request the API must reject, such as an empty question set; if the first run shows it is accepted, change the probe |
| Secrets leak to fork pull requests | Key exposure | `workflow_dispatch` only, with secrets in the `live-api` environment; no `pull_request` or `pull_request_target` trigger |
| Live APIs are down or change | Manual run fails | This is the suite's job; it runs manually, so it never blocks merges |
