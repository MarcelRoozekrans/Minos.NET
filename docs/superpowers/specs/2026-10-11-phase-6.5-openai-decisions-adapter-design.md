# Phase 6.5 Design — OpenAI `/v1/decisions` adapter and image state

**Date:** 2026-10-11
**Phase:** `6.5`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)

## Goal

A `Minos.NET.OpenAI` package beside `Minos.NET.SystemOne` that sends a question set to OpenAI's `POST /v1/decisions`, and image state in the core that both protocols send where the provider supports it (#115). Cloudflare's Clef, which 6.4 took out, is documented and live-tested through the existing OpenRouter preset (#151).

## Decisions (maintainer, 2026-10-11)

- **Both parts, OpenAI built from the docs.** There is no OpenAI key, so the OpenAI adapter is built and tested against fixtures taken from OpenAI's Decisions guide, and marked beta. Image state is tested live through OpenRouter. Two alternatives were rejected:
  - image state and OpenRouter only, with the adapter deferred until a key or a published schema exists;
  - both parts plus a live OpenAI test, which needs an `OPENAI_API_KEY` the maintainer does not have.
- **Images sit beside the state.** `DecisionRequest` gains an `Images` list, so every state form, including a typed `TState`, carries images unchanged, and each protocol merges state and images into its own wire parts. The rejected alternative was a multi-part `DecisionContent`, which mixes text and images in one list and has no natural form for typed state plus images.
- **The docs state every provider difference.** A Provider differences table covers each way the protocols and presets differ, with dated notes from the probes.
- **A refusal fails the call.** A `refusal` answer returns the new `DecisionErrorKind.Refused`, with `Failures` naming each refused question. The rejected alternative was a per-answer refused state, which every typed answer, handle and generated set would have to model.

## Research (2026-10-11)

### OpenAI's Decisions API

From OpenAI's guide, https://developers.openai.com/api/docs/guides/decisions. The guide documents the format by example only: it has no formal schema, error body, limits or usage object. The API has been in public beta since 2026-10-06.

| Part | Shape |
|---|---|
| Request | `{"model":"gpt-6-luna","input":…,"questions":[…]}`. `gpt-6-luna` is the only model. |
| `input` | A text string, or a `user` message whose `content` mixes `input_text` and `input_image` parts. Images must be inline base64 data URLs; remote URLs and `file_id` are not supported. |
| `predicate` | `type`, `name`, `instructions`. |
| `choice` | `type`, `name`, `instructions`, `choices: [{"value","description"}]`. |
| `score` | `type`, `name`, `instructions`, `levels: [{"label","description"}]`, lowest first, indexed from 0. |
| Response | `answers: [...]`, each with `type` and the question's `name`. |
| `predicate` answer | `probability`. |
| `choice` answer | `choice`, `probabilities: [{"value","probability"}]`, `confidence`. |
| `score` answer | `score`, the probability-weighted mean of level indices; `probabilities: [{"value","label","probability"}]`; `confidence`. |
| Refusal | `{"type":"refusal","name":…}`; other fields are not documented. |
| Pricing | $0.10 per 1M input tokens; output is free. |

### OpenRouter, probed live

Probes against `https://openrouter.ai/api/v1/systemone` with the maintainer's key, about $0.0003 in total:

- `GET /api/v1/models?output_modalities=decisions` lists 19 decision models, among them `openai/gpt-6-luna-decisions`, `cloudflare/clef`, `cloudflare/clef-flash`, `cloudflare/clef-omni` and `perplexity/pplx-decider-v1.1-27b`, which list image input, and `typesafe/jev-1.13`, which lists text only.
- OpenRouter serves Luna and Clef in the System One format, so the existing OpenRouter preset reaches them. Luna and clef-omni return 404 `zdr-violation-by-account` on this account, because it allows only zero-data-retention endpoints; the setting is at https://openrouter.ai/settings/privacy.
- `cloudflare/clef-flash` answered a three-question text request with HTTP 200, with `usage.cost`, an `id` and a `provider` field.
- A top-level `images` field is rejected: *"Put each image in the `state` array as {"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}."* With images, `state` is an array of `{"type":"text","text":…}` and `{"type":"image_url","image_url":{"url":"data:…"}}` parts.
- On a solid red 128×128 PNG, `perplexity/pplx-decider-v1.1-27b` answered red with 0.9994. `cloudflare/clef` and `clef-flash` billed the image tokens and answered blue. `typesafe/jev-1.13`, a text-only model, accepted the image with no error.

## Approach

### The OpenAI package

`Minos.NET.OpenAI`, namespace `Minos.OpenAI`, depends on `Minos.NET.DependencyInjection` and ZeroAlloc.Rest, as `Minos.NET.SystemOne` does.

- **`OpenAIDecisionClient`**, an `IDecisionClient` that runs the existing retry, logging and telemetry pipeline over a one-attempt transport.
- **`OpenAIDecisionClientOptions`**:
  - `BaseAddress`, default `https://api.openai.com/`; requests go to `v1/decisions` under it;
  - `ApiKey`, else `OPENAI_API_KEY`, sent as a Bearer token. The key is required: a missing key fails validation;
  - `Model`, default `gpt-6-luna`;
  - `Timeout`, `Retry` and `UseStandardPipeline`, as on `SystemOneClientOptions`;
  - `Capabilities`, an `OpenAICapabilities`.
- **`OpenAIDefaults`**: the environment-variable name, the base address and the default model.
- **`AddOpenAIDecisionClient`**, default and keyed, binding from configuration or a delegate, returning `OpenAIDecisionClientServiceBuilder`, which carries `HttpClient`, as `AddSystemOneClient` does.
- **`OpenAIDecisionsProtocol`**, internal, behind the existing protocol seam. It writes the request with `Utf8JsonWriter`, reads the answers array into the answer slots by `name`, and reads the error body. The questions JSON is written once per set and cached, as `SystemOneProtocol` does.
- Telemetry reports the provider as `openai`.
- `ListModelsAsync` is not offered: `OpenAICapabilities.ModelListing` is `false`.

### The mapping

| Minos | OpenAI request | OpenAI answer → Minos |
|---|---|---|
| Noul | `{"type":"predicate","name","instructions"}` | `probability` → the Noul probability. |
| Choice | `{"type":"choice","name","instructions","choices":[{"value":key,"description"}]}`; an option with no criterion omits `description`. | `choice` → the chosen key; `probabilities` → the keyed map; `confidence` passes through. |
| Score | `{"type":"score","name","instructions","levels":[{"label":"0","description"},…]}`, lowest first. | `score` → the score; `probabilities` → the level map, keyed by `value`; `confidence` passes through. |
| State, text, no images | `"input": "<text>"` | — |
| State, JSON, or any images | `"input":[{"role":"user","content":[{"type":"input_text","text":…},{"type":"input_image","image_url":"data:…"}…]}]`; JSON state is sent as its raw JSON text. | — |

JSON instructions and JSON criteria are sent as their raw JSON text, since OpenAI's fields are strings.

A missing answer, or an answer whose `type` does not match the question's kind, is `InvalidResponse`. An answer whose `name` is not in the set is skipped, as System One skips unknown keys.

### What OpenAI cannot express

These are checked before sending, like MIN201 to MIN203, and return `Unsupported` with one `QuestionFailure` each. Nothing is rewritten silently.

| Rule | When |
|---|---|
| MIN204 | A Noul has `WhenTrue` or `WhenFalse`: OpenAI's predicate takes only instructions. |
| MIN205 | A criterion has `Examples` or `NotFor`: OpenAI's descriptions are plain strings. |

### Refusals

`DecisionErrorKind.Refused = 13` is new in the core. When any answer is a `refusal`, the call returns it, with one `QuestionFailure` per refused question, rule `refusal`, and is not retried. The other answers are discarded, because a typed set needs every answer.

### Errors

OpenAI's error body is assumed to be its standard `{"error":{"message","type","param","code"}}`; the guide does not document one for this endpoint. Kinds follow the HTTP status, as for System One: 401 and 403 are `Unauthorized`, 400 and 422 `Validation`, 429 `RateLimited`, 503 `Overloaded`, other 5xx `Server`. `message` becomes `DecisionError.Message` and `param` is kept in `Detail`. A body that is not that shape still maps by status.

### Image state

- **`DecisionImage`**, a readonly value in the core:
  - `FromBytes(ReadOnlyMemory<byte> data, string mediaType)` copies the bytes. It accepts `image/png`, `image/jpeg`, `image/webp` and `image/gif`, and throws `ArgumentException` for anything else or for empty data;
  - `FromDataUrl(string dataUrl)` accepts only a `data:<type>;base64,<data>` URL of those types, and decodes it once to check it;
  - `MediaType` and `Data` getters.
- **`DecisionRequest.Images`**, an `IReadOnlyList<DecisionImage>`, empty by default, set through a new constructor overload.
- **Extensions:** every `DecisionClientExtensions` evaluation overload gains a twin that takes `IReadOnlyList<DecisionImage> images` after the state. The existing overloads are unchanged.
- **Encoding:** each protocol writes the data URL straight into the request writer, base64-encoding the bytes in place with no intermediate string. A request without images writes exactly the bytes it writes today.

### System One with images

With images, `state` becomes an array: first `{"type":"text","text":<state>}`, holding the text or the JSON state's raw text, then one `{"type":"image_url","image_url":{"url":"data:<type>;base64,…"}}` per image, in order. Without images nothing changes.

### Capabilities

- `SystemOneCapabilities.Images`, declared in 6.4, is now enforced. `OpenAICapabilities` has the same members as `SystemOneCapabilities`.
- **MIN206:** a request with images to a client whose capabilities say `Images = false` returns `Unsupported` before sending.

| Preset | Images default | Why |
|---|---|---|
| TypeSafe | false | Jev is text-only. |
| OpenRouter | false | OpenRouter mixes text and image models, and a text model accepted an image silently, so image support is opt-in through `Capabilities.Images = true`. |
| VllmSemanticRouter | false | Not documented. |
| Custom | false | Unknown server. |
| OpenAI | true | Documented. |

OpenAI's other defaults: all three kinds; no `MaxQuestions` or `MaxChoiceOptions`, as none is published; `ModelListing = false`.

### #115's analyzer item

#115 asks for an analyzer that warns when a question set uses a capability a configured provider lacks, "where this is statically knowable". It is not: images arrive at call time and the provider comes from configuration. MIN206 covers it at run time. #115 gets a comment saying so.

### Cloudflare's Clef through OpenRouter (#151)

The Providers docs gain a section on Clef through the OpenRouter preset, with the models `cloudflare/clef` and `cloudflare/clef-flash`, and a note that their image answers were wrong in our probe. A live test runs clef-flash on text. #151 closes with a comment pointing to it; a direct Workers AI preset can come back as a new issue if someone needs it.

### Provider differences in the docs

Asked for by the maintainer: a "Provider differences" section in `docs/client-and-errors.md`, under Providers, so a caller choosing or switching a provider sees what changes without reading code. Phase 6.7 moves it into the Providers page. It is one table, one row per difference and one column per protocol or preset, followed by short per-model notes:

| Row | What it states |
|---|---|
| Wire format | System One `/v1/systemone` with a `questions` map and an `answers` object, against OpenAI `/v1/decisions` with arrays matched by `name`. |
| Question kinds and their names | `noul`, `choice`, `score` against `predicate`, `choice`, `score`; any kind a preset's defaults leave out. |
| Noul `WhenTrue` and `WhenFalse` | Sent on System One; MIN204 on OpenAI. |
| Criterion `Examples` and `NotFor` | Sent on System One; MIN205 on OpenAI. |
| JSON instructions, criteria and state | Sent as JSON on System One; as raw JSON text on OpenAI. |
| Limits | TypeSafe's and OpenRouter's 255 options (MIN203); no published limits for the others. |
| Images | Each preset's default and the opt-in, MIN206, data URLs only, and where images go on each wire. |
| Refusals | OpenAI only, as `Refused`; System One has none. |
| Noul confidence, usage and cost | Which fields each provider returns, as the fixtures and probes show them, such as OpenRouter's `usage.cost` and OpenAI's undocumented usage. |
| Model listing | TypeSafe only. |
| Auth | Required for TypeSafe, OpenRouter and OpenAI; optional for vLLM-SR and Custom. |
| Status | OpenAI is a public beta, built from its guide's examples. |

The per-model notes cover what the probes found: Clef's wrong image answers, `typesafe/jev-1.13` accepting an image silently, and OpenRouter's zero-data-retention setting blocking Luna and clef-omni. Each note gives its date. A Docs.Tests check keeps the table's MIN ids and preset names in step with the code, as the existing docs tests do for snippets.

### Out of scope

- A live OpenAI test: there is no key. A Luna test through OpenRouter is added but skips unless `MINOS_LIVE_LUNA=1`, because the account's zero-data-retention setting blocks Luna.
- Remote image URLs and file ids: neither protocol accepts them.
- Image size and count limits as capabilities: no provider in scope publishes them reliably.
- OpenAI model listing.

## Risks

| Risk | Mitigation |
|---|---|
| OpenAI's format differs from its guide's examples, or changes during the beta. | The package and docs say beta. Fixtures name their source. A live test is added as soon as a key exists. |
| The `input_image` part shape is assumed from the guide's description and from OpenAI's Responses API. | The fixture records the assumption; it is the first thing a live test checks. |
| OpenRouter's image routing or the Perplexity model changes. | The live image test is in the manual live smoke only, not a required check. |
| Base64 encoding allocates. | It writes into the request writer's buffer; an AOT gate measures an image call. |

## Amendments while planning (2026-10-11)

- **Capabilities are neutral, in the core.** By the maintainer's decision, `SystemOneCapabilities` and `SystemOneQuestionKinds` become `Minos.DecisionCapabilities` and `Minos.QuestionKinds` before 0.9.0 ships. Both clients use them and answer `GetService<DecisionCapabilities>()`. There is no `OpenAICapabilities`. The check for MIN201 to MIN203 and MIN206 lives once, in the core.
- **The protocol-neutral transport moves into the core as internals:** `IDecisionProtocol`, the state writers, `DecisionTransport` and `RetryAfterHeader`. The two ZeroAlloc.Rest adapters, the error mapper and the raw serializer, become shared source compiled into both protocol packages, and no assembly may see both copies. The core still does not reference ZeroAlloc.Rest.
- **`DecisionRequest.Images` is an `init` property,** not a constructor overload, so `with` copies it.
- **OpenAI's `input` is a string whenever there are no images,** JSON state included, as its raw JSON text; with images, it is the one-message array.
- **`QuestionSetDefinition` gets a second protocol-cache slot,** for OpenAI's `questions` array.
- **MIN204 and MIN205 run through the protocol,** and the transport merges them with the capability failures into one `Unsupported` error: capability failures first, then protocol failures.
- **OpenAI's unit tests go in a new `Minos.NET.OpenAI.Tests` project;** its WireMock tests go in `Minos.NET.Integration.Tests`.
- **A `Refused` error has status 200,** like `InvalidResponse` from a 200 body.
