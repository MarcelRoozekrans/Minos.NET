# Phase 10.4 Design — `Confidence routing as a framework feature`

**Date:** 2026-11-06
**Phase:** `10.4`
**Surface:** `Docs`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-07
**Milestone design:** `docs/superpowers/specs/2026-11-04-milestone-10-design.md`

## Goal

An "Escalation" guide on the docs site, a concept page plus recipes, teaches routing between deciders as a framework feature, and a dotnet/extensions proposal draft in the repository is ready for the maintainer to post (#119).

## Why

Phases 10.1 to 10.3 built `UseEscalation` and `UseFallback`, documented them as reference in `docs/pipeline.md`, and measured them on Banking77 in `docs/reports/triage/banking77/`. Reference tells a reader what an option does. It does not tell them how to pick a threshold, why the time budget decides whether escalation ever runs, or which order the stages compose in and why. The triage report shows the cost of getting that wrong: with the default 5 s budget the local call took 5.5 s, so nothing escalated and nothing was billed. The guide teaches that decision work. The proposal draft takes the same evidence to the .NET ecosystem, which has `IChatClient` but no decision primitive.

## Goals, non-goals, anti-goals

- **Goals:**
  - a docs category that a team can follow from "should I route between deciders" to a configured, tested pipeline;
  - every quoted figure tied by a docs test to the committed triage report, and every C# block compiled in `Minos.NET.Docs.Tests`;
  - a proposal draft that stands on its own, with the evidence behind it and nothing private in it.
- **Non-goals:**
  - any change under `src/` or to the triage sample: this phase documents what 10.1 to 10.3 shipped;
  - posting the proposal: the maintainer posts it, or tells me to;
  - a threshold sweep or new billed run;
  - a verdict that every app should escalate. The guide says when it does not pay.
- **Anti-goals:**
  - the guide restating `docs/pipeline.md`: the recipes link to the reference sections and add the reasoning;
  - a number in the guide that no test ties to the report;
  - a private detail in the public proposal or on the public docs site: no workload names, hostnames, account or environment names, or paths under a home directory.

## Decisions

**The maintainer's choices, made in the brainstorm:**

1. **The proposal is a discussion first, with an API sketch appended.** It asks whether Microsoft.Extensions.AI wants a decision primitive and shows Minos as the working implementation. It is not a formal API-review proposal, which would presume the shape is settled.
2. **The guide is a concept page plus recipes.**
3. **The pages live in a new "Escalation" category,** `docs/escalation/`, because `docs/patterns/confidence-routing.md` already exists and covers a different layer: what to do with one answer's confidence. The existing pattern page gets a pointer to the new category, and the Patterns index stays at four patterns.

**Fixed earlier (milestone design):** the guide covers thresholds sized to the cost of being wrong, the time check, the fallback chain, composition order, privacy of targets and chat-model escalation. It says escalation needs a faster local server or a larger budget to pay off on CPU hardware. The OpenAI step is not shown live (#161). The draft is checked for private details before the maintainer sees it. Done means the draft is approved, not posted.

**My calls, for you to correct:**

4. **Page set** (the folder `docs/escalation/`, with `_category_.json` label "Escalation" at a free category position between Running locally and Patterns):
   - `index.md` (id `escalation`): what routing between deciders is, the triage result in one table, when it pays and when it does not, and a map of the recipes;
   - `thresholds.md`: thresholds per question key, sized to the cost of being wrong, with a Noul's certainty as max(p, 1−p); how the triage report's `intent` 0.85 and Noul 0.80 came out of the calibration sweep; how an escalation threshold relates to an app's own acting floor;
   - `time-budget.md`: `Budget`, `Deadline` and `ExpectedLatency`; the first triage run where the 5 s budget made every escalation `NoTimeLeft`; the second at 15 s; how to read the local call's median from your own records before setting a budget; that the budget leaves out time the host spent before the call;
   - `fallback.md`: `UseFallback` as a chain for failure, not for doubt; keyed clients with DI; how it differs from escalation; what the path records;
   - `composing-and-privacy.md`: the documented stage order and why escalation sits outside fallback; the rule that a target must meet the same data rules as the primary; recording and erasure of a path that crossed providers;
   - `chat-model-target.md`: `ChatDecisionClient` as one more target, and why a `Verbalized` `ProbabilitySource` is weaker evidence than `Model` or `Logprobs`.
5. **Numbers come from the report by test.** A docs test reads `triage-report.json` and the report README and checks each figure the pages quote (split by path, escalated questions, target calls, accuracy, medians, the two budgets), as `performance.md` does for its tables. The first run's figures (5.5 s median, 106 questions, 0 target calls) are quoted from the report README, which records them, with a test on the README text.
6. **Snippets are compiled** MarkdownSnippets regions in `Minos.NET.Docs.Tests`, one small app threaded through the recipes, reusing the types the Phase 9.5 guide snippets already define where they fit. No snippet calls a real provider.
7. **Links in:** the existing `docs/patterns/confidence-routing.md` and `docs/patterns/index.md` link to the category, `docs/pipeline.md`'s escalation and fallback sections link to the recipes, and `docs/samples.md` links to the guide from the triage sample. The root README's guide list gains the category if it lists one page per guide, as the docs tests require.
8. **The proposal draft** is `docs/plans/2026-11-06-dotnet-extensions-decision-proposal-draft.md`, which the site excludes. Its sections: summary and the one question asked; the gap (`IChatClient` returns text, so a classification needs structured output and has no calibrated probability or confidence); prior art, limited to what the vendors' public documentation says, checked while writing and dropped where it cannot be; the usage story with Minos code; the evidence from the Banking77 triage and shadow reports; the API sketch appended, listing the abstraction (`IDecisionClient`, `DecisionRequest`, `DecisionResponse`, `DecisionError`), the pipeline builder and the two stages as optional; open questions for the maintainers (package placement, naming, how probability is expressed, an error result against exceptions, how a path is reported). It names no private workload.
9. **A denylist test guards the draft and the new pages:** it fails on the names of the private workload, the maintainer's domains, home-directory paths, key shapes and e-mail addresses. The list lives in the test, so a new entry is one line.
10. **Delivery:** one docs-only PR, titled `docs:`, with `BEGIN_COMMIT_OVERRIDE` in the body. The pre-push review report goes in `docs/plans/`. The maintainer's approval of the draft is recorded in this spec's status line and in ROADMAP.md on completion.

**Calls added after the builder check (mine, for you to correct):**

11. **The threshold sweep is the committed calibration report** `docs/reports/local/banking77/` (`report.md`, `report.json`). `thresholds.md` quotes the rows for 0.85 and 0.80 from it, and the figures test reads `report.json`. No new sweep.
12. **Which figures are canonical.** The triage report counts at two levels and the pages say which: tickets (400; 101 had a target call) and questions (1,200; 106 escalated). The first run's 106 questions below threshold and the second run's 106 escalated questions are the same questions at the same thresholds, so the pages state the unit each time and quote both runs without contradiction. The first run's figures are quoted from the report README, with a text test.
13. **Site wiring is a discovery task in the plan.** The published-page set in the docs tests, the sidebar-order test, `docusaurus.config.ts`'s comment ("the guide is docs/*.md and docs/patterns/"), and the navbar entry are updated to include `docs/escalation/`. The category index follows `docs/patterns/index.md`: `id` set, position 1 within the folder. The workflow that builds the site is `docs.yml`.
14. **The denylist** holds the workload names and the maintainer's domain as plain entries in the test source. The repository already names the workload in its specs, so the test adds no new exposure; what it protects is the Microsoft post and the published site. The test scans the draft and `docs/escalation/` only, and a second, narrower check keeps `docs/superpowers/` and `docs/planning/` out of the published set as today.
15. **Prior art in the draft** uses only claims I verify against the vendors' public pages while writing, each with its source link in a list at the end of the draft for the maintainer to check. A claim I cannot verify is left out, so the section may be short.
16. **Approval gate.** The PR stays open for the maintainer's review. The draft is approved when the maintainer says so in the PR; I then set this spec's status and complete the phase. The phase is not completed on a merge alone.

## Approaches

| Approach | Trade-off |
|---|---|
| **A. A new Escalation category: concept page plus recipes (chosen)** | Each topic can be linked on its own and read in minutes; a reader who only needs the time budget does not scroll past thresholds. It is more pages to keep consistent, which the docs tests cover. |
| B. One worked-example page | Reads start to finish and mirrors the Phase 9.5 guide, but five topics make a long page that is hard to link into. The maintainer did not pick it. |
| C. Extend `docs/pipeline.md` | No new page, but it mixes reference and teaching in a page that is already 700 lines. |

For the proposal: discussion-first (chosen), a formal API proposal, or both in one file. A formal proposal asks Microsoft to review a shape that has been in use for a few weeks, and "both" doubles what the maintainer must review and what could leak.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A quoted figure drifts when the report is rebuilt | A wrong number on a public page | Each figure is read from the report by a test |
| Prior-art claims in the draft are vendor facts the maintainer noted as unverified | A wrong public claim in a permanent post | Cite only what public documentation says, checked while writing; drop the rest |
| The draft leaks a private detail | Permanent exposure once posted | The denylist test, the full re-read before the maintainer sees it, and the maintainer reviews before posting |
| The new category's sidebar position collides with an existing page | A docs test fails or the order is odd | Choose the position from the existing front matter and let the sidebar test confirm |
| The guide goes stale when a later phase changes the stages | Pages disagree with the code | Snippets are compiled, so an API change fails the build; prose links to the reference |
