# Phase 6.1 Design — `Rename to Minos and move out of the ZeroAlloc org`

**Date:** 2026-10-09
**Phase:** `6.1`
**Surface:** `Refactor`
**Stage:** phase (one phase, implementation-ready)

## Goal

Rename the library from ZeroAlloc.Jev to **Minos**. Minos is the judge of the underworld in Greek myth, named in the line of the maintainer's Daedalus.NET and Thalos.NET.

The project also moves out of the ZeroAlloc-Net org into the maintainer's personal account as **`MarcelRoozekrans/Minos.NET`**, and follows the conventions of his personal libraries (Thalos.NET, Rag.NET, AdoNet.Async). Packages, namespaces, public types, analyzer IDs, telemetry names, docs, samples, logo, repository and docs site all move.

Behaviour and the wire format do not change (#120).

## Decisions (maintainer, 2026-10-09)

| Question | Decision | Why |
|---|---|---|
| Where the project lives | **`MarcelRoozekrans/Minos.NET`**, a repository transfer out of ZeroAlloc-Net | The maintainer's decision. A transfer keeps history, issues and PRs, and GitHub redirects the old URLs. |
| Name | **Minos** | Greek-themed like Daedalus.NET and Thalos.NET. It fits a library that judges a state. `Minos`, `Minos.NET` and every planned package id were free on nuget.org on 2026-10-09; `MarcelRoozekrans/Minos` and `Minos.NET` were free on GitHub. |
| Package ids and namespace | **Package ids `Minos.NET`, `Minos.NET.SystemOne`, `Minos.NET.OpenAI`, later `Minos.NET.Local`, plus `Minos.NET.DependencyInjection`. Root namespace `Minos`.** | Thalos.NET's convention: `Thalos.NET.*` package ids with namespace `Thalos`. |
| Package layout | **An abstraction-only core, plus one package per protocol** | Decided earlier the same day. **Phase 6.2** splits `/v1/systemone` out into `Minos.NET.SystemOne`. This phase only renames, so the `/v1/systemone` code stays in the core for now. |
| `ZeroAlloc.Jev` | **Retired, never published.** NuGet tags `jev`, `typesafe`, `systemone` and `decision-model` keep it discoverable, and the README names Jev as a supported provider. | Nothing was ever published under it. |
| Analyzer IDs | **`JEV` → `MIN`, numbers kept:** `MIN001`–`MIN006`, `MIN101`–`MIN109` | Short and clearly Minos in `#pragma` lines and `.editorconfig`. |
| Type names | **Question and answer nouns lose the prefix; generic and infrastructure words take `Decision`.** | Approved on 2026-10-09 before the move. The rule does not depend on the org. |
| ZeroAlloc packages | **Kept as ordinary NuGet dependencies:** ZeroAlloc.Rest, Resilience, Results, Telemetry, Validation, Inject, TestHelpers | Thalos.NET does the same. Leaving the org is about the project's home and brand, not its dependencies. |

## Type mapping

| Today | After |
|---|---|
| `JevQuestionsAttribute` (`[JevQuestions]`) | `QuestionsAttribute` (`[Questions]`) |
| `JevQuestionSet`, `IJevQuestionSet`, `JevQuestionSetBuilder` | `QuestionSet`, `IQuestionSet`, `QuestionSetBuilder` |
| `JevQuestion`, `JevQuestionFailure` | `Question`, `QuestionFailure` |
| `JevAnswer`, `JevAnswers`, `JevAnswerReader` | `Answer`, `Answers`, `AnswerReader` |
| `JevCriterion` | `Criterion` |
| `IJevClient`, `JevClient`, `JevClientOptions` | `IDecisionClient`, `DecisionClient`, `DecisionClientOptions` |
| `JevError`, `JevErrorKind` | `DecisionError`, `DecisionErrorKind` |
| `JevContent`, `JevUsage`, `JevOptionSet` | `DecisionContent`, `DecisionUsage`, `DecisionOptionSet` |
| `JevDefaults`, `JevProvider` | `DecisionDefaults`, `DecisionProvider` (temporary; Phase 6.4's presets replace it) |
| `JevServiceCollectionExtensions` (`AddJevClient`) | `DecisionServiceCollectionExtensions` (`AddDecisionClient`) |
| Namespace `ZeroAlloc.Jev` (and `.Transport`, `.Telemetry` …) | `Minos` (and the same sub-namespaces) |
| Project and assembly `ZeroAlloc.Jev[.X]` | `Minos.NET[.X]`. For example `src/Minos.NET`, `src/Minos.NET.Generator`, `tests/Minos.NET.Tests`, `samples/Minos.NET.AotSmoke`. The solution becomes `Minos.NET.slnx`. |

Members follow their type: for example `JevErrorKind.Validation` becomes `DecisionErrorKind.Validation`, and the `Jev`-named members of the DI options builder follow the same rule. Internal types follow the same rule. Phase 7.1's API review may still polish names before the 1.0 freeze.

## What does not change

- **Wire format:** the `/v1/systemone` request and response JSON, and the routes.
- **Vendor-specific names:**
  - `TYPESAFE_API_KEY`, `OPENROUTER_API_KEY`, `TYPESAFE_BASE_URL`;
  - the model aliases `jev-latest` and `jev-preview`, which are TypeSafe's model names;
  - the docs' references to Jev as TypeSafe's model.
- **Behaviour:** retries, errors, validation, allocation, AOT and telemetry semantics.
- **History:** `CHANGELOG.md`, git history, and the release line, which continues from 0.5.x. Versioning moves to GitVersion in Milestone 7, not here.

## Approach

**1. Rename inside the repository: one PR, no behaviour change.**

- **Projects:** `src/`, `tests/`, `samples/` and `benchmarks/`, from `ZeroAlloc.Jev*` to `Minos.NET*`. That covers folders, `.csproj` names, `PackageId`, `RootNamespace` (`Minos…`), `AssemblyName`, `InternalsVisibleTo`, and the solution file.
- **Types and members:** follow the mapping above, in the generator's emitted source, the analyzers and the code fixes too.
- **Analyzers:**
  - Diagnostic IDs move from `JEV` to `MIN`. The help links, which point at the new docs URL, and the titles follow.
  - Past releases in `AnalyzerReleases.Shipped.md` are never edited. The `JEV` rules are listed as removed and the `MIN` rules as new in `AnalyzerReleases.Unshipped.md`, in the format the release-tracking analyzers (RS2000–RS2008) accept.
- **Public API files:** the removed entries are marked `*REMOVED*` and the new ones added in `PublicAPI.Unshipped.txt`. This is a breaking change in a 0.x line, recorded as such.
- **Telemetry and identity:**
  - The `ActivitySource`, `Meter` and logger category become `Minos`.
  - Log message templates that say "Jev" now say "Minos" or "decision", with the event ids unchanged.
  - The `User-Agent` product token becomes `Minos.NET`.
  - The observability page and its name tests follow.
- **Package metadata,** shared in `Directory.Build.props` as in Thalos.NET:
  - `Authors` and `Copyright` become Marcel Roozekrans; the licence stays MIT;
  - `PackageProjectUrl` and `RepositoryUrl` become `https://github.com/MarcelRoozekrans/Minos.NET`;
  - `PackageIcon` is the new logo;
  - tags are `jev;typesafe;systemone;decision-model;decisions`.
- **Logo:** ZeroAlloc.Rest's shared icon goes. A new Minos mark is designed with the `logo-design` skill and saved as `assets/logo.svg` and `assets/logo.png`. The pack tests' pinned icon hashes are updated to the new files. The maintainer approves the mark before it is committed.
- **Docs and README:**
  - Every page, snippet region, table, heading and anchor is updated, and so are the docs tests that tie them to code.
  - The README gets the Minos title, install lines and logo, and a line saying Jev (TypeSafe) is a supported provider. The "ZeroAlloc family" wording goes.
  - **The README explains the name**, as the sibling repositories do. It uses both of their styles: a one-line note under the title, as in Thalos.NET, and an "About the name" section, as in Daedalus.NET, linked from the table of contents if the README has one. The wording is the maintainer's to adjust:

    > Named after Minos, the judge of the dead in Greek myth.

    > ## About the name
    >
    > In Greek mythology, **Minos** was king of Crete and, after his death, one of the three judges of the underworld. Every soul came before him and left with a verdict. That is what this library does. You hand it a state and a few typed questions, and a decision model returns a verdict for each one: yes or no, which option, how severe, with a calibrated confidence.
    >
    > Minos does not care which model judges. TypeSafe's Jev, OpenAI's Decisions API or a model running on your own machine all answer the same typed questions. The name also keeps it in the same Cretan story as its siblings: Minos had [Daedalus](https://github.com/MarcelRoozekrans/Daedalus.NET) build the Labyrinth, and set [Talos](https://github.com/MarcelRoozekrans/Thalos.NET) to guard his island.

    The README's no-raw-HTML test still holds, since this is plain Markdown. The docs tests' README link and anchor checks cover the new section.
  - Docs links move to `https://marcelroozekrans.github.io/Minos.NET/`.
- **Docs site, moved into this repository as in Rag.NET and AdoNet.Async:**
  - a Docusaurus app at the repository root (`docusaurus.config.ts`, `sidebars.ts`, `package.json` with a lockfile);
  - the existing `docs/` pages;
  - the planning, plans and superpowers folders excluded, as today;
  - built by a `docs.yml` workflow and deployed to GitHub Pages;
  - modelled on Rag.NET's `docs.yml` and config, with `onBrokenLinks: 'throw'` kept;
  - `docs-site.yml` and `trigger-website.yml`, which built and dispatched to ZeroAlloc-Net/.website, are removed.
- **CI:**
  - solution and project paths;
  - the AOT smoke and surface projects;
  - the `aot-surface` rooted assemblies;
  - benchmark paths.
  - `release-please.yml`'s `ship-release-tracking` job, which calls `ZeroAlloc-Net/.github`, is replaced by an equivalent in-repo step or job. It does the same move of unshipped analyzer rules and public API on the release PR, so nothing in the repository depends on the ZeroAlloc org's workflows.
  - The repository adopts the maintainer's `renovate-config` preset in `renovate.json`, as Thalos.NET does, and `.commitlintrc.yml` is kept.
- **The paused Phase 5.5 branch is not touched.** Milestone 7's publish phase follows Thalos.NET's design instead: GitVersion, release-please, and NuGet Trusted Publishing from `ci.yml`'s `publish-nuget` job, with no stored API key. Only the parts that still apply are reused, such as the package inspection.

**2. Outside the repository, after the code PR merges, in order:**

1. **The maintainer transfers the repository** from `ZeroAlloc-Net/ZeroAlloc.Jev` to `MarcelRoozekrans` and renames it `Minos.NET`. GitHub redirects old URLs, clones and the API.
2. **The secrets and variables come along:** the `live-api` environment, with `TYPESAFE_API_KEY` and `OPENROUTER_API_KEY` and its `main`-only branch policy. `RELEASE_PLEASE_TOKEN` was an org secret, so the maintainer re-creates it, or a fine-grained PAT, on the personal repository. The org's `NUGET_API_KEY` no longer applies.
3. **GitHub Pages:** the maintainer enables Pages with source "GitHub Actions"; `docs.yml` then deploys.
4. **Leaving the org's docs:** a ZeroAlloc-Net/.website PR, asked of the maintainer, removes the `repos/jev` submodule, the `docs-jev` app and the home-page entry. The maintainer retires the `za-docs-jev` Cloudflare project and redirects `jev.zeroalloc.net` to the GitHub Pages URL.
5. **Re-pointing:**
   - this repository's `live-smoke.yml` and any remaining URLs to the new home;
   - the ruleset (the old org ruleset does not transfer): the maintainer re-creates `main` protection with required checks;
   - Renovate is enabled for the repository.

Steps 1–5 need maintainer actions. STATE.md lists them until they are done.

**3. Verification gates. All must pass with the renamed code.**

- `dotnet build -c Release` with 0 warnings, and the whole test suite.
- **AOT:** the `aot-surface` job (whole surface, no IL2xxx/IL3xxx warnings), `aot-smoke`, and entry-point coverage. Every public entry point keeps a `[Covers]` check under its new name.
- **Allocation budgets:** unchanged, measured the same way.
- **Docs:** the docs tests, including links, anchors, tables tied to code, the snippet sync with an empty `dotnet mdsnippets` diff, and the README tests. The Docusaurus build passes locally and in `docs.yml` with `onBrokenLinks: 'throw'`.
- **Pack tests:** the new package ids, tags, metadata and logo hashes.
- **A "no ZeroAlloc.Jev left" check,** as a new test. It scans source, docs, samples, workflows and package metadata, and fails on any of these outside an explicit allow-list:
  - `Jev` identifiers;
  - `ZeroAlloc.Jev`;
  - `ZeroAlloc-Net/ZeroAlloc.Jev`;
  - `jev.zeroalloc.net`.

  The allow-list covers the environment variables, the `jev-latest` and `jev-preview` model strings, prose naming Jev as TypeSafe's model, `JEV` IDs in shipped analyzer history, `CHANGELOG.md`, and the planning and history documents. `ZeroAlloc.*` package dependencies are allowed.
- **Live smoke on `main`** after the transfer: 13/13.

## Files / Modules Touched

- **In the repository:**
  - every project under `src/`, `tests/`, `samples/` and `benchmarks/`;
  - the solution, `Directory.Build.props`, `Directory.Packages.props` (if it names projects) and `mdsnippets.json`;
  - every `docs/*.md` page except the planning and history documents, and `README.md`;
  - `assets/`;
  - `.github/workflows/*`, with `docs-site.yml` and `trigger-website.yml` removed, `docs.yml` added and `release-please.yml` changed;

- **Outside it:** ZeroAlloc-Net/.website, the Cloudflare project and the domain redirect.

The `refactor-analysis` pre-plan step produces the authoritative list and the safe order.

## Tests

- **Unit, generator, analyzer, DI and integration:** they pass under the new names, with snapshot or verified-source files regenerated and their diffs checked to be name-only.
- **Docs:** all docs tests, and a Docusaurus build with `onBrokenLinks: 'throw'`.
- **AOT and pack:** both pass, with the new ids, tags, metadata and logo.
- **The no-ZeroAlloc.Jev check**, described above.
- **Regression:** allocation budgets unchanged, and the live smoke run 13/13 after the transfer.

## Open Questions

None. The maintainer settled the home, name, id and namespace convention, package layout, the fate of `ZeroAlloc.Jev`, the analyzer prefix and the type-naming rule on 2026-10-09. The logo itself is approved during the phase.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A behaviour change slips into a mechanical rename | A silent regression | No logic edits. Generated-source snapshot diffs must be name-only, and the full suite, AOT, budget and live gates must pass unchanged. |
| The release-tracking or PublicApiAnalyzers reject the ID and type churn | The build fails | Follow the analyzers' documented removed/added format, and never edit shipped history. |
| The transfer loses org-level secrets, the ruleset or variables | Release-please or live runs fail after the move | Step 2 lists every org-provided piece: `RELEASE_PLEASE_TOKEN`, the ruleset, `live-api` (which transfers with the repository, but check it), and Renovate. Each is checked before the phase closes. |
| `ship-release-tracking` lived in the org's `.github` repository | Unshipped analyzer and API entries are never moved to shipped | Replace it with an in-repo job that does the same, and test it on the first release PR after the move. |
| The docs-site move breaks links | A dead jev.zeroalloc.net, a broken `docs.yml` | `docs.yml` builds with `onBrokenLinks: 'throw'`. jev.zeroalloc.net redirects to the Pages URL before the org app is removed. |
| `Question` or `Answer` collides with types in a user's own code | A compile ambiguity for raw-API users | The guide notes the `using` alias, and 7.1's review may revisit. |
| Snapshot and verified files churn hugely | Review fatigue | Regenerate them in one dedicated commit, and confirm the diff is name-only by a scripted check. |
