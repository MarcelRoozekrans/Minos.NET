# Phase 6.1 Design — `Name decision and rename`

**Date:** 2026-10-09
**Phase:** `6.1`
**Surface:** `Refactor`
**Stage:** phase (one phase, implementation-ready)

## Goal

Rename the library from ZeroAlloc.Jev to **ZeroAlloc.Decisions**, a vendor-neutral name. Packages, namespaces, public types, analyzer IDs, telemetry names, docs, samples, the repository and the docs site all move. Behaviour and the wire format do not change (#120).

## Decisions (maintainer, 2026-10-09)

| Question | Decision | Why |
|---|---|---|
| Umbrella name | **ZeroAlloc.Decisions** | Names the category ("decision models", OpenAI's Decisions API) rather than one vendor's product, and matches the org's plural-noun style (Results, Collections). The NuGet id and the org repository name were both free on 2026-10-09. |
| Package layout | **An abstraction-only core, plus one package per protocol:** `ZeroAlloc.Decisions`, `ZeroAlloc.Decisions.SystemOne`, `ZeroAlloc.Decisions.OpenAI`, later `ZeroAlloc.Decisions.Local`, plus `ZeroAlloc.Decisions.DependencyInjection` | Clean separation: the core carries no wire protocol. **Phase 6.2** splits `/v1/systemone` out into `.SystemOne`. This phase only renames, so the `/v1/systemone` code stays in the core for now. |
| `ZeroAlloc.Jev` | **Retired; never published.** NuGet tags `jev`, `typesafe`, `systemone` and `decision-model` keep it discoverable, and the README names Jev as a supported provider | Nothing was ever published under it, so nobody needs a redirect package. |
| Analyzer IDs | **`JEV` → `ZAD`, numbers kept:** `ZAD001`–`ZAD006`, `ZAD101`–`ZAD109` | The org's `ZA`+letter style (ZAM for Mediator, ZAI for Inject). It is short in `#pragma` lines and `.editorconfig`, and no other org repository uses it. |
| Type names | **Question and answer nouns lose the prefix. Generic and infrastructure words take `Decision`.** | Like `[Noul]`, `[Choice]` and `[Score]`, the domain nouns need no product prefix in their own namespace. Bare `Client`, `Error` or `Content` would say nothing and would collide. |

## Type mapping

| Today | After |
|---|---|
| `JevQuestionsAttribute` (`[JevQuestions]`) | `QuestionsAttribute` (`[Questions]`) |
| `JevQuestionSet`, `IJevQuestionSet`, `JevQuestionSetBuilder` | `QuestionSet`, `IQuestionSet`, `QuestionSetBuilder` |
| `JevQuestion`, `JevQuestionFailure` | `Question`, `QuestionFailure` |
| `JevAnswer`, `JevAnswers`, `JevAnswerReader` | `Answer`, `Answers`, `AnswerReader` |
| `JevCriterion` | `Criterion` |
| `IJevClient`, `JevClient`, `JevClientOptions` | `IDecisionClient`, `DecisionClient`, `DecisionClientOptions` |
| `JevError`, `JevErrorKind` | `DecisionError`, `DecisionErrorKind` |
| `JevContent`, `JevUsage`, `JevOptionSet` | `DecisionContent`, `DecisionUsage`, `DecisionOptionSet` |
| `JevDefaults`, `JevProvider` | `DecisionDefaults`, `DecisionProvider` (temporary; Phase 6.4's presets replace it) |
| `JevServiceCollectionExtensions` (`AddJevClient`) | `DecisionServiceCollectionExtensions` (`AddDecisionClient`) |
| Namespace `ZeroAlloc.Jev` (and `.Transport`, `.Telemetry` …) | `ZeroAlloc.Decisions` (and the same sub-namespaces) |

Members follow their type: for example `JevErrorKind.Validation` becomes `DecisionErrorKind.Validation`, and the `Jev`-named methods and properties of the DI options builder follow the same rule. Internal types follow the same rule, so the code reads consistently. Phase 7.1's API review may still polish names before the 1.0 freeze. This phase does not argue individual names beyond this table.

## What does not change

- **Wire format:** the `/v1/systemone` request and response JSON, and the routes.
- **Vendor-specific names, which are correct as they are:**
  - `TYPESAFE_API_KEY`, `OPENROUTER_API_KEY`, `TYPESAFE_BASE_URL`;
  - the model aliases `jev-latest` and `jev-preview`, which are TypeSafe's model names;
  - the docs' references to Jev as TypeSafe's model.
- **Behaviour:** retries, errors, validation, allocation, AOT and telemetry semantics.
- **The release line:** release-please continues from 0.5.x, and `CHANGELOG.md` keeps its history.

## Approach

**1. Rename inside the repository: one PR, no behaviour change.**

- **Projects:** `src/`, `tests/`, `samples/` and `benchmarks/`, `ZeroAlloc.Jev*` → `ZeroAlloc.Decisions*`. That covers folders, `.csproj` names, `PackageId`, `RootNamespace`, `AssemblyName`, `InternalsVisibleTo`, and `ZeroAlloc.Jev.slnx` → `ZeroAlloc.Decisions.slnx`.
- **Types and members:** follow the mapping above, in the generator's emitted source, the analyzers and the code fixes too.
- **Analyzers:**
  - Diagnostic IDs move from `JEV` to `ZAD`. The help links and titles follow.
  - Past releases in `AnalyzerReleases.Shipped.md` are never edited. The `JEV` rules are listed as removed and the `ZAD` rules as new in `AnalyzerReleases.Unshipped.md`, in the format the release-tracking analyzers (RS2000–RS2008) accept.
- **Public API files:** `PublicAPI.Shipped.txt` stays as shipped. The removed `Jev` entries are marked `*REMOVED*` and the new entries added in `PublicAPI.Unshipped.txt`, as the PublicApiAnalyzers require. This is a breaking change in a 0.x line, recorded as such.
- **Telemetry and identity:**
  - The `ActivitySource`, `Meter` and logger category names become `ZeroAlloc.Decisions`.
  - Log message templates that say "Jev" now say "Decisions" or "decision", with the event ids unchanged.
  - The `User-Agent` product token becomes `ZeroAlloc.Decisions`.
  - The observability page and its name tests follow.
- **Docs and README:**
  - Every page, snippet region, table, heading and anchor is updated, and so are the docs tests that tie the docs to the code.
  - The README title, install lines and logo alt text change. A line says Jev (TypeSafe) is a supported provider.
  - The docs site's base URL in links becomes `https://decisions.zeroalloc.net`, applied in step 2's PR (see below), together with the site move.
- **Package tags:** `jev;typesafe;systemone;decision-model` on both packages.
- **Repository references:** links to `github.com/ZeroAlloc-Net/ZeroAlloc.Jev` change to `ZeroAlloc.Decisions`. GitHub redirects the old URL once the maintainer renames the repository.
- **CI and workflows:**
  - solution and project paths;
  - the AOT smoke and surface projects;
  - the `aot-surface` rooted assemblies;
  - benchmark paths;
  - the `docs-site.yml` checkout path, `repos/decisions`, applied with step 2.
- **The paused Phase 5.5 branch is not touched.** Its package ids are updated when Phase 7.4 replays it.

**2. Repository and docs site, after the code PR merges, in order:**

1. The maintainer renames the GitHub repository to `ZeroAlloc-Net/ZeroAlloc.Decisions`. GitHub redirects old URLs, clones and the API.
2. A ZeroAlloc-Net/.website PR, asked of the maintainer like the earlier ones, does three things:
   - renames the submodule `repos/jev` to `repos/decisions`, pointing at the renamed repository;
   - renames the app `apps/docs-jev` to `apps/docs-decisions` (`za-docs-decisions` in `wrangler.jsonc` and `package.json`);
   - updates the home-page entry and the README row.
3. The maintainer creates the Cloudflare Workers project `za-docs-decisions`, with the same build settings as `za-docs-rest`, and the custom domain `decisions.zeroalloc.net`. A redirect rule sends `jev.zeroalloc.net/*` to `decisions.zeroalloc.net/$1`.
4. A follow-up PR here points `docs-site.yml` and `trigger-website.yml` at the new paths, and switches the README and docs links to `decisions.zeroalloc.net`.

Steps 2–4 depend on maintainer actions. STATE.md lists them until they are done.

**3. Verification gates. All must pass with the renamed code.**

- `dotnet build -c Release` with 0 warnings, and the whole test suite.
- **AOT:** the `aot-surface` job (whole surface, no IL2xxx/IL3xxx warnings), `aot-smoke`, and entry-point coverage. Every public entry point keeps a `[Covers]` check under its new name.
- **Allocation budgets:** unchanged. The same gates are measured the same way.
- **Docs:** the docs tests, including links, anchors, tables tied to code, the snippet sync (`dotnet mdsnippets` with an empty diff) and the README tests.
- **Pack tests:** for the new package ids, tags and the packed icon.
- **Live smoke on `main`** after the merge: 13/13.
- **A "no Jev left" check,** as a new docs/pack test. It scans source, docs, samples and package metadata for `Jev` identifiers and fails on anything outside an explicit allow-list:
  - the environment variables;
  - the `jev-latest` and `jev-preview` model strings;
  - prose naming Jev as TypeSafe's model;
  - the `JEV` IDs in `AnalyzerReleases.Shipped.md`;
  - `CHANGELOG.md`, and planning and history documents.

## Files / Modules Touched

Every project under `src/`, `tests/`, `samples/` and `benchmarks/`, the solution file, every `docs/*.md` page except the planning and history documents, `README.md`, the `.github/workflows/*` paths, `Directory.Build.props` (if it names projects), `mdsnippets.json`, and the AOT surface root list. The `refactor-analysis` pre-plan step produces the authoritative list and the safe order.

## Tests

- **Unit, generator, analyzer, DI and integration:** they pass under the new names, with snapshot or verified-source files regenerated and their diffs checked to be name-only.
- **Docs:** all docs tests pass, including the renamed diagnostics page's tie to `ZAD` IDs.
- **AOT and pack:** both pass, with the new package ids and the tags checked.
- **The no-Jev check**, described above.
- **Regression:** allocation budgets unchanged, and the live smoke run 13/13 after the merge.

## Open Questions

None. The maintainer settled the name, the package layout, the fate of `ZeroAlloc.Jev`, the analyzer prefix and the type-naming rule on 2026-10-09.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A behaviour change slips into a mechanical rename | A silent regression | No logic edits in this phase. Generated-source snapshot diffs must be name-only, and the full suite, AOT, budget and live gates must pass unchanged. |
| The release-tracking or PublicApiAnalyzers reject the ID and type churn | The build fails | Follow the analyzers' documented removed/added format, and never edit shipped history. |
| `Question` or `Answer` collides with types in a user's own code | A compile ambiguity for raw-API users | Typed users rarely touch these. The guide notes the `using` alias, and 7.1's review may revisit. |
| The repository and docs-site move breaks CI or links | A failing `docs-site` job, dead links | Move in the ordered steps above. GitHub redirects the repository and a redirect rule covers the docs domain. Step 4's PR fixes this repo's references once the new paths exist. |
| Snapshot and verified files churn hugely | Review fatigue | Regenerate them in one dedicated commit, and confirm the diff is name-only by a scripted check that maps old names to new and expects an empty remainder. |
