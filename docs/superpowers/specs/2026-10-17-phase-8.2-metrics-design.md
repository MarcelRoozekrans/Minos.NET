# Phase 8.2 Design — `Metrics and reports in Minos.NET.Evaluation`

**Date:** 2026-10-17
**Phase:** `8.2`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)

## Goal

Given a provider's `IDecisionClient` and a loaded `DecisionDataset`, run every item and save the per-item results. Then compute a calibration report as versioned JSON and as Markdown. The report says how accurate and how well calibrated the provider is, per question kind, on the number users gate on. It also gives a threshold sweep, latency, and cost per 1,000 decisions.

## Decisions

By the maintainer:
- **Milestone design, 2026-10-17:**
  - Calibrate the number users gate on.
  - Send one request per item.
  - Take cost from the provider when it reports one, otherwise from a dated price table.
  - No recalibration: that is #124.
- **This phase, 2026-10-17:**
  - **A run saves its raw results to a file.** Reports are computed from that file, so changing a metric or the Markdown never needs a new billed run, and Phase 8.4's reports can be regenerated from committed results.
  - **One request at a time by default.** A configurable degree of parallelism raises it.

My calls:
- **Scoring:**
  - **Noul:** the answer is `true` when `Probability ≥ 0.5`. Its confidence is `max(p, 1 − p)`. It is correct when the answer equals the expected `bool`.
  - **Choice:** the answer is the option at `ChosenIndex`, read through the response definition's option keys. Its confidence is `Confidence`. It is correct when the key equals the expected key, compared ordinally.
  - **Score:** the answer is the level `ChosenIndex`. Its confidence is `Confidence`. It is correct only on an exact level match.
  - **Unscored questions:** a question with no expected answer is sent and its answer saved, but it is not scored.
- **Failures are abstentions.** A request that fails, with any `DecisionError` (Unsupported included) or a cancellation of that item alone, is saved with its error. It counts as unanswered for every scored question on the item.
  - Accuracy is computed over answered questions.
  - Coverage at threshold 0 is the answered share.
  - The report shows the error count and the error kinds.
- **Bins:** 10 bins that each hold the same number of answers, sorted by confidence. With fewer than 10 answered questions there are fewer bins, one per answer. The reliability table shows each bin's count, its mean confidence, and its accuracy.
- **ECE:** the count-weighted mean of |accuracy − mean confidence| over the bins. It is also computed with 10 equal-width bins. The JSON carries both; the Markdown shows the equal-mass value and names the binning.
- **Base rate, shown beside accuracy:**
  - Noul: the larger of the true and false rates among the expected answers.
  - Choice and Score: the share of the most common expected answer.
  - The base rate is what a constant answer would score.
- **Threshold sweep:** thresholds from 0.50 to 0.99 in steps of 0.01. At each one: coverage, the share of scored questions answered with confidence ≥ t, and accuracy among those. It is computed per kind and over all kinds together.
- **Latency:** per request, measured with `Stopwatch` around `EvaluateAsync`. The report gives the median and p95 using nearest-rank, over successful requests only, and says so. A response with `IsCached` is flagged in the results and left out of latency.
- **Cost:**
  - **Per item:**
    - When the response's `Usage.Cost` is set, that is the cost.
    - Otherwise, when a price matches the response's model, the cost is the tokens times the price.
    - Otherwise the cost is unknown.
  - **Per 1,000 decisions:** the mean cost over successful requests with a known cost, times 1,000.
  - **Prices used:** the report lists them, each with its date and source, and says how many items had a cost the provider reported, a cost computed from a price, or no cost.
- **The price table is a library object, `PriceTable`.** Each entry has a model id or alias, a price per million input tokens, a price per million output tokens, a date (`DateOnly`) and a source text.
  - **Matching:** an entry matches a response model when the model equals the entry's model id or starts with it followed by `-`. For example, `jev-1.14` matches `jev-1.14-20261014`.
  - **Sources:** the tool in 8.3 reads the table from configuration. 8.2 only consumes it.
- **Determinism:**
  - JSON and Markdown use invariant culture.
  - Numbers are rounded to 4 decimals in the Markdown and kept at full precision in the JSON.
  - The Markdown is produced from the report object alone, so the same results always render the same Markdown.

## Settled after the builder check (my calls)

1. **The sweep covers 0.00 to 0.99 in steps of 0.01.**
   - In the JSON, a Choice or Score confidence can sit below 0.5, so the unfiltered row at 0.00 must be visible.
   - The Markdown shows 0.00, 0.30, 0.50, 0.60, 0.70, 0.80, 0.85, 0.90, 0.95 and 0.99.
   - Coverage is relative to scored questions, so failures count as uncovered.
2. **Denominators:**
   - *Scored* means the question has an expected answer. *Answered* means scored and its request succeeded.
   - Accuracy, ECE, bins and base rate use answered questions. Coverage uses scored questions.
   - The summary table shows scored, answered and accuracy.
   - Unscored questions appear only as a count in the report header.
3. **Dataset name:** `DatasetRunOptions.DatasetName`, a string defaulting to `"dataset"`. The 8.3 tool fills it with the file name. `CalibrationReport.Create` checks the item count and every id, in order, against the dataset.
4. **Cost edge cases:**
   - A price needs both token counts. If either is missing, the cost is unknown.
   - A reported `Cost` of 0 counts as reported. A negative one counts as unknown.
   - Cached responses are left out of cost and latency, and counted separately, because the cost belongs to the original call.
5. **Saved answers:**
   - A Choice answer is saved as its option key and a Score answer as its level index. Answers are read against the item's own definition.
   - Expected answers are never copied into the results.
6. **The report object carries the run header.** `ToJson` embeds it. The Markdown title date is the header's `finished` date in UTC.
7. **Models:**
   - The title names the header's default model, and a line lists the distinct response models with their counts.
   - A response with a null model has an unknown cost, with no fallback.
8. **Errors:**
   - Every `DecisionError` kind is counted in the error table, including Unsupported and validation errors.
   - A run never stops early, so an all-error run is a valid report.
   - Cancellation of the caller's token throws.
   - An `OperationCanceledException` that does not come from the caller's token is saved as an error of kind `Cancelled`.

**Facts confirmed:**
- `Minos.NET.Evaluation.Tests` gains a reference to `ZeroAlloc.TestHelpers`, whose version is already in `Directory.Packages.props`, for `TextSnapshot.VerifyText`.
- With equal-mass bins, when the count does not divide by 10 the first bins get one extra answer each. The hand-computed test pins this.
- Whether report getters need `[Covers]` follows the existing `EntryPointCoverageTests` rules.
- `DatasetProblem` and `DatasetProblems` have internal constructors, which the results reader in the same assembly may use.

## The results file, version 1

UTF-8 JSONL.
- **Line 1:** a header object:
  - `kind`: `minos-run`
  - `version`: 1
  - `dataset`: the file name and the number of items
  - `client`: the provider name and endpoint from `DecisionClientMetadata`, when the client offers it, and the default model
  - `started` and `finished`: UTC timestamps
  - `parallelism`
- **One line per item, in dataset order whatever the parallelism:**
  - `id`, the item's line number, `latencyMs`, `cached`;
  - `model`, `inputTokens`, `outputTokens`, `cost` (the reported cost), `responseId`;
  - either `answers`, keyed by question key, each with its kind, the answer value, the confidence, and for Noul the probability;
  - or `error`, with its kind, status code and message.

The expected answers are not copied into the results. A report is computed from the results file plus the dataset, and the header's item count and every id are checked against that dataset. A mismatch is a problem, never a silent join.

## Public API, added to `Minos.NET.Evaluation`

Names are the builder's call within these shapes:

- **`DatasetRunner`:**
  - `static Task<EvaluationResults> RunAsync(IDecisionClient client, DecisionDataset dataset, DatasetRunOptions? options = null, CancellationToken cancellationToken = default)`.
  - `DatasetRunOptions` holds `MaxParallelism` (default 1, at least 1) and an optional `IProgress<int>` that reports completed items.
  - Cancelling the token stops the run and throws. A run is not resumable in v1.
- **`EvaluationResults`:** the header and the per-item results.
  - `Save(string path)` and `Save(Stream)`.
  - `static Result<EvaluationResults, DatasetProblems> Load(string path)` and `Parse(Stream)`, with line-numbered problems, as the dataset loader has.
- **`PriceTable` and `ModelPrice`:** the entry described under Decisions.
- **`CalibrationReport`:**
  - `static Result<CalibrationReport, DatasetProblems> Create(EvaluationResults results, DecisionDataset dataset, PriceTable? prices = null)`.
  - Per-kind and overall metric objects with the numbers listed above.
  - `string ToJson()`, versioned, with `kind: "minos-report"` and `version: 1`, and `string ToMarkdown()`.

Everything is Native AOT and trim compatible, with the repository's gates as in 8.1: PublicAPI, AOT smoke `[Covers]`, the AotSurface root, and surface rules. The project stays non-packable until 8.3.

## The Markdown report

The order is:
1. a title with the provider and model, and the date;
2. the dataset name with its item count;
3. the error count and kinds;
4. a summary table per kind: answered, accuracy, base rate, ECE and count;
5. a reliability table per kind;
6. the threshold sweep at 0.50, 0.60, 0.70, 0.80, 0.85, 0.90, 0.95 and 0.99 per kind;
7. latency, median and p95, with the request count;
8. cost per 1,000 decisions, with the prices used and the cost-source counts;
9. a short "How to read this" paragraph: the gated number, the binning, base rate, abstentions, and small-sample caution.

The full sweep is in the JSON.

## Tests

- **Metrics against hand-computed values.** A fixed 12-item results set with known confidences and correctness. Assert:
  - accuracy, base rate and equal-mass ECE, to 1e-9;
  - each bin's count, mean confidence and accuracy;
  - the sweep coverage and accuracy at 0.50, 0.80 and 0.95;
  - median and p95 latency, nearest-rank;
  - cost per 1,000 decisions, from a mix of reported and priced costs plus one unknown.

  Plus the edge cases:
  - fewer than 10 answers;
  - all one class;
  - every answer at confidence 1.0;
  - every request failed;
  - an empty dataset.
- **Scoring:**
  - Noul at exactly p = 0.5 is `true` with confidence 0.5;
  - a Choice key compared ordinally;
  - Score exact match;
  - an unscored question is saved but not scored.
- **Runner, with a fake client:**
  - one request per item;
  - results in dataset order with `MaxParallelism` 4;
  - at most N requests in flight;
  - a `DecisionError` becomes an abstention with the error saved;
  - a cached response is flagged;
  - the progress callback is called;
  - cancellation throws and stops sending.
- **Results file:**
  - Save, then Load, gives an equal value;
  - problems carry line numbers;
  - a wrong `kind` or `version` is a problem;
  - a mismatch with the dataset is a problem in `Create`.
- **Prices:** exact and dated-suffix matches, no match, and a reported cost taking precedence.
- **Report output:**
  - the JSON parses and holds `kind` and `version`;
  - the Markdown for the fixed set is pinned as a snapshot. ZeroAlloc.TestHelpers has `TextSnapshot.VerifyText` if the repository already uses it; otherwise a committed expected file.
- **AOT smoke:** a run over a fake client and a report under AOT, covering every new entry point.
- **Regression:** the full suite. The core is untouched, so no allocation budget changes.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Equal-mass bins on ties: many answers at the same confidence | Unstable bin edges | Sort by confidence, then by item order, and cut by count. Ties may straddle bins, which is acceptable and documented. |
| A provider's model id does not match any price, for example a new dated suffix | Cost shows as unknown | The report counts the items with unknown cost. The tool in 8.3 warns on it. |
| Parallel runs produce bursts that cross rate limits | Errors that are not the model's | The default is sequential, and the error kinds show RateLimited separately. |
| The JSON report is consumed later by 8.4's guide and by #124 | Breaking changes later | It carries `kind` and `version` from the start. |
