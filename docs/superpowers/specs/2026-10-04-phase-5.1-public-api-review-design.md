# Phase 5.1 Design — Public API review

**Date:** 2026-10-04
**Phase:** 5.1
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)

## Goal

Review ZeroAlloc.Jev's whole public API and freeze it for 1.0. The API is 445 members: 438 in `ZeroAlloc.Jev` and 7 in `ZeroAlloc.Jev.DependencyInjection`. Make the breaking changes the review and the known issues call for, adopt ZeroAlloc.Telemetry 1.11.0, and close #21.

This is the first phase of Milestone 5 (`docs/superpowers/specs/2026-10-04-milestone-5-design.md`).

## Decisions

The maintainer took these decisions during the brainstorm on 2026-10-04.

| Question | Decision | Why |
|---|---|---|
| #67 `Json = true` | **Remove it from every question-set attribute**, as decided on 2026-09-30. | It is the only place the attribute API takes wire format instead of C#. Built sets keep structured JSON through `JevContent` and `JevCriterion.Json`. |
| #23 `JevErrorKind`'s zero value | **Number the members from 1, with no zero member.** | `default(JevErrorKind)` then matches no member and prints as `0`, so an unset kind is visible as a bug. No member is added that no real error could produce. The repository's `latest-recommended` analysis level does not include CA1008, so nothing is suppressed. This was checked by building with the change. |
| #24 `JevError` construction | **A required `(kind, message)` constructor, with `StatusCode`, `RetryAfter`, `Detail` and `Exception` as `init` properties.** | A field added after 1.0 is then a new property, not a breaking constructor change. RS0026 forbids the alternative, a second overload with optional parameters. |
| #25 disposal during a request | **A new `JevErrorKind.Disposed`.** A call already in flight when `Dispose` runs returns a `Disposed` failure. A call started after `Dispose` still throws `ObjectDisposedException`. | A caller debugging a failure can tell disposal apart from a real timeout. A call made after disposal is caller misuse, and Jev throws for misuse. |
| #85 exception-path telemetry | **Adopt ZeroAlloc.Telemetry 1.11.0.** On an exception, `error.type` is the exception's full type name, and the span's status description is left out. | This follows the GenAI conventions and the logging privacy rule: an exception message can quote request or response text. |
| How deep the review goes | **A checklist pass over every public type, against the .NET Framework Design Guidelines.** Every finding is fixed in this phase. | It meets the milestone's "reviewed and frozen" bar. Breaking changes are cheapest now, because nothing has been published to NuGet. |

## Approach

**1. The review document.** Before any code change, write `docs/plans/2026-10-04-phase-5.1-api-review.md`. It has one row per public type in both packages, with a verdict on each checklist item:
- naming, against the .NET Framework Design Guidelines;
- nullability annotations;
- openness: every class is already sealed, so this records which types stay open and why;
- constructors and overload sets, against RS0026 and RS0027;
- exceptions against `Result` failures, and which cases throw;
- default values and value semantics;
- generated-code helpers such as `JevAnswerReader`, which stay public and hidden from IntelliSense because generated code calls them;
- whether the XML docs are complete and accurate.

A finding links the commit that fixes it. A finding that is additive and a sizeable piece of work in its own right is filed as a post-1.0 issue, and the row links it. A breaking finding is always fixed in this phase.

**2. The known changes.**

| Issue | Change | Breaking |
|---|---|---|
| #67 | Remove `Json` from `NoulAttribute`, `ChoiceAttribute`, `ScoreAttribute`, `CriteriaAttribute` and `LevelAttribute`. Remove JEV109, the analyzer descriptor for JEV108 (it can no longer fire; the id stays for the run-time builder, and both removals go under "Removed Rules" in `AnalyzerReleases.Unshipped.md`), JEV004's and JEV003's JSON branches, and the generator's `JsonMinifier`. Rewrite or remove the affected generator snapshots, analyzer tests and fixtures. | Yes. Setting `Json` stops compiling. |
| #23 | Give every `JevErrorKind` member an explicit value from 1 upward, with no zero member. | Yes. The numeric values change. |
| #24 | `JevError(JevErrorKind kind, string message)`, with `init` properties for `StatusCode`, `RetryAfter`, `Detail` and `Exception`. Update the library's error mapping and every caller in the tests, samples and guide. | Yes. Positional optional arguments stop compiling. |
| #25 | Add `JevErrorKind.Disposed`. `_disposed` becomes a volatile field, and the failure path checks it, so a request torn down by `Dispose` returns `Disposed`. A call started after `Dispose` throws `ObjectDisposedException`, as before. Document both in the XML docs and in `docs/client-and-errors.md`. | Additive. |
| #85 | Bump `ZeroAlloc.Telemetry` to 1.11.0. Configure `IJevOperations` so an exception leaves out the status description. Telemetry 1.11.0 sets `error.type` to the exception's full type name, `GetType().FullName`, as the GenAI conventions expect. | Behaviour only. |
| #21 | Close it with a comment that cites the Phase 4.4 note in `docs/client-and-errors.md`. | No. |

**3. The PublicAPI files.** Every removal and change goes through `PublicAPI.Unshipped.txt`, with `*REMOVED*` lines and new entries, so RS0016 and RS0017 track the whole change. At the end of the phase, Shipped and Unshipped together describe the 1.0 surface, and Phase 5.4's release moves them into Shipped.

**4. The guide.**
- `docs/typed-evaluation.md` drops the `Json = true` sections, and points to `JevContent` and `JevCriterion.Json` for structured JSON.
- `docs/diagnostics.md` drops JEV109 and JEV108 from the analyzer rule table, which stays tied to the analyzer descriptors. A short "Reported by the run-time builder" note documents JEV108, with its own test tied to the builder.
- `docs/client-and-errors.md` covers the kinds table with `Disposed` and the explicit numbering, the init-property construction of `JevError`, and the disposal note.
- `docs/testing-your-code.md` builds `JevError` with init properties in its fake.
- `docs/observability.md` drops the exception-path gap note.

**5. Release notes.** Each breaking change is a `feat!` or `fix!` commit with a `BREAKING CHANGE:` footer. The phase PR's `BEGIN_COMMIT_OVERRIDE` lists them, and its title is itself a valid conventional entry. The 0.3.3 lesson applies: GitHub may not associate the squash commit with the PR. `release-please-config.json` sets `bump-minor-pre-major: true`, so the breaking entries release 0.4.0, not 1.0.0.

## Files / Modules Touched

The refactor impact analysis, which runs before the plan, produces the authoritative list. Starting points:
- `src/ZeroAlloc.Jev/`: `JevErrorKind.cs`, `JevError.cs`, `JevClient.cs` for disposal and error mapping, the five attribute types, `IJevOperations` and its telemetry attributes, `PublicAPI.Unshipped.txt`, plus any type the review changes.
- `src/ZeroAlloc.Jev.Generator/`: `JsonMinifier` and its callers.
- `src/ZeroAlloc.Jev.Analyzers/`: JEV004, JEV108 and JEV109.
- `src/ZeroAlloc.Jev.DependencyInjection/`: anything the review changes.
- `Directory.Packages.props`: the Telemetry 1.11.0 pin.
- `tests/`: the unit, generator, analyzer, DI, docs and AOT-smoke tests affected by the changes.
- `docs/`: the five guide pages above, plus the new review document `docs/plans/2026-10-04-phase-5.1-api-review.md`.

## Tests

- **Regression:** every existing suite stays green, updated where the API changed.
- **New unit tests:**
  - `default(JevErrorKind)` is not a defined member, and every member is non-zero;
  - `JevError`'s init properties round-trip;
  - a call in flight when `Dispose` runs returns `Disposed`, and a call after `Dispose` throws `ObjectDisposedException`.
- **Telemetry:** a thrown call and a cancelled call each produce a span whose `error.type` is the exception's full type name, with no status description.
- **Generator and analyzers:** setting `Json` is a compile error, JEV109 and the JEV108 analyzer descriptor no longer exist, and the builder still reports JEV108 for JSON nested too deep.
- **Disposal:** a disposed client never retries, and a request torn down by `Dispose` reports `Disposed`, tested in both orders against a real timeout.
- **Allocation:** every budget stays unchanged or tightened. Re-measure the telemetry budgets, listening and not, after the 1.11.0 bump. If one rises, find and fix the cause; never loosen the budget.
- **Docs:** every snippet compiles, and the table tests for diagnostics and error kinds pass.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The review finds more than the known changes | The phase grows | A breaking finding is fixed here. An additive finding that is sizeable on its own is filed as a post-1.0 issue. |
| Removing `Json = true` leaves dead shared code, such as `JevLimits.MaximumJsonDepth` | Dead code in the frozen release | The refactor analysis maps every user of the removed code before the plan is written. Anything the builder still uses stays. |
| The Telemetry 1.11.0 bump changes allocations | A budget fails | Re-measure, and fix the cause at the source. |
| The in-flight disposal check races with a real timeout | The wrong kind is reported | A request reports `Disposed` only when `_disposed` was set before the failure was mapped. A test covers both orders. |
| The breaking changes bump the version too far | An accidental 1.0.0 release | `bump-minor-pre-major: true` is set, so they release 0.4.0. 1.0.0 comes from Phase 5.4. |
