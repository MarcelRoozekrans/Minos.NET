# Phase 6.6: Conformance suite — design

**Date:** 2026-10-11
**Milestone:** 6, Provider-neutral core (`docs/superpowers/specs/2026-10-09-milestone-6-design.md`)
**Issue:** #116, conformance part. The calibration part is Milestone 8.
**Surface:** Infra

## Goal

A suite that checks any decision endpoint: request and response shapes for Noul, Choice and Score, multi-question requests, probability distributions, error shapes with request ids, and model reporting. It runs green in CI against recorded TypeSafe and OpenRouter fixtures and against OpenAI fixtures, and Phase 8.3 later ships the same code as a dotnet tool.

## Decisions

- **OpenAI fixtures come from OpenAI's guide for now.** There is no OpenAI key. The success probes replay fixtures built from the guide's examples, as Phase 6.5's were, labeled `source: "guide"`. An issue tracks re-recording them once a key exists; until then the milestone item "recorded OpenAI fixtures" is only partly met, and STATE says so. The bad-key probe needs no key, so OpenAI's 401 is recorded for real.
- **Approach A: a library plus replay tests.** `Minos.NET.Conformance` holds the probes, checks, runner and report as plain code. A test project runs it in replay mode in CI. Phase 8.3 wraps it as the tool. Rejected: tests only, which 8.3 would rewrite, and building the tool now, which pulls Phase 8.3 forward.
- **`DecisionError.RequestId`** is added to the public API, read from the provider's request-id header on HTTP errors.

## Header probe, 2026-10-11

A POST with an invalid key to each endpoint, unbilled, gave these 401 responses:

| Provider | Request-id header | Error body |
|---|---|---|
| TypeSafe, `/v1/systemone` | `x-typesafe-request-id: req_…` | `{"detail":{"error_type":"authentication_error","message":…}}` |
| OpenRouter, `/api/v1/systemone` | none sent; `request-id` is listed in `Access-Control-Expose-Headers` | `{"error":{"message":"Missing Authentication header","code":401}}` |
| OpenAI, `/v1/decisions` | `x-request-id: req_…` | `{"error":{"message":"A valid API key is required.","type":"invalid_request_error","param":null,"code":null}}` |

All three also send Cloudflare's `CF-RAY`, which identifies the CDN hop, not the provider's request, so it is not used.

## Architecture

### Projects

- `src/Minos.NET.Conformance`, `IsPackable=false` in this phase. References only `Minos.NET`. Namespace `Minos.Conformance`.
- `tests/Minos.NET.Conformance.Tests`: unit tests for the checks, runner and report, and the replay suite, in the normal `build` job with no keys.
- `tests/Minos.NET.Live.Tests` gains `ConformanceRecordTests`, behind `MINOS_LIVE` like the other live tests, run by `live-smoke.yml` on `main`.

### Components

- **`ConformanceTarget`**: a name (`typesafe`, `openrouter`, `openai`), a factory `Func<HttpClient, IDecisionClient>`, the model to request, and the target's model rule for R2. The client's `DecisionCapabilities`, from `GetService`, decides which probes apply; a probe that does not apply is skipped with the reason.
- **`ExchangeCapture`**: a `DelegatingHandler` that records, per probe, the request body, the response status, the response body and an allowlist of headers: the request-id headers below and `Retry-After`. It never records `Authorization`, `x-api-key` or any other header. For the bad-key probe it replaces the key header with a fixed invalid value, so no target needs a special factory.
- **Probes**, fixed and ordered, each a `DecisionRequest` with a stable id:
  - `noul`, `choice`, `score`: one question each;
  - `mixed`: Noul, Choice and Score in one set, with keys in non-alphabetical order;
  - `keyed`: a built set with keyed options;
  - `invalid`: a request the provider must reject with 400 or 422;
  - `bad-key`: the `noul` probe with an invalid key.
- **Checks**: pure functions over one probe's captured exchange and Minos's result, each returning `CheckResult(Id, Outcome, Detail)` with `Outcome` pass, fail or skipped.
- **`ConformanceRunner.RunAsync(target, mode, fixtures)`**: runs every probe and check and returns a `ConformanceReport`.
- **`ConformanceReport`**: target, model, mode, fixture source and date, and the check results; written as JSON and as markdown. This is the start of Phase 8.3's report format.
- **Modes:**
  - `Live`: real calls.
  - `Record`: real calls, saving each exchange, errors included, into a fixture file.
  - `Replay`: answers each probe from the fixture file by probe id, not by body hash; an unknown or missing probe id fails the run instead of being skipped.

### Fixtures

`tests/Minos.NET.Conformance.Tests/Fixtures/<target>.json`, one file per target, with a header of `source` (`recorded`, `guide` or `tests`), `model` and `recorded` date, and one exchange per probe.

- **TypeSafe and OpenRouter:** recorded on `main` by `ConformanceRecordTests`. The run uploads the files as a workflow artifact; they never commit from CI. They reach the repository through a PR.
- **Until the first recording**, they are built from the recorded response fixtures already in `tests/Minos.NET.Tests/Fixtures`, with `source: "tests"`.
- **OpenAI:** success probes from the guide, `source: "guide"`, no recorded date; the `bad-key` exchange is the probe's real 401, marked recorded per exchange.
- A test fails when a fixture says `recorded` without a model and date.
- A safety test, like `RecordingsSafetyTests`, scans every fixture for key shapes and auth headers.

## Checks

Shape:
- **S1:** the response is a JSON object with exactly one answer per question asked.
- **S2:** each answer's type matches its question: Noul is `noul` on `/v1/systemone` and `predicate` on OpenAI; Choice and Score are `choice` and `score` on both.
- **S3:** Minos reads the response without an error, and the typed result reads every key.

Distribution:
- **D1:** every probability is finite and in [0, 1].
- **D2:** a Choice's or Score's probabilities sum to 1 within 0.01 and cover exactly the options or levels sent.
- **D3:** a Score's `score` equals Σ level × probability within 0.01.
- **D4:** a reported `confidence` is in [0, 1]; skipped when the provider does not report one.

Multi-question:
- **M1:** the `mixed` answers are matched by key; a parser or provider relying on order fails.

Errors:
- **E1:** `invalid` returns 400 or 422 with a JSON body that Minos maps to `Validation` or `InvalidRequest`, with a non-empty message.
- **E2:** `bad-key` returns 401 or 403, mapped to `Unauthorized`, and is not retried.
- **E3:** an error response's request-id header, when present, equals `DecisionError.RequestId`. When a provider sends none, E3 is skipped and the report says so; OpenRouter's 401 is such a case.
- **E4:** a 429 met during the run has its `Retry-After` reflected in `DecisionError.RetryAfter` and its request id read. A 429 cannot be provoked, so E4 is skipped when none occurs; no synthetic 429 fixture is kept.

Model:
- **R1:** a successful response names a model, and `DecisionResponse.Model` equals it.
- **R2:** the reported model matches the requested one by the target's rule: TypeSafe answers an alias with a versioned id such as `jev-1.13.0`; OpenRouter answers with a prefixed form such as `~typesafe/jev-latest` or `typesafe/jev-1.13-20260917`. The rule is stated in the report.
- **R3:** usage, when present, has non-negative token counts.

Outcome rules:
- A check that cannot run is skipped, never passed.
- Replay requires zero failures, and asserts each target's expected skip set, so a check that starts skipping fails the test.

## `DecisionError.RequestId`

- `public string? RequestId { get; init; }` on `DecisionError`, in the core's `PublicAPI.Unshipped.txt`.
- Read on HTTP error responses only, from the first header present in this order: `x-request-id`, `x-typesafe-request-id`, `request-id`. The order and names are pinned by a test. `CF-RAY` and body fields such as OpenRouter's `id` are not used.
- Null for network, time-out, cancellation and refusal errors.
- `ToString()` includes it. Logging event 1002 and the error span carry it as `minos.request_id`.
- The success path does not change; the existing AOT gates must hold. The error path is outside the allocation budgets.

## Testing

- Every check has a passing and a failing hand-made exchange, including the 0.01 boundaries, an extra answer, a missing answer and a wrong type.
- Runner: each mode, skip reasons, replay failing on an unknown or missing probe id, the bad-key key swap.
- Report: JSON round-trip and a markdown snapshot through `TextSnapshot.VerifyText`.
- Replay suite: `typesafe`, `openrouter` and `openai`, zero failures, the expected skip set per target.
- `RequestId`: header order, absence, each error kind that leaves it null, `ToString`, the log event and span tag.
- `aot-surface` and the AOT smoke gates cover the core change. The conformance library is not shipped in 6.6, so it is outside the AOT surface.

## Risks

| Risk | Mitigation |
|---|---|
| A provider's request-id header differs on other errors than 401. | The record run captures every allowlisted header for every probe; the header order is corrected before complete-phase if a recorded error shows another name. |
| OpenRouter routes to varying upstreams, so model strings vary. | R2's OpenRouter rule accepts the prefixed and versioned forms; a new form fails visibly in the record run. |
| OpenAI's real format differs from the guide. | `source: "guide"` in the fixture and the report; the tracking issue. |
| The `invalid` probe is accepted by a lenient provider. | E1 fails, which is a real conformance finding, recorded in the report rather than hidden. |
