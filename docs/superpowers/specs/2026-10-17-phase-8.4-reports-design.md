# Phase 8.4 Design — `Reports and the guide`

**Date:** 2026-10-17
**Phase:** `8.4`
**Surface:** `Docs`
**Stage:** phase (one phase, implementation-ready)

## Intent

A .NET developer who has decided to use Minos, but not which provider, opens "Choosing a provider and a threshold" on
the docs site. They learn, for each provider:
- how often it is right;
- whether its confidence can be trusted;
- what it costs per 1,000 decisions;
- roughly how fast it answers.

They also learn how to pick a threshold once they have chosen.

Every number in the guide comes from a calibration report committed to the repository. Each report was made by
`minos calibrate` (Minos.NET.Tool 1.2.0, on nuget.org since 2026-10-17) on the public Banking77 sample.

**Why now:** this closes Milestone 8. More providers will follow, for example OpenAI (#161). The maintainer's point is
that choosing between providers matters more as their number grows, so adding one must be cheap: one new report and
one new row, with no rewrite of the guide.

## Goals

- Calibration reports for three providers, each over both sample sets, committed under `docs/reports/`:
  - **TypeSafe** (Jev);
  - **Clef Flash through OpenRouter**, under zero data retention;
  - **the local decision model**, `Mapika/decider-2b-GGUF:Q4_K_M` served by ollajev.

  The sets are `banking77-minos-v1.jsonl` (400 Choice items) and `banking77-urgency-v1.jsonl` (60 Score items).
- A guide page, `docs/choosing-a-provider.md`, published on the docs site. Its comparison table comes from the
  committed reports, and a test fails when the table and the reports disagree.
- The urgency labels are spot-checked and corrected, so the urgency set is no longer a draft.
- The milestone's Definition of Done is satisfied and ticked:
  - the tool is on nuget.org;
  - the reports are committed;
  - the guide is published.

## Non-goals

- New library or tool features. If a run exposes a defect in the tool or the library, fix it in this phase when it is
  small. Otherwise file it.
- Recalibration or cost-aware thresholds (#124).
- Saving partial results on Ctrl+C (#230).
- OpenAI as a provider (#161).
- Ranking providers. The guide shows the evidence and the trade-offs; it does not crown a winner.

## Anti-goals

These would make the phase a failure even if everything else works:
- A number in the guide that no committed report backs, or that drifts from its report.
- A claim of a difference between providers that the sample is too small to support. The milestone's risk table
  applies: report item and bin counts beside the metrics, use equal-mass bins, and state the uncertainty.
- A billed run the maintainer did not start.
- Latency presented as a property of the provider rather than of where the run happened.
- Missing PolyAI and CC BY 4.0 attribution on the guide.

## Decided by the maintainer (2026-10-17)

1. **Readers are choosing a provider.** The guide leads with the comparison. Picking a threshold is the second part.
   The guide must take new providers without a rewrite.
2. **Hosted runs are made by a dispatched CI workflow.**
   - A new `.github/workflows/calibrate.yml`, run by `workflow_dispatch` only. It uses the `live-api` environment's
     `TYPESAFE_API_KEY` and `OPENROUTER_API_KEY`.
   - Its input chooses the provider: TypeSafe or Clef.
   - It installs `Minos.NET.Tool` 1.2.0 from nuget.org and runs `minos calibrate` once per sample set.
   - It uploads each output folder as an artifact.
   - The maintainer starting a run is the approval for that billed run. No test or other workflow makes a hosted call.
3. **The local model runs in `local-systemone.yml`.** After the server starts, `minos calibrate` runs against
   `http://127.0.0.1:8000/` on both sets, and the output folders are uploaded as an artifact. Settled item 4 says how
   it is wired.
   - The tool comes from nuget.org, as in decision 2.
   - It costs nothing.
   - Its latency is labelled as a GitHub-hosted CPU runner.
4. **The urgency spot-check is done, with three corrections.**
   - **Corrections**, applied in `datasets/banking77/urgency-labels.csv`:
     - `b77-card_arrival-25` goes from 0 to 1;
     - `b77-activate_my_card-02` goes from 1 to 0;
     - `b77-change_pin-18` goes from 1 to 0.
   - **Kept:** `b77-change_pin-22` stays at 1, because the customer states a deadline. `b77-lost_or_stolen_card-31`
     stays at 2.
   - **The rule:**
     - A card that is overdue, or held but unusable, is 1.
     - A how-to or information question is 0.
     - A request to activate a card or set a PIN is 0, unless the customer states a real time constraint.
   - **Afterwards:**
     - `build.py` rebuilds the JSONL.
     - The README's "awaiting the maintainer's spot-check" paragraph and its table of flagged labels become a short
       record. It says the spot-check was done on 2026-10-17, lists the 15 items checked and the three changes, and
       states the rule.
     - The dataset version stays 1: the format is unchanged, and no report has used the draft labels.

5. **TypeSafe's price comes from the maintainer.** TypeSafe responses carry token counts but no cost (see
   `docs/providers.md`). The maintainer supplies the input and output price per million tokens, with its source and
   date. It goes into `docs/reports/prices.json`, under the model id the TypeSafe run reports. Clef through OpenRouter
   reports its own cost, so it needs no entry.

## Decided by me (the maintainer can override)

- **Report layout:**
  - One folder per provider and set: `docs/reports/<provider>/<set>/`. The provider slug is one of `typesafe`, `clef-flash` and `local`; the set is one of `banking77` and `urgency`.
  - Each folder holds `results.jsonl`, `report.json` and `report.md`, exactly as the tool wrote them, plus a short
    `README.md`. The README gives the date, the provider and model id, the dataset file and version, where the run
    happened (workflow run URL, runner type), the tool version and the prices used.
  - `docs/reports/` must not become a docs site page, and it must not break the docs tests that treat top-level
    `docs/*.md` files as pages.
- **The guide's comparison table is generated and checked:**
  - A docs test reads every `docs/reports/*/*/report.json` and checks the guide's table cell by cell, much as the
    existing docs tests tie copied tables to the code.
  - The values checked are: accuracy, ECE with its bin count, the coverage and accuracy at a reference threshold, cost
    per 1,000 and median latency, each with its item count.
  - Adding a provider means a new report folder and a new table row. The test lists any report folder missing from the
    table.
- **The guide's shape:**
  1. What the reader is choosing, and the dataset, with attribution.
  2. The comparison table.
  3. One short section per provider: where it is strong and where it falls down, citing its report. A provider that
     refuses or mishandles a question set gets that recorded as a finding, as the milestone design says.
  4. Choosing a threshold, with the sweep from the reports and `ConfidenceThresholds.Classify` in a compiled snippet.
  5. Running `minos calibrate` on your own data, linking to datasets.md.
  6. How to read the uncertainty: the item counts, and why small differences do not rank providers.
  7. `## Next`, as every page has.
- **Prices:**
  - A provider that reports its cost needs no prices file.
  - For one that does not, `calibrate.yml` passes a committed `docs/reports/prices.json` with dated prices and their
    source.
  - The local model shows cost 0, with a note that it costs hardware instead.
- **Parallelism:** `--parallel 1` for every run, so the latency figures mean one request at a time.

## Settled after the builder check (my calls)

1. **`calibrate.yml` inputs.**
   - `provider` is `typesafe` or `clef`.
   - `set` is `urgency`, `banking77` or `both`, with `both` as the default.
   - The 60-item urgency set is the cheap first run, so the maintainer can dispatch it first to prove the routing,
     including Clef under `zdr: true`, before paying for 400 items.
   - There is no separate conformance input.
2. **The model ids are pinned in the config:**
   - TypeSafe: `jev-latest` is pinned, and the model id the response reports is what the prices entry and the report
     README record.
   - Clef: `cloudflare/clef-flash`, after the check against the public model list.
3. **Docs site exclusion.**
   - `reports` is added to `docusaurus.config.ts`'s docs `exclude` and to `PublishedPages.Unpublished` in the docs
     tests. Without that, the tool's `report.md` files would publish as pages and fail the front-matter, Next and link
     gates.
   - The guide links to report folders with absolute GitHub URLs, the form the README uses, because site links to
     excluded files break the link tests.
4. **The local run is a separate job.**
   - A new `calibrate` job in `local-systemone.yml`, run only on `workflow_dispatch`. It has its own
     `timeout-minutes` of 120 and repeats the server setup.
   - The existing job, which runs on every push to `main`, keeps its 30-minute limit and its behaviour.
   - So calibration does not run on every push.
5. **The PR split is simpler than the Constraints section says.**
   - PR 1 carries no guide page at all, so nothing needs hiding. PR 1 holds:
     - the workflows, the run config and `prices.json`;
     - the label corrections and the README record;
     - the docs exclusion;
     - a configuration test showing that `ProviderPreferences:ZeroDataRetention` binds through the tool's
       `ToolConfiguration`;
     - the workflow wiring pins.
   - PR 2 adds:
     - the report folders;
     - the guide, with its place in the sidebar, the README list and its neighbours' `## Next`;
     - the report-to-table docs test;
     - the ticked Definition of Done.
6. **The tables.**
   - The guide has one comparison table per set, Banking77 (Choice) and urgency (Score), with one row per provider.
   - The figures come from the report's per-kind block: `choice` for Banking77 and `score` for urgency. The latency
     and cost columns come from `latency` and `cost`.
   - The test reads the report JSON fields that hold each figure; their exact paths come from the report writer in
     `Minos.NET.Evaluation`.
7. **The tool is pinned:** the package `Minos.NET.Tool` 1.2.0, run as the command `minos`.

## Constraints

- **Billed calls:** hosted calls happen only in `calibrate.yml`, started by the maintainer. One run, both sets, makes
  460 requests.
- **Zero data retention:** the OpenRouter account allows only zero-data-retention endpoints. The Clef section sets
  `ProviderPreferences` with `ZeroDataRetention`, from #202, through the tool's configuration file.
- **The Clef model id:** the milestone design gives `cloudflare/clef-flash`. Check it against OpenRouter's public
  model list, `GET https://openrouter.ai/api/v1/models`, which needs no key and makes no billed call, before the
  workflow is merged.
- **Docs gates:** every page needs front matter, a `## Next` and compiled C# snippets. Links and anchors are tested.
  NoOldNameTests applies: "jev" is allowed only in real model ids.
- **Sequence:** the workflow change must reach `main` before it can run with the `live-api` keys, since that
  environment is restricted to `main`. So the phase lands in two PRs:
  1. **PR 1:** `calibrate.yml`, the local calibrate step, the config and prices files, the label corrections and the
     guide's tested scaffolding. The scaffolding is the report-to-table test and a guide that is empty, or a draft
     hidden from the sidebar.
  2. **Then:** the maintainer dispatches the hosted runs, and the local workflow runs on `main`.
  3. **PR 2:** the downloaded reports, the filled guide and the ticked Definition of Done.

  The published site never shows an empty guide: Settled item 5 keeps the guide out of PR 1 entirely.

## Left to the builder

- **Workflow details:** the job layout of `calibrate.yml`, artifact names and retention, and the hosted job's timeout.
- **The tool's config file for the runs:** one file with `TypeSafe`, `Clef` and `Local` sections, or one per
  workflow.
- **The reference threshold** in the table, chosen from the sweeps once the reports exist, with the reason given in
  the guide.
- **Which statistics show the uncertainty**, for example a binomial interval on accuracy. These must be computed from
  the committed results, by the docs test or by a small script whose output the test checks.

## Tests

- **Docs:** the guide passes every existing docs gate. Its table matches the report JSON cell by cell. Every report
  folder has its README with the required fields.
- **Dataset:** `test_build.py` still passes after the rebuild, and the three corrected labels appear in the rebuilt
  JSONL.
- **Workflows:** WorkflowWiringTests, or its equivalent, pins that:
  - `calibrate.yml` is `workflow_dispatch` only, uses `live-api`, installs Minos.NET.Tool 1.2.0 and passes
    `--parallel 1`;
  - the local step runs against `127.0.0.1:8000`.
- **Regression:** the full suite, the AOT smoke app and the gates.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The Clef id or zero-data-retention routing is rejected | No Clef report | Check the id against the public model list, and run conformance through the workflow first if it is cheap. Record a refusal as a finding. |
| The local CPU run is too slow for the job limit | No local report | Its own dispatch-only job with a 120-minute limit. If that is not enough, run the sets as separate dispatches. |
| A provider reports no cost and no price is known | The cost column is empty | A dated price from the provider's public pricing page, with its source in `prices.json`. |
| 60 urgency items give very noisy figures | Over-reading Score results | The guide states the counts and treats the urgency figures as indicative. |
