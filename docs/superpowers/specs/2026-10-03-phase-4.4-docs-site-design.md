# Phase 4.4 Design — Docs site, logo and README

**Date:** 2026-10-03
**Phase:** 4.4
**Surface:** Docs
**Stage:** phase (one phase, implementation-ready)

## Goal

Make jev.zeroalloc.net serve the user guide from ZeroAlloc-Net/.website and list Jev on zeroalloc.net. Also give Jev the org logo, and cut the README down to an overview that links the site.

This is the last phase of Milestone 4 (`docs/superpowers/specs/2026-10-02-milestone-4-design.md`).

## Decisions

The maintainer took these decisions during the brainstorm on 2026-10-02 and 2026-10-03.

| Question | Decision | Why |
|---|---|---|
| zeroalloc.net home page | **List Jev as available**: a full `packages.ts` entry with `available: true`. | The maintainer wants it visible now. Its NuGet link stays dead until the first release, because NuGet publishing is off (#29). |
| Logo | **Reuse the shared ZeroAlloc icon.** Byte-identical copies of ZeroAlloc.Rest's `assets/icon.svg` and `icon.png`, the indigo square with the white Z. | ZeroAlloc.Rest and Results already share it. Jev's current icon is a placeholder "J". |
| README | **An overview plus one example.** It has the logo, badges, disclaimer, what Jev is, install, one compiled example, a line per guide page linking the site, samples, building and testing, and license. | The guide is the source of user docs, as Phase 4.3 decided. Contributor docs stay in the README. |
| Site build check | **Jev's CI builds the docs site** in a new `docs-site` job. | A broken page then fails the Jev PR, not the later automatic .website submodule PR. Other libraries don't check this; the maintainer chose to. |
| Broken links on the site | **`onBrokenLinks: 'throw'`** in `apps/docs-jev`. | This is the one deviation from the sibling apps, which use `'warn'`. A broken link fails the build instead of shipping. |
| Who changes .website | **This session opens the PR**, following the `docs-orm` PR (ZeroAlloc-Net/.website#25) file for file. The maintainer reviews and merges it. | This was settled in the milestone design. |

## Approach

**1. The ZeroAlloc-Net/.website PR.** It goes on a branch of .website and follows #25.
- **Submodule:** `.gitmodules` and `repos/jev` point at `https://github.com/ZeroAlloc-Net/ZeroAlloc.Jev`.
- **Docs app:** `apps/docs-jev/` is a copy of `apps/docs-rest/` with only the names changed. It holds `docusaurus.config.ts`, `package.json` (`@zeroalloc/docs-jev`), `sidebars.ts`, `tsconfig.json`, `src/css/custom.css`, `wrangler.jsonc` (`za-docs-jev`), `.gitignore` and `README.md`. The config:
  - **Site:** `title: 'ZeroAlloc.Jev'` and `url: 'https://jev.zeroalloc.net'`.
  - **Docs path:** `path: '../../repos/jev/docs'`.
  - **Icon:** `staticDirectories: ['static', '../../repos/jev/assets']`, the same `icon.png` mechanism as Rest.
  - **Excludes:** Rest's three patterns, plus `**/planning/**` and `**/superpowers/**`.
  - **Broken links:** `onBrokenLinks: 'throw'`.
- **Home page:** a `packages.ts` entry for ZeroAlloc.Jev with `available: true`, its docs, GitHub and NuGet fields, and a one-line description. There is no benchmark headline, because Jev has no comparison figure to quote.
- **Other files:** a row in `README.md`'s app table and its `pnpm dev --filter` list, and `pnpm-lock.yaml`.
- **Checks:** before opening the PR, build `@zeroalloc/docs-jev` locally in the clone. .website's `build` workflow then builds it on the PR.

**2. The logo.** `assets/icon.svg` and `assets/icon.png` are replaced by byte-identical copies of ZeroAlloc.Rest's. `Directory.Build.props` already packs `assets/icon.png` as the NuGet `PackageIcon`. The site reads the same file.

**3. The README.**
- **Order:** logo, badges, the unofficial-client disclaimer kept verbatim, two or three lines on what Jev is, install, one typed example, documentation links, samples, building and testing, then license.
- **Logo:** a Markdown image with an absolute `raw.githubusercontent.com` URL. The README is packed into the NuGet package; nuget.org does not resolve relative paths and does not render raw HTML.
- **Example:** a MarkdownSnippets region from `tests/ZeroAlloc.Jev.Docs.Tests`, run as a test. This removes the README's last hand-written C#.
- **Documentation links:** one line per guide page, each an absolute `https://jev.zeroalloc.net/<route>` URL, again for nuget.org.
- **What goes:** everything else. Phase 4.3's final review confirmed that every README fact has a guide home.

**4. The `docs-site` CI job**, in a new `.github/workflows/docs-site.yml`.
- **When it runs:** on pull requests and on pushes to `main` that touch `docs/**`, `assets/**` or the workflow itself.
- **Steps:**
  1. Check out ZeroAlloc-Net/.website with its submodules.
  2. Replace `repos/jev` with this repository's checkout.
  3. Run `pnpm install --frozen-lockfile`.
  4. Run `pnpm exec turbo build --filter @zeroalloc/docs-jev`.
- **Node and pnpm:** set up the way .website's `build.yml` does, with Node 24 and `pnpm/action-setup`.
- **Not a required check:** a path-filtered job that is skipped would block merges if it were required.
- **What it catches:** the app uses `markdown.format: 'detect'`, so `.md` pages are parsed as CommonMark, not MDX. The job catches broken links and anchors (through `'throw'`), bad front matter, and any build error.

**5. Small fixes.** The header comment of `.github/workflows/trigger-website.yml` still says the site picks the repository up "once Phase 4.3 registers it". It changes to describe the live behaviour.

**Order of landing.** The `docs-site` job builds against .website's `main`, so the .website PR merges first. The Jev PR then merges once its `docs-site` job passes.

**Outside both repositories, for the maintainer.**
- Create the Cloudflare Workers project `za-docs-jev`, connected the way the other docs apps are.
- Add the `jev.zeroalloc.net` custom domain.

Until then, the README's site links and the home-page docs link don't load.

## Tests

- **README example:** it compiles as a snippet region and runs as a test against canned answers.
- **Site links:** a new docs test maps every `https://jev.zeroalloc.net/...` link in the README to a published page and anchor, using the site's routing: file path, `routeBasePath: '/'`, and `slug: /` for getting-started. A renamed page or heading then fails the build.
- **Pack:** the pack tests still find `icon.png` in the package.
- **Site build:** the `docs-site` job builds the app with `'throw'`, and so does .website's CI on its PR.
- **End to end:** after both PRs merge, a push to `docs/` dispatches `submodule-update`, and .website opens its automatic submodule PR.
- **Regression:**
  - the Release build has 0 warnings and every suite passes;
  - `dotnet mdsnippets` followed by `git diff --exit-code` shows no drift;
  - every allocation budget is unchanged.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The .website PR waits on review | The Jev PR's `docs-site` job can't pass until then | The Jev PR waits behind it. Nothing else depends on this phase. |
| `'throw'` fails .website's whole build on a broken Jev link | Other sites can't deploy until it is fixed | Jev's own `docs-site` job catches the break before the submodule moves. |
| The README's site links are dead until Cloudflare is set up | Readers hit a missing site | The PR body and the STATE handoff flag the maintainer step. The link test guarantees that every target exists. |
| Docusaurus heading ids differ from the github-slugger rule the docs tests use | Anchors pass the tests and break on the site | The local site build checks every anchor with `'throw'`. A mismatch is fixed in the tests' slug rule, not worked around. |
| The NuGet link on the home page is dead until the first release | A broken link on zeroalloc.net | The maintainer accepted this. NuGet publishing waits on #29. |
