# Phase 6.7: Providers docs and samples — design

**Date:** 2026-10-12
**Milestone:** 6, Provider-neutral core (`docs/superpowers/specs/2026-10-09-milestone-6-design.md`)
**Surface:** Docs

## Goal

A Providers page with the presets and the capability matrix, and a sample that runs one question type against three providers by configuration only. This meets the Milestone 6 item "A Providers docs page shows the presets and the capability matrix. A sample switches providers by configuration only."

## Decisions

- **The three providers are TypeSafe, OpenRouter and a local `/v1/systemone` server.** All three replay real recordings. The local server is ollajev 0.4.0 serving `Mapika/decider-2b-GGUF:Q4_K_M`, as the `local-systemone` CI job runs it, through the `Custom` preset with no key. OpenAI is left out of the sample because there is no key to record with; #161 tracks that.
- **The provider content moves to its own page.** The provider, capability and image sections of `client-and-errors.md` move to `providers.md`, so every provider fact has one home. Rejected: a summary page that links out, which would duplicate two tables.
- **One run per provider, chosen in configuration.** Rejected: one run asking all three side by side through keyed clients, which shows keyed DI more than switching an app's provider.
- **One Choice question, routing support tickets.** It shows a distribution and runs on every preset.
- **No change under `src/`.** This phase is docs, samples, tests and CI only.

## The sample: `samples/Minos.NET.Samples.ProviderSwitch`

### Scenario

About eight authored support tickets. Each gets one Choice question, routing it to `billing`, `technical`, `account` or `sales`. The report prints each ticket with its choice and confidence, then the provider and the model that answered.

The tickets are our own text, as the other samples' data is.

### Configuration

`appsettings.json` holds one section per provider:

| Section | Settings |
|---|---|
| `Minos:Providers:TypeSafe` | `Provider: TypeSafe`; the key comes from `TYPESAFE_API_KEY` |
| `Minos:Providers:OpenRouter` | `Provider: OpenRouter`; the key comes from `OPENROUTER_API_KEY` |
| `Minos:Providers:Local` | `Provider: Custom`, `BaseAddress: http://localhost:8000/`, the decider-2b model, no key |

`Minos:Active` names the section to use. It is set in the file and can be overridden with `--provider <name>` or the environment variable `Minos__Active`. `Program.cs` binds the active section through `AddSystemOneClient(IConfiguration)` and nothing else differs between providers.

### Recordings

One file per provider: `recordings/typesafe.json`, `recordings/openrouter.json` and `recordings/local.json`, in the existing `RecordingsFile` format.

One file per provider is required. TypeSafe and OpenRouter receive byte-identical request bodies, because both use the `jev-latest` model, and the replay handler keys entries by the hash of the request body. A shared file would hold two entries for one hash.

The shared `SampleHost` learns a recordings path per provider and takes the provider label from the active section. The three existing samples keep their single `recordings.json` and do not change.

### Recording runs

- The billed `live-smoke` workflow gains a step that runs the sample with `--record` against TypeSafe and OpenRouter, and uploads both files as an artifact.
- The free `local-systemone` workflow records `local.json` the same way and uploads it.
- The files reach the repository through a pull request, as the conformance fixtures do.

Until the first recording, the sample is built and tested on canned answers, so the phase PR does not depend on a billed run. The recordings arrive in the complete-phase PR, after the maintainer approves the billed run.

### Errors

- An unknown `Minos:Active` value, or a missing section, exits with code 2 and a message naming the configured providers, as a bad mode argument does today.
- Replay with no recording file for the active provider fails with the re-record command for that provider.
- `--live` against `Local` while no server runs fails with the client's own error. The sample's README says to start the server first.

### CI

The samples step in `ci.yml` today runs each sample that has a `recordings.json`. It also runs, for each file in a sample's `recordings/` folder, the sample with `--provider <name>` in replay mode, under the same 120-second limit and the same exit-code and output checks. All three providers replay on every pull request.

### Tests, in `tests/Minos.NET.Samples.Tests`

- The routing and report rules on canned answers.
- A snapshot of the report for each provider.
- The recordings safety scan covers the `recordings/` folder: no key shape, no auth header, the exact entry shape.
- The three provider sections differ only in provider settings: the same keys under `Minos:Providers:*` apart from `Provider`, `BaseAddress`, `Model` and `ApiKey`.
- An unknown or missing active provider exits with code 2 and names the configured providers.

## The Providers page: `docs/providers.md`

### What moves from `client-and-errors.md`

Unchanged except for the introductions:

- Providers: the presets, custom servers and OpenAI.
- Provider differences, with the notes from the probes and the Clef and Luna notes.
- Capabilities: the defaults, overriding them, the `Unsupported` error and reading the resolved capabilities.
- Images, with which providers take them.

`client-and-errors.md` keeps the client, its options, retries, errors and request ids, and gains one short paragraph that links to the Providers page.

### New sections

- **At a glance:** the capability matrix first on the page. It merges the five-row capability defaults table and the 12-row provider differences table into one matrix, one column per `SystemOneProvider` member plus OpenAI.
- **Switching providers:** the sample's `appsettings.json` and how `Minos:Active` picks a provider. A table shows the three providers' answers side by side, and a test ties it to the recordings.
- **Running a local server:** the ollajev and decider-2b commands that the CI job uses, and the `Custom` preset settings that point at the server.
- **Adding OpenAI:** an `AddOpenAIDecisionClient` configuration section, compiled in the docs tests, with a note that the sample has no OpenAI recording until #161.

### Placement

- `sidebar_position` 6, right after "The client and its errors". Every later page and the `patterns` category move down one.
- An entry in the README's Documentation list, in sidebar order.
- Every link and anchor into the moved sections points at the new page. The existing link and anchor tests catch any that are missed.
- `docs/samples.md` and `samples/README.md` list the new sample.

### Docs tests

The table tests move into `ProvidersPageTests`, reading from `providers.md`:

- The capability rows of the matrix match each client's resolved `DecisionCapabilities`, as the capability-defaults test checks today.
- The matrix columns equal the `SystemOneProvider` names plus `OpenAI`, no cell is blank, and every MIN id in it exists. These fold in today's `ProviderDifferencesTests`.
- The side-by-side table matches the recordings' answers.
- The tests in `ProvidersTests` that read `client-and-errors.md` read `providers.md` instead.

## Out of scope

- OpenAI in the sample, until #161.
- Keyed multi-provider registration, which `dependency-injection.md` already covers; the Providers page links to it.
- New capabilities or other public API.
