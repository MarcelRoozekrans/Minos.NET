# Phase 1.3 Design — Question generator core

**Date:** 2026-09-25
**Phase:** 1.3
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

> Roadmap context: `docs/superpowers/specs/2026-09-25-question-generator-roadmap-design.md`. API facts verified against https://docs.typesafe.ai/api.md on 2026-09-25.

## Goal

Developers declare a set of Jev questions as a `[JevQuestions]` partial C# type, and a source generator emits the request's `questions` JSON at compile time plus an allocation-lean parser that turns the response's `answers` object into strongly typed `Noul`, `Choice<T>` and `Score<T>` values — with no transport, reflection or runtime schema building.

## Approach

**User-facing declaration.** A `partial record` or `partial class` marked `[JevQuestions]` declares one partial get-only property per question, typed `Noul`, `Choice<TEnum>` or `Score<TEnum>`, each carrying `[Noul("instructions", True = "...", False = "...")]`, `[Choice("instructions")]` or `[Score("instructions")]`. Choice options and Score levels are enum members: `[Criteria("description")]` on a Choice member (optional — absent sends `null`, which the API documents as "no extra detail"), `[Level("description")]` on a Score member (required — levels cannot be null). Instructions, criteria and levels are strings only in this phase; object/array content is Phase 2.3.

```csharp
[JevQuestions]
public partial record TicketTriage
{
    [Noul("Does `message` ask for a credential?", True = "Asks for a password, API key, or MFA code", False = "No credential is requested")]
    public partial Noul RequestsCredentials { get; }

    [Choice("Which team should handle `message`?")]
    public partial Choice<Team> Team { get; }

    [Score("How urgent is `message`?")]
    public partial Score<Urgency> Urgency { get; }
}

public enum Team    { [Criteria("Charges, invoices, refunds")] Billing, [Criteria("Login, profile, permissions, or security")] Account, [Criteria("No listed team fits")] Other }
public enum Urgency { [Level("Can wait")] Low, [Level("This week")] Medium, [Level("Today")] High }
```

**Wire mapping.** Question property names and Choice enum member names become wire keys via the same snake_case algorithm as `JevJsonContext` (`SnakeCaseLower`): `RequestsCredentials` → `requests_credentials`, `Billing` → `billing`. A `Key = "..."` named argument on `[Noul]` / `[Choice]` / `[Score]` / `[Criteria]` overrides the derived key. Score levels become the ordered `criteria` array in **declaration order**; level index *i* is the *i*-th declared member regardless of its numeric value. There is no "none of the above" construct — the API has no such concept; a catch-all is an ordinary option with a description. The sketch's `NotFor` / `Examples` are a Jev.Net convention (not an API field) and belong to Phase 2.3.

**Runtime types (hand-written, public, in `Jev.Net`).**
- `readonly struct Noul` — `double Probability`; `bool Value => Probability >= 0.5`.
- `readonly struct Choice<T> where T : struct, Enum` — `T Value` (the option the API named in `choice`), `double Confidence`, `ProbabilityMap<T> Probabilities`.
- `readonly struct Score<T> where T : struct, Enum` — `T Value` (argmax of `probabilities`; ties resolve to the lower level), `double Expected` (the wire `score`), `double Confidence`, `ProbabilityMap<T> Probabilities`.
- `readonly struct ProbabilityMap<T>` — a slice `(double[] buffer, int offset, JevOptionSet<T> options)`; indexer by `T`, `Count`, and a struct enumerator yielding `(T Option, double Probability)`.
- `abstract class JevOptionSet<T> where T : struct, Enum` — `Count`, `IndexOf(T)`, `this[int]`; a generated sealed subclass per enum maps values ↔ indices with a `switch`, so explicit enum values work and no reflection, module initializer or global registry is needed.
- `interface IJevQuestionSet<TSelf>` — `static abstract ReadOnlySpan<byte> QuestionsUtf8 { get; }` and `static abstract TSelf Parse(ref Utf8JsonReader answers)`.
- Attributes: `JevQuestionsAttribute`, `NoulAttribute`, `ChoiceAttribute`, `ScoreAttribute`, `CriteriaAttribute`, `LevelAttribute`. `[Choice]` resolves to `ChoiceAttribute` even though `Choice<T>` exists, because C# attribute lookup ignores non-attribute types.
- None of these are records: record equality over a `double[]` slice would compare references and mislead. Default struct equality stands.

**Generated code per `[JevQuestions]` type.** An `IIncrementalGenerator` using `ForAttributeWithMetadataName`, with equatable models for incremental caching, emits: the `IJevQuestionSet<TSelf>` implementation; `QuestionsUtf8` as a `"""…"""u8` literal holding the complete `questions` object (the generator escapes JSON strings itself — it runs on netstandard2.0 inside the compiler without System.Text.Json); private backing fields and the partial property bodies; `Parse`; and one internal `JevOptionSet<T>` subclass per enum used. `Parse` expects the reader positioned on the `answers` object, matches keys with `reader.ValueTextEquals("…"u8)`, reads each answer's fields order-independently (the Phase 1.2 fixture `response-type-last.json` puts `type` last), validates `type` against the declared question kind, maps option keys to enum values via the generated switch, and writes probabilities into **one** `double[]` sized at compile time to the total Choice + Score option count — each `ProbabilityMap<T>` is a slice of it. Unknown answer keys are skipped. A missing expected answer, a mismatched `type`, an option or level key not in the enum, or a missing required field throws `JsonException` — the same failure channel as the wire model, which Phase 1.5 maps to `JevError`. The envelope (`model`, `usage`) is not Parse's concern; the client reads it in Phase 2.1.

**Generator diagnostics (JEV1xx).** The generator reports only what prevents it from generating code: the type is not `partial`; a question property is not a `partial` get-only property of type `Noul` / `Choice<T>` / `Score<T>`; the attribute does not match the property type; a Score enum member lacks `[Level]`; the type has no accessible parameterless constructor; two questions or two options map to the same wire key (generation would produce invalid JSON). API-rule analyzers (option and level limits, empty text, state-field references) remain Phase 2.2's JEV001+.

## Tests

- **Generator unit (`Jev.Net.Generators.Tests`):** snapshot tests of the emitted source for a Noul-only, Choice-only, Score-only and mixed question set, using ZeroAlloc.TestHelpers `GeneratorSnapshot` (verify first that 1.3.3 works now that #50 is fixed); one test per JEV1xx diagnostic; an incremental-caching test asserting an unrelated edit leaves the generator steps cached.
- **End-to-end (`Jev.Net.Tests`, generator attached as analyzer):**
  - Round-trip: question sets mirroring the Phase 1.2 fixtures (`is_urgent` Noul, `department` Choice with a `null` criterion, `frustration` Score) — `QuestionsUtf8` deserialized through `JevJsonContext` into `IReadOnlyDictionary<string, JevQuestion>` equals the `questions` of `request-noul.json`, `request-choice.json`, `request-score.json`.
  - Parse: `response-noul.json`, `response-choice.json`, `response-score.json`, `response-type-last.json` yield the expected `Noul` / `Choice<T>` / `Score<T>` values, including `Probabilities` lookups.
  - Parse failures: missing answer, wrong `type`, unknown option key, unknown level index each throw `JsonException`; an extra unknown answer key is skipped.
  - Edge cases: explicit enum values (`Low = 10`) index correctly; Score argmax tie resolves to the lower level; JSON escaping of quotes, backslashes, control characters, non-ASCII and backticks round-trips exactly; `Key =` overrides.
  - Naming parity: the generator's snake_case equals `JsonNamingPolicy.SnakeCaseLower` across a table of names (acronyms, digits, single letters).
- **Packaging:** local `dotnet pack` listing contains `analyzers/dotnet/cs/Jev.Net.Generators.dll`; Phase 1.8 turns this into a CI gate.
- **Regression:** the existing 44 Phase 1.1/1.2 tests stay green; the build stays warning-free under `TreatWarningsAsErrors`.

## Open Questions

None blocking. Resolved during the brainstorm: typed names `Noul` / `Choice<T>` / `Score<T>`; Score `Value` is argmax with `Expected` exposing the raw score; one shared probability buffer per parse; `Parse` reads `answers` only and throws `JsonException`; `[NoneOfTheAbove]` dropped.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Generator's JSON escaping or snake_case diverges from STJ | Emitted `questions` differ from what the wire model would send, or keys mismatch answers | Round-trip tests through `JevJsonContext`; naming-parity table test against `JsonNamingPolicy.SnakeCaseLower`; escaping test set |
| Roslyn version mismatch with consumers' SDK | Generator fails to load or partial properties unsupported | Pin to the .NET 10 SDK's Roslyn; `global.json` already requires SDK 10.0.401+ |
| Non-incremental pipeline (models capturing symbols) | IDE slowdowns for consumers | Equatable models only; caching test in the suite |
| `GeneratorSnapshot` in ZeroAlloc.TestHelpers 1.3.3 still unusable | No snapshot tests | Check first; fall back to asserting generated source with a plain `CSharpGeneratorDriver` and string comparison, and file the gap upstream |
| API adds fields to answers or new answer types | Parse fails on valid responses | Unknown answer keys are skipped; unknown fields inside a known answer are skipped too |
