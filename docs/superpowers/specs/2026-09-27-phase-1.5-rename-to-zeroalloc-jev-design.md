# Phase 1.5 Design — Rename to ZeroAlloc.Jev

**Date:** 2026-09-27
**Phase:** 1.5
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)

> Why: the NuGet id `Jev.Net` is owned by another publisher (JohnCampionJr / Brightshore, since 2026-09-20). The project becomes `ZeroAlloc.Jev`, published from the `ZeroAlloc.NET` NuGet account with its repository in the `ZeroAlloc-Net` GitHub org. Org conventions were surveyed from ZeroAlloc.Rest, .Results, .Resilience, .Inject, .Validation and .Telemetry on 2026-09-27.

## Goal

Every name, project, package and generated reference moves from `Jev.Net` to `ZeroAlloc.Jev`; the repository conforms to the ZeroAlloc-Net org's layout, package metadata and CI/release conventions; a Native AOT smoke app proves the whole client path publishes with zero IL warnings; and the repository is published publicly as `ZeroAlloc-Net/ZeroAlloc.Jev` with CI green — while nothing is released to nuget.org.

## Approach

**Naming map.** Package id and root namespace `Jev.Net` → `ZeroAlloc.Jev`; sub-namespaces `Jev.Net.Serialization` / `Jev.Net.Transport` → `ZeroAlloc.Jev.Serialization` / `ZeroAlloc.Jev.Transport`. Projects and folders: `src/Jev.Net` → `src/ZeroAlloc.Jev`; `src/Jev.Net.Generators` → `src/ZeroAlloc.Jev.Generator` (singular, as in every org repo; bundled in the main package under `analyzers/dotnet/cs`, not packed separately); `tests/Jev.Net.Tests` → `tests/ZeroAlloc.Jev.Tests`; `tests/Jev.Net.Generators.Tests` → `tests/ZeroAlloc.Jev.Generator.Tests`; `Jev.Net.slnx` → `ZeroAlloc.Jev.slnx`. Public type names keep their `Jev` prefix (`JevClient`, `JevError`, `JevQuestionsAttribute`, …) — they name the API, not the package — and diagnostic ids JEV101–JEV106 are unchanged. The generator's attribute metadata names become `ZeroAlloc.Jev.*Attribute`, emitted code references `global::ZeroAlloc.Jev.*`, and the diagnostic category becomes `ZeroAlloc.Jev.Generator`; generator snapshots are regenerated and re-reviewed. `InternalsVisibleTo` targets, `PublicAPI.*.txt` entries (regenerated through the RS0016/RS0017 code fix), fixture paths and the User-Agent product token (`ZeroAlloc.Jev/{version}`) follow. The local working folder `C:\Projects\Prive\Jev.Net` is not renamed.

**Org conformance.** Decided by the survey or by facts:
- Single target `net10.0` (ZeroAlloc.Rest is net10-only); central package management (as ZeroAlloc.Rest); `.slnx`; `global.json` `latestMinor`; existing analyzer set and `EnforceCodeStyleInBuild` kept.
- `Directory.Build.props`: add `PackageProjectUrl` `https://jev.zeroalloc.net`, `RepositoryUrl` `https://github.com/ZeroAlloc-Net/ZeroAlloc.Jev`, `RepositoryType` `git`; replace the packable-opt-in pattern with the org's opt-out (`IsPackable=false` for projects whose name contains `.Tests`, `.Benchmarks` or `.AotSmoke`, and for the generator explicitly); `Company` / `Copyright` stay `Marcel Roozekrans` (org majority).
- `assets/logo.svg` → `assets/icon.svg`.
- `renovate.json` extends the org configuration (`github>ZeroAlloc-Net/.github`) in the org's shape.
- `.commitlintrc.yml` keeps the project-management scopes (`roadmap`, `state`, `sync`, `milestone`) that the planning workflow uses, and adds `generator` and `samples` scopes as needed.
- The README is rewritten for the new name: title, install line `dotnet add package ZeroAlloc.Jev`, unofficial-client disclaimer kept.
- Living planning files (`docs/planning/ROADMAP.md`, `MILESTONE.md`, `STATE.md`, `CONVENTIONS.md`) use the new names; dated specs and plans stay as historical records.

**Native AOT smoke.** `samples/ZeroAlloc.Jev.AotSmoke` in the org shape: `OutputType=Exe`, `PublishAot=true`, `InvariantGlobalization=true`, `OptimizationPreference=Size`, `IsPackable=false`, and — as in ZeroAlloc.Rest — `TreatWarningsAsErrors=false` with the org's exact list `WarningsAsErrors: IL2026;IL2067;IL2075;IL2091;IL3050;IL3051`. It references `src/ZeroAlloc.Jev` (and the generator as an analyzer) and exercises the real code paths over an in-process stub `HttpMessageHandler`: a successful `EvaluateAsync`, a 422 with JSON detail, `ListModelsAsync`, a malformed 2xx body (`InvalidResponse`), `ListModelsAsync` on OpenRouter (`Unsupported`), and a compile-time `[JevQuestions]` type round-tripping `QuestionsUtf8` and `Parse`. Any mismatch exits non-zero. Verified locally with `dotnet publish -r win-x64 -c Release` and by running the binary; CI runs it on linux-x64.

**GitHub surface.** Adapted from ZeroAlloc.Rest and the org's reusable workflows in `ZeroAlloc-Net/.github`: `.github/workflows/ci.yml` (restore, build, test on ubuntu; `aot-smoke` job installing clang/zlib, publishing linux-x64 and running the binary), `release-please.yml` with `release-please-config.json`, `.release-please-manifest.json` and a seeded `CHANGELOG.md`, and `publish-from-manifest.yml` (inert until a NuGet API key secret exists in 1.8). Benchmarks, GitVersion alpha pushes, the API-compat baseline (needs a first release) and the docs-site trigger (Phase 4.3) are out of scope.

**Going public.** At the end of the phase, after a final pre-publication audit (no secrets, no session links, no private data in any file or commit; audit of 2026-09-27 found none) and an explicit confirmation from the maintainer: create **public** repository `ZeroAlloc-Net/ZeroAlloc.Jev`, add it as `origin`, push `main`, and watch `ci.yml` (including `aot-smoke`) go green. Then re-run `init-conventions`, because branch protection or required pull requests may now apply. No NuGet secret is configured, so nothing is published to nuget.org.

## Tests

- **Regression:** all existing tests (180 in the main test project, 55 in the generator tests) pass unchanged in behaviour after the rename; Release build with 0 warnings.
- **Generator:** snapshots regenerated with `ZA_SNAPSHOT_UPDATE=1` and reviewed: the only differences are `Jev.Net` → `ZeroAlloc.Jev` in `global::` references and namespaces.
- **Package:** `dotnet pack` produces `ZeroAlloc.Jev.{version}.nupkg` containing `lib/net10.0/ZeroAlloc.Jev.dll` and `analyzers/dotnet/cs/ZeroAlloc.Jev.Generator.dll`, with repository and project URLs in the nuspec, the icon, the README, and no dependency on the generator.
- **Native AOT:** the smoke app publishes with zero IL2xxx/IL3xxx warnings and exits 0 locally (win-x64) and in CI (linux-x64).
- **Leftovers:** a repository-wide search finds no `Jev.Net` in code, project files or living docs outside dated historical specs and plans.
- **Remote:** the public repository's first `ci.yml` run is green, including `aot-smoke`.

## Open Questions

None blocking. Decided in the brainstorm: include the org's `.github` CI/release surface in this phase; create the repository at the end of the phase, public, after a final audit and confirmation; nothing is published to nuget.org.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A `Jev.Net` string survives in generated code or metadata names | Generator stops finding the attributes; users get no generated code | Snapshot and end-to-end tests fail loudly; final repository-wide search |
| `git mv` plus text replacement corrupts escape-sensitive files | Broken test data | Verify escape-bearing files byte-wise with python and `chr(92)` after edits |
| Org workflows assume secrets or tools (GitVersion, NuGet key) not yet configured | CI red on first push | Keep only CI, AOT smoke, release-please and an inert publish workflow; drop GitVersion steps until 1.8 |
| Publishing the repository exposes something private | Irreversible disclosure | Pre-publication audit of every file and commit, then explicit maintainer confirmation before `gh repo create` |
| Required pull requests after creation block direct commits | Later phases stall | Re-run `init-conventions` after creation; `CONVENTIONS.md` then drives the branch guard |
