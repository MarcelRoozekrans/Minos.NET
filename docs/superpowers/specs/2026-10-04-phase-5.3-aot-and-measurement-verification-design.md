# Phase 5.3 Design — AOT, trim and measurement verification

**Date:** 2026-10-04
**Phase:** 5.3
**Surface:** Infra
**Stage:** phase (one phase, implementation-ready)

## Goal

Prove that ZeroAlloc.Jev's whole public API is clean under Native AOT and trimming, and that the smoke app exercises every public entry point. Then make the allocation measurements trustworthy: fix the flaky gates at their cause, and trace the allocation creep since Phase 3.

This is the third phase of Milestone 5 (`docs/superpowers/specs/2026-10-04-milestone-5-design.md`).

## Decisions

The coverage test makes sure each entry point actually runs when compiled. Neither check alone covers both. |

## Approach

**1. Whole-assembly analysis.**
- **The host.** A new project, `samples/ZeroAlloc.Jev.AotSurface`, publishes with Native AOT. It roots both packages through `TrimmerRootAssembly` and uses `TrimMode=full`. It also includes one `[JevQuestions]` set, so the generated code is analysed as well.
- **CI.** A new `aot-surface` job in `ci.yml`, next to `aot-smoke`, publishes it on ubuntu-latest. Any IL2xxx or IL3xxx warning fails the job.
- **Required check.** Whether `aot-surface` becomes a required check is the maintainer's decision. The plan asks at PR time.

**2. Entry-point coverage.**
- **The test.** It parses `src/ZeroAlloc.Jev/PublicAPI.*.txt` and `src/ZeroAlloc.Jev.DependencyInjection/PublicAPI.*.txt`, removing `*REMOVED*` lines. Its entry points are every public constructor and method. Properties, operators, fields and enum members are covered through their types.
- **The manifest.** The AOT smoke app declares what it covers in a manifest, for example an attribute on each check, or a checked-in list kept in sync by a test. The test fails, naming every uncovered entry point.
- **Matching.** Signatures are matched exactly as RS0016 prints them, overloads included.
- **The smoke app.** It grows to cover the gaps, with its checks grouped by public type in separate files.

**3. Trustworthy measurement.**
- **#79, the relative gates.** Identical code swings by about 17 to 37 B between runs. Find the cause before changing any gate. The candidates are:
  - continuations hopping threads, so `GC.GetAllocatedBytesForCurrentThread` misses or double-counts;
  - timer or thread-pool work;
  - a cold first call.

  Fix the measurement itself. For example, use `GC.GetTotalAllocatedBytes(precise: true)` in a quiet process, or keep the measured path on one thread. A tolerance is allowed only if the noise is shown to be irreducible, with the reason written beside it and a follow-up issue filed.
- **#74, the unit tests.** Move the hand-rolled zero-allocation tests to `AllocationGate`.
- **#73, the smoke app's measuring helper.** Replace the local `SynchronousBytesPerCall` with ZeroAlloc.TestHelpers 1.5.0's measuring API, after checking what the pinned version provides.
- **#68, the creep.** Trace the cause of the drift since Phase 3: about 20 B on non-yielding calls, and 5254 to 5363 B on the yielding call with no factory. Then set the budgets from what the cause shows. No budget is ever raised.

**4. The roadmap split.** Update `docs/planning/ROADMAP.md` and `MILESTONE.md`:
- 5.3 is renamed;
- a new 5.4, "Live and alias verification", is inserted;
- the 1.0 release becomes 5.5;
- the milestone design gets a dated note recording the split.

## Tests

- **Trim and AOT warnings:** the `aot-surface` publish has none.
- **Coverage:** the coverage test passes. Mutation-check it: a public method without smoke coverage must make it fail.
- **Flakiness:** each measurement fix is proven by repetition. The fixed gates pass 20 consecutive runs, locally and on Linux CI, where the old gate failed about every second run. The before and after rates are recorded.
- **Regression:** every suite stays green, and every budget stays the same or gets tighter.

## Open Questions

None. Whether `aot-surface` becomes a required check is a decision for PR time, not a design question.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Rooting everything uncovers trim warnings in a dependency | Red CI | Fix the cause where it lives: in Jev, or upstream through the ZeroAlloc org session. Never suppress the warning. |
| The 17–37 B swing has no stable fix | The gate stays flaky | Document the cause, add a tolerance sized from the measurements, and file a follow-up issue, as the no-workarounds rule requires. |
| The coverage test is noisy for overloads, generics and default interface members | False failures | Match on the PublicAPI signatures, exactly as RS0016 prints them. |
| The smoke app grows large | Maintenance cost | Group the checks by public type, in separate files. |
