# Phase 10.1 Design — `Escalation middleware`

**Date:** 2026-11-04
**Phase:** `10.1`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)

> Details Phase 10.1 of the Milestone 10 design (`docs/superpowers/specs/2026-11-04-milestone-10-design.md`), which carries the binding requirements, the maintainer's decisions and the settled calls this spec builds on. Issue #119.

## Goal

`UseEscalation` in the core: a pipeline stage that asks the app's own client first, re-asks only the questions below their per-key threshold on a keyed target client, within the time left, and returns one merged `DecisionResponse` whose new `Path` says, per question, which client answered and why.

## Why

Daedalus.NET gives up below 0.6 confidence on its demand Score and falls back to a default (`NodeSelectionMapper.LowConfidence`). Escalation replaces "give up" with "ask a stronger decider", only for the unsure questions and only when the time budget allows. The per-question path is the foundation for 10.2 (fallback reuses it), 10.3 (the sample's report splits by it), the recorder and the dotnet/extensions draft.

## Goals, non-goals, anti-goals

- **Goals:** the stage, the path API, a way for typed callers to read the path, the time check, telemetry, logging and the recorder carrying the path.
- **Non-goals:** the fallback chain (10.2); more than one escalation target (a chain of targets is 10.2's `UseFallback` placed under the target); measured latency medians; seeding thresholds automatically from calibration reports (the 10.4 guide shows how to copy a report's threshold into configuration); splitting the shadow report or dataset export by path (10.3 decides whether its report needs that).
- **Anti-goals:** any state (question text, task text, options' text, images) in a log message, a span, a metric tag or an exception message; added latency or allocations on the path where no question is unsure beyond the threshold checks and the path itself; a breaking change to any shipped type.

## Decisions

### Made by the maintainer in this brainstorm (2026-11-04)

1. **The path names every client with a string.** The primary is named by `EscalationOptions.PrimaryName`, default `"primary"`; the target by its DI key. A string per client keeps the recorder, span tags and counters uniform, and 10.2's chain reuses it.
2. **Typed callers get `response.As<T>()`.** `EvaluateAsync<T>` returns only `T`, and the conversion from a response is internal, so today a typed caller cannot see the path, nor `Usage` or `Model`. A public `DecisionResponse.As<T>() where T : IQuestionSet<T>` lets a caller call `EvaluateAsync(new DecisionRequest(T.Definition, state))` and read both the typed answers and the envelope. It throws `InvalidOperationException` when the response answers a different definition, as the typed calls do today.
3. **Usage per call in the path, total on the response.** `Path.Calls` lists each call made: client name, model and usage. `response.Usage` sums what the calls reported; a count or cost is `null` only when no call reported it. A report prices each call by its own model from `prices.json`.
4. **The path lives on the response:** `DecisionResponse.Path`, an init-only `DecisionPath?`, `null` when no routing stage ran. Rejected: a route on each `QuestionAnswer` (grows the struct for every caller, and typed results still would not carry it); a side channel through a scope or `GetService` (easy to mismatch under concurrency, hard to propose upstream).
5. **The cache stores the path** (decided after the builder check). `CachedDecision` and `CachedDecisionFormat` in `Minos.NET.Caching` carry `Path`, routes and calls, so a cache outside the escalation stage keeps it on a hit; an entry written before this change reads as no path. The documented order is still caching inside escalation, per client, which caches each tier's answers separately. A cached hit of a merged response reports `IsCached` true and keeps its stored calls, each with the `IsCached` it had when stored.

### Settled after the builder check (my calls)

1. **Usage:** the response's total is summed from `Path.Calls`, per field: `InputTokens`, `OutputTokens` and `Cost` are each `null` only when no call reported that field. `Calls[0]` is the primary call, with the primary response's own `Model` and `Usage`, `null` when it reported none. Each call's `Model` is its own response's `Model`.
2. **`As<T>()`** goes through the same internal conversion as the typed `EvaluateAsync<T>` calls, so both behave alike. It works on any response, one built with the public constructor included. "A different definition" is decided by reference, as `EnsureDefinition` does today: `QuestionSetDefinition` has reference identity. A merged response keeps the primary's definition instance, so `As<T>()` works on it.
3. **Deadline propagation:** the stage does not bound the primary call itself; the caller's token governs it. A primary that overruns finds no time left, and its unsure questions are routed `NoTimeLeft`. The stage resolves the effective deadline once, at entry: the request's `Deadline`, or entry plus `Budget`. It then stamps that absolute `Deadline` on the request it passes to the inner client and on the subset request, so a deadline-aware stage below, such as 10.2's `UseFallback`, uses the same clock.
4. **Equality:** `DecisionRequest` already has a hand-written `Equals` and `GetHashCode`; `Deadline` is left out of both, and every other member keeps its current equality.
5. **Per-question failures** arrive inside a `DecisionError`, so a response is all success or a failure. There are no partial answers to route, and `RouteReason` needs no `PrimaryFailed`.
6. **A target response for another definition** (not the subset's instance) is treated as a target failure, `TargetFailed`, with a log event. Kinds and option counts are already checked by the `DecisionResponse` constructor. An escalated answer keeps its own `ProbabilitySource`.
7. **One escalation stage per pipeline.** Building a second `UseEscalation` over one that is already in the pipeline throws `InvalidOperationException` from `Build`, found through `GetService`; more tiers are 10.2's job.
8. **Record format version 3,** written only when the record's response has a path, following the existing rule that version 2 is written only when an answer is marked. Routes are stored per answer, and the calls once per record. Versions 1 and 2 still read.
9. **Target resolution, found while planning:** the core has no DI dependency, so its `UseEscalation` overloads take the target as a client or a factory, as `UseShadowRecording` does, with `EscalationOptions.TargetName` naming it. The by-key overload `UseEscalation(builder, string targetKey, …)` lives in `Minos.NET.DependencyInjection`, and names the target by its key.
10. **Name review, plan task 1:** one rename. `DecisionCall.Client` becomes `DecisionCall.ClientName`: the value is a client's name, not a client, and a string property named `Client` reads as an `IDecisionClient`. It now matches the other name strings, `DecisionClientMetadata.ProviderName` and `EscalationOptions.PrimaryName` and `TargetName`. The other names stay. `Model`, `Usage` and `IsCached` keep the names `DecisionResponse` already uses, rather than Microsoft.Extensions.AI's `ModelId` on `ChatResponse`, so a call reads like the response it came from. `Path` stays as the maintainer chose it (decision 4); it is a different type from the `Path` string on `SystemOneDecisionClientOptions`, which is the endpoint's HTTP path. `QuestionRoute`, `AnsweredBy`, `PrimaryCertainty`, `TargetCertainty`, `RouteReason` and its four values, `DecisionPath`, `Routes`, `Calls` and `As<T>()` stay as proposed.

### Carried from the milestone design

- Unsure: a Score or Choice when `Confidence` < threshold; a Noul when `max(p, 1 − p)` < threshold.
- Only unsure questions are re-asked, as a subset `QuestionSetDefinition` with each question's definition unchanged, the original state and images, `RetryAttempt` 0, and the request's `Model` cleared (the target uses its own configured model). The answers merge back by key.
- The escalated answer wins even when it is less confident; the path records both certainties.
- The deadline is absolute, read from the stage's `TimeProvider`, not part of `DecisionRequest` equality or the cache key. Expected latency is configured per target only.
- Merged metadata: `Model`, `Id`, `UpstreamProvider` are the primary's; `IsCached` is true only when every answer came from the cache; each answer keeps its own `ProbabilitySource`.

## Approaches

1. **`DecisionResponse.Path` (chosen).** One init-only object on the response, mirroring `Id`, `UpstreamProvider` and `IsCached`. Additive, carried by `AsCached()`, and it maps one to one onto a proposal for Microsoft.Extensions.AI.
2. **A route on each `QuestionAnswer`.** Reads well per answer but grows a hot struct for every caller and still does not reach typed results.
3. **A side channel.** No core type change, but awkward, unsafe under concurrent calls, and not proposable upstream.

The spike on the local branch `spike/10.1-path` (throwaway, not pushed) built approach 1 with internal types and an internal stage. It confirmed that merging at the answer-slot level through the internal response constructor is simple: an escalated answer's probabilities are copied into the primary's probability buffer at the question's offset, and its `ProbabilitySource` travels with the slot.

## API (proposed; names are reviewed in the plan's first task)

```csharp
namespace Minos;

public sealed class DecisionResponse
{
    public DecisionPath? Path { get; init; }                      // null: no routing stage ran
    public T As<T>() where T : IQuestionSet<T>;                  // typed answers from this response
}

public sealed class DecisionPath
{
    public IReadOnlyList<QuestionRoute> Routes { get; }          // one per question, definition order
    public IReadOnlyList<DecisionCall> Calls { get; }            // each call made, in order
}

public readonly struct QuestionRoute : IEquatable<QuestionRoute>
{
    public string Key { get; }
    public string AnsweredBy { get; }                            // client name: PrimaryName or the target key
    public RouteReason Reason { get; }
    public double PrimaryCertainty { get; }                      // Confidence, or max(p, 1 - p) for a Noul
    public double? TargetCertainty { get; }                      // set when the target answered
}

public enum RouteReason { Confident, Escalated, NoTimeLeft, TargetFailed }

public sealed record DecisionCall(string ClientName, string? Model, DecisionUsage? Usage, bool IsCached);

public sealed record DecisionRequest
{
    public DateTimeOffset? Deadline { get; init; }               // not in equality or the cache key
}

public sealed class EscalationOptions
{
    public string PrimaryName { get; set; } = "primary";
    public double DefaultThreshold { get; set; }                 // 0 to 1
    public IDictionary<string, double> Thresholds { get; }      // per question key
    public TimeSpan ExpectedLatency { get; set; }               // the target's, configured
    public TimeSpan? Budget { get; set; }                       // used when the request has no Deadline
}

public static class EscalatingDecisionClientBuilderExtensions
{
    public static DecisionClientBuilder UseEscalation(this DecisionClientBuilder builder, string target, Action<EscalationOptions>? configure = null);
}

public sealed class EscalatingDecisionClient : DelegatingDecisionClient { /* public ctor taking inner, target, options, logger, timeProvider */ }
```

`Thresholds` binds from configuration as a section of key/value pairs, the way Daedalus's thresholds do now. A threshold of 0 never escalates; 1 escalates every answer below certainty 1.

## Behaviour

1. Resolve the effective deadline and stamp it on the request. Call the inner client. A failure is returned as is: escalation never turns a primary failure into a success (that is 10.2's fallback).
2. Classify each answer against its key's threshold, or the default. When none is unsure, return the response with a path of `Confident` routes and one call. No subset is built.
3. **Time check.** The deadline is the request's `Deadline`, else stage entry plus `Budget`, else none. If a deadline exists and `deadline − now < ExpectedLatency`, mark the unsure questions `NoTimeLeft` and return the primary's answers.
4. Build the subset definition for the unsure keys, cached per key set on the stage with a small bounded cache, so a repeating pattern does not allocate a new definition per call.
5. Call the target, resolved by DI key from the build's services, with a token linked to the caller's and cancelled at the deadline. On a failure or a deadline cancellation, mark the unsure questions `TargetFailed` and return the primary's answers. The caller's own cancellation still throws `OperationCanceledException`.
6. Merge: copy each escalated answer's slot and probabilities into the primary's positions, route `Escalated` with both certainties, add the target's call, sum usage per the rule above, and return.

## Telemetry, logging, recorder

- **Span:** when the stage runs inside `UseOpenTelemetry`, the span gets `minos.escalation.escalated` (the count of escalated questions) and `minos.escalation.skipped` with the reason when escalation was skipped. Question keys and state are never tags.
- **Metric:** a counter `minos.escalations` with tags `minos.escalation.target` and `minos.escalation.reason`, incremented per escalated or skipped question set, not per question.
- **Logging:** new events in `DecisionLog` after 1013 for an escalation, a skip for time, and a target failure. They carry only the client names, counts and error kind, with no state.
- **Recorder:** each `RecordedAnswer` gains `AnsweredBy`, `Reason`, `PrimaryCertainty` and `TargetCertainty`, and the record gains the calls. This is a new record format version; the reader keeps reading the two existing versions, and a record without a path reads as `null` path fields.

## Tests

- **Unit, the stage:** Score, Choice and Noul thresholds, including a Noul at 0.05 that does not escalate; a confident answer is never re-asked; only unsure keys reach the target, with `RetryAttempt` 0; the escalated answer wins when less confident, with both certainties; per-key thresholds over the default; time skip with a fake clock (`NoTimeLeft`); request `Deadline` over `Budget`; a slow target cancelled at the deadline (`TargetFailed`); a failing target; the caller's cancellation throws; the subset cache reuses definitions.
- **Unit, the merge:** a merged response compared question by question against full responses from each client; usage sums including the null rules; `IsCached` only when every call was cached; `As<T>()` on a merged response; `As<T>()` on the wrong definition throws.
- **Telemetry and logging:** the tags, the counter, and the events, with a check that no state string reaches any of them.
- **Recorder:** round trip of the new record version; old versions still read.
- **Cache:** a merged response round-trips through the cache format with its path, in memory and distributed; an entry written without a path reads as `Path == null`; `Deadline` does not change the cache key.
- **Composition:** `UseEscalation` with `UseRetries`, `UseCaching`, `UseOpenTelemetry` and keyed DI registration.
- **AOT:** zero IL2 and IL3 warnings; the smoke app gates allocations on the all-confident path.
- **API:** ApiCompat clean against 1.9.0.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The merged response differs subtly from a full one (offsets, usage) | Wrong answers or costs | Question-by-question comparison tests against full responses. |
| `Deadline` on the request leaks into the cache key or equality | Cache misses, or two requests compare unequal for no reason | Explicit tests on equality, hashing and the cache key. |
| The public names freeze too early | A breaking change later | Name review as the plan's first task; minor release; the dotnet/extensions draft comes after the sample uses the API. |
| A record format change breaks existing readers | Old record files fail to load | The reader keeps the old versions; a test loads a committed old-version file. |
| Keyed target resolution fails at build time in apps without DI | Confusing exception | The public constructor takes the target client directly; the builder extension resolves by key and throws a clear message naming the key. |
