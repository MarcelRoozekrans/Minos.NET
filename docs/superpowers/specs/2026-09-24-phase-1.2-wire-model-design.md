# Phase 1.2 Design — Wire model

**Date:** 2026-09-24
**Phase:** 1.2
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

## Goal

Public, AOT-safe C# types that exactly mirror TypeSafe's HTTP API (`POST /v1/systemone`, `GET /v1/models`), with a System.Text.Json source-generated serializer context that phase 1.4 plugs into ZeroAlloc.Rest.

## Approach

**Serializer choice.** System.Text.Json source generation, not ZeroAlloc.Serialisation: ZeroAlloc.Rest bridges ZeroAlloc.Serialisation through `RestSerializerAdapter<T>`, which is intentionally single-type per client, while this client needs at least four request/response types. ZeroAlloc.Rest's `SystemTextJsonSerializer(JsonSerializerOptions)` accepts options whose `TypeInfoResolver` is our generated context, which is AOT-safe at runtime.

**Public low-level model.** These types are the M1 public request/response surface (matching the official SDKs' object model); M2's builders and `Choice<TEnum>` produce them. All live in namespace `Jev.Net`, one type per file. Request/response, question/answer and model-list types are `sealed class`es with `required`/`init` properties; the two polymorphic bases (`JevQuestion`, `JevAnswer`) are `abstract class`es with a `private protected` constructor so the hierarchy is closed to this assembly. They are classes, not records, because a record's compiler-generated equality compares collection-typed members (dictionaries, lists) by reference identity, not by content, which is misleading; a record hierarchy also cannot be closed, since every derived record must itself remain a record. `JevUsage`, `ModelCard` and `NoulCriteria` remain `sealed record`s: they hold no collections, so record value equality is correct and useful for them.

| Type (`sealed class` unless noted) | Members (C# → JSON) |
|---|---|
| `JevContent` (readonly struct) | string or `JsonElement`; implicit from `string`; `FromString`, `FromJson`; `IsString`, `TryGetString`, `TryGetJson`; value equality (`JsonElement.DeepEquals`); `ToString` |
| `SystemOneRequest` | `State` → `state` (required `JevContent`), `Model` → `model` (default `JevDefaults.Model`), `Questions` → `questions` (required `IReadOnlyDictionary<string, JevQuestion>`) |
| `JevQuestion` (`abstract class`, discriminator `type`) | `Instructions` → `instructions` (required `JevContent`) |
| `NoulQuestion` (`"noul"`) | `Criteria` → `criteria` (`NoulCriteria?`) |
| `NoulCriteria` (`sealed record`) | `WhenTrue` → `true`, `WhenFalse` → `false` (both `JevContent?`) — renamed in C# because `True`/`False` collide with VB keywords (CA1716) and read poorly |
| `ChoiceQuestion` (`"choice"`) | `Criteria` → `criteria` (required `IReadOnlyDictionary<string, JevContent?>`; null values are written as JSON null) |
| `ScoreQuestion` (`"score"`) | `Criteria` → `criteria` (required `IReadOnlyList<JevContent>`) |
| `SystemOneResponse` | `Model`, `Answers` (`IReadOnlyDictionary<string, JevAnswer>`), `Usage` (`JevUsage`) — all required |
| `JevUsage` (`sealed record`) | `InputTokens` → `input_tokens`, `OutputTokens` → `output_tokens` (required `int`) |
| `JevAnswer` (`abstract class`, discriminator `type`) | — |
| `NoulAnswer` (`"noul"`) | `Noul` (required `double`) |
| `ChoiceAnswer` (`"choice"`) | `Choice` (string), `Probabilities` (`IReadOnlyDictionary<string, double>`), `Confidence` (double) — all required |
| `ScoreAnswer` (`"score"`) | `Score` (double), `Legend` (`IReadOnlyDictionary<string, string>`), `Probabilities` (`IReadOnlyDictionary<string, double>`), `Confidence` (double) — all required |
| `ModelList` | `Models` (required `IReadOnlyList<ModelCard>`) |
| `ModelCard` (`sealed record`) | `Name`, `Description`, `ReleaseDate` → `release_date` (required strings; release-date format is undocumented) |

`JevContent` accepts only a JSON string, object or array; `FromJson` and the converter's `Read` reject numbers, booleans, `null` and undefined, since that is what the Jev API's flexible fields actually accept.

**Serialization internals** (namespace `Jev.Net.Serialization`, internal): `JevJsonContext : JsonSerializerContext` with `PropertyNamingPolicy = SnakeCaseLower`, `DefaultIgnoreCondition = WhenWritingNull`, `AllowOutOfOrderMetadataProperties = true` (so `type` need not be the first property), `RespectNullableAnnotations = true` (so JSON `null` into a non-nullable required member, such as a response's `model` or a choice answer's `choice`, is a `JsonException` instead of silently producing a `null`-backed value), registering `SystemOneRequest`, `SystemOneResponse`, `ModelList`. `JevContentConverter` (applied via `[JsonConverter]` on `JevContent`) writes a string or the raw element and reads a string token as text, an object or array token via `JsonElement.ParseValue`; JSON `null`, a number or a boolean into a `JevContent` is a `JsonException`, and writing an uninitialised `default(JevContent)` throws `InvalidOperationException`. `JevJson.Options` exposes the context's options for phase 1.4. `InternalsVisibleTo("Jev.Net.Tests")`.

**Not in this phase:** API-limit validation (≤255 options, 2–10 levels) → phase 2.4; typed-object helpers on `JevContent` → phase 2.3; transport → 1.3; mapping `JsonException` to `JevError` → 1.4. Required members on response types make missing fields a `JsonException`; an unknown answer `type` also throws `JsonException` ("Read unrecognized type discriminator id") — verified with a probe on SDK 10.0.401.

## Tests

- Unit (`JevContent`): implicit string, `FromJson` object/array, string-valued `JsonElement` normalises to text, `TryGet*`, equality (string and deep JSON), `default` write throws, null into non-nullable throws.
- Serialization (requests): each API-reference request example (noul with criteria, choice with a null option description, score, structured object instructions/state) serialises to JSON equal (`JsonNode.DeepEquals`) to its fixture; `WhenTrue`/`WhenFalse` map to `true`/`false`; omitted optional criteria are not written.
- Serialization (responses): each API-reference response example (noul, choice, score) deserialises with every field asserted; `type` in last position works; unknown `type` throws `JsonException`; `/v1/models` fixture deserialises.
- AOT: `IsAotCompatible` analyzers stay clean under warnings-as-errors (no reflection-based `JsonSerializer` overloads — tests use `JevJsonContext.Default.*` type infos).

## Open Questions

None — visibility (public low-level model) and flexible-field representation (`JevContent`) decided in brainstorm.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Records generate many public members, bloating `PublicAPI.Unshipped.txt` | Noisy diffs | Accept; generate entries with the RS0016 code fix rather than by hand |
| API returns extra/renamed fields later | Deserialisation break | Extra fields ignored by default; required-field removal surfaces as `JsonException`, mapped in 1.4; live smoke (1.6) is the early warning |
| `JsonElement` retained in `JevContent` pins a parsed buffer | Memory | `JsonElement.ParseValue` / `Clone` produce detached elements sized to the value only |
