# Phase 6.2 Design — `Neutral question model and adapter boundary`

**Date:** 2026-10-10
**Phase:** `6.2`
**Surface:** `Refactor`
**Stage:** phase (one phase, implementation-ready)

## Goal

Question sets describe themselves in a provider-neutral model, and everything that knows the `/v1/systemone` wire format moves behind an internal protocol seam. Requests and answers stay byte-for-byte and value-for-value the same (#115).

## Decisions (maintainer, 2026-10-10)

- **Where the seam lives:** an internal `IDecisionProtocol` in core, with `/v1/systemone` as its only implementation. There is no public adapter contract and no new package in 6.2. The `Minos.NET.SystemOne` package and a public adapter contract come in 6.3/6.4, once the client pipeline exists.
- **How visible the model is:** the neutral model is first-class public API. It is documented, inspectable and tracked by PublicAPI. Generated types and the runtime `QuestionSet` expose the same model, so one adapter handles both. The 6.4/6.5 adapters and the 6.6 conformance suite build on it.
- **Approach A: definition in, answer slots out.** The generator emits a definition and a `Create(AnswerSlots)` factory. Protocols serialize the definition and fill the slots. Two alternatives were rejected:
  - keeping the generated systemone literal and parser as a fast path leaves TypeSafe's format in every generated type and needs two parse paths;
  - emitting code per protocol ties the generator to every adapter and shuts out third-party adapters.

## Where `/v1/systemone` is baked in today

- **Generated `[Questions]` types:** each carries `QuestionsUtf8`, the request's `questions` object as a UTF-8 literal. Each also carries `Parse(ref Utf8JsonReader)`, which reads the `answers` object of a `/v1/systemone` response through the public `AnswerReader` and `DecisionOptionSet<T>.IndexOfKey(ref Utf8JsonReader)`. Both are public static abstract members of `IQuestionSet<TSelf>`.
- **The runtime `QuestionSet`:** it writes the same JSON at `Build()`, as the public `QuestionSet.QuestionsUtf8`. It parses through an internal `QuestionPlan[]` into `AnswerSlot`s, a shape that is already neutral.
- **The client:** `TypedRequestWriter` composes `{"state","model","questions"}`. `TypedEvaluation` and `ResponseFields` read the response envelope. `DecisionErrorMapper` reads TypeSafe's and OpenRouter's error bodies.

## The neutral model

The model is the public, read-only, protocol-free form of the internal `QuestionSpec` that `QuestionSetBuilder` already validates into. Its names follow the Phase 6.1 naming rule.

| Type | Holds |
|---|---|
| `QuestionKind`, now public | `Noul`, `Choice`, `Score` |
| `QuestionSetDefinition` | `Questions`: an `IReadOnlyList<QuestionDefinition>` in declaration order, which is also wire order |
| `QuestionDefinition` | `Key`: the wire name, snake_case<br>`Kind`<br>`Instructions`: a `DecisionContent`<br>`WhenTrue` and `WhenFalse`: Noul only<br>`Options` |
| `OptionDefinition` | `Key`<br>`Criterion`: the existing public type, with text or JSON, examples and not-for; optional for Choice options, present for Score levels |

- **Score levels are keyed by position:** `"0"`, `"1"`, …, the keys `/v1/systemone` already uses for a Score's `probabilities`. The generator and both level builders key them this way today. Enum member names stay out of the model until a protocol needs them; Phase 6.5 decides that for OpenAI's rubric. *Corrected 2026-10-10 while planning: an earlier draft said the keys came from enum members.*
- **Factories:** `QuestionDefinition.Noul(…)`, `.Choice(…)` and `.Score(…)` build definitions.
  - Generated code calls them once per type, into a static field.
  - `QuestionSetBuilder.Build()` produces the same types, so a generated set and a built set with the same questions yield equal definitions.
- **Exposure:** `IQuestionSet<TSelf>` declares `static abstract QuestionSetDefinition Definition { get; }`, and `QuestionSet` exposes `Definition`.
- **The name:** *Definition* was chosen over *Description*, which already means an option's criterion text in the docs and attributes. It was also chosen over *Schema*, which suggests JSON Schema.
- **Internal precomputation:** the definition also precomputes what protocols need on every call:
  - the UTF-8 option keys for key-to-index lookup;
  - each question's offset into the shared probability buffer;
  - the buffer's total length.

## The protocol seam

There is one internal interface in core, `IDecisionProtocol`. `SystemOneProtocol` is its only implementation. It owns:

| Responsibility | Today | After 6.2 |
|---|---|---|
| The `questions` JSON | Generated literal, or written at `Build()` | Written from the `QuestionSetDefinition` |
| The request envelope `{"state","model","questions"}` | `TypedRequestWriter` | The protocol's request writer, `SystemOneRequestWriter`, behind `SystemOneProtocol.WriteRequest`; every client request path goes through it. Writing the state, with its text, JSON, UTF-8 and typed kinds and checks, stays shared in `Transport/RequestStates`. |
| A criterion's `{"description","examples","not_for"}` fragment and the escaping | `Criterion.WriteTo`, `Serialization/GeneratorJsonEncoder` | The protocol's questions writer and `Protocols/SystemOneJsonEncoder`; `Criterion` is plain data with public getters |
| Reading answers | Generated `Parse`, `QuestionSet.Parse`, `AnswerReader` | The protocol, into answer slots |

*Amended 2026-10-10 after the final review: the request envelope, the criterion fragment and the encoder are now behind the seam, and `ProtocolBoundaryTests` guards their field names.*

**Deferred to Phase 6.3.** These stay where they are in 6.2, so the seam does not reach them yet:
- **the endpoint path:** it is bound in the source-generated REST interface `IDecisionApi`;
- **the response envelope:** finding `answers` in `TypedEvaluation`, and telemetry's `ResponseFields` and `ConfidenceValues`;
- **error bodies:** `DecisionErrorMapper`.

Moving them means choosing the protocol per client, which is 6.3's pipeline. *Narrowed 2026-10-10 while planning.*

- **What `DecisionClient` keeps:** HTTP, retries, telemetry, logging and disposal. It asks the protocol only for request bytes and for answers.
- **Choosing the protocol:** in 6.2 the client creates `SystemOneProtocol` itself. Phases 6.3 and 6.4 decide how a protocol is chosen and configured.

**Caching the serialized questions:**
- On first use, the protocol serializes a definition's `questions` object. It keeps the bytes in an internal per-protocol slot on the definition, which is immutable and created once per set.
- From the second call on, a request costs what it costs today: a field read and a copy into the pooled body.
- The first call for each generated type pays a one-time serialization, which the compile-time literal used to save. It is measured, but it is not in any per-call budget.

**Unchanged:** the raw API, `EvaluateAsync(SystemOneRequest)` and `ListModelsAsync`, still goes straight to `/v1/systemone`. So do the raw DTOs `SystemOneRequest`, `SystemOneResponse`, `Question`, `Answer` and their subtypes, and `DecisionProvider`. They move in 6.3/6.4. Moving them now would move them twice.

## The answer side

1. **Reading:** the protocol reads the wire answers. For each question in the definition it fills one `AnswerSlot`: the chosen option or level index, the probability (Noul) or expected value (Score), the confidence, and the offset of its distribution in a shared `double[]`.
2. **Allocation:** the slots are stack-allocated. The `double[]` is sized from the definition's precomputed length, and it is the one buffer the typed answers keep.
3. **Hand-over:** a new public `ref struct AnswerSlots` hands the slots to the set, through accessors that take the question's index in the definition:
   - `Noul(int index)`;
   - `Choice<T>(int index, DecisionOptionSet<T> options)`;
   - `Score<T>(int index, DecisionOptionSet<T> options)`.
4. **Building the result:** generated code replaces `Parse` with `static TSelf Create(AnswerSlots answers)`, declared on `IQuestionSet<TSelf>`:

```csharp
public static Triage Create(AnswerSlots answers) => new()
{
    __minos_IsUrgent = answers.Noul(0),
    __minos_Queue = answers.Choice(1, __DecisionOptions_Queue.Instance),
};
```

5. **Runtime sets:** the runtime `QuestionSet` builds its `Answers` from the same slots.

**What leaves generated code:**
- **`AnswerReader`:** it becomes internal to the protocol.
- **`DecisionOptionSet<T>.IndexOfKey(ref Utf8JsonReader)`:** it is removed. The protocol maps wire keys to indexes through the definition's UTF-8 option keys, with the same linear scan, no longer generated per question. The option set keeps `Count`, `this[int]` and `IndexOf(T)`.

**Errors keep their current form:**
- A missing answer, an unknown option or level, a wrong JSON type or a missing field is still a `JsonException` from the protocol. It maps to the same `DecisionError` kind and message as today.
- "Missing" is decided against the definition instead of per generated `foundN` flag.
- Unknown answer keys are still skipped.

**Allocations:** today's generated parse allocates the `double[]` and the result, and the new path allocates exactly those two. Every typed-evaluation allocation budget must come out equal or lower.

A later protocol, such as 6.5's OpenAI adapter, fills the same slots from its own wire answers. The generated `Create` does not change.

## Public API changes

0.x allows breaking changes. This one ships as `refactor(core)!` with a `BREAKING CHANGE` footer, in 0.7.0.

| Removed | Replaced by |
|---|---|
| `IQuestionSet<TSelf>.QuestionsUtf8` | `IQuestionSet<TSelf>.Definition` |
| `IQuestionSet<TSelf>.Parse(ref Utf8JsonReader)` | `IQuestionSet<TSelf>.Create(AnswerSlots)` |
| `QuestionSet.QuestionsUtf8` | `QuestionSet.Definition` |
| `AnswerReader`, the whole class | `AnswerSlots.Noul`, `.Choice`, `.Score`; the reader becomes internal |
| `DecisionOptionSet<T>.IndexOfKey(ref Utf8JsonReader)` | key lookup inside the protocol |

**Added:**
- `QuestionKind`;
- `QuestionSetDefinition`;
- `QuestionDefinition` and its three factories;
- `OptionDefinition`;
- `AnswerSlots`.

**Generator:**
- It emits `Definition` and `Create` instead of the literal and the parser.
- Hint names, the `__minos_` prefix and the `__DecisionOptions_*` classes stay. The option classes lose `IndexOfKey`.
- Every snapshot is regenerated and reviewed.

**Analyzers:**
- No new or renamed rules.
- MIN102 now reserves `Definition` and `Create` instead of `Parse` and `QuestionsUtf8`. Its id, category and severity are unchanged, so release tracking needs no entry. Only the behaviour and its docs change.

## Tests

- **Wire bytes:**
  - Before the change, capture today's generated `QuestionsUtf8` for every generator snapshot case, and `Build()` output for every builder test case, as fixtures from `main`.
  - Assert that `SystemOneProtocol` writes byte-identical `questions` objects and request bodies.
- **Answers:**
  - The existing parse tests run against the new path with unchanged expectations: every kind, every error, unknown keys skipped, and the same `DecisionError` kind and message.
- **The model:**
  - factories and immutability;
  - Score level keys;
  - a generated set and a built set with the same questions producing equal definitions.
- **`AnswerSlots`:** each accessor, plus out-of-range and wrong-kind indexes.
- **The cache:** serialization runs once per definition per protocol, and a second call allocates nothing.
- **The seam:** `ProtocolBoundaryTests` fails when any file outside `Protocols/` names a `/v1/systemone` wire field. Only the files deferred to 6.3 are exempt. Injecting a fake protocol has to wait for 6.3's pipeline, because `GeneratedAnswerParser<T>` is static. *Changed 2026-10-10 while planning.*
- **Regression and gates:**
  - WireMock integration tests, samples replay, AOT surface and AOT smoke: unchanged expectations, apart from the moved budget checks.
  - One Live smoke run: 13/13. *Amended 2026-10-10 after the final review: it runs on `main` after the merge, not on the branch, because the live-api environment deploys only from `main`.*
  - Build with 0 warnings and `dotnet test` green.
  - `mdsnippets` with no diff, and the docs build.
- **Allocation budgets:** every budget equals or beats `main`, and the end-to-end budgets are identical. The checks on removed APIs move to their replacements, and the count stays at 21 or more.
- **Pre-push review:** its report is kept in `docs/plans/`.

## Open Questions

None. The seam's placement, the model's visibility and the approach were decided on 2026-10-10. How a protocol is chosen and configured is Phase 6.3's and 6.4's question.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The serialized `questions` bytes drift from today's literal: escaping, property order, null criteria | A silent wire change against TypeSafe | Byte-equality fixtures captured from `main` for every snapshot and builder case. The protocol reuses `GeneratorJsonEncoder`. |
| The slots path allocates more than the generated parser | A loosened budget | Slots are stack-allocated, and the buffer and result stay the only allocations. Budgets are compared to `main`, and a regression blocks the phase rather than being re-baselined. |
| `ref struct` parameters on a static abstract member don't compile or bind for every target the generator supports | A generator rewrite | Prove it with the first task's spike: one hand-written set compiled against the new `IQuestionSet` under the repo's Roslyn 5 and C# version. |
| Error messages change because "missing" moves from per-field flags to the definition | A user-visible change to `DecisionError` text | The existing error tests run unchanged against the new path. |
| The definition duplicates `QuestionSpec` and `QuestionPlan` | Two models drift | `QuestionSetBuilder` builds the public definition, and `QuestionPlan` is derived from it or removed. The impact analysis decides which. *Resolved 2026-10-10 after the final review: `QuestionPlan` is removed, and a built set keeps only its option sets beside the definition.* |
| A large generated-snapshot churn hides a real difference | A regression slips in | The byte-equality and parse tests carry the proof, so the snapshots are reviewed for shape only. |
