# Phase 5.1 Public API Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Review ZeroAlloc.Jev's whole public API and freeze it for 1.0. Remove `Json = true`, number `JevErrorKind` from 1, add `Disposed`, move `JevError` to init properties, adopt ZeroAlloc.Telemetry 1.11.0, and fix every finding the review makes.

**Architecture:**
1. **The review comes first.** It is a document pass, so its findings can be planned with the known changes.
2. **Then the known changes,** in the impact analysis's build-safe groups.
3. **Then a task that fixes the review's findings.** The controller writes its brief from the review document.
4. **Last, a sweep:** re-measure, audit the PublicAPI files, and verify.

**Tech Stack:**
- .NET 10 and C# 14, Native AOT, and Roslyn source generators and analyzers (netstandard2.0, Roslyn 5.0).
- PublicApiAnalyzers (RS0016 and RS0017) and analyzer release tracking.
- ZeroAlloc.Telemetry and ZeroAlloc.Resilience.
- xUnit, MarkdownSnippets and ZeroAlloc.TestHelpers.

**Spec:** `docs/superpowers/specs/2026-10-04-phase-5.1-public-api-review-design.md`
**Impact analysis:** `docs/plans/2026-10-04-phase-5.1-public-api-review-impact-analysis.md`. It is the authority for file:line references and the risk register. Every task reads its group there.

## Global Constraints

**Builds and analyzers**
- Build and test with `-c Release` only. `TreatWarningsAsErrors` is on, with the MA*, CA, HLQ, xUnit, JEV, RS0016 and RS0017 analyzers and analyzer release tracking. Never suppress a diagnostic.
- Every public API change goes through `src/*/PublicAPI.Unshipped.txt`, as `*REMOVED*` lines for anything in `PublicAPI.Shipped.txt` plus the new lines. `PublicAPI.Shipped.txt` is never edited in this phase.
- Every analyzer rule removed from `src/ZeroAlloc.Jev.Analyzers` is listed under `### Removed Rules` in `AnalyzerReleases.Unshipped.md`. `AnalyzerReleases.Shipped.md` is never edited.

**Allocation budgets**
- Every budget stays unchanged or gets tighter. If a budget fails, find and fix the cause. Never raise the number.
- The AOT smoke app is published from PowerShell, with the Visual Studio Installer folder on PATH. A failed link leaves a stale exe that still runs, so check the exe's timestamp.

**Docs**
- Every C# block in `docs/` and `README.md` is a MarkdownSnippets region from `tests/ZeroAlloc.Jev.Docs.Tests`.
- Run `dotnet mdsnippets` twice. The second run must change nothing.
- Prose in `docs/` wraps at 120 characters.

**Commits**
- Commits are conventional, with scopes from `.commitlintrc.yml`: core, generator, di, tests, benchmarks, samples, docs, ci, deps, roadmap, state, sync, milestone and main.
- A breaking change is a `feat!` or `fix!` commit with a `BREAKING CHANGE:` footer.
- No commit body has nested parentheses, and no commit or PR has a `claude.ai/code/session` URL.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Implementer subagents commit on `phase/5.1-api-review` and never push.

**Decisions that bind every task**
- `JevErrorKind` has explicit values from 1 upward, with no zero member, plus `Disposed`.
- `JevError` is `(JevErrorKind kind, string message)`, with `init` properties for `StatusCode`, `RetryAfter`, `Detail` and `Exception`.
- On an exception, the span carries `error.type` as the exception's `GetType().FullName`, and no status description.
- A call in flight when `Dispose` runs returns a `Disposed` failure, and a disposed client never retries. A call started after `Dispose` throws `ObjectDisposedException`.

- [ ] **Step 1: Find out how a torn-down request arrives.** Write a test with an owned client whose handler blocks until released. Start a call, `Dispose` the client, then release the handler. Record whether the call ends as a failed `Result` (`Network` or `Timeout`) or as a thrown exception. Record also whether the retry proxy retries it, by counting attempts. Put both results in the report.
- [ ] **Step 2: Write the failing tests:**
  - an in-flight evaluate, typed and built-set call all return `Disposed`;
  - none of them retries, so the attempt count is 1;
  - a call started after `Dispose` throws `ObjectDisposedException`;
  - a real timeout before `Dispose` still reports `Timeout`;
  - a borrowed `HttpClient` is never disposed by the client, so its calls are unaffected.
- [ ] **Step 3: Implement it.**
  - `_disposed` becomes volatile.
  - A failure is mapped to `Disposed` only when `_disposed` was set before the mapping. Do this before the retry decision, so the retry predicate never retries a disposed client. Put the check where the client can see `_disposed`, and do not make the mapper reach into the client through a static or global.
  - The logging of retried attempts and the span both see the final kind.
