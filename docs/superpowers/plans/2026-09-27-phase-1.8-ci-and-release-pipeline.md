# Phase 1.8 CI and Release Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI gates allocations under Native AOT, smoke-runs every benchmark, verifies the packed `.nupkg`, fails on any trim or AOT warning, and signals the org website on docs changes. NuGet publishing stays off.

**Architecture:**
- `AllocationGate` checks go into the existing AOT smoke app.
- `benchmarks/ZeroAlloc.Jev.Benchmarks` is a new BenchmarkDotNet project, with `benchmarks.yml` calling the org's shared smoke workflow.
- `tests/ZeroAlloc.Jev.PackTests` is a new project that packs the library and inspects the zip.
- The generator is packed from its real `GetTargetPath`.
- `trigger-website.yml` is copied from the org template.

**Tech Stack:** .NET 10, BenchmarkDotNet 0.15.8 (the same as the siblings), ZeroAlloc.TestHelpers 1.3.3 (`AllocationGate`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-27-phase-1.8-ci-and-release-pipeline-design.md`

### Task 1: Allocation gates and full IL warnings in the AOT smoke app

**Files:**
- Modify: `samples/ZeroAlloc.Jev.AotSmoke/ZeroAlloc.Jev.AotSmoke.csproj`, `Program.cs`, `.github/workflows/ci.yml` (the aot-smoke comment only)
- Create: `samples/ZeroAlloc.Jev.AotSmoke/AllocationChecks.cs`

**Interfaces:**
- `ZeroAlloc.TestHelpers.AllocationGate.AssertBudget(int budgetBytes, int iterations, Action action, string label)`. It throws `InvalidOperationException` when the average allocation per call exceeds the budget.
- `AssertBudgetValueTask<T>(int, int, Func<ValueTask<T>>, string)` does the same for async actions.
- The helper is source-only, from the `ZeroAlloc.TestHelpers` package's contentFiles, and `internal`.

- [ ] **Step 1: csproj.**
  - Replace `<TreatWarningsAsErrors>false</TreatWarningsAsErrors>` and the six-code `WarningsAsErrors` line with `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`.
  - Add `<PackageReference Include="ZeroAlloc.TestHelpers" PrivateAssets="all" />`, whose version already comes from `Directory.Packages.props`.
- [ ] **Step 2: `AllocationChecks.cs`.** Add a static class with one method per gate. Each calls `AllocationGate.AssertBudget` with 1000 iterations, catches the `InvalidOperationException`, and records a smoke failure through the app's existing `Check(false, …)` pattern, so a breach turns the smoke run red with the gate's message. There are five gates:
  1. **`GeneratedParse`:** the smoke app's generated question set (`SmokeTriage.Parse`) over fixed UTF-8 answer bytes, parsed from a `byte[]` created once outside the action.
  2. **`ReadNoul`:** `JevAnswerReader.ReadNoul` over a fixed Noul answer.
  3. **`ReadChoice`:** `JevAnswerReader.ReadChoice` into a caller-owned `double[]` created once.
  4. **`ReadScore`:** `JevAnswerReader.ReadScore`, the same way.
  5. **`EvaluateRoundTrip`:** `JevClient.EvaluateAsync` over the smoke app's canned handler, created once. This covers request serialization and response deserialization through the public API only, because `JevJsonContext` is internal. Use `AssertBudgetValueTask`.

  The reader signatures are in `src/ZeroAlloc.Jev/JevAnswerReader.cs`; follow how the generated code calls them.
- [ ] **Step 3: Measure, then set the budgets.**
  - Measure each path first, for example with a temporary budget of 0, running the published AOT binary and reading the reported per-call average.
  - Set each budget:
    - 0 where the measurement is 0;
    - otherwise the measured value rounded up to the next multiple of 64 bytes, with a comment naming what the bytes are, for example "the result record plus its probability buffer" or "HttpRequestMessage, headers and content".
  - Record every measurement in the report.
  - Then prove the gate fires: temporarily set one budget below its measurement, confirm the smoke app exits non-zero with the gate's message, and restore it.
- [ ] **Step 4: Wire into Program.** Call the gates from `Main` after the existing checks. The expected output is 13 `PASS` lines, the existing 8 plus 5 gates, and exit 0.
- [ ] **Step 5: ci.yml comment.** Update the aot-smoke comment: the smoke csproj now treats every warning as an error, which closes #30, and the job runs the allocation gates.
- [ ] **Step 6: Verify and commit.**
  - Publish and run on win-x64 as in earlier phases: `dotnet publish samples/ZeroAlloc.Jev.AotSmoke/ZeroAlloc.Jev.AotSmoke.csproj -r win-x64 -c Release -o artifacts/aot`, then run the binary. If the MSVC linker is missing from PATH, add the Visual Studio tools to PATH for the session.
  - Expect no warnings, 13 PASS lines and exit 0.
  - `dotnet build ZeroAlloc.Jev.slnx -c Release` must give 0 warnings. Don't commit `artifacts/`.
  - If `TreatWarningsAsErrors` surfaces a warning from a dependency, stop and report NEEDS_CONTEXT with the warning. Don't suppress it.

```xml
<!-- Pack the generator from its real build output rather than a hard-coded bin path (#14). -->
<Target Name="PackJevGenerator" BeforeTargets="_GetPackageFiles">
  <MSBuild Projects="..\ZeroAlloc.Jev.Generator\ZeroAlloc.Jev.Generator.csproj"
           Targets="GetTargetPath"
           Properties="Configuration=$(Configuration)">
    <Output TaskParameter="TargetOutputs" ItemName="_JevGeneratorAssembly" />
  </MSBuild>
  <ItemGroup>
    <None Include="@(_JevGeneratorAssembly)" Pack="true" PackagePath="analyzers/dotnet/cs" Visible="false" />
  </ItemGroup>
</Target>
```
