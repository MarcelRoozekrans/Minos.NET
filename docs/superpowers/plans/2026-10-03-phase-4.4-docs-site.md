# Phase 4.4 Docs Site, Logo and README Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the user guide at jev.zeroalloc.net through ZeroAlloc-Net/.website and list Jev on zeroalloc.net. Give Jev the shared ZeroAlloc icon, cut the README down to an overview that links the site, and build the site in Jev's own CI.

**Architecture:** There are two repositories.
- **ZeroAlloc-Net/.website** gets one PR: the `repos/jev` submodule, an `apps/docs-jev` Docusaurus app copied from `apps/docs-rest`, and a home-page entry.
- **This repository** gets the icon, a short README, a test that every README site link resolves to a real page and anchor, and a `docs-site` workflow that builds the app against the PR's own `docs/`.

The local site build in Task 2 is the ground truth for the site's routes and heading ids. The README link test in Task 3 is written to match what that build emits.

**Tech Stack:**
- **This repository:** .NET 10 and xUnit (`tests/ZeroAlloc.Jev.Docs.Tests`, `tests/ZeroAlloc.Jev.PackTests`), MarkdownSnippets 28.5.0 (`dotnet mdsnippets`), and GitHub Actions.
- **.website:** a pnpm 12.8.1 workspace (Node 24, turbo), with Docusaurus 3.10.2 and Cloudflare Workers (`wrangler.jsonc`).

**Spec:** `docs/superpowers/specs/2026-10-03-phase-4.4-docs-site-design.md`

## Global Constraints

**Builds and docs**
- Build and test with `-c Release` only. `TreatWarningsAsErrors` is on, with the MA*, CA, HLQ, xUnit and JEV analyzers; never suppress a diagnostic.
- Every C# block in a Markdown file is a MarkdownSnippets region from `tests/ZeroAlloc.Jev.Docs.Tests`, and that includes `README.md`. Region names are unique and carry a page prefix. Run `dotnet mdsnippets` twice; the second run must change nothing.
- Prose is wrapped at 120 characters in `docs/`. `README.md` keeps its existing one-paragraph-per-line style.

**The .website app and the README**
- `apps/docs-jev` is a copy of `apps/docs-rest`, with only the names changed and two deliberate differences:
  - `onBrokenLinks: 'throw'`;
  - `exclude` adds `'**/planning/**'` and `'**/superpowers/**'` to Rest's three patterns.
- The README keeps the unofficial-client disclaimer verbatim and the "Status: early development, not yet published to NuGet" line.
- README links to the guide are absolute `https://jev.zeroalloc.net/...` URLs, and its logo is an absolute `https://raw.githubusercontent.com/ZeroAlloc-Net/ZeroAlloc.Jev/main/assets/icon.png` URL. The README is packed into the NuGet package, and nuget.org can't resolve relative paths.

**Commits and pull requests**
- Commits are conventional. Allowed scopes come from `.commitlintrc.yml`: core, generator, di, tests, benchmarks, samples, docs, ci, deps, roadmap, state, sync, milestone and main.
- A commit has no nested parentheses in its body, and no `claude.ai/code/session` URLs in a commit or PR.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Implementer subagents commit on `phase/4.4-docs-site` and never push.
- In .website, commits follow that repository's history style (`feat(jev): ...`), and the PR opens against `main` from a branch named `feat/docs-jev`.
- Subagents don't open PRs or push. The controller pushes the .website branch and opens its PR, as the milestone design allows.

**Secrets**
- Never print or write `OPENROUTER_API_KEY` or `TYPESAFE_API_KEY`.

**pnpm**
- Corepack can't download pnpm on this machine. Run it as `npx -y pnpm@12.8.1 ...`.
