# Phase 5.3 AOT, Trim and Measurement Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove ZeroAlloc.Jev's whole public API is clean under full trimming and Native AOT, and make the AOT smoke app exercise every public entry point. Fix the flaky allocation gates at their cause, then trace the allocation creep since Phase 3. Close #68, #73, #74 and #79.

**Architecture:** Two new checks:
- an `AotSurface` host that roots both packages, published in a new CI job;
- a coverage test that compares the PublicAPI files with a manifest of the checks in the smoke app.

The measurement work starts by finding causes. Code changes follow only from what the evidence shows.

**Tech Stack:**
- .NET 10 Native AOT and ILLink: `TrimmerRootAssembly`, `TrimMode=full`.
- PublicApiAnalyzers file format.
- ZeroAlloc.TestHelpers 1.5.0: `AllocationGate` and its measuring API.
- xUnit and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-04-phase-5.3-aot-and-measurement-verification-design.md`

## Global Constraints

**Builds and warnings**
- Build and test with `-c Release` only. `TreatWarningsAsErrors` is on, with the MA*, CA, HLQ, xUnit, JEV, RS0016 and RS0017 analyzers. Never suppress a diagnostic, and that includes IL2xxx and IL3xxx trim and AOT warnings.
- The public API must not change. Phase 5.1 froze it. If a fix truly needs an API change, stop and report it.

**Allocation budgets and measurement**
- Every allocation budget stays unchanged or gets tighter. If a budget fails, find the cause; never raise the number.
- Publish the AOT smoke app from PowerShell with the Visual Studio Installer folder on PATH:

  ```
  $env:PATH += ';C:\Program Files (x86)\Microsoft Visual Studio\Installer'
  ```

  A failed link leaves a stale exe that still runs, so check the exe's timestamp before trusting a result.
- A tolerance on an allocation gate is allowed only when the noise has been shown to be irreducible. The reason goes beside the code, and a follow-up issue is filed.

**Upstream fixes**
- A cause that sits in a ZeroAlloc library (Rest, Resilience, Telemetry, Validation, Results or TestHelpers) or in the .NET runtime is reported with evidence. The controller files it through the ZeroAlloc org session. It is never worked around in Jev.

**Commits**
- Commits are conventional. The allowed scopes come from `.commitlintrc.yml`: core, generator, di, tests, benchmarks, samples, docs, ci, deps, roadmap, state, sync, milestone and main.
- No commit body has nested parentheses, and no commit or PR has a `claude.ai/code/session` URL.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Implementer subagents commit on `phase/5.3-verification` and never push.

**Docs**
- Every C# block in `docs/` is a MarkdownSnippets region. Run `dotnet mdsnippets` twice; the second run must change nothing.
- Prose in `docs/` wraps at 120 characters.

### Task 2: The entry-point coverage test

**Files:**
- Create:
  - a coverage manifest in `samples/ZeroAlloc.Jev.AotSmoke`, either an attribute on each check or a checked-in list;
  - a coverage test, in an existing test project or a small new one;
  - new smoke checks, grouped by public type.
- Modify: `samples/ZeroAlloc.Jev.AotSmoke/Program.cs`.

- [x] **Step 1: Write the failing coverage test.**
  - **Reading the API files:** parse both packages' `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt`. Drop `*REMOVED*` lines and every line they remove.
  - **Entry points:** every constructor and method of a public type, with signatures exactly as RS0016 prints them. Leave out property accessors, operators, fields, enum members, compiler-generated record members and `override` members of `object`. They are covered through their types; record this rule in a comment.
  - **The check:** compare the entry points with the manifest, and fail listing every uncovered signature.
  - **Run it:** run the test and record how many entry points are covered and how many are missing.
- [x] **Step 2: Write the manifest from what the smoke app already exercises.** Each check names the entry points it calls. A test, or a source scan, must keep the manifest honest: it fails if a named entry point isn't actually referenced in the check's code. Pick the simplest way that can't silently drift.
- [x] **Step 3: Add smoke checks for every missing entry point,** grouped by public type, so that each one runs under Native AOT and asserts its result. Publish and run the smoke app; every check must pass.
- [x] **Step 4: Mutation-check and commit.** Remove one entry point from the manifest and confirm the test fails. Add a fake public method and confirm it fails too. Revert both. Then commit with the message `test(samples): require the AOT smoke app to exercise every public entry point`.

### Task 3: Find and fix the relative gates' noise (#79) and adopt the measuring API (#73)

**Files:** `samples/ZeroAlloc.Jev.AotSmoke/AllocationChecks.cs`, plus whatever the evidence points to.

- [x] **Step 1: Measure the swing.** Run the relative gates 30 times on a fresh publish, and record the distribution of both sides of each comparison. They are `EvaluateRoundTripThroughDependencyInjectionAgainstHandBuilt`, the configuration-bound gate, and the NullLoggerFactory gate.
- [x] **Step 2: Find the cause.** Test each candidate on its own:
  - **Thread hops.** Does `GC.GetAllocatedBytesForCurrentThread` miss or double-count when a continuation hops threads? Compare it with `GC.GetTotalAllocatedBytes(precise: true)`, and with a single-threaded synchronization context.
  - **Background work.** Timer or thread-pool allocations, from `HttpClient` internals or `SocketsHttpHandler` pooled-connection cleanup.
  - **First-call effects.** Lazy initialization, or a first-call allocation that isn't warmed up the same way on both sides.
  - **Iteration count and rounding.**

  Write the evidence in the report.
- [x] **Step 3: Adopt the measuring API (#73).** Replace `SynchronousBytesPerCall` with ZeroAlloc.TestHelpers 1.5.0's measuring API. Read the package to confirm the API's name and its semantics.
  - **If the API carries the same flaw:** if the cause found in Step 2 lives in that API too, for example the thread-local counter, stop and report it upstream.
- [x] **Step 4: Fix the measurement at its cause.** If the noise is irreducible, use the documented tolerance rule from the constraints.
- [x] **Step 5: Prove the fix.** The fixed gates must pass 20 consecutive fresh runs locally. Record the before and after flake rates.
- [x] **Step 6: Commit** with the message `fix(samples): measure the relative allocation gates without the noise that made them flaky`. The body states the cause, and says it closes #73 and #79.
