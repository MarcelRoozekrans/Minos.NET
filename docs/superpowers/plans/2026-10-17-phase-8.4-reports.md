# Phase 8.4 Reports and the Guide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Calibration reports for TypeSafe, Clef Flash and the local model on both Banking77 sets, committed, and a
"Choosing a provider and a threshold" guide whose tables a test ties to those reports.

**Architecture:** The work lands in two PRs with the maintainer's runs in between. PR 1 (Tasks 1–3) corrects the
urgency labels and adds the run configuration, keeps `docs/reports/` off the site, and adds two dispatch-only
workflows that run `minos calibrate` from nuget.org and upload the output. Then the maintainer starts the runs on
`main`. PR 2 (Tasks 4–5) imports the artifacts, applies prices with `minos report`, and writes the guide with a docs
test that checks every figure.

**Tech Stack:** GitHub Actions, Minos.NET.Tool 1.2.0 (`minos`), xUnit docs tests in `tests/Minos.NET.Docs.Tests`,
Python 3 standard library for `datasets/banking77/build.py`, Docusaurus.

**Spec:** `docs/superpowers/specs/2026-10-17-phase-8.4-reports-design.md`

## Global Constraints

- **Billed calls:**
  - Hosted calls happen only in `calibrate.yml`, which runs on `workflow_dispatch` only, uses the `live-api`
    environment and is started by the maintainer.
  - No test makes a network call.
- **The tool:** the package `Minos.NET.Tool` version `1.2.0` from nuget.org, run as the command `minos`.
- **Every run:** `--parallel 1`.
- **Provider and set slugs:**
  - Report folders are `docs/reports/<provider>/<set>/`.
  - `<provider>` is one of `typesafe`, `clef-flash` and `local`.
  - `<set>` is one of `banking77` (`datasets/banking77/banking77-minos-v1.jsonl`) and `urgency`
    (`datasets/banking77/banking77-urgency-v1.jsonl`).
- **Model ids:**
  - TypeSafe: `jev-latest`.
  - Clef: `cloudflare/clef-flash`. `tests/Minos.NET.Live.Tests/ClefLiveTests.cs` already calls this id live, so the
    spec's check against the model list is satisfied.
  - Local: `Mapika/decider-2b-GGUF:Q4_K_M` at `http://127.0.0.1:8000/`.
- **Zero data retention:** the Clef section sets `"ProviderPreferences": { "ZeroDataRetention": true }`.
- **Urgency corrections:**
  - `b77-card_arrival-25` goes from 0 to 1.
  - `b77-activate_my_card-02` goes from 1 to 0.
  - `b77-change_pin-18` goes from 1 to 0.
  - The dataset version stays 1.
- **Docs gates:** front matter, a `## Next` on every page, compiled C# snippets, tested links and anchors, and
  NoOldNameTests ("jev" only in real model ids). Build with `export MSBUILDDISABLENODEREUSE=1`.
- **Commits:**
  - Conventional, with allowed scopes.
  - No nested parentheses in bodies, and no session links.
  - End each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**A plan decision that refines the spec.** Prices are applied after the runs, not during them.
- The workflows run `minos calibrate` without `--prices`.
- In Task 4, `minos report --results … --dataset … --prices docs/reports/prices.json` rebuilds `report.json` and
  `report.md` from the downloaded results, with no provider call.
- **Why:** TypeSafe's price, which the maintainer supplies, is then needed only in PR 2, and a price correction never
  needs a rerun.
- The report README records that the report was rebuilt with prices.

## Review Focus

1. **The figures in a dispatched run** depend only on the committed run config and the tool version. A run on
   different settings must be visible in its README. Task 3 pins every argument in WorkflowWiringTests, and Task 4
   checks each README against its `report.json` header.
2. **A Clef request** must carry `zdr: true`. If the `ProviderPreferences` binding silently drops it, a reader expects
   the request to be refused, not routed to a retaining endpoint. Task 2's binding test pins it.
3. **A provider row** whose report shows errors or unsupported items must say so in the guide, not show an accuracy as
   if every item was answered. Task 5's table test checks the item and error counts beside accuracy.
4. **The rebuilt dataset** must change exactly the three labels and nothing else. Task 1's test checks the three
   values, and `test_the_committed_files_match_a_fresh_build` catches any other drift.
5. **A report folder with no row in the guide**, or a row with no folder, makes the guide's claim of covering every
   committed report false. Task 5's test fails both ways.

### Task 3: The calibrate workflows

**Files:**

**Interfaces:**
- Consumes: Task 2's `docs/reports/minos.json` and its section names.
- Produces: the artifact names Task 4 downloads, `calibration-<provider>-<set>`, for example
  `calibration-typesafe-urgency`. Each holds the tool's output folder contents.

`calibrate.yml`:
- **Trigger:** `on: workflow_dispatch` only, with two `choice` inputs:
  - `provider`: options `typesafe` and `clef`, no default, required;
  - `set`: options `both`, `urgency` and `banking77`, default `both`.
- **Job:** one job, `calibrate`, with `environment: live-api`, `runs-on: ubuntu-latest`, `timeout-minutes: 60` and
  `permissions: contents: read`.
- **Steps:**
  1. Check out with `persist-credentials: false`.
  2. Set up .NET 10.
  3. `dotnet tool install Minos.NET.Tool --version 1.2.0 --tool-path "$RUNNER_TEMP/minos-tool"`.
  4. Map the input to a section: `typesafe` → `TypeSafe`, `clef` → `Clef`.
  5. For each selected set, run
     `"$RUNNER_TEMP/minos-tool/minos" calibrate --dataset <file> --config docs/reports/minos.json --provider <section> --parallel 1 --out "$RUNNER_TEMP/out/<provider>-<set>"`.
     Pass the keys as `TYPESAFE_API_KEY: ${{ secrets.TYPESAFE_API_KEY }}` and
     `OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}`.
  6. Upload each folder as `calibration-<provider>-<set>`, with `if: always()` so a partial run is kept.
     `results.partial.jsonl` comes back too.
- **Header comment:** the file starts with a comment saying that every dispatch is a billed run started by the
  maintainer, and that it makes 400, 60 or 460 requests depending on the set.

The `calibrate` job in `local-systemone.yml`:
- `if: github.event_name == 'workflow_dispatch'`, with `timeout-minutes: 120`.
- The same Python, model cache, `ollajev` install and server start as the existing job. Repeat those steps; there is
  no shared action.
- Then the tool install as above, the same calibrate loop over both sets with `--provider Local`, and the uploads as
  `calibration-local-<set>`.
- The existing `local-systemone` job is unchanged.

The guide follows the section order in the spec. Its two tables are under `### Banking77 (Choice)` and
`### Urgency (Score)`. The rows are in the order typesafe, clef-flash, local, and each table has these columns:
- `Provider`
- `Model`
- `Items`
- `Errors`
- `Accuracy`
- `ECE`
- `Bins`
- `Coverage at <t>`
- `Accuracy at <t>`
- `Cost per 1,000`
- `Median latency`

`<t>` is the reference threshold, chosen from the sweeps and explained in the guide. Figures use the report's own
rounding; the reports' Markdown is the formatting reference.
- The local cost shows `0` with a footnote saying it costs hardware instead.
- Latency carries a note naming the runner.
- The uncertainty section gives a 95% Wilson interval on each accuracy. `ProviderGuideTests` computes it from the
  report's correct and total counts.
