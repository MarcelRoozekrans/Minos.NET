# Phase 10.3 Ticket-Triage Sample Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new sample, `Minos.NET.Samples.TicketTriage`, triages the 400 Banking77 messages local first with `UseEscalation` to TypeSafe, writes a records file, and builds its own report of the split by path, accuracy, the confidence signal, latency and cost; a dispatch-only CI job runs it, and a second PR commits the report from an approved billed run.

**Architecture:** One console project with two modes. Run mode builds the pipeline an app would build (local client, wrapped by `UseEscalation` with a timed target), decides the items one at a time and writes one JSON line per item. Report mode reads the records, the dataset labels and `prices.json`, and writes `triage-report.json` and `triage-report.md`; its maths lives in one class the tests drive with hand-built records. No package gains any public API.

**Tech Stack:** .NET 10, C#, xUnit, `Minos.NET`, `Minos.NET.SystemOne`, `Minos.NET.Evaluation` (`DecisionDataset`, `AnswerRecord`, `PriceTable`), `System.Text.Json` `Utf8JsonWriter`.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-10.3-ticket-triage-design.md`, read with the 10.1 and 10.2 specs it builds on. "Call N" below is the spec's "My calls" number; "settled N" is its "Settled after the builder check" number.

## Global Constraints

- The sample is not a package: no `PublicAPI.*.txt` change, no new public member in `src/`, and it stays out of the AOT smoke.
- No message text in a log line, the summary line, a records line or the report. Item ids are fine.
- A billed run starts only after the maintainer approves it through `AskUserQuestion`, and only from `main`. No task before Part 2 calls a provider.
- Fixed thresholds: `intent` (Choice) 0.85, `card_not_arrived` 0.80, `about_a_payment` 0.80. `ExpectedLatency` 300 ms, `Budget` 5 s, `PrimaryName` `local`, `TargetName` `typesafe`.
- The report states what was measured and gives no verdict on adopting escalation.
- Invariant culture and `\n` line endings in every written file; `Date` and other clocks never appear in the report body, so a rebuild is byte for byte.
- Commits are conventional with scopes from `.commitlintrc.yml` (`samples`, `ci`, `docs`, `tests`, `roadmap`, `state`; there is no `reports` or `plans` scope, use `docs`). No nested parentheses in commit bodies. No Claude signature, no `Co-Authored-By` trailer, no session link (the owner's global rule overrides the harness default).
- Tests in `tests/Minos.NET.Samples.Tests`, written test first.

## Decisions made in this plan (on top of the spec)

1. **Thresholds are not in the records, and the report does not need them.** The escalation stage marks a question unsure exactly when its certainty is below its threshold, so `Reason != Confident` means "below the threshold". The signal section reads "caught" as reason not `Confident` and "missed" as `Confident`.
2. **A ticket "with an escalation" is one whose path has a target call that was not skipped** (status `Answered` or `Failed`). A ticket whose questions were all skipped for time, or all confident, is "without". This keeps a failed target's wait in the "with" group.
3. **Cost follows `MetricsCalculator.Cost`:** a call's reported `Usage.Cost` first, else tokens times the price found by `PriceTable.TryFind`, else unknown. Per 1,000 tickets is the known total divided by the decided tickets, times 1,000; a ticket's calls are summed first. Its tokens and models come from `DecisionPath.Calls`.
4. **Percentiles are nearest-rank,** `rank = max(1, ceil(q*n))` in integers, as `MetricsCalculator.NearestRank`. Rounding: ratios at 4 decimals (`F4`), money `G6`, milliseconds `0.#`, unknown as `n/a`, shares printed with their counts.
5. **Record format version 1,** with the field names in Task 1. A Score answer, a `FellBack` reason or an unknown version is rejected by the reader.
6. **Failed items** are written as `{"v":1,"id":"...","error":"<DecisionErrorKind>","totalMs":n}`; they count in Run and are left out of everything else.

## Review Focus

- A ticket with no unsure question: the response may carry no path. Pinned in Task 3 by a test that asserts what the stage returns, and the record writer handles both shapes.
- A route whose target failed or was skipped for time: the final answer is the local one, and the report must not credit the target. Task 4.
- A dataset id missing from the dataset or a duplicated record id: report mode exits 2 and names the id. Task 6.
- An unpriced served model: cost reads `n/a` and the unknown count is shown. Task 5.
- A run with every item failed: the report builds with zero rates shown as `n/a`, never a division by zero. Task 4.
