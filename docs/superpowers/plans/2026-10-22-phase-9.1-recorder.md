# Phase 9.1 Decision Recorder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `Minos.NET.Recording` package records every decision through a pipeline stage. Records are written to an app-chosen sink from a background queue. They have outcomes attached by decision id, they can be erased by the app's key, and the package is Native AOT clean.

**Architecture:**
- An app-owned `DecisionRecorder` holds a bounded queue and one background writer, and calls an `IDecisionRecordSink`.
- A `RecordingDecisionClient` stage builds each record from the request and the result, redacts it, and enqueues it without waiting.
- An `AsyncLocal` scope carries the decision id and erasure key into the call.
- The record's JSONL file format and its reader are public, so Phase 9.2 can read them.

**Tech Stack:** .NET 10, `System.Threading.Channels`, source-generated System.Text.Json, `System.Diagnostics.Metrics`, Microsoft.Extensions.Logging.Abstractions, ZeroAlloc.Results, and xUnit with TextSnapshot.

**Spec:** `docs/superpowers/specs/2026-10-22-phase-9.1-recorder-design.md`. Its "Settled after the builder check" section overrides the Decisions section where they differ.

## Global Constraints

- **Package:** `Minos.NET.Recording` with `RootNamespace` `Minos.Recording`.
  - Public types live in namespace `Minos.Recording`, except `UseRecording`, which goes in `Minos` as `UseCaching` does.
  - It sets `IsAotCompatible` true and `MinosNoValidationBaseline` true, and uses the PublicApiAnalyzers.
  - It references `Minos.NET`, `Microsoft.Extensions.Logging.Abstractions` and `ZeroAlloc.Results`, and nothing else.
- **AOT:**
  - zero IL2 and IL3 warnings;
  - JSON only through a source-generated `JsonSerializerContext`;
  - no reflection.
- **Never in logs, traces, metric tags or exception messages:**
  - the state, before or after redaction;
  - a decision id;
  - an erasure key;
  - a provider error message.

  Logs carry counts and exception type names only.
- **Never fails or delays a decision.** The stage returns the inner client's result unchanged and never awaits the sink.
  - The one exception is a second fresh request in one scope, with `RetryAttempt == 0`. It throws `InvalidOperationException` before the inner call.
- **Defaults:**
  - `RecordingOptions.Capacity` is 1024;
  - `RecordingOptions.FlushTimeout` is 5 s;
  - generated decision ids are `Guid.CreateVersion7().ToString()`.
- **The record format is JSONL.** Every line has `"kind"`, which is `"record"`, `"outcome"` or `"erasure"`, and `"version": 1`.
  - The question set uses the dataset line's `questions` shape from `docs/datasets.md`.
- **Log events:**
  - 1009 records dropped;
  - 1010 a sink call failed;
  - 1011 redaction failed;
  - 1012 the flush timed out, with lost items counted.

  They are added to core `DecisionLog`, through `InternalsVisibleTo` for `Minos.NET.Recording` and `Minos.NET.Recording.Tests`.
- **Metrics:** on `new Meter("Minos")` in Recording:
  - `minos.recording.records`, with tag `result`: `written`, `dropped_full`, `dropped_redaction`, `redaction_failed` or `sink_failed`;
  - `minos.recording.outcomes`, with `result`: `written` or `failed`;
  - `minos.recording.erasures`, with `result`: `written` or `failed`;
  - the observable gauge `minos.recording.queue_length`.
- **Build and tests:** run `export MSBUILDDISABLENODEREUSE=1` first. Snapshots use `TextSnapshot.VerifyText`; approve them with `ZA_SNAPSHOT_UPDATE=1`.
- **Commits:**
  - conventional, with scopes from `.commitlintrc.yml`;
  - no nested parentheses in bodies, and no session links;
  - each message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A sink that hangs or throws on every call** must leave decisions exactly as fast and as successful as with no recorder. Task 3 pins this with a blocking sink and a throwing sink.
2. **Erasure must not be lost silently.** A full queue waits rather than drops, `EraseAsync` completes only after the sink has erased, and a flush timeout counts the lost erasures. Task 2 pins all three.
3. **Parallel decisions must never cross scopes:** 50 concurrent calls, each in its own scope, each get their own id on their own record. This is pinned in Task 3.
4. **A sentinel in state, id and key must not reach any log, span, metric tag or exception text**, including on the failure paths. This is pinned in Task 3 across the full scenario list.
5. **A JSONL file written by one version must be read back by the public reader, outcomes and tombstones applied, and the highest attempt kept.** That includes a file whose last line is truncated by a crash: the reader skips it and reports it, and does not throw. This is pinned in Task 1.

- [ ] **Step 3: Implement** the stage and the scope.
  - **The scope** is an `AsyncLocal<ScopeState?>`. The state holds the id, the key and a flag saying whether a fresh decision was recorded. `RetryAttempt` comes from the request.
  - **The stage:**
    1. Read the scope and enforce the fresh-decision rule before the inner call.
    2. Call the inner client.
    3. Build the record. Run `Redact` in a try/catch, so it can rewrite, drop, or fail.
