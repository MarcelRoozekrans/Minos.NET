# Phase 2.2 Analyzers and Code Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Jev diagnostic comes from `ZeroAlloc.Jev.Analyzers`: JEV001–006 are new, and JEV101–107 move out of the generator with the #5–#10 fixes. `ZeroAlloc.Jev.CodeFixes` inserts `[Criteria]` and `[Level]` descriptions. The generator reports nothing.

**Architecture:**
- **Shared model builder.** `ModelBuilder`, `Models` and `Diagnostics` become a symbol-based model builder shared by source. The files stay in `src/ZeroAlloc.Jev.Generator` and are linked with `<Compile Include … Link>` into `src/ZeroAlloc.Jev.Analyzers`.
- **Generator.** It calls the builder from its incremental pipeline and ignores the diagnostics.
- **Analyzer.** It calls the same builder from a symbol action and reports the diagnostics.
- **New rules.** JEV001–006 are added to the shared rules, so the generator also skips emitting code for sets that JEV001 or JEV002 make invalid.
- **Code fixes.** They live in their own assembly, which references Workspaces.
- **Packaging.** All three analyzer assemblies are packed through `GetTargetPath` targets.

**Tech Stack:** .NET 10, Roslyn 5.0.0 (with `Microsoft.CodeAnalysis.CSharp` and `.Workspaces` pinned exactly), `Microsoft.CodeAnalysis.CSharp.Analyzer.Testing` and `CodeFix.Testing` 1.1.4, and xUnit 2.9.3.

**Spec:** `docs/superpowers/specs/2026-09-27-phase-2.2-analyzers-and-code-fixes-design.md`

### Task 3: New diagnostics JEV001–JEV006

**Files:** `src/ZeroAlloc.Jev.Generator/Diagnostics.cs` and `ModelBuilder.cs` (the shared rules), `src/ZeroAlloc.Jev.Analyzers/AnalyzerReleases.Unshipped.md`, a new `tests/ZeroAlloc.Jev.Analyzers.Tests/ApiRuleTests.cs`, and generator tests.

**Rules** (from the spec; category `ZeroAlloc.Jev`):

| ID | Severity | Rule |
|---|---|---|
| JEV001 | Error | Choice enum with no members |
| JEV002 | Error | Score enum with no members |
| JEV003 | Warning | Instructions, a `[Criteria]` description or a `[Level]` description is an empty or whitespace string; null or omitted is fine |
| JEV004 | Warning | A backticked identifier in instructions matches no public instance property or field of the `State` type |
| JEV005 | Warning | A Score with 1 level or more than 10, or a Choice with more than 255 options |
| JEV006 | Info | A Choice enum member without `[Criteria]` |

**JEV004 matching.**
- **When it runs:** only when `State` is set.
- **Which tokens:** a backticked token that matches the pattern `^[A-Za-z_][A-Za-z0-9_-]*$`.
- **What counts as a match:** the token, compared case-insensitively, against any of these for each public instance property or field of the state type:
  - the C# name;
  - a `[JsonPropertyName("…")]` value;
  - camelCase, snake_case and kebab-case forms of the C# name. Reuse `SnakeCase`, and derive kebab-case from it by replacing `_` with `-`.
- **Where it reports:** on the attribute argument, naming the token and the state type.
- **Skipped:** dotted and other tokens.

**Generator behaviour.** JEV001 and JEV002 make the set invalid, so the generator emits nothing. JEV003–006 don't block generation.

- [ ] **Step 1: Failing tests.**
  - One firing and one non-firing case per rule.
  - JEV005 boundaries: Score with 1, 2, 10 and 11 levels; Choice with 255 and 256 options. Build the enum sources with a loop, not by hand.
  - JEV003: `""`, `"   "`, null or omitted, and a valid string.
  - JEV004: each naming form matches; a typo reports; a dotted path is skipped; a set without `State` reports nothing; `[JsonPropertyName]` works.
  - JEV006: fires per bare member, not for members that have `[Criteria]`.
  - The generator emits nothing for JEV001 and JEV002 sets.
- [ ] **Step 2: Implement** the descriptors and the rules in the shared builder, and update the release tracking.
- [ ] **Step 3: Repo self-check.** Build the whole solution. Every JEV003, JEV004 or JEV005 warning on the repo's own question sets — tests, smoke app, benchmarks, live tests — gets fixed in source. JEV006 is Info and doesn't block the build. Report every change.
