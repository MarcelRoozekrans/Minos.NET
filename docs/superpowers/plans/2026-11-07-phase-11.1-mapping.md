# Mapping and Gap Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tested mapping page between the Minos and Microsoft.Extensions.AI decision types, a pin and build script for the upstream commit, and a gap list, for Phase 11.1.

**Architecture:** Docs and tooling only; no change under `src/`. A pin file and script build the upstream Abstractions at a fixed commit. A docs page lists identifiers that a Docs test checks against the Minos public API and, when an upstream build is present, against the built assembly.

**Tech Stack:** Markdown (Docusaurus), bash, GitHub Actions, xUnit with `System.Reflection.MetadataLoadContext`, C# 14 on net10.0.

**Spec:** `docs/superpowers/specs/2026-11-07-phase-11.1-mapping-design.md`

## Global Constraints

- No change under `src/`. Commit messages are `docs: <subject>`, `test: <subject>` or `ci: <subject>`, no scope, no Claude trailer, no nested parentheses in the body.
- Run `MSBUILDDISABLENODEREUSE=1` before `dotnet` commands (#145).
- Every docs page has front matter `id`, `title`, `sidebar_position` (integer), `description`, and ends with a `## Next` section; a value with `: ` or ` #` is quoted.
- No private details in the page or the gap list: no home-directory paths, hostnames, keys or e-mail addresses.
- The new category takes the next free sidebar position after the highest in `docs/`.

## Review Focus

1. A mapping row that claims one to one where the upstream type differs: the identifiers test catches a missing member, not a wrong semantic, so each row's note is read against the pinned source.
2. The skipped upstream check passing silently: the skip reason must be visible, and the CI job must set the variable.
3. The pin: the commit exists and the script builds it from a clean checkout.

### Task 1: The pin and the build script

**Files:** Create `tools/upstream/decisions-pin.json`, `tools/upstream/build-decisions.sh`, `tools/upstream/README.md`.

- [ ] **Step 1:** Write `decisions-pin.json` with `repository` `dotnet/extensions`, `commit` `02e54f023bdf3c8c2729353b110c22f5f8593957`, `checked` `2026-11-07`, and `project` the path of the Abstractions csproj.
- [ ] **Step 2:** Write `build-decisions.sh`: read the pin with `jq`, shallow-fetch that commit into `artifacts/upstream/src`, `dotnet build` the project in Release, and write the full path of `Microsoft.Extensions.AI.Abstractions.dll` to `artifacts/upstream/abstractions.path`. ### Task 2: The identifiers test

**Files:** Create `tests/Minos.NET.Docs.Tests/ExtensionsAiDecisionsMappingTests.cs`.

- [ ] **Step 1:** Write a failing test that reads `docs/extensions-ai-decisions/mapping.md`, collects the code-span identifiers in the first column of each table, and asserts the page exists and has at least one row per area in the spec.
- [ ] **Step 2:** Add the Minos check: each identifier marked `Minos:` resolves to a public type or member of `Minos.NET`; a missing one fails with its name.
- [ ] **Step 3:** Add the upstream check: when `MINOS_UPSTREAM_ABSTRACTIONS` is set, load that assembly in a `MetadataLoadContext` and assert each `Upstream:` identifier is public there. When unset, the test skips with a reason that names the variable and `build-decisions.sh`. Use `Assert.Skip`-style so the skip is visible.
- [ ] **Step 4:** Run with `dotnet test tests/Minos.NET.Docs.Tests -c Release --filter ExtensionsAiDecisionsMapping`. Expected: fails for the missing page.
- [ ] **Step 5:** Commit: `test: check the decision mapping page against both APIs`.
