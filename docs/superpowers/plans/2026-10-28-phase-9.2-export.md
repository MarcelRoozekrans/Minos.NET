# Phase 9.2 Export to the Dataset Format Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a record file's decisions and their confirmed outcomes into a Milestone 8 dataset, plus a signals companion file, from `Minos.NET.Evaluation` and `minos export`.

**Architecture:** `Minos.NET.Evaluation` references `Minos.NET.Recording`. A static `DecisionDatasetExport.WriteAsync` takes the `IAsyncEnumerable<RecordedDecision>` that `DecisionRecordFile.ReadAsync` returns. For each decision it builds one dataset line, writing the question set and the state with Recording's internal `QuestionSetFormat` through a new `InternalsVisibleTo`. It checks the line with `DecisionDataset.Parse` before writing it, and returns a `DatasetExportSummary`. The tool's `ExportCommand` wraps it with the record-file reader and file handling.

**Tech Stack:** .NET 10, C#, System.Text.Json `Utf8JsonWriter`, System.CommandLine (the tool), xUnit, Native AOT smoke app.

**Spec:** `docs/superpowers/specs/2026-10-28-phase-9.2-export-design.md`. Read its "Decisions", "Approach" and "Settled after the builder check" sections before any task.

## Global Constraints

- `export MSBUILDDISABLENODEREUSE=1` before every `dotnet` command.
- Warnings are errors. Never suppress a diagnostic (`#pragma`, `NoWarn`, `[SuppressMessage]`, `.editorconfig` severity) to get green: fix the cause.
- Native AOT: the packages stay at zero IL2 and IL3 warnings. No reflection-based `JsonSerializer` calls; write with `Utf8JsonWriter`.
- Every new public member goes in `src/Minos.NET.Evaluation/PublicAPI.Unshipped.txt`, has XML docs, and is exercised by the AOT smoke app with `[Covers("…")]` (`tests/Minos.NET.AotSmoke.Tests/EntryPointCoverageTests.cs` enforces it).
- No message, summary member or tool output holds a decision id, an erasure key or any state.
- The dataset is format version 1; no `version` member is written on dataset lines. Signals lines carry `"version":1`.
- Commits: conventional, with a scope from `.commitlintrc.yml` (`core`, `recording`, `tests`, `docs`, `samples`, `ci`, …; Evaluation and the tool have no scope of their own, so use none). No nested parentheses in commit bodies. No `Co-Authored-By` trailer and no session links.
- Match the surrounding code: comment density, `ConfigureAwait(false)`, `ArgumentNullException.ThrowIfNull`, XML-doc style of `DecisionRecordFile.cs`.

## Review Focus

1. **A key confirmed once validly and later invalidly** keeps the valid answer: the invalid one is dropped before the merge (Task 2 test `InvalidLaterAnswer_DoesNotReplaceAValidEarlierOne`).
2. **Unicode and structured content in the state and the criteria**, such as emoji, a JSON object state, or a Choice option whose criterion is a `json` object, comes through byte-for-byte equal after a load (Task 2 test `StructuredStateAndJsonCriteria_RoundTrip`).
3. **A record file that ends in a cut line**, as a crash leaves it, still exports the complete decisions, with exit 0 and the problem printed (Task 5 test `Export_CutLastLine_ExportsTheRestAndExitsZero`).
4. **An erasure after an outcome** removes the decision and its signals from the export (Task 4 integration test).
5. **An existing `--out` directory that already holds `dataset.jsonl`** is overwritten, not appended to (Task 5 test `Export_OverwritesAnEarlierExport`).

- [ ] **Step 3: Implement `DatasetExportSummary` and `DecisionDatasetExport.WriteAsync`.** Per decision, in this order:
  1. Count it in `DecisionsRead`.
  2. Without a `ConfirmedOutcome`, count it in `SkippedWithoutConfirmedOutcome`.
  3. With `Record.ImageCount > 0`, count it in `SkippedWithImages`.
  4. Check every confirmed answer against its question:
     - the key names a question of `Record.Definition`;
     - its `Kind` equals the question's;
     - a Choice key is one of `Options[i].Key`;
     - a Score level is below `Options.Count`.

     Count each failure in `KeysDropped`.
  5. Merge the valid answers per key. A later `At` wins, and on an equal `At` the later outcome in the file wins. Count a key once in `KeysOverridden` when the winning answer differs from an earlier valid one. With no key left, count it in `SkippedWithoutValidKey`.
  6. Write the line into an `ArrayBufferWriter<byte>` with a `Utf8JsonWriter`:
     - `id`;
     - `state`, through `QuestionSetFormat.WriteContent`;
     - `questions`, through `QuestionSetFormat.Write`;
     - `expected`: a boolean for Noul, the option key for Choice, the level for Score;
     - `source`: the distinct sources of the winning outcomes, in file order, joined with `", "`.
  7. Check the line with `DecisionDataset.Parse(new MemoryStream(line))`. If it fails, count it in `SkippedInvalidItem` and write nothing.
  8. Otherwise write the line plus `\n` to `dataset`, and count it in `ItemsWritten`.

  Call `cancellationToken.ThrowIfCancellationRequested()` before each decision. Pass the token to the enumeration with `WithCancellation` and to `Stream.WriteAsync`. Map `ConfirmedAnswer` to the expected value directly; don't go through `ExpectedAnswer`.
