# Phase 3.3 — DI package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `services.AddJevClient(...)` registers a singleton `IJevClient` over `IHttpClientFactory`, and `services.AddJevClient(name, ...)` registers keyed clients, each with its own named options and its own `HttpClient`. The client logs through the host's `ILoggerFactory`, telemetry is on, an evaluation through a resolved client allocates no more than the same call on a hand-built client, and all of it runs under Native AOT with zero IL2xxx/IL3xxx warnings.

**Architecture:** The core gains one public method, `JevClient.ConfigureHttpClient(HttpClient, JevClientOptions?)`. It applies the base address, the per-attempt time-out and the User-Agent that an owned client gets, through `JevClientSettings.ResolveHttp`, a key-free split of `Resolve` that shares its checks and messages. A new package, `ZeroAlloc.Jev.DependencyInjection`, holds one static class, `JevServiceCollectionExtensions`, in `Microsoft.Extensions.DependencyInjection`, with four overloads. Each registration has an options name `O` and an `HttpClient` name `H`. It adds the named options `O`, and it adds the named `HttpClient` `H` with these settings:
- a `SocketsHttpHandler` primary handler with `PooledConnectionLifetime`;
- an infinite handler lifetime;
- `ConfigureHttpClient` from options `O`;
- the factory's own request loggers removed.

It then adds a `TryAddSingleton` or `TryAddKeyedSingleton` factory that builds `new JevClient(factory.CreateClient(H), monitor.Get(O), sp.GetService<ILoggerFactory>())`.

**Tech Stack:** C# 14 / .NET 10, Microsoft.Extensions.Http 10.0.0, which brings DependencyInjection.Abstractions, Options and Logging. Microsoft.Extensions.DependencyInjection keyed services, xUnit 2.9.3, Microsoft.Extensions.Diagnostics.Testing `FakeLogger`, WireMock.Net, BenchmarkDotNet, ZeroAlloc.TestHelpers `AllocationGate`, Native AOT.

**Spec:** `docs/superpowers/specs/2026-10-01-phase-3.3-di-package-design.md` (milestone: `docs/superpowers/specs/2026-09-30-milestone-3-design.md`)

## Spec gaps found

The plan probe found three places where the spec cannot be met exactly as written. Each has the smallest resolution that keeps the spec's intent, and the plan applies it. **Gap 1 was confirmed by the maintainer on 2026-10-01: remove the factory loggers. The spec now records all three resolutions.**

1. **The factory's default request logging allocates on every call, even when nothing logs.** The spec asks that "DI adds nothing per call". `AddHttpClient` gives every named client the factory's `LoggingScopeHttpMessageHandler` and `LoggingHttpMessageHandler`. These format the redacted request URI and open a logging scope before they check whether any logger is enabled.
   - Measured on 2026-10-01, `EvaluateAsync(SystemOneRequest)` over a canned handler, per call:

     | Runtime | Hand-built client over a configured `HttpClient` | Resolved, factory loggers kept | Resolved, loggers removed |
     |---|---|---|---|
     | JIT, win-x64 | 4376 B | 4720 B | 4376 B |
     | Native AOT, win-x64 | 4376 B | 4720 B | 4376 B |

     The factory loggers add **344 B per call**.
   - **Resolution, applied by this plan:** `AddJevClient` calls `.RemoveAllLoggers()` on Jev's named clients. The spec does not require the factory's request logs.
     - The client already logs each operation and each retried attempt itself, through events 1001–1006.
     - `ZeroAlloc.Rest` already emits a span for each attempt.
     - A caller who wants the factory's logs back calls `.AddDefaultLogger()` on the returned builder, at that cost.
     - The README says so, and a test proves both directions.
   - **Alternative, if the maintainer prefers to keep the factory's logs:**
     - drop the `.RemoveAllLoggers()` line and the two logger tests in Task 2;
     - in Task 6, replace the relative gate with a budget measured by rule 11;
     - change the spec's cost line to "DI adds the factory's request logging, about 344 B per call";
     - change the README paragraph.

     Nothing else changes.
   - The cause sits in `Microsoft.Extensions.Http`, not in ZeroAlloc. It is worth a report to dotnet/runtime, but nothing here waits on it. Removing the loggers is a design choice about which component logs an HTTP attempt. It does not hide a failure.
2. **No host is "without an `ILoggerFactory`".** `AddHttpClient` calls `AddLogging()`, so the container always holds a `LoggerFactory`, even if the app never registers logging. The probe confirmed this. "Without one" therefore means "without a logging provider".
   - The client's logger then has every level disabled. So the client takes the unlogged path, logs nothing and allocates nothing for logging, as in Phase 3.1. The AOT gate shows 4376 B for both the resolved client and the hand-built client with no factory.
   - **Resolution:** the test is `WithoutALoggingProvider_TheClientResolvesAndEvaluates`, and the README says "without a logging provider".
3. **A base address without a trailing slash never reaches the client from the options.** `JevClientSettings` appends the slash to an options base address, and the existing test `BaseAddress_GetsTrailingSlash` covers that. The `httpClient.BaseAddress must end with '/'.` check only fires for an `HttpClient` that already has a base address.
   - **Resolution:** the "throws on first resolve" test sets the base address through the returned builder's `.ConfigureHttpClient(...)`, which runs after Jev's own configuration. The message is unchanged.

## Global Constraints

From the spec:

- **New package** `ZeroAlloc.Jev.DependencyInjection`, `net10.0`, `IsAotCompatible`.
  - It depends on `ZeroAlloc.Jev` and on `Microsoft.Extensions.Http` 10.0.0, and on nothing else. The pack tests assert this.
  - It takes no OpenTelemetry dependency, and it has no analyzers or generators of its own.
- **Public API, exactly:**
  - `JevServiceCollectionExtensions`, a static class in the namespace `Microsoft.Extensions.DependencyInjection`, with these overloads:
    - `AddJevClient(this IServiceCollection)`
    - `AddJevClient(this IServiceCollection, Action<JevClientOptions>)`
    - `AddJevClient(this IServiceCollection, string)`
    - `AddJevClient(this IServiceCollection, string, Action<JevClientOptions>)`
  - Every overload returns `IHttpClientBuilder`.
  - The surface is overloads only, with no optional parameters, per RS0026.
  - The core gains `public static void JevClient.ConfigureHttpClient(HttpClient httpClient, JevClientOptions? options)`.
- **Names:**

  | Client | Options name `O` | `HttpClient` name `H` | Service |
  |---|---|---|---|
  | Default | `Options.DefaultName`, the empty string | `ZeroAlloc.Jev` | `TryAddSingleton<IJevClient>` |
  | Keyed | `name` | `ZeroAlloc.Jev:{name}` | `TryAddKeyedSingleton<IJevClient>(name, ...)` |

- **Wiring per registration:**
  - `AddOptions<JevClientOptions>(O)`, plus `.Configure(configure)` when a delegate is given.
  - `AddHttpClient(H)`, with:
    - `.ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler { PooledConnectionLifetime = TimeSpan.FromMinutes(2) })`;
    - `.SetHandlerLifetime(Timeout.InfiniteTimeSpan)`;
    - `.ConfigureHttpClient((sp, c) => JevClient.ConfigureHttpClient(c, monitor.Get(O)))`.
  - The client factory is `new JevClient(factory.CreateClient(H), monitor.Get(O), sp.GetService<ILoggerFactory>())`.
- **Repeat calls** for the same name register no second client, but their configure delegates still apply, in order.
- **Errors:**
  - A `null` `services` or `configure` throws `ArgumentNullException`.
  - A `null` or empty `name` throws an `ArgumentException`. A `null` name throws `ArgumentNullException`, which is one.
  - Both throw at registration.
  - Invalid options throw the core's existing exception on the first resolve.
- **Lifetime:**
  - The container builds the client on its first resolve, and disposes it with the provider.
  - The factory's handler is never disposed while the provider lives. The probe showed it is not disposed afterwards either.
- **`ConfigureHttpClient`:**
  - It sets the base address only when the client has none. The address comes from the options, from `TYPESAFE_BASE_URL` for TypeSafe, or from the provider's default.
  - It sets `Timeout`, and adds the `ZeroAlloc.Jev` User-Agent.
  - It needs no API key.
  - It uses the existing checks and messages.
  - The existing constructors do not change.
- **Cost:**
  - An evaluation through a resolved client allocates no more than the same call on a hand-built client. An AOT gate checks this in the same run.
  - Registration and the first resolve are not budgeted.
  - A benchmark compares the two clients.
  - Every existing budget holds unchanged.
- **CI:** no change. `ci.yml` builds, tests and packs `ZeroAlloc.Jev.slnx`, and the new projects join it through the solution.

Rulings this plan applies. Each resolves a detail the spec leaves open. Only ruling 5 goes beyond the spec's text, and it does so through Gap 1.

1. **`JevHttpSettings`.** `ResolveHttp` returns an internal `readonly record struct JevHttpSettings(Uri BaseAddress, TimeSpan Timeout)`.
   - `Resolve` and `ResolveHttp` share two new private checks, `EnsureKnownProvider` and `EnsureValidTimeout`.
   - `Resolve` calls them first, in its existing order, so no constructor gets a new path or a new message.
   - The owned-client path and `ConfigureHttpClient` share one private `ApplyHttpSettings(HttpClient, JevHttpSettings)`.
2. **A testable environment.** `ConfigureHttpClient` has an internal overload that takes a `Func<string, string?> environment`, as `JevClientSettings.Resolve` does. The core tests use a fake environment. The DI tests set real environment variables, in a collection that runs alone.
3. **The User-Agent is added once.** `ApplyHttpSettings` adds it only when `DefaultRequestHeaders.UserAgent` does not already contain it. So calling `ConfigureHttpClient` twice, which a caller may do, still sends one product token.
4. **The `HttpClient` is configured by the first registration only.** `AddJevClient` checks whether an `IJevClient` is already registered under the same key, using `null` for the default client. On a repeat call it still adds the options delegate and returns `AddHttpClient(H)`'s builder, but it does not configure the `HttpClient` again.
   - The probe showed why. A repeat `ConfigurePrimaryHttpMessageHandler` replaces a primary handler that the caller set through the first call's builder.
   - With the guard removed, both repeat-call tests fail, because the requests go to a real `SocketsHttpHandler`.
5. **The factory's request loggers are removed**, per Gap 1, with `.RemoveAllLoggers()`. `.AddDefaultLogger()` on the returned builder restores them.
6. **What "the same call on a hand-built client" means.** A borrowed `HttpClient` sends no User-Agent. The factory's client does, which costs 64 B per call; the probe measured 4312 B against 4376 B. So the comparison client is a hand-built `JevClient` over an `HttpClient` that `JevClient.ConfigureHttpClient` configured. That is also the README's recommendation for anyone using the factory without this package. The existing `EvaluateRoundTrip` gate, over an unconfigured borrowed client, is unchanged.
7. **Two AOT gates.**
   - `EvaluateRoundTripThroughDependencyInjectionAgainstHandBuilt` takes as its budget the hand-built client's own measurement from the same run. That is the spec's "no more than", exactly.
   - `EvaluateRoundTripThroughDependencyInjection` has an absolute budget, set by rule 8.
8. **Budgets are measured, never estimated.** The absolute DI gate starts at 0 B in Task 6 Step 3. Step 6 reads its measured figure from the gate's `FAIL` line. Step 7 sets the budget by the Phase 1.8 rule: the measurement times 1.1, rounded up to the next multiple of 64 B.
9. **The DI test project** references only the DI package, which brings the core with it. It links the unit tests' `StubHandler.cs`, `Fixture.cs` and `Fixtures/response-noul.json`. It gets no `InternalsVisibleTo`: everything it tests is public.
10. **The pack fixture is shared.** `PackFixture`'s packing moves, unchanged, into an internal `PackedProject(string projectName)`. `PackFixture` and the new `DependencyInjectionPackFixture` each wrap one `PackedProject`. Both pack test classes join the `Packing` collection, so two `dotnet pack` runs never build `ZeroAlloc.Jev` at the same time.
11. **`JevClientOptions.Timeout`'s remarks** say it "Applies only to an `HttpClient` the client creates". That becomes false, so Task 1 rewrites it.
12. **The default and keyed overloads are two tasks.** Task 2 ships the default client and every private helper. Task 3 adds the two keyed overloads and `AddKeyed`. Each task has its own failing tests.

```csharp
namespace ZeroAlloc.Jev.Tests;

/// <summary>

    public void ExistingBaseAddress_IsKept()

    public void TypeSafeBaseAddressEnvironment_IsSet()

        using var http = new HttpClient();

        Configure(http, new JevClientOptions(), ("TYPESAFE_BASE_URL", "http://env.local/jev"));

    {
        using var http = new HttpClient();
```

```csharp
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Options;
using ZeroAlloc.Jev;
using OptionsDefaults = Microsoft.Extensions.Options.Options;

namespace Microsoft.Extensions.DependencyInjection;

/// <summary>Registers <see cref="IJevClient"/> in an <see cref="IServiceCollection"/>, over <see cref="IHttpClientFactory"/>.</summary>
/// <remarks>
/// Each registration is one <see cref="JevClient"/> singleton over its own named <see cref="HttpClient"/>, which
/// <see cref="JevClient.ConfigureHttpClient(HttpClient, JevClientOptions)"/> configures from the registration's named
/// <see cref="JevClientOptions"/>. The client reads those options once, when the container first builds it, and logs
/// through the container's <see cref="ILoggerFactory"/>. Its spans and metrics come from the <c>ZeroAlloc.Jev</c> source
/// and meter. Invalid options throw when the client is first resolved.
/// </remarks>
public static class JevServiceCollectionExtensions
{
    // The default client's HttpClient name; a keyed client's is this, a colon and its key.
    private const string HttpClientName = "ZeroAlloc.Jev";

    /// <summary>
    /// Registers the default <see cref="IJevClient"/>, configured from the default named <see cref="JevClientOptions"/>,
    /// defaults and environment variables.
    /// </summary>
    /// <param name="services">The services to add to.</param>
    /// <returns>The builder of the client's <see cref="HttpClient"/>, for adding handlers.</returns>
    /// <exception cref="ArgumentNullException"><paramref name="services"/> is <see langword="null"/>.</exception>
    public static IHttpClientBuilder AddJevClient(this IServiceCollection services)
    {
        ArgumentNullException.ThrowIfNull(services);
        return AddDefault(services, configure: null);
    }

    /// <summary>Registers the default <see cref="IJevClient"/>, configured by <paramref name="configure"/>.</summary>
    /// <param name="services">The services to add to.</param>
    /// <param name="configure">
    /// Configures the default named <see cref="JevClientOptions"/>. Each call adds its delegate, and they run in order.
    /// </param>
    /// <returns>The builder of the client's <see cref="HttpClient"/>, for adding handlers.</returns>
    /// <exception cref="ArgumentNullException"><paramref name="services"/> or <paramref name="configure"/> is <see langword="null"/>.</exception>
    public static IHttpClientBuilder AddJevClient(this IServiceCollection services, Action<JevClientOptions> configure)
    {
        ArgumentNullException.ThrowIfNull(services);
        ArgumentNullException.ThrowIfNull(configure);
        return AddDefault(services, configure);
    }

    private static IHttpClientBuilder AddDefault(IServiceCollection services, Action<JevClientOptions>? configure)
    {
        var builder = AddOptionsAndHttpClient(services, OptionsDefaults.DefaultName, HttpClientName, serviceKey: null, configure);
        services.TryAddSingleton<IJevClient>(provider => Create(provider, OptionsDefaults.DefaultName, HttpClientName));
        return builder;
    }

    // Configures the HttpClient on the first registration of its client only, so a repeat call cannot replace a primary
    // handler the caller set through the first call's builder. The factory's own request logging is removed: its
    // handlers allocate on every request even when nothing logs, and the client logs each operation and each retried
    // attempt itself. AddDefaultLogger on the returned builder brings it back.
    private static IHttpClientBuilder AddOptionsAndHttpClient(
        IServiceCollection services, string optionsName, string httpClientName, string? serviceKey, Action<JevClientOptions>? configure)
    {
        var options = services.AddOptions<JevClientOptions>(optionsName);
        if (configure is not null)
        {
            options.Configure(configure);
        }

        var repeat = IsRegistered(services, serviceKey);
        var builder = services.AddHttpClient(httpClientName);
        if (!repeat)
        {
            builder
                .ConfigurePrimaryHttpMessageHandler(static () => new SocketsHttpHandler { PooledConnectionLifetime = TimeSpan.FromMinutes(2) })
                .SetHandlerLifetime(Timeout.InfiniteTimeSpan)
                .ConfigureHttpClient((provider, httpClient) => JevClient.ConfigureHttpClient(httpClient, OptionsOf(provider, optionsName)))
                .RemoveAllLoggers();
        }

        return builder;
    }

    // Whether an IJevClient is already registered under serviceKey; null is the default client.
    private static bool IsRegistered(IServiceCollection services, string? serviceKey)
    {
        for (var i = 0; i < services.Count; i++)
        {
            var descriptor = services[i];
            if (descriptor.ServiceType == typeof(IJevClient) && Equals(descriptor.ServiceKey, serviceKey))
            {
                return true;
            }
        }

        return false;
    }

    private static JevClient Create(IServiceProvider provider, string optionsName, string httpClientName)
        => new(
            provider.GetRequiredService<IHttpClientFactory>().CreateClient(httpClientName),
            OptionsOf(provider, optionsName),
            provider.GetService<ILoggerFactory>());

    private static JevClientOptions OptionsOf(IServiceProvider provider, string optionsName)
        => provider.GetRequiredService<IOptionsMonitor<JevClientOptions>>().Get(optionsName);
}
```

```csharp
using System.Diagnostics;
using System.IO.Compression;
using System.Reflection;

namespace ZeroAlloc.Jev.PackTests;

/// <summary>
/// Packs one shipping project under <c>src</c> once, into a unique temp directory, via <c>dotnet pack</c> run as a child
/// <see cref="Process"/>. Reuses the src output the solution build already produced with <c>--no-build</c> when it
/// exists, and redirects the generated nuspec away from the project's own <c>obj</c> directory, so this never races or
/// corrupts the concurrent solution build or a later pack step.
/// </summary>
internal sealed class PackedProject : IDisposable
{
    private readonly string _tempDir;

    /// <param name="projectName">The project's directory and file name under <c>src</c>, such as <c>ZeroAlloc.Jev</c>.</param>
    public PackedProject(string projectName)
    {
        var repoRoot = FindRepoRoot();
        var configuration = typeof(PackedProject).Assembly
            .GetCustomAttribute<AssemblyConfigurationAttribute>()?.Configuration
            ?? "Release";

        _tempDir = Path.Combine(Path.GetTempPath(), "jev-pack-tests-" + Guid.NewGuid().ToString("N"));
        Directory.CreateDirectory(_tempDir);

        var projectPath = Path.Combine(repoRoot, "src", projectName, projectName + ".csproj");
        var srcOutputDll = Path.Combine(repoRoot, "src", projectName, "bin", configuration, "net10.0", projectName + ".dll");
        var reuseSrcOutput = File.Exists(srcOutputDll);

        // Redirect the generated .nuspec into our own temp dir: dotnet pack --no-build still writes it under
        // the project's obj/, and this test can otherwise race a concurrent solution build or pack step there.
        var nuspecOutputPath = Path.Combine(_tempDir, "nuspec-obj") + Path.DirectorySeparatorChar;

        var startInfo = new ProcessStartInfo("dotnet")
        {
            RedirectStandardOutput = true,
            RedirectStandardError = true,
            UseShellExecute = false,
            WorkingDirectory = repoRoot,
        };
        startInfo.ArgumentList.Add("pack");
        startInfo.ArgumentList.Add(projectPath);
        startInfo.ArgumentList.Add("-c");
        startInfo.ArgumentList.Add(configuration);
        startInfo.ArgumentList.Add("-o");
        startInfo.ArgumentList.Add(_tempDir);
        startInfo.ArgumentList.Add($"-p:NuspecOutputPath={nuspecOutputPath}");
        startInfo.ArgumentList.Add($"-p:PackageVersion={PackageVersion}");
        if (reuseSrcOutput)
        {
            startInfo.ArgumentList.Add("--no-build");
        }

        using var process = Process.Start(startInfo)
            ?? throw new InvalidOperationException("Failed to start 'dotnet pack'.");
        var stdout = process.StandardOutput.ReadToEnd();
        var stderr = process.StandardError.ReadToEnd();
        process.WaitForExit();

        if (process.ExitCode != 0)
        {
            throw new InvalidOperationException(BuildPackFailureMessage(process.ExitCode, stdout, stderr));
        }

        var nupkg = Directory.GetFiles(_tempDir, "*.nupkg").FirstOrDefault();
        if (nupkg is null)
        {
            throw new InvalidOperationException(
                $"'dotnet pack' exited 0 but produced no .nupkg in '{_tempDir}'.{Environment.NewLine}" +
                BuildPackFailureMessage(process.ExitCode, stdout, stderr));
        }

        NupkgPath = nupkg;
        NuspecPath = ExtractNuspec(nupkg, _tempDir);
    }

    public string NupkgPath { get; }

    public string NuspecPath { get; }

    /// <summary>Gets the version this packs: unique per run, so no package cache can hold an older build of it.</summary>
    public string PackageVersion { get; } = "0.0.0-packtest.g" + Guid.NewGuid().ToString("N");

    /// <summary>Gets the directory holding the packed <c>.nupkg</c>, usable as a local package source.</summary>
    public string OutputDirectory => _tempDir;

    public void Dispose()
    {
        try
        {
            Directory.Delete(_tempDir, recursive: true);
        }
        catch (IOException)
        {
            // Best effort: a lingering handle on Windows must not fail the test run.
        }
        catch (UnauthorizedAccessException)
        {
            // Best effort: a lingering handle on Windows must not fail the test run.
        }
    }

    private static string BuildPackFailureMessage(int exitCode, string stdout, string stderr)
        => $"'dotnet pack' exited with code {exitCode}.{Environment.NewLine}" +
           $"--- stdout ---{Environment.NewLine}{stdout}{Environment.NewLine}" +
           $"--- stderr ---{Environment.NewLine}{stderr}";

    private static string ExtractNuspec(string nupkgPath, string tempDir)
    {
        using var archive = ZipFile.OpenRead(nupkgPath);
        var entry = archive.Entries.First(e => e.FullName.EndsWith(".nuspec", StringComparison.Ordinal));
        var destination = Path.Combine(tempDir, entry.Name);
        entry.ExtractToFile(destination, overwrite: true);
        return destination;
    }

    private static string FindRepoRoot()
    {
        var directory = new DirectoryInfo(AppContext.BaseDirectory);
        while (directory is not null)
        {
            if (File.Exists(Path.Combine(directory.FullName, "ZeroAlloc.Jev.slnx")))
            {
                return directory.FullName;
            }

            directory = directory.Parent;
        }

        throw new InvalidOperationException(
            $"Could not find 'ZeroAlloc.Jev.slnx' by walking up from '{AppContext.BaseDirectory}'.");
    }
}
```

```csharp
    /// <see cref="EvaluateRoundTrip"/>'s call through a client <c>AddJevClient</c> registered, against the same call on a
    /// hand-built client over an <see cref="HttpClient"/> that <see cref="JevClient.ConfigureHttpClient"/> configured the

    {
        var services = new ServiceCollection();
        services
            .AddJevClient(options =>
            {
                options.ApiKey = "smoke-key";
                options.BaseAddress = new Uri("https://example.test/api/");

        // DI adds nothing per call: the hand-built client's own measurement is the budget.
        GateValueTask(

            action: () => resolved.EvaluateAsync(request),
            label: "EvaluateRoundTripThroughDependencyInjectionAgainstHandBuilt",
            passDescription: "EvaluateAsync through a DI-resolved client allocates no more than through a hand-built one");

        // Not yet measured: Task 6 Step 7 replaces this comment and the 0 B budget from Step 6's measurement.
        GateValueTask(
            budgetBytes: 0,
            action: () => resolved.EvaluateAsync(request),
            label: "EvaluateRoundTripThroughDependencyInjection",
            passDescription: "EvaluateAsync through a DI-resolved client stays within its allocation budget");
    }

    // Bytes allocated per call, measured as AllocationGate measures them: two warm-up calls, a full collection, then
    // 1000 calls that must each complete synchronously.
    private static long SynchronousBytesPerCall<T>(Func<ValueTask<T>> call)
    {
        const int Iterations = 1000;
        Drain(call());
        Drain(call());
        GC.Collect();
        GC.WaitForPendingFinalizers();
        GC.Collect();
        var before = GC.GetAllocatedBytesForCurrentThread();
        for (var i = 0; i < Iterations; i++)
        {
            Drain(call());
        }

        return (GC.GetAllocatedBytesForCurrentThread() - before) / Iterations;

        static void Drain(ValueTask<T> pending)
        {
            if (!pending.IsCompletedSuccessfully)
            {
                throw new InvalidOperationException("The call did not complete synchronously, so its measurement would include awaiter machinery.");
            }

            _ = pending.Result;
        }
    }
```

```csharp
namespace ZeroAlloc.Jev.Benchmarks;

/// <summary>
/// <see cref="ClientBenchmarks.EvaluateAsync"/>'s call through a client <c>AddJevClient</c> registered, against the same
/// call on a hand-built client over an <see cref="HttpClient"/> that <see cref="JevClient.ConfigureHttpClient"/>

/// </summary>
[MemoryDiagnoser]
public class DependencyInjectionBenchmarks : IDisposable
{
    private ServiceProvider _provider = null!;
    private IJevClient _resolvedClient = null!;
    private HttpClient _handBuiltHttp = null!;
    private JevClient _handBuiltClient = null!;
    private SystemOneRequest _request = null!;

    [GlobalSetup]
    public void Setup()
    {
        var services = new ServiceCollection();
        services
            .AddJevClient(options =>
            {
                options.ApiKey = "bench";
                options.BaseAddress = new Uri("https://example.test/api/");
            })
            .ConfigurePrimaryHttpMessageHandler(() => new ClientBenchmarks.CannedHandler(HttpStatusCode.OK, ClientBenchmarks.NoulResponseJson));
        _provider = services.BuildServiceProvider();
        _resolvedClient = _provider.GetRequiredService<IJevClient>();

        _handBuiltHttp = new HttpClient(new ClientBenchmarks.CannedHandler(HttpStatusCode.OK, ClientBenchmarks.NoulResponseJson));
        JevClient.ConfigureHttpClient(_handBuiltHttp, new JevClientOptions { BaseAddress = new Uri("https://example.test/api/") });
        _handBuiltClient = new JevClient(_handBuiltHttp, new JevClientOptions { ApiKey = "bench" });

        _request = new SystemOneRequest
        {
            State = "Help! My payouts have been failing for 3 days.",
            Questions = new Dictionary<string, JevQuestion>(StringComparer.Ordinal)
            {
                ["is_urgent"] = new NoulQuestion { Instructions = "Does this convey urgency?" },
            },
        };
    }

    public void Cleanup() => Dispose();

    public void Dispose()

        _handBuiltClient?.Dispose();
        _handBuiltHttp?.Dispose();
        _provider?.Dispose();
```

````markdown
### Dependency injection

`ZeroAlloc.Jev.DependencyInjection` registers the client in a .NET host, over `IHttpClientFactory`:

```csharp
builder.Services.AddJevClient(options => options.ApiKey = builder.Configuration["TypeSafe:ApiKey"]);

public sealed class TicketTriage(IJevClient jev)
{
    // ...
}
```

For several providers or configurations, register keyed clients and inject each one with `[FromKeyedServices]`:

```csharp
builder.Services.AddJevClient("typesafe", options => options.ApiKey = typesafeKey);
builder.Services.AddJevClient("openrouter", options =>
{
    options.Provider = JevProvider.OpenRouter;
    options.ApiKey = openRouterKey;
});

public sealed class Router([FromKeyedServices("openrouter")] IJevClient jev)
{
    // ...
}
```

- **One singleton per registration.** It reads its named `JevClientOptions` once, when first resolved. The default client reads the default name, and a keyed client reads its key. Repeat calls for the same name add their configure delegates in order, and register no second client.
- **The `HttpClient` comes from the factory.** It is named `ZeroAlloc.Jev`, or `ZeroAlloc.Jev:{name}` for a keyed client.
  - Its primary handler is a `SocketsHttpHandler` that recycles connections every 2 minutes, so DNS changes are picked up.
  - The factory never rotates that handler, because the singleton keeps its `HttpClient` for life.
  - `JevClient.ConfigureHttpClient` gives it the base address, the per-attempt `Timeout` and the User-Agent.
- **`AddJevClient` returns the `IHttpClientBuilder`,** so you can add your own handlers. If you add a retry handler, such as `AddStandardResilienceHandler`, set `MaxRetries = 0`, so retries don't multiply.
- **Logging goes through the host's `ILoggerFactory`.** Without a logging provider, or with Jev's levels disabled, the client logs nothing and allocates nothing for logging.
  - The factory's own request logs are off for Jev's clients, because their handlers allocate on every request even when nothing logs.
  - The client logs each operation and each retried attempt itself.
  - Call `AddDefaultLogger()` on the returned builder to bring the factory's logs back, at that cost.
- **Telemetry is on.** Subscribe with `AddSource("ZeroAlloc.Jev")` and `AddMeter("ZeroAlloc.Jev")`, as [Telemetry](#telemetry) shows. The package takes no OpenTelemetry dependency.
- **Invalid options throw when the client is first resolved, not at registration.** That covers a missing API key, a non-positive `Timeout` or an invalid base address. The exception is the core's `ArgumentException` or `InvalidOperationException`.
- **Disposal.** The container disposes the client with the provider. The `HttpClient` belongs to the factory, and is left alone.

**Cost.** An evaluation through a resolved client allocates exactly what the same call allocates on a hand-built client over a configured `HttpClient`, so DI adds nothing per call. Registration and the first resolve happen once. See [Phase 3.3 — DI package](docs/performance.md#phase-33--di-package).

**Without the package.** `JevClient.ConfigureHttpClient(httpClient, options)` configures any `HttpClient` the way the client configures its own. Call it before the client sends a request, for instance on a named client of your own:

```csharp
services.AddHttpClient("jev").ConfigureHttpClient(http => JevClient.ConfigureHttpClient(http, options));

var jev = new JevClient(httpClientFactory.CreateClient("jev"), options);
```
````
