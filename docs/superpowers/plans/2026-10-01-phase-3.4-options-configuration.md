# Phase 3.4 — Options and configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `JevClientOptions` bind from `IConfiguration` through two new `AddJevClient` overloads, and every `AddJevClient` registration validates its options at host startup with the core's own rules. Retry and timeout settings bind the same way as every other option.

**Architecture:** The core gains one public method, `JevClientOptions.Validate()`. It runs `JevClientSettings.Resolve`, the method every `JevClient` constructor already runs, so the two cannot drift. The DI package adds an internal `JevClientOptionsValidator : IValidateOptions<JevClientOptions>` for each options name, plus `ValidateOnStart()`. Both are registered on the first registration of a name, next to the existing `HttpClientConfigured` marker. Two new overloads call `OptionsBuilder<JevClientOptions>.Bind(configuration)`, with the configuration-binder source generator enabled in the DI csproj.

**Tech Stack:** C# 14 / .NET 10, Microsoft.Extensions.Options.ConfigurationExtensions 10.0.0 (brings Configuration.Binder and its source generator), Microsoft.Extensions.Http 10.0.0, Microsoft.Extensions.Hosting and Microsoft.Extensions.Configuration (tests and the smoke app only), xUnit 2.9.3, WireMock.Net, ZeroAlloc.TestHelpers `AllocationGate`, Native AOT.

**Spec:** `docs/superpowers/specs/2026-10-01-phase-3.4-options-configuration-design.md` (milestone: `docs/superpowers/specs/2026-09-30-milestone-3-design.md`)

## Spec gaps found

The plan probe found one place where the spec cannot work as written. The plan applies the smallest fix that keeps the spec's intent, and the spec's Section 2 now records it.

1. **`TryAddEnumerable` collapses validators for different names into one.** The spec registered `JevClientOptionsValidator(name)` with `TryAddEnumerable`, so that repeat calls would not stack validators. `TryAddEnumerable` deduplicates by implementation type, and an instance descriptor's implementation type is the instance's class. So the validator for a second name, such as a keyed client, would never be added, and its options would go unvalidated.
   - Probe on 2026-10-01: after `TryAddEnumerable` with `new V("a")` and then `new V("b")`, the collection held **1** validator.
   - **Resolution:** `AddOptionsAndHttpClient` already knows whether this is the first registration of a name, through its `repeat` flag. That flag comes from the `HttpClientConfigured` marker, and the marker's `HttpClient` name maps one-to-one to the options name. The validator and `ValidateOnStart()` are added inside the existing `if (!repeat)` block, so each name gets exactly one validator.
   - Two tests guard this. A keyed client's invalid options must not fail the default client, which proves the validators are scoped by name. A repeat registration must report its failure once, which proves validators do not stack.

## Global Constraints

From the spec:

- **New public API, exactly:**
  - Core: `public void JevClientOptions.Validate()`. It throws what a `JevClient` constructor throws for the same options, with the same type and message: `ArgumentException` (including `ArgumentOutOfRangeException`) for an invalid value, and `InvalidOperationException` for a missing API key or an invalid environment variable. It reads `TYPESAFE_API_KEY`, `OPENROUTER_API_KEY` and `TYPESAFE_BASE_URL` the way the constructor does.
  - DI: `AddJevClient(this IServiceCollection services, IConfiguration configuration)` and `AddJevClient(this IServiceCollection services, string name, IConfiguration configuration)`. Both return `IHttpClientBuilder`. There are no optional parameters (RS0026).
- **Validation for every `AddJevClient` registration**, whether it binds configuration or not:
  - It uses one `IValidateOptions<JevClientOptions>` per options name, which skips every other name and calls `options.Validate()`. It maps `ArgumentException` or `InvalidOperationException` to `ValidateOptionsResult.Fail(exception.Message)`.
  - It calls `ValidateOnStart()`, so a generic host fails at `StartAsync`.
  - Without a host, the first resolve throws `OptionsValidationException`, carrying the core's message.
- **Binding:**
  - `AddOptions<JevClientOptions>(O).Bind(configuration)`, where `O` is `Options.DefaultName` for the default client and `name` for a keyed one.
  - The keys are the property names: `Provider`, `ApiKey`, `BaseAddress`, `Model`, `Timeout`, `MaxRetries`, `InitialBackoff`, `MaxRetryDelay` and `Jitter`.
  - A `configure` delegate registered later for the same name overrides bound values.
- **The DI csproj** sets `<EnableConfigurationBindingGenerator>true</EnableConfigurationBindingGenerator>`, so binding uses no reflection.
- **Dependencies:**
  - The DI package depends on exactly `ZeroAlloc.Jev`, `Microsoft.Extensions.Http` 10.0.0 and `Microsoft.Extensions.Options.ConfigurationExtensions` 10.0.0. The pack test asserts this.
  - ZeroAlloc.Validation.Options is not used.
- **Not in scope:**
  - Configuration reloads. The client is a singleton that reads its options once.
  - Custom retry policies through DI.
- **Cost:**
  - A client bound from configuration allocates per call no more than a hand-built client. The relative AOT gate is reused for it.
  - The absolute 4864 B gate and every existing budget are unchanged.
- **Native AOT:** the smoke app binds, resolves and evaluates a default and a keyed client, with zero IL2xxx/IL3xxx warnings. A binder-generator gap goes upstream, never into a suppression.

    /// <summary>Every case's name.</summary>
    public static TheoryData<string> All => Names(static _ => true);

    /// <summary>
    /// The cases that read no environment variable: they set no fake variable, and their options carry an API key. With
    /// a key set, the resolver throws before it would read <c>TYPESAFE_BASE_URL</c>, or never reads it because the
    /// base address is set too. So these cases throw the same in any process environment.
    /// </summary>
    public static TheoryData<string> OptionsOnly
        => Names(static invalid => invalid.Environment.Length == 0 && !string.IsNullOrWhiteSpace(invalid.Options().ApiKey));

    /// <summary>Gets the case named <paramref name="name"/>.</summary>
    public static InvalidOptionsCase Get(string name) => Cases[name];

    private static TheoryData<string> Names(Func<InvalidOptionsCase, bool> include)
    {
        var names = new TheoryData<string>();
        foreach (var (name, invalid) in Cases)
        {
            if (include(invalid))
            {
                names.Add(name);
            }
        }

        return names;
    }

/// <summary>One invalid options case.</summary>
/// <param name="options">Creates the case's options; each call returns a fresh instance.</param>
/// <param name="exception">The exact exception type the resolver throws.</param>
/// <param name="environment">The fake environment variables the case runs against.</param>
public sealed class InvalidOptionsCase(
    Func<JevClientOptions> options, Type exception, params (string Name, string Value)[] environment)
{
    /// <summary>Gets the exact exception type the resolver throws.</summary>
    public Type Exception { get; } = exception;

    /// <summary>Gets the fake environment variables the case runs against.</summary>
    public (string Name, string Value)[] Environment { get; } = environment;

    /// <summary>Creates the case's options.</summary>
    public JevClientOptions Options() => options();

    /// <summary>Reads a fake environment variable, or <see langword="null"/> when the case does not set it.</summary>
    public string? Lookup(string name)
        => Array.Find(Environment, variable => string.Equals(variable.Name, name, StringComparison.Ordinal)).Value;
}

using Microsoft.Extensions.Options;
using OptionsDefaults = Microsoft.Extensions.Options.Options;

namespace ZeroAlloc.Jev.DependencyInjection;

/// <summary>
/// Validates one <c>AddJevClient</c> registration's <see cref="JevClientOptions"/> through
/// <see cref="JevClientOptions.Validate()"/>, the check the client's constructor runs, so startup and construction apply
/// one rule set. Options of any other name are skipped.
/// </summary>
/// <param name="optionsName">The registration's options name: the empty default name, or a keyed client's key.</param>
internal sealed class JevClientOptionsValidator(string optionsName) : IValidateOptions<JevClientOptions>
{
    public ValidateOptionsResult Validate(string? name, JevClientOptions options)
    {
        ArgumentNullException.ThrowIfNull(options);
        if (!string.Equals(name ?? OptionsDefaults.DefaultName, optionsName, StringComparison.Ordinal))
        {
            return ValidateOptionsResult.Skip;
        }

        try
        {
            options.Validate();
            return ValidateOptionsResult.Success;
        }
        catch (ArgumentException exception)
        {
            return ValidateOptionsResult.Fail(exception.Message);
        }
        catch (InvalidOperationException exception)
        {
            return ValidateOptionsResult.Fail(exception.Message);
        }
    }
}

    // Adds the options and configures the HttpClient. The HttpClient name maps one-to-one to the options name, so the
    // first registration of either is the first of both. That first registration alone also:
    // - adds the options' validator and ValidateOnStart, so repeat calls do not stack validators. TryAddEnumerable
    //   cannot do this: it compares implementation types, so it would keep one validator for every name.
    // - configures the HttpClient, so a repeat call cannot replace a primary handler the caller set through the first
    //   call's builder. The factory's own request logging is removed: its handlers allocate on every request even when
    //   nothing logs, and the client logs each operation and each retried attempt itself. AddDefaultLogger on the
    //   returned builder brings it back.
    private static IHttpClientBuilder AddOptionsAndHttpClient(
        IServiceCollection services, string optionsName, string httpClientName, Action<JevClientOptions>? configure)
    {
        var options = services.AddOptions<JevClientOptions>(optionsName);
        if (configure is not null)
        {
            options.Configure(configure);
        }

        var repeat = IsHttpClientConfigured(services, httpClientName);
        var builder = services.AddHttpClient(httpClientName);
        if (!repeat)
        {
            services.AddKeyedSingleton(httpClientName, new HttpClientConfigured());
            services.AddSingleton<IValidateOptions<JevClientOptions>>(new JevClientOptionsValidator(optionsName));
            options.ValidateOnStart();
            builder
                .ConfigurePrimaryHttpMessageHandler(static () => new SocketsHttpHandler { PooledConnectionLifetime = TimeSpan.FromMinutes(2) })
                .SetHandlerLifetime(Timeout.InfiniteTimeSpan)
                .ConfigureHttpClient((provider, httpClient) => JevClient.ConfigureHttpClient(httpClient, OptionsOf(provider, optionsName)))
                .RemoveAllLoggers();
        }

        return builder;
