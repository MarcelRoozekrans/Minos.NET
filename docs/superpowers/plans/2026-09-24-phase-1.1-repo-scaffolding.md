# Phase 1.1 Repo Scaffolding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A buildable, testable, packable Jev.Net solution skeleton following the ZeroAlloc.Rest / AdoNet.Async repository standards.

**Architecture:** Repo-wide build policy lives in `Directory.Build.props` + `Directory.Packages.props` (central package management). One AOT-compatible library (`src/Jev.Net`) with public-API tracking and one xUnit test project (`tests/Jev.Net.Tests`). No runtime behaviour beyond a `JevDefaults` placeholder type.

**Tech Stack:** .NET SDK 10.0.401, net10.0, xUnit v2 (plain `Assert`), Microsoft.CodeAnalysis.PublicApiAnalyzers, Meziantou / Roslynator / ErrorProne.NET / NetFabric.Hyperlinq / ZeroAlloc.Analyzers.

**Spec:** `docs/superpowers/specs/2026-09-24-phase-1.1-repo-scaffolding-design.md`

## Global Constraints

- Target framework: `net10.0` only.
- SDK pin: `10.0.401`, `rollForward: latestMinor`.
- `TreatWarningsAsErrors=true`; RS0016/RS0017 in `WarningsAsErrors`.
- Package id `Jev.Net`, licence `MIT`, author `Marcel Roozekrans`; description must say it is an **unofficial** client.
- Tests use plain xUnit `Assert` — no FluentAssertions.
- Line endings LF (`.gitattributes`).
- Commits: conventional format per `docs/planning/CONVENTIONS.md`; body ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never include a `claude.ai/code/session_*` link; no nested parentheses in bodies.
- Out of scope (later phases): wire model, WireMock.Net, AOT smoke app, benchmarks, CI workflows, release-please/GitVersion config, `RepositoryUrl` (no remote yet).

## Follow-ups from the final review

Carried forward to the phases that own them; read these when brainstorming those phases.

- **Phase 1.4 (transport):** ZeroAlloc.Rest's generator emits `public` types (`ClientEmitter.cs:58` client class, `DiEmitter.cs:30` DI extensions). Inside Jev.Net they become public API and PublicApiAnalyzers will demand entries — decide whether to accept them or get ZeroAlloc.Rest to honour the interface's accessibility. Filed upstream as https://github.com/ZeroAlloc-Net/ZeroAlloc.Rest/issues/295 — confirmed on 1.3.4: `internal` interface + `internal` DTOs fails with CS0050; `internal` interface + `public` DTOs compiles but leaks the client and DI extensions publicly.
- **Phase 1.4 (transport):** `JevDefaults.Model` / `ApiKeyEnvironmentVariable` are `public const`, which inlines into consumers. Decide whether defaults that can change (at least `Model`) become `static` properties.
- **Phase 1.8 (CI and release):** pre-publish checklist — `RepositoryUrl`, `PackageProjectUrl`, `RepositoryType`, `ContinuousIntegrationBuild`, symbol packages (`IncludeSymbols` / snupkg), absolute GitHub URLs in `README.md` (packed README breaks relative links on nuget.org).
- **Phase 1.8 (CI and release):** benchmarks project goes under `tests/` with any BenchmarkDotNet-shape suppressions local to its csproj; the AOT smoke app needs an explicit IL2xxx/IL3xxx `WarningsAsErrors` list (see ZeroAlloc.Rest). Packing is now opt-in (`IsPackable=true` only in `src/Jev.Net`), so new projects are non-packable by default.
