# Phase 10.1 Escalation Middleware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `UseEscalation` in the core: ask the app's client first, re-ask only the unsure questions on a target client within the time left, and return one merged `DecisionResponse` whose `Path` says per question which client answered and why.

**Architecture:** New public path types and `DecisionResponse.Path`/`As<T>()` in `src/Minos.NET`; an `EscalatingDecisionClient : DelegatingDecisionClient` in `src/Minos.NET/Pipeline` that merges at the internal answer-slot level; telemetry through the ZeroAlloc.Telemetry attributes on `IDecisionEvaluation`; the path stored by `Minos.NET.Caching` and `Minos.NET.Recording`. The spike on local branch `spike/10.1-path` shows the merge (`EscalatingDecisionClientSpike.cs`); read it, do not merge it.

**Tech Stack:** .NET 10, C#, xUnit, ZeroAlloc.Results / Telemetry, System.Text.Json Utf8 reader/writer, Native AOT.

**Spec:** `docs/superpowers/specs/2026-11-04-phase-10.1-escalation-design.md` (and the milestone design it cites).

## Global Constraints

- Native AOT clean: zero IL2 and IL3 warnings; no reflection-based System.Text.Json.
- No state (question text, task text, option text, images, question keys in telemetry) in a log message, a span or metric tag, or an exception message.
- Off by default; decorate, never replace, the app's `IDecisionClient`.
- No added latency or allocation on the all-confident path beyond the threshold checks and the path itself.
- Additive API only; ApiCompat clean against 1.9.0. Every new public member goes in the project's `PublicAPI.Unshipped.txt`; RS0026/RS0027 apply (no optional-parameter overload pairs).
- Commits: conventional, scopes from `.commitlintrc.yml` (`core`, `di`, `caching`, `recording`, `tests`, `samples`, `docs`); no nested parentheses in commit bodies; no Claude signature lines.
- Allocation gates run only in the published AOT smoke executable (`samples/Minos.NET.AotSmoke`), not in `dotnet test`.

## Decisions made in this plan (on top of the spec)

1. **Target resolution.** The core has no DI dependency, so the core overloads take the target as a client or a factory, as `UseShadowRecording` does. The by-key overload `UseEscalation(builder, string targetKey, …)` lives in `Minos.NET.DependencyInjection`, which resolves the keyed `IDecisionClient` that `AddDecisionClient(name, …)` registers. The target's name in the path is the key for that overload, and `EscalationOptions.TargetName` for the others (required, non-empty).
2. **Defaults:** `DefaultThreshold = 0.6` (Daedalus's current floor), `ExpectedLatency = TimeSpan.Zero`, `Budget = null`. With neither a `Deadline` nor a `Budget`, there is no time check.
3. **Options are validated at `Build`:** thresholds must be in [0, 1] and not NaN; `ExpectedLatency` is not negative; `Budget` is positive when set; names are non-empty and `PrimaryName != TargetName`. A violation throws `ArgumentException` from `Build`, as `UseRetries` does.
4. **Threshold keys not in a definition are ignored**, so one options instance can serve several question sets.
5. **Subset cache:** stored in `QuestionSetDefinition`'s protocol-data slot 3: a `ConcurrentDictionary<ulong, QuestionSetDefinition>` keyed by the unsure-index bitmask, capped at 64 entries (when full, a new subset is built and not stored). A definition with more than 64 questions builds its subset every time.
6. **Counter granularity:** `minos.escalations` adds 1 per call whose primary answer had at least one unsure question, tagged with the target and the set-level reason: `escalated`, `no_time_left` or `target_failed`.

## Review Focus

1. **A deadline already past at entry:** the primary is still called (the stage does not gate it), and unsure questions route `NoTimeLeft` with no target call. Test in Task 4.
2. **An empty question set or one where no threshold is met:** no subset is built, no target call is made, and `Path` has one `Confident` route per question and one call. Test in Task 3.
3. **Concurrent calls with the same and different unsure patterns:** answers never cross between calls, and the subset cache stays at most 64 entries. Test in Task 3.
4. **Disposing the stage:** disposes the primary (as `DelegatingDecisionClient` does) and does **not** dispose a target it did not create, since a keyed target is owned by the container. Test in Task 4.
5. **A target that throws, rather than returning a failure:** an exception other than the caller's `OperationCanceledException` propagates unchanged, as other stages do; it is not swallowed into `TargetFailed`. Test in Task 3.
