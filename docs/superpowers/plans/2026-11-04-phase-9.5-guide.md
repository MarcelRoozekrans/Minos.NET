# Phase 9.5 "Running decisions locally and privately" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A docs page, `docs/running-locally.md`, that follows one app through record, shadow, outcomes, export,
report, decide and switch, with tested snippets and figures checked against the Banking77 shadow report.

**Architecture:** The app's code lives in `tests/Minos.NET.Docs.Tests/RunningLocally.cs` as mdsnippets regions, run
by `RunningLocallyTests`. The page embeds those regions, and `RunningLocallyPageTests` checks its JSON blocks,
commands and report figures. The one library addition is `UseShadowRecording`, shipped separately in #313.

**Tech Stack:** .NET 10, xUnit, MarkdownSnippets (`dotnet mdsnippets`), Docusaurus front matter.

**Spec:** `docs/superpowers/specs/2026-11-03-phase-9.5-guide-design.md`

## Global Constraints

- No change under `src/`, `samples/` or `docs/reports/`.
- Page front matter: `id: running-locally`, `title: Running decisions locally and privately`, `sidebar_position: 14`.
- Final sidebar order: 14 the guide, 15 `native-aot`, 16 `diagnostics`, 17 `testing-your-code`, 18 `patterns`
  (`docs/patterns/_category_.json`), 19 `samples`, 20 `performance`, 21 `conformance`.
- The page names no project for the zero-data-retention case, and the code does not name Daedalus.
- Every report figure on the page is test-checked against `docs/reports/shadow/banking77/shadow-report.json`.
- The local server is `ollajev` serving `Mapika/decider-2b-GGUF:Q4_K_M` on port 8000, through the `Custom` preset at
  `http://localhost:8000/`, with no key.
- Commands name Minos.NET.Tool 1.8.0 or later.
- Plain style of the existing pages; run the anti-slop catalogue over the page before committing it.
- Snippet regions are named `RunningLocally_*`, and each has exactly one source (`SnippetSourceTests`).
- New type names must not clash with any existing type in `Minos.Docs.Tests` (`NameClashTests`).
- Commits use `docs(docs):` or `test(tests):`; no nested parentheses in commit bodies.

## Review Focus

1. `Minos:Shadow` naming the same section as `Minos:Active`: a reader who copies the "after" config but forgets to
   remove `Shadow` would shadow a provider with itself. Expect an `InvalidOperationException` naming the section.
   Pinned in Task 1.
2. `Minos:Shadow` naming a section that does not exist: expect an `InvalidOperationException` naming it, not a silent
   unshadowed app. Pinned in Task 1.
3. A primary call that fails while shadowing: the caller gets the primary's error, and the app does not throw from
   the shadow. Pinned in Task 1.
4. The redacted record: the provider receives the text, the kept record does not hold it unmasked. Pinned in Task 1.
5. A rebuilt report with different figures: the page test fails naming the figure and its JSON path. Pinned in Task 2.

### Task 1: The example app and its behaviour tests

**Model:** opus. It wires a shadow candidate from configuration beside the active client, which has to fit the
existing `UseRecording(shadow, recorder)` and DI registration API without new library code.

**Files:**
- Create: `tests/Minos.NET.Docs.Tests/RunningLocally.cs`
- Create: `tests/Minos.NET.Docs.Tests/RunningLocallyTests.cs`

**Interfaces:**
- Consumes: `DecisionRecorder`, `RecordingOptions.Redact`, `ShadowOptions(candidate, dailyCap)`,
  `UseRecording(...)`, `AddSystemOneDecisionClient(IConfiguration)` and the named overloads, `RecordFileReading`,
  `DecisionOutcome.Confirmed`, `ConfirmedAnswer.ForChoice/ForNoul`, the way `TicketDecisions.RouteAsync` in
  `Recording.cs` gets a decision id, and `ScriptedDecision` for scripted HTTP replies.
- Produces, each in its own `#region`:
  - `RunningLocally_Questions`: `public enum PaymentTopic` with three options, each with a `[Criterion]`, and
    `[Questions] public partial record PaymentReview` with one `[Noul]` `IsDisputed` and one `[Choice]`
    `Choice<PaymentTopic> Topic`.
  - `RunningLocally_Register`:
    `public static class LocalReadiness { public static IHostApplicationBuilder AddRecordedDecisions(this IHostApplicationBuilder builder, IDecisionRecordSink sink) }`.
    It reads `Minos:Active` and `Minos:Shadow`, which name sections under `Minos:Providers`. It registers one
    `DecisionRecorder` over `sink` with a `Redact` that masks e-mail addresses in text, the active client bound from
    its section, and recording outermost. When `Minos:Shadow` is set, the shadow candidate is a client bound from
    that section, in `new ShadowOptions(candidate, dailyCap: 2000) { MaxConcurrent = 1, Timeout = TimeSpan.FromSeconds(30) }`.
    Unset means record only.
  - `RunningLocally_Review`:
    `public static class PaymentReviews { public static Task<(PaymentReview? Review, string? DecisionId)> ReviewAsync(IDecisionClient client, string customerId, string text, CancellationToken cancellationToken) }`,
    with `customerId` as the erasure key.
  - `RunningLocally_Outcomes`:
    `public static class PaymentOutcomes { public static ValueTask ConfirmAsync(IDecisionRecorder recorder, string decisionId, bool disputed, PaymentTopic topic, CancellationToken cancellationToken) }`,
    with source `"payments-desk"`.
  - `internal static class RunningLocallyConfig` with `const string Before` and `const string After`: the two
    `appsettings.json` texts the page shows. `Before` has `"Active": "TypeSafe"`, `"Shadow": "Local"`, a `TypeSafe`
    section and a `Local` section with `"Provider": "Custom"`, `"BaseAddress": "http://localhost:8000/"` and
    `"Model": "Mapika/decider-2b-GGUF:Q4_K_M"`. `After` is the same with `"Active": "Local"` and no `Shadow`.
    This class is not a snippet; Task 2's page test compares the page's JSON blocks with it.
