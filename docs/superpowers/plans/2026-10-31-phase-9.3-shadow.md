# Phase 9.3 Shadow Mode and Its Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run a candidate `IDecisionClient` beside the primary in the background through the recording stage, write its answers into the decision's record with a second write, and build a shadow report from a record file with `ShadowReport` and `minos shadow-report`.

**Architecture:** `RecordingDecisionClient` gains an internal `ShadowRunner`. After the primary's record is queued, the runner checks the conditions, reserves a cap slot and a concurrency slot, and starts the candidate on the thread pool with `ExecutionContext` flow suppressed. When the candidate finishes, the runner queues the same record again with a `ShadowResult`. `DecisionRecorder` keeps a registry of running shadows. It discards a late write for a decision it has erased since, and cancels running candidates on dispose. The record line gains a `shadow` member. `Minos.NET.Evaluation` reads `RecordedDecision` values into a `ShadowReport` with agreement, confusion tables and both sides' calibration, written as JSON and Markdown.

**Tech Stack:** .NET 10, C#, `System.Text.Json` `Utf8JsonWriter` and source-generated DTOs, `System.Threading.Channels`, `TimeProvider` with `FakeTimeProvider` in tests, System.CommandLine, xUnit, Verify snapshots, the Native AOT smoke app.

**Spec:** `docs/superpowers/specs/2026-10-31-phase-9.3-shadow-design.md`. Read all of it before any task. Its "Settled after the builder check" section overrides the "Decisions" above it where they differ.

## Global Constraints

- `export MSBUILDDISABLENODEREUSE=1` before every `dotnet` command.
- Warnings are errors. Never suppress a diagnostic (`#pragma`, `NoWarn`, `[SuppressMessage]`, `.editorconfig` severity) to get green: fix the cause.

- No log, metric tag, span, exception message, report member or tool output holds the state, a decision id or an erasure key. The candidate's error message is never logged or recorded.
- Shadow mode never changes the primary's result, never waits for the candidate, and never uses the caller's cancellation token for the candidate.

## Review Focus

1. **An outcome added between the two writes** survives the second write in both shipped sinks and through the file reader (Task 1 test `SecondWrite_KeepsOutcomesAddedBetween`, Task 2 test `ShadowWrite_KeepsOutcomeQueuedBeforeIt`).
2. **An erasure that the writer handles while the candidate runs** leaves nothing behind, by key and by decision id, even though the record line would otherwise come after the erasure line (Task 2 tests `EraseByKey_WhileShadowRuns_DropsTheShadowWrite` and `EraseById_WhileShadowRuns_DropsTheShadowWrite`).
3. **Many concurrent primaries against a cap of N** never start more than N candidates in a UTC day (Task 3 test `Cap_UnderConcurrency_NeverStartsMoreThanTheCap`).
4. **A 77-option Choice**, as in Phase 9.4's Banking77 set, gives a sparse JSON table and a top-20 Markdown list, not a 77×77 grid (Task 5 test `LargeChoice_MarkdownListsTopDisagreements`).
5. **A pre-9.3 record file** and the `TheLineFormat_IsPinned` snapshot still read and write byte for byte the same when no decision is shadowed (Task 1 test `UnshadowedRecord_LineIsUnchanged`).

### Task 2: The recorder's shadow writes, erasure guard and disposal

**Model:** opus. The registry, the single writer and dispose interact, and a wrong order resurrects erased data.

**Files:**
- Modify: `src/Minos.NET.Recording/DecisionRecorder.cs`
- Modify: `src/Minos.NET.Recording/RecordingTelemetry.cs`
- Test: create `tests/Minos.NET.Recording.Tests/ShadowWriteTests.cs`; modify `tests/Minos.NET.Recording.Tests/RecordingMeterTests.cs`

**Interfaces:**
- Consumes: `DecisionRecord.WithShadow` (Task 1).
- Produces, all `internal` on `DecisionRecorder`:
  - `bool TryBeginShadow(string decisionId, string? erasureKey, out CancellationToken stopping)`. It registers a running shadow and returns `false` once the recorder is disposed or when that id is already registered. `stopping` is cancelled when dispose starts.
  - `void EndShadow(DecisionRecord shadowed)`. It queues a shadow write without waiting; a full queue or a disposed recorder counts `dropped` and unregisters.
  - `void AbandonShadow(string decisionId)`. It unregisters without a write, for a candidate cancelled by dispose, and counts `dropped`.
  - `RecordingTelemetry.Shadows`, a `Totals` of `written`, `failed`, `dropped`, `skipped_cap` and `skipped_busy`, observed by the counter `minos.recording.shadows`, unit `{shadow}`, with the description "Shadow writes by result: written, failed, dropped, skipped_cap or skipped_busy." Add the constants `SkippedCap = "skipped_cap"` and `SkippedBusy = "skipped_busy"`.
- Behaviour:
  - `WorkKind.Shadow` items reach the sink through `WriteAsync`. They count in `Shadows`, never in `Records`.
  - When the writer handles an erasure, before calling the sink, it marks every registered shadow whose erasure key equals the erased key, or whose id equals the erased decision id, as erased.
  - When it handles a shadow write, it unregisters the entry. A write that is missing from the registry or marked erased is counted `dropped` and not written.
  - `DisposeAsync` cancels `stopping` first, then drains as today.

### Task 3: `ShadowOptions` and the shadow runner in the recording stage

**Model:** opus. Concurrency, the cap's atomic reserve, flow suppression and "never touch the primary" all meet here.

**Files:**
- Create: `src/Minos.NET.Recording/ShadowOptions.cs`, `src/Minos.NET.Recording/ShadowRunner.cs` (internal)
- Modify: `src/Minos.NET.Recording/RecordingDecisionClient.cs`, `RecordingDecisionClientBuilderExtensions.cs`, `PublicAPI.Unshipped.txt`
- Test: create `tests/Minos.NET.Recording.Tests/ShadowModeTests.cs` and `tests/Minos.NET.Recording.Tests/ShadowCandidate.cs` (a candidate scripted with `TaskCompletionSource`, recording each request it saw and the `Activity.Current` and `DecisionRecording.Current` it ran with); modify `tests/Minos.NET.Recording.Tests/NeverRecordedTests.cs` and `UseRecordingTests.cs`

**Interfaces:**
- Consumes: Task 2's `TryBeginShadow`, `EndShadow`, `AbandonShadow`, `RecordingTelemetry.Shadows`; Task 1's `ShadowResult` and `WithShadow`.
- Produces:
  - `public sealed class ShadowOptions`:
    - `ShadowOptions(IDecisionClient candidate, int dailyCap)`. It throws `ArgumentNullException` for a null candidate, `ArgumentOutOfRangeException` for `dailyCap < 1`, and `ArgumentException` when `candidate.GetService<IDecisionRecorder>()` is not null, with the message "The candidate records its own decisions: shadow a client without UseRecording.";
    - `IDecisionClient Candidate { get; }` and `int DailyCap { get; }`;
    - `TimeSpan Timeout { get; set; }`, default 30 s. It must be positive and not `InfiniteTimeSpan`, else `ArgumentOutOfRangeException`;
    - `int MaxConcurrent { get; set; }`, default 4 and at least 1;
    - `string? Model { get; set; }`, default `null`.
  - `public RecordingDecisionClient(IDecisionClient innerClient, DecisionRecorder recorder, ShadowOptions? shadow)`. The existing two-parameter constructor calls it with `null`.
  - `public static DecisionClientBuilder UseRecording(this DecisionClientBuilder builder, ShadowOptions shadow, DecisionRecorder? recorder = null)`, which resolves the recorder as the existing overload does.
  - `internal sealed class ShadowRunner(ShadowOptions options, DecisionRecorder recorder)` with `void TryStart(DecisionRequest request, DecisionRecord queued)`.
- Behaviour, from spec decisions 3 to 6 and settled items 2, 5 and 6:
  - `RecordCore` calls `TryStart` only when `TryEnqueue` returned true, the primary succeeded, and the response was not cached. Retried attempts and redaction drops never reach it.
  - `TryStart` order:
    1. Reserve a cap slot. The day is `recorder.Time.GetUtcNow().UtcDateTime.Date`; the count resets when the day changes; check and increment in one step under a lock. Over the cap, count `skipped_cap`.
    2. `Interlocked.Increment` the running count. Over `MaxConcurrent`, decrement it, give the cap slot back and count `skipped_busy`.
    3. `TryBeginShadow`. A `false` result releases both slots.
    4. Start the candidate under `using (ExecutionContext.SuppressFlow())` with `Task.Run`, and return.
  - The candidate's request is `new DecisionRequest(request.Definition, request.State) { Model = options.Model, Images = request.Images }`, with the unredacted state and `RetryAttempt` 0.
  - Its token comes from a `CancellationTokenSource` created with `options.Timeout` and `recorder.Time`, linked to `stopping`.
  - Latency is measured with `recorder.Time`. Provider, endpoint and default model come from the candidate's `DecisionClientMetadata`, read once in the constructor, as the stage does for the inner client.
  - Error kinds:
    - the candidate's own error result gives its `Kind`, with `RefusedKeys` read as the stage reads them;
    - an `OperationCanceledException` after the timeout fired gives `Timeout`;
    - an `HttpRequestException` gives `Network`;
    - any other exception gives `Server`;
    - a cancellation from `stopping` calls `AbandonShadow` instead.
  - Every path ends with `EndShadow(queued.WithShadow(result))` or `AbandonShadow`, and releases the running count. Nothing the runner does can throw into the primary's call.

**Interfaces:**
- Consumes: `DecisionRecord.Shadow` (Task 1), `DecisionRecordFile.ReadAsync`.
- Produces:
  - `public sealed class ShadowReport`:
    - `static ShadowReport Create(IEnumerable<RecordedDecision> decisions, PriceTable? prices = null)`;
    - `static Task<ShadowReport> CreateAsync(IAsyncEnumerable<RecordedDecision> decisions, PriceTable? prices = null, CancellationToken cancellationToken = default)`;
    - `int DecisionsRead`, `int DecisionsShadowed`;
    - `ShadowSide Primary`, `ShadowSide Candidate`;

    - `string ToJson()`, `string ToMarkdown()`.
  - `public sealed class ShadowSide`:
    - `IReadOnlyList<ModelCount> Models`, the served models;
    - `ErrorSummary Errors` and `int Refusals`;
    - `LatencySummary Latency` and `CostSummary Cost`;
    - `int VerbalizedAnswers`;
    - `KindMetrics? Noul`, `KindMetrics? Choice`, `KindMetrics? Score` and `KindMetrics Overall`, the calibration against confirmed outcomes;
    - `int CalibratedDecisions` and `int CalibratedKeys`.
  - `public sealed class ShadowQuestion`:
    - `string Key`, `QuestionKind Kind`, and `IReadOnlyList<string> Labels`, the option keys or levels in definition order, empty for Noul;
    - `int Compared`, `int PrimaryOnly`, `int CandidateOnly`;
    - `double? Agreement` and `double? MeanLevelDifference` (the latter for Score only);
    - `IReadOnlyList<ConfusionCell> Confusion`, the non-zero cells, empty for Noul;
    - `bool IsSmall`, true when `Compared < 30`;
    - `IReadOnlyList<KeyValuePair<string, int>> SignalsWhenAgreed` and `SignalsWhenDisagreed`.
  - `public readonly record struct ConfusionCell(string Primary, string Candidate, int Count)`.
- Rules, from spec decision 10 and settled items 1 and 8:
  - The two sides are compared per key with the same answer rule:
    - a Noul is "yes" when its probability is at least 0.5;
    - a Choice compares option keys by `ChosenIndex`;
    - a Score compares levels.
  - Groups are keyed by question key, kind and labels, ordered by first appearance.
  - Calibration counts a key of a decision only when it was shadowed, both sides answered the key, and the merged confirmed answer fits. Image decisions are included.
  - Signal counts are per decision: a decision where every compared key agreed counts its signals under "agreed", any other compared decision under "disagreed". The counts are ordered by name, ordinal.
  - JSON writes the cells sparse. Markdown prints a full grid for up to 12 labels; for more, it prints the 20 most frequent off-diagonal cells, ties broken by primary then candidate label, ordinal. Small groups are marked "(small: n < 30)".
  - The JSON and Markdown layout follow `ReportJsonWriter` and `ReportMarkdownWriter`. Reuse their helpers for the shared sections (latency, cost, kind metrics) rather than copy them.
