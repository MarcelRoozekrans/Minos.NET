# Phase 8.1 Dataset Format and Loader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A versioned JSONL format for labelled decision datasets, a loader in a new `Minos.NET.Evaluation` project that turns each line into a `QuestionSetDefinition` with expected answers, and a Banking77 sample dataset.

**Architecture:**
- `DecisionDataset.Parse` reads each line with `Utf8JsonReader` or `JsonDocument`, never reflection.
- It builds each item's questions through the core's `QuestionSetBuilder`, so the core's validation and its MIN ids apply.
- It collects every problem, each with its line number, instead of stopping at the first one.
- The project is not packable in 8.1. Phase 8.3 publishes it.
- The sample dataset is built by a Python script from a vendored, CC BY 4.0 subset of Banking77, and committed.

**Tech Stack:** .NET 10, C#, System.Text.Json, xUnit, Python 3 (standard library only).

**Spec:** `docs/superpowers/specs/2026-10-17-phase-8.1-dataset-design.md`. Milestone context: `docs/superpowers/specs/2026-10-17-milestone-8-design.md`.

## Global Constraints

- **Project:** `src/Minos.NET.Evaluation`, root namespace `Minos.Evaluation`. It has `IsPackable` false, `IsAotCompatible` true, PublicAPI analyzers, and XML docs. Its only references are `Minos.NET` and `ZeroAlloc.Results`.
- **Format members, exactly:** `id`, `state`, `questions`, `expected`, `source`, `version`. Question members are `type`, `instructions` and `criteria`. A criterion object's members are `description`, `examples` and `not_for`. Any other member is a problem.
- **`version`:** absent, or `1`. Any other value is the problem "This file uses dataset format version N; this loader reads version 1."
- **`state`:** a JSON string, object or array. A number, boolean or null is a problem.
- **Expected values:** a Noul takes a JSON boolean, a Choice takes a string option key, and a Score takes an integer level index from 0.
- **Problems** are `(int Line, string Message)`, with 1-based line numbers. A core failure's message starts with its MIN id, for example "MIN003: …". The core's warnings, MIN003 and MIN005, are problems too.
- **No exceptions for content.** The loader throws only for a missing file or an I/O failure.
- **No change** to `src/Minos.NET` or any other existing package, and no allocation budget change.
- **The sample** lives in `datasets/banking77/`:
  - `banking77-minos-v1.jsonl`: 400 items, all 40 test messages for each of 10 intents;
  - `banking77-urgency-v1.jsonl`: 60 items, 6 per intent picked by a stable hash;
  - attribution to PolyAI, CC BY 4.0, from the pinned commit of `PolyAI-LDN/task-specific-datasets`;
  - the authored urgency labels under CC0, drafted by Claude and awaiting the maintainer's spot-check.
- **Commits:** conventional, with scopes from `.commitlintrc.yml`. Use `feat` with no scope for the new project; `evaluation` is not in the scope list, so the scope is omitted. No nested parentheses in commit bodies. End each commit with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A file with a UTF-8 BOM or CRLF line endings,** which Windows editors write: it loads with the same line numbers. Pinned in Task 2.
2. **A very large file:** the loader streams line by line rather than reading the whole file into one string, and reports line numbers past 10,000 correctly. Pinned in Task 2 with a generated 12,000-line stream.
3. **Duplicate question keys within one line's `questions` object:** JSON allows them, and the second must not silently win. Pinned in Task 2 as a problem.
4. **An expected Choice key that differs only in case from an option,** such as `Card_Arrival`: option keys are ordinal, so it is a problem. Pinned in Task 2.
5. **A Score level index that is a JSON number with a fraction or exponent,** such as `1.0`: it is not an integer, so it is a problem. Pinned in Task 2.

### Task 2: Every problem, with its line number

**Files:**
- Modify: `src/Minos.NET.Evaluation/DatasetReader.cs`
- Test: `tests/Minos.NET.Evaluation.Tests/DatasetProblemTests.cs`

**Interfaces:**
- Consumes the Task 1 types.

- [ ] **Step 1: Write the failing tests.** Each test parses a small string and asserts the problems as `(Line, message substring)` pairs, in order. Put the problem on line 2 unless the test says otherwise.
  - `MalformedJson`: the problem names the line and says the line is not valid JSON.
  - `MissingMember`: one test each for a missing `id`, `state`, `questions` and `expected`. Each message names the member.
  - `DuplicateId`: the id on lines 1 and 3. The problem is on line 3 and names line 1.
  - `UnknownMember`: `expect` at the top level, `instruction` on a question, and `example` in a criterion object. Each names the member and its path.
  - `StateOfTheWrongType`: number, boolean and null.
  - `WrongType`: a question with `"type":"yesno"`.
  - `ExpectedKeyWithoutQuestion`.
  - `ExpectedOptionNotInCriteria`, and the Review Focus 4 case-only mismatch `Card_Arrival`.
  - `ScoreLevelOutOfRange`: -1, and 3 for three levels.
  - `ScoreLevelNotAnInteger`: `1.0` and `1e0`, from Review Focus 5.
  - `ExpectedValueOfTheWrongType`: a string for a Noul, a number for a Choice, a boolean for a Score.
  - `NewerVersion`: `"version":2` gives exactly the message in Global Constraints.
  - `DuplicateQuestionKey`, from Review Focus 3: the same key twice in one `questions` object.
  - `CoreRuleFailure`: blank instructions give a problem starting with `MIN003`. A one-level Score gives one starting with `MIN005`.
  - `SeveralProblemsInOneFile`: problems on lines 1, 3 and 4 all come back, and the valid line 2 does not make the whole parse succeed.
  - `BomAndCrlf`, from Review Focus 1: a BOM and CRLF file with a problem on line 3 reports line 3.
  - `LargeStream`, from Review Focus 2: a generated 12,000-line stream with one bad line at 11,000 reports line 11,000.
