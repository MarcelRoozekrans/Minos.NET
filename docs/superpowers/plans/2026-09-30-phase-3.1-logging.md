# Phase 3.1 — Logging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `JevClient` logs every evaluation and model listing, every retried attempt and every unexpected exception through `ILogger` with stable event ids, never logs request or answer content, and stays silent and allocation-free without a logger.

**Architecture:** An internal `JevLog` class holds the six events as `[LoggerMessage]` partials, none with more than six fields. Two new public constructors take an `ILoggerFactory`. `JevClient` logs each operation once, when it completes, through a wrapper that it adds only when the logger has a level enabled that the operation can emit, checked per call. With no logger, or one with those levels disabled, the operation runs exactly the unlogged code it runs today. An internal `LoggingJevApi : IJevApi` decorator sits between the ZeroAlloc.Resilience proxy and the ZeroAlloc.Rest transport. It sees every attempt with its `[RetryAttempt]` number and logs `AttemptRetrying` for each failure the proxy will retry, using the proxy's own two tests.

**Tech Stack:** C# 14 / .NET 10, Microsoft.Extensions.Logging.Abstractions 10.0.0 with its `[LoggerMessage]` source generator, ZeroAlloc.Rest 3.1.0 / ZeroAlloc.Resilience 3.3.0, xUnit 2.9.3, Microsoft.Extensions.Diagnostics.Testing 10.10.0 (`FakeLogger`), WireMock.Net, BenchmarkDotNet, ZeroAlloc.TestHelpers `AllocationGate`, Native AOT.

**Spec:** `docs/superpowers/specs/2026-09-30-phase-3.1-logging-design.md` (milestone: `docs/superpowers/specs/2026-09-30-milestone-3-design.md`)

## Global Constraints

From the spec:

- `JevClient` logs through `ILogger`, using Microsoft's source-generated `[LoggerMessage]`: every evaluation and model listing, at Debug on success and Warning on failure; every retried attempt, at Warning; every unexpected exception, at Error.
- Logs never contain request or answer content. With no logger the client stays silent and allocation-free.
- Two new public constructors take an `ILoggerFactory`: `JevClient(JevClientOptions? options, ILoggerFactory? loggerFactory)` and `JevClient(HttpClient httpClient, JevClientOptions? options, ILoggerFactory? loggerFactory)`. Neither has optional parameters, so they satisfy RS0026. The existing four constructors are unchanged and log nothing. A null factory means no logging. The logger category is `ZeroAlloc.Jev.JevClient`, created with `loggerFactory.CreateLogger("ZeroAlloc.Jev.JevClient")`.
- `JevClient` logs each operation once, when it completes: `evaluate` for `EvaluateAsync(SystemOneRequest)`, `evaluate-typed` for the typed overloads, `evaluate-built-set` for `EvaluateAsync(JevQuestionSet, …)`, and `list-models`. This layer sees the whole outcome, including `InvalidResponse` from typed parsing.
- An internal `LoggingJevApi` decorator implements `IJevApi` and sits between the ZeroAlloc.Resilience proxy and the ZeroAlloc.Rest transport. When an attempt fails with an error the proxy will retry, it logs a Warning with the attempt number. It uses the same transient test as the retry policy, `IJevApi.IsTransient`.
- Events, each with a stable `EventId` in the 1000 range, in an internal static `JevLog` class:

  | Id | Name | Level | Fields |
  |---|---|---|---|
  | 1001 | `EvaluationSucceeded` | Debug | operation, model, provider, question count, duration ms |
  | 1002 | `EvaluationFailed` | Warning | operation, model, error kind, status code, duration ms, message |
  | 1003 | `AttemptRetrying` | Warning | attempt, error kind, status code, retry-after |
  | 1004 | `ModelsListed` | Debug | provider, model count, duration ms |
  | 1005 | `ModelsListFailed` | Warning | provider, error kind, status code, duration ms, message |
  | 1006 | `UnexpectedException` | Error | operation, exception |

- No event exceeds six fields, keeping `[LoggerMessage]` on its struct-free path (a larger one generates a struct HLQ006 rejects). Provider is fixed per client and retry-after is already on `AttemptRetrying`, so `EvaluationFailed` leaves both out. Each template keeps its placeholders in parameter order, so the generator emits `LoggerMessage.Define`; a scratch probe with this repository's analyzer set verified this for all six, 1002 included, with no generated struct.
- Question count is `request.Questions.Count` on the raw `SystemOneRequest` path and `JevQuestionSet.Plan.Length` for a built set. For a generated set it is counted once per type from `T.QuestionsUtf8`'s top-level entries, and only when a logger exists. An internal generated constant cannot work: the set compiles into the caller's assembly, where the library cannot reach an internal member.
- Never logged: the state, instructions, criteria, answers, the API key and any header value, and `JevError.Detail`. `JevError.Message` is logged because it is library text. If a message path turns out to carry request or response data, log only the kind and status for that path.
- Cost:
  - Every log call is guarded by the generated `IsEnabled` check.
  - Duration uses `Stopwatch.GetTimestamp()` and `Stopwatch.GetElapsedTime`, taken only when the relevant level is enabled.
  - With no logger, or with logging disabled, no work or allocation is added: each operation checks `IsEnabled` for the levels it can emit before entering the logging path.
  - The existing `AllocationGate` budgets hold unchanged, and gates with a disabled logger prove it.
  - In this plan, `JevLog.IsAnyEnabled(logger)` is that per-call check: Debug for success, Warning for failure and Error for an unexpected exception. When it is false, `JevClient` calls the unwrapped path directly, with no extra state machine. `LoggingJevApi` does the same for Warning on every attempt.
- The decorator returns the inner call's `ValueTask` unchanged when logging is disabled. The existing retry, integration and allocation tests pass unchanged.
- A hand-written `IJevClient` that relies on the default interface methods does not log. The README says so.
- `Microsoft.Extensions.Logging.Abstractions` is a runtime dependency that flows to consumers, at the lowest version that supports `[LoggerMessage]` on .NET 10, through Central Package Management. The pack tests assert it.

Decisions already made for this phase:

- `new JevClient(null, null)` becomes CS0121: both two-parameter overloads accept two `null` literals, and nullability annotations do not take part in overload resolution. The spec's mandated signatures make this unavoidable, and its Risks row accepts it before 1.0, as of 2026-09-30. Before this phase, that call always threw `ArgumentNullException` for the null `httpClient`. Every typed call shape still resolves. A compile test pins them, and the README notes the `(null, null)` case. The overloads keep the spec's shape.
- Retries that will follow are detected in the decorator exactly as the proxy decides. The proxy passes `retryCount` as `null` on the first attempt and as the attempt index, 1 and up, on each retry. It retries a result that `IJevApi.IsTransient` accepts unless that attempt's index is `MaxAttempts - 1`. The decorator logs when `IJevApi.IsTransient(error)` holds and `(retryCount ?? 0) < retry.MaxAttempts - 1`. It receives the same `RetryPolicy` instance that the proxy uses. The logged `Attempt` is the 1-based number of the failed attempt, `(retryCount ?? 0) + 1`. Thrown exceptions are never retried, because `NeverRetry` holds.
- `FakeLogger` comes from `Microsoft.Extensions.Diagnostics.Testing` 10.10.0, which supports net10.0 and depends on `Microsoft.Extensions.Logging` 10.0.12. It is pinned in `Directory.Packages.props` and referenced only by `tests/ZeroAlloc.Jev.Tests` and `tests/ZeroAlloc.Jev.Integration.Tests`.
- `Microsoft.Extensions.Logging.Abstractions` is pinned at **10.0.0**, the first .NET 10 release, as the library's floor. Nothing brings it transitively today: `src/ZeroAlloc.Jev/obj/project.assets.json` holds only `Microsoft.Extensions.DependencyInjection.Abstractions/10.0.12`, from ZeroAlloc.Resilience. `Microsoft.Extensions.Logging` is pinned at **10.0.12**, the current servicing release, for the tests and the AOT smoke app. A lower version would be a downgrade against `Diagnostics.Testing`, and NU1605 is an error here. Neither package reaches the library's nuspec.

Rulings this plan applies. Both match the updated spec:

1. **Generated-set question count.** The generator exposes no count today. An internal generated constant cannot work: the `[JevQuestions]` type is compiled into the caller's assembly, where an internal member is out of `ZeroAlloc.Jev`'s reach through `T`. Exposing one means a new static member on the public `IJevQuestionSet<TSelf>`, which is public API and which the spec rules out.
   - **Ruling:** the count is the number of top-level properties in `T.QuestionsUtf8`, the questions object the generator writes at compile time. It is read once per `T` into an internal `GeneratedQuestionCount<T>.Value`, touched only when the client has a logger. There is no generator change and no snapshot update. This matches the spec's question-count paragraph.
2. **Message privacy.** `JevErrorKind.InvalidResponse` messages can quote the response. For example, `JevAnswerReader` throws `'{value}' is not one of the options.` with the server's answer, and System.Text.Json reader messages cite body characters. Per the spec's mitigation, `ErrorMessage` for an `InvalidResponse` is the fixed `"The response could not be read."`. Every other kind logs `JevError.Message` unchanged. The privacy test proves the quoting case is real and that it stays out of the logs.

```csharp
using Microsoft.Extensions.Logging.Testing;

namespace ZeroAlloc.Jev.Tests;

/// <summary>Reads a <see cref="FakeLogRecord"/>'s structured fields.</summary>
internal static class LogAssert
{
    /// <summary>Gets a structured field's value, <see langword="null"/> when the event logged a null.</summary>
    /// <exception cref="InvalidOperationException">The record has no field named <paramref name="key"/>.</exception>
    public static string? Field(FakeLogRecord record, string key)
    {
        var state = record.StructuredState ?? throw new InvalidOperationException("The record has no structured state.");
        for (var i = 0; i < state.Count; i++)
        {
            if (string.Equals(state[i].Key, key, StringComparison.Ordinal))
            {
                return state[i].Value;
            }
        }

        throw new InvalidOperationException($"The record has no '{key}' field.");
    }
}
```

```csharp
using System.Diagnostics;
using Microsoft.Extensions.Logging;

namespace ZeroAlloc.Jev;

/// <summary>
/// The client's log events, in the <see cref="Category"/> category. They carry metadata only: never the state,
/// instructions, criteria, answers, API key, a header value or <see cref="JevError.Detail"/>.
/// </summary>
/// <remarks>
/// No event has more than six fields, and each template keeps its placeholders in parameter order, so the generator
/// emits a <c>LoggerMessage.Define</c> call rather than a state struct, whose reference-type <c>GetEnumerator</c>
/// NetFabric.Hyperlinq.Analyzer's HLQ006 rejects.
/// </remarks>
internal static partial class JevLog
{
```

```csharp
using System.Text.Json;

namespace ZeroAlloc.Jev;

/// <summary>
/// The number of questions in a <c>[JevQuestions]</c> set, for the client's logs: the top-level properties of its
/// <see cref="IJevQuestionSet{TSelf}.QuestionsUtf8"/>, the questions object the generator wrote at compile time.
/// </summary>
/// <remarks>
/// Read once per set type, on first use, which only a client with a logger makes. It is not a generated constant: the
/// set is compiled into the caller's assembly, where an internal member is out of this library's reach, and a public
/// one would be a new member of <see cref="IJevQuestionSet{TSelf}"/>.
/// </remarks>
/// <typeparam name="T">The question set.</typeparam>
internal static class GeneratedQuestionCount<T>
    where T : IJevQuestionSet<T>
{
    /// <summary>The set's question count.</summary>
    public static readonly int Value = Count(T.QuestionsUtf8);

    private static int Count(ReadOnlySpan<byte> questionsUtf8)
    {
        // The generator caps JSON text at 60 levels below a question's instructions or criterion; 128 leaves room above
        // the root, question and criteria levels without depending on that arithmetic.
        var reader = new Utf8JsonReader(questionsUtf8, new JsonReaderOptions { MaxDepth = 128 });
        reader.Read();
        var count = 0;
        while (reader.Read() && reader.TokenType == JsonTokenType.PropertyName)
        {
            count++;
            reader.Read();
            reader.Skip();
        }

        return count;
    }
}
```

```csharp
using Microsoft.Extensions.Logging;
using ZeroAlloc.Resilience;
using ZeroAlloc.Results;

namespace ZeroAlloc.Jev.Transport;

/// <summary>
/// Sits between the ZeroAlloc.Resilience proxy and the ZeroAlloc.Rest transport, so it sees every attempt, and logs
/// <see cref="JevLog.AttemptRetrying"/> for each failed attempt the proxy will retry.
/// </summary>
/// <remarks>
/// <para>
/// The proxy passes <see langword="null"/> as the retry count on the first attempt, and the attempt index, 1 and up, on
/// each retry; it also sends that index as <c>X-TypeSafe-Retry-Count</c>. It retries a result that
/// <see cref="IJevApi.IsTransient"/> accepts unless the attempt's index is <c>MaxAttempts - 1</c>, and it never
/// retries a thrown exception. This decorator applies the same two tests to the same <see cref="RetryPolicy"/>.
/// If the caller cancels during the backoff, the retry it logged does not happen.
/// </para>
/// <para>
/// With <see cref="LogLevel.Warning"/> disabled it returns the inner call's <see cref="ValueTask{TResult}"/> itself,
/// and a call that completed synchronously is inspected in place, so neither adds a state machine.
/// </para>
/// </remarks>
/// <param name="inner">The transport.</param>
/// <param name="logger">The client's logger.</param>
/// <param name="retry">The policy the proxy retries with.</param>
internal sealed class LoggingJevApi(IJevApi inner, ILogger logger, RetryPolicy retry) : IJevApi
{
    public ValueTask<Result<SystemOneResponse, JevError>> EvaluateAsync(
        SystemOneRequest body, string authorization, int? retryCount, CancellationToken ct)
        => Observe(inner.EvaluateAsync(body, authorization, retryCount, ct), retryCount);

    public ValueTask<Result<RawJson, JevError>> EvaluateRawAsync(RawJson body, string authorization, int? retryCount, CancellationToken ct)
        => Observe(inner.EvaluateRawAsync(body, authorization, retryCount, ct), retryCount);

    public ValueTask<Result<ModelList, JevError>> ListModelsAsync(string authorization, int? retryCount, CancellationToken ct)
        => Observe(inner.ListModelsAsync(authorization, retryCount, ct), retryCount);

    private ValueTask<Result<T, JevError>> Observe<T>(ValueTask<Result<T, JevError>> attempt, int? retryCount)
    {
        if (!logger.IsEnabled(LogLevel.Warning))
        {
            return attempt;
        }

        if (attempt.IsCompletedSuccessfully)
        {
            var result = attempt.Result;
            LogIfRetrying(result, retryCount);
            return new ValueTask<Result<T, JevError>>(result);
        }

        return ObserveAsync(attempt, retryCount);
    }

    private async ValueTask<Result<T, JevError>> ObserveAsync<T>(ValueTask<Result<T, JevError>> attempt, int? retryCount)
    {
        var result = await attempt.ConfigureAwait(false);
        LogIfRetrying(result, retryCount);
        return result;
    }

    private void LogIfRetrying<T>(Result<T, JevError> result, int? retryCount)
    {
        var index = retryCount ?? 0;
        if (result.IsFailure && IJevApi.IsTransient(result.Error) && index < retry.MaxAttempts - 1)
        {
            JevLog.AttemptRetrying(logger, index + 1, result.Error.Kind, result.Error.StatusCode, result.Error.RetryAfter);
        }
    }
}
```

```csharp
    private ValueTask<Result<T, JevError>> EvaluateGeneratedAsync<T>(long started, RawJson body, CancellationToken ct)

    // Checked per call: without a logger, or with every level the operation can emit disabled, this returns call
    // itself, so the client runs exactly the unlogged code and pays no extra state machine.
    private ValueTask<Result<TResult, JevError>> WithLogging<TResult>(
        ValueTask<Result<TResult, JevError>> call, string operation, string model, int questionCount, long started, CancellationToken ct)
        => _logger is { } logger && JevLog.IsAnyEnabled(logger)
            ? LogEvaluationAsync(logger, call, operation, model, questionCount, started, ct)

    // Logs the whole outcome once, after any retries and after typed parsing; the filter logs a thrown exception
    // without catching it, so it surfaces unchanged.
    private async ValueTask<Result<TResult, JevError>> LogEvaluationAsync<TResult>(
        ILogger logger,
        ValueTask<Result<TResult, JevError>> call,
        string operation,
        string model,
        int questionCount,
        long started,
        CancellationToken ct)
    {
        try
        {
            var result = await call.ConfigureAwait(false);
            var durationMs = JevLog.ElapsedMilliseconds(started);
            if (result.IsSuccess)
            {
                JevLog.EvaluationSucceeded(logger, operation, model, _provider, questionCount, durationMs);
            }
            else
            {
                var error = result.Error;
                var message = JevLog.SafeMessage(error);
                JevLog.EvaluationFailed(logger, operation, model, error.Kind, error.StatusCode, durationMs, message);
            }

            return result;
        }
        catch (Exception exception) when (JevLog.LogUnexpected(logger, operation, exception, ct))
        {
            throw;
        }
    }
```

```csharp
using System.Collections.Concurrent;
using Microsoft.Extensions.Logging;

namespace ZeroAlloc.Jev.AotSmoke;

/// <summary>An in-process provider that keeps every record, so the smoke app can check the client's events under Native AOT.</summary>
internal sealed class CapturingLoggerProvider : ILoggerProvider
{
    private readonly ConcurrentQueue<CapturedLog> _records = new();

    /// <summary>Gets the records so far, in the order they were logged.</summary>
    public CapturedLog[] Records => _records.ToArray();

    public ILogger CreateLogger(string categoryName) => new CapturingLogger(categoryName, _records);

    public void Dispose()
    {
    }

    private sealed class CapturingLogger(string category, ConcurrentQueue<CapturedLog> records) : ILogger
    {
        public IDisposable? BeginScope<TState>(TState state)
            where TState : notnull => null;

        public bool IsEnabled(LogLevel logLevel) => logLevel != LogLevel.None;

        public void Log<TState>(LogLevel logLevel, EventId eventId, TState state, Exception? exception, Func<TState, Exception?, string> formatter)
        {
            var fields = new Dictionary<string, object?>(StringComparer.Ordinal);
            if (state is IReadOnlyList<KeyValuePair<string, object?>> values)
            {
                for (var i = 0; i < values.Count; i++)
                {
                    fields[values[i].Key] = values[i].Value;
                }
            }

            records.Enqueue(new CapturedLog(category, logLevel, eventId.Id, formatter(state, exception), fields));
        }
    }
}

/// <summary>One captured record: its category, level, event id, formatted message and structured fields.</summary>
internal sealed record CapturedLog(string Category, LogLevel Level, int EventId, string Message, IReadOnlyDictionary<string, object?> Fields)
{
    /// <summary>Gets a field's value, or <see langword="null"/> when the record has no such field.</summary>
    public object? Field(string key) => Fields.TryGetValue(key, out var value) ? value : null;
}
```

````markdown
### Logging

Pass an `ILoggerFactory` to log through `Microsoft.Extensions.Logging`:

```csharp
using var jev = new JevClient(new JevClientOptions { ApiKey = apiKey }, loggerFactory);
// or over your own HttpClient:
using var jev = new JevClient(httpClient, options, loggerFactory);
```

The client logs in the `ZeroAlloc.Jev.JevClient` category. It logs each operation once, when it completes, each attempt it will retry, and each unexpected exception. A `null` factory logs nothing, and so do the four constructors without one. Without a logger, or with every level an operation can emit disabled, such as through `NullLoggerFactory` or a filter, the call runs the unlogged path: no logging work and no allocation.

| Id | Event | Level | Fields |
|---|---|---|---|
| 1001 | `EvaluationSucceeded` | Debug | `Operation`, `Model`, `Provider`, `QuestionCount`, `DurationMs` |
| 1002 | `EvaluationFailed` | Warning | `Operation`, `Model`, `ErrorKind`, `StatusCode`, `DurationMs`, `ErrorMessage` |
| 1003 | `AttemptRetrying` | Warning | `Attempt`, `ErrorKind`, `StatusCode`, `RetryAfter` |
| 1004 | `ModelsListed` | Debug | `Provider`, `ModelCount`, `DurationMs` |
| 1005 | `ModelsListFailed` | Warning | `Provider`, `ErrorKind`, `StatusCode`, `DurationMs`, `ErrorMessage` |
| 1006 | `UnexpectedException` | Error | `Operation`, and the exception |

- **`Operation`** is `evaluate` for `EvaluateAsync(SystemOneRequest)`, `evaluate-typed` for the typed overloads, `evaluate-built-set` for a built `JevQuestionSet`, and `list-models`.
- **`EvaluationFailed`** covers every failure the call returns, including an `InvalidResponse` from reading typed answers.
- **`AttemptRetrying`** is logged for each failed attempt the client retries. `Attempt` is 1 for the first attempt, and matches the `X-TypeSafe-Retry-Count` of the retry that follows. The last attempt is reported by the operation's failure event instead.
- **`UnexpectedException`** means a programming error. The exception surfaces unchanged. Cancellation you requested is not logged.

**Never logged:** the state, instructions, criteria, answers, the API key, any header value, and `JevError.Detail`, which holds the server's error body. `ErrorMessage` is `JevError.Message`, which is the library's own text. For `InvalidResponse`, whose message can quote the response, it is `The response could not be read.` instead.

A hand-written `IJevClient` that relies on the default interface methods for typed and built-set evaluation logs nothing. The logging lives in `JevClient`.

With the new overloads, `new JevClient(null, null)` no longer compiles (CS0121), because both two-parameter constructors accept two `null` literals. It always threw `ArgumentNullException` before. For defaults and environment variables, write `new JevClient((JevClientOptions?)null)`.
````
