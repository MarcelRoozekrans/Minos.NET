**Spec:** `docs/superpowers/specs/2026-10-12-phase-7.2-public-api-review-design.md`
**Plan:** `docs/superpowers/plans/2026-10-12-phase-7.2-public-api-review.md`, Task 1

Five reviewers audited the six packages against the spec's checklist on 2026-10-13: the core question model, the core client and pipeline, SystemOne, OpenAI, and DependencyInjection with the two stage packages. The controller merged their output, removed duplicates and checked the claims with the biggest impact against the source.

**How to review:** rule on each **B** finding by writing **Approved**, **Rejected** or **Amended: <change>** on its Ruling line, or in the table below. **N** findings are applied without a ruling unless you strike one. Where a finding offers alternatives, such as CORE-05 and CACHE-09, an Approved ruling takes the first proposal.

## Minos.NET

### CORE-01: The public answer constructors cannot build a usable Choice or Score

- **Flag:** B
- **Lines:**
  `Minos.Choice<T>.Choice(T value, double confidence, Minos.ProbabilityMap<T> probabilities) -> void`
  `Minos.Score<T>.Score(T value, double expected, double confidence, Minos.ProbabilityMap<T> probabilities) -> void`
  `Minos.KeyedChoice.KeyedChoice(string! value, double confidence, Minos.KeyedProbabilityMap probabilities) -> void`
  `Minos.KeyedScore.KeyedScore(int level, double expected, double confidence, Minos.KeyedProbabilityMap probabilities) -> void`
  `Minos.Noul.Noul(double probability) -> void`
- **Problem:** These constructors are public, but the map types they take have only internal constructors
  (`ProbabilityMap.cs:28`, `KeyedProbabilityMap.cs:16`). The only map a caller can pass is `default`, which has no
  options. The result is an answer whose `Value` names an option that its own `Probabilities` does not contain:
  `choice.Probabilities[choice.Value]` throws `ArgumentOutOfRangeException` (`ProbabilityMap.cs:51-55`), and
  `Score<T>.Normalized` / `KeyedScore.Normalized` silently return 0 because `Probabilities.Count` is 0
  (`Score.cs:42-43`, `KeyedScore.cs:40-41`). The constructors also do not check the 0-to-1 ranges their docs state
  (`Choice.cs:12-17`, `Noul.cs:8`). Nothing documents them: no docs page, sample or README constructs an answer
  struct, and `testing-your-code.md:104-160` tests through a fake `IDecisionClient` with `QuestionAnswer` factories. The
  generator never calls them either. It reads answers through `AnswerSlots` (`SourceEmitter.cs:213-216`). A 1.0 user
  who finds them, for example to unit-test a helper like `fan-out.md:110` that takes `Choice<ReviewTopic>`, gets a
  broken value.
- **Proposal:** Make the four map-taking constructors `internal`. Keep `Noul(double)` public, because a Noul is
  complete without a map. Document it in `testing-your-code.md`, in a short "Testing code that reads one answer"
  paragraph next to the fake client. If the maintainer wants test-constructible Choice and Score values, that needs
  public `ProbabilityMap<T>` / `KeyedProbabilityMap` factories (feature, file for 1.x). Until then the constructors
  should not be public.
- **Checklist area:** Documented
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-02: `QuestionAnswer.Value` means a Noul's probability or a Score's expected level, a third meaning of "Value"

- **Flag:** B
- **Lines:**
  `Minos.QuestionAnswer.Value.get -> double`
  `static Minos.QuestionAnswer.Noul(double value) -> Minos.QuestionAnswer`
  `static Minos.QuestionAnswer.Score(int level, double value, double confidence, double[]! probabilities) -> Minos.QuestionAnswer`
- **Problem:** Each typed answer has a `Value`: `Noul.Value` is the yes/no `bool` (`Noul.cs:14`), and
  `Score<T>.Value` is the most probable level (`Score.cs:22`). The neutral `QuestionAnswer.Value` is neither. It is
  the Noul's probability or the Score's *expected* level, and 0 for a Choice (`QuestionAnswer.cs:43-44`). The typed
  forms call these two numbers `Noul.Probability` and `Score<T>.Expected`. So a stage or fake author who reads
  `answer.Value` on a Score expecting the level gets 1.05, and a Noul answer's `Value` is a double here but a bool on
  `Noul`. The testing docs repeat the vague wording "the level, the value, the confidence" (`testing-your-code.md:159`).
  The checklist asks for one name per concept. Here one name covers three concepts.
- **Proposal:** Replace `Value` with two properties named as the typed answers name them:
  `public double Probability { get; }` (the Noul's probability, 0 otherwise) and `public double Expected { get; }`
  (the Score's expected level, 0 otherwise). Rename the factory parameters to match:
  `QuestionAnswer.Noul(double probability)` and
  `QuestionAnswer.Score(int level, double expected, double confidence, double[] probabilities)`. Update
  `testing-your-code.md:157-159`, `pipeline.md:459` and the `DecisionResponse` constructor remarks
  (`DecisionResponse.cs:21`).
- **Checklist area:** Naming
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-03: `DecisionResponse.Usage` drops token counts and cost that the provider did send

- **Flag:** B
- **Lines:**
  `Minos.DecisionUsage.InputTokens.get -> int`
  `Minos.DecisionUsage.OutputTokens.get -> int`
  `Minos.DecisionResponse.Usage.get -> Minos.DecisionUsage?`
- **Problem:** `DecisionUsage` makes both counts `required int` (`DecisionUsage.cs:7-10`). `DecisionResponse.Usage`
  is therefore `null` whenever either count is missing (`DecisionResponse.cs:157-162`), and the `Cost` is lost with
  it. The response does read the three values separately: the readers pass `inputTokens`, `outputTokens` and `cost`
  one by one (`SystemOneResponseReader.cs:121`, `OpenAIResponseReader.cs:107`), and the telemetry tags read each one on
  its own (`IDecisionEvaluation.cs:26-35`, "one count can be present without the other", `DecisionResponse.cs:139`).
  The providers page says vLLM and Custom send "`usage` as the server sends it" and OpenAI's usage "is not documented"
  (`providers.md:43`), so partial usage is a real case. A 1.0 caller sees less than the library's own telemetry sees.
  Microsoft.Extensions.AI's `UsageDetails` uses nullable counts for this reason.
- **Proposal:** `public int? InputTokens { get; init; }` and `public int? OutputTokens { get; init; }`, no longer
  `required`. `DecisionResponse.Usage` is non-null when any of input tokens, output tokens or cost was reported, and
  `null` only when none was. Update the `Usage` summary to: "Gets the token usage and cost the provider reported, or
  `null` when it reported none; a count the provider left out is `null`."
- **Checklist area:** Nullability
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-04: `DecisionResponse.Provider` uses "Provider" for a different concept than the rest of the library

- **Flag:** B
- **Lines:** `Minos.DecisionResponse.Provider.get -> string?`
- **Problem:** Everywhere else, "provider" names where the client sends calls. `DecisionClientMetadata.ProviderName` is
  `typesafe`, `openrouter`, `vllm-sr` and so on (`DecisionClientMetadata.cs:4`, `pipeline.md:349`), and it becomes
  `gen_ai.provider.name`. `SystemOneClientOptions.Provider` picks that preset. `DecisionResponse.Provider` is
  something else: the *upstream* host that OpenRouter routed to (`DecisionResponse.cs:125`, "such as OpenRouter's").
  It is always `null` for TypeSafe and OpenAI (`OpenAIResponseReader.cs:107` passes `provider: null`). A user who
  reads `response.Provider` to learn which provider answered gets `null`, or a host name unrelated to their
  configuration. The checklist asks for one name per concept, and Provider is one of the names it lists. The member is
  also undocumented: `client-and-errors.md:480-481` describes `Id`, `Provider` and `Cost` on the raw
  `SystemOneResponse`, but no page mentions `DecisionResponse.Id`, `.Provider` or `.Usage`.
- **Proposal:** Rename to `UpstreamProvider`, with the summary "Gets the upstream provider an aggregator routed the
  call to, such as the host OpenRouter picked; `null` when the provider is not an aggregator or did not say." In
  `pipeline.md`, where a stage's view of the response is described (near line 292), add one paragraph that lists
  `DecisionResponse.Model`, `Usage`, `Id`, `UpstreamProvider` and `IsCached`.
- **Checklist area:** Naming
- **Merge note:** S1-05 proposes the same rename on the raw `SystemOneResponse.Provider`; rule on both together.
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-05: `[Criteria]` is a plural name for the description of one option

- **Flag:** B
- **Lines:**
  `Minos.CriteriaAttribute`
  `Minos.CriteriaAttribute.CriteriaAttribute(string! description) -> void`
  (and its `Description`, `Key`, `Examples`, `NotFor` members)
- **Problem:** The attribute describes a single Choice option (`CriteriaAttribute.cs:3`, "Describes a Choice
  option"). The same concept in the run-time API is the singular `Criterion` (`Criterion.cs:16`). The builder's
  `Describe(T option, Criterion criterion)` and `OptionDefinition.Criterion` use the singular too. The Score
  counterpart, `[Level]`, is singular. So one concept has two names, and one of them is grammatically wrong. It is the
  most-typed attribute in the docs (`[Criteria` appears across the question-type, typed-evaluation and pattern pages).
  1.0 is the last point at which it can be renamed without a deprecation cycle.
- **Proposal:** Rename to `CriterionAttribute`, used as `[Criterion("…")]`. This does not clash with the `Criterion`
  class. C# attribute lookup takes the only candidate that derives from `Attribute`. The generator, the analyzers,
  the code fixes and every docs page update with it. Maintainer's call: `[Option("…")]`, which parallels `[Level]`, is
  the alternative.
- **Checklist area:** Naming
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-06: The class `Answers` and the property `DecisionResponse.Answers` are different types with one name

- **Flag:** B
- **Lines:**
  `Minos.Answers`
  `Minos.DecisionResponse.Answers.get -> Minos.QuestionAnswerList`
  `static Minos.DecisionClientExtensions.EvaluateAsync(this Minos.IDecisionClient! client, Minos.QuestionSet! questionSet, Minos.DecisionContent state) -> System.Threading.Tasks.ValueTask<ZeroAlloc.Results.Result<Minos.Answers!, Minos.DecisionError!>>`
- **Problem:** `Answers` is the typed result of a built `QuestionSet`, read with handles (`Answers.cs:10`).
  `DecisionResponse.Answers` is a `QuestionAnswerList` of neutral `QuestionAnswer`s (`DecisionResponse.cs:110`). Both
  live in the `Minos` namespace and both describe "the answers to a set". A reader who sees `response.Answers` in a
  stage, then `Answers` in a built-set call, is led to think they are the same type. They share no members. The
  ProviderSwitch sample reads `result.Value.Answers[0]` (`ProviderSwitchSample.cs:44`), and
  `question-sets-at-run-time.md` reads an `Answers` with `Get(handle)`.
- **Proposal:** Rename the class to `QuestionSetAnswers`, which pairs with `QuestionSet` and `QuestionSetBuilder`. The
  `EvaluateAsync(QuestionSet, …)` overloads then return `Result<QuestionSetAnswers, DecisionError>`.
  `DecisionResponse.Answers` keeps its name.
- **Checklist area:** Naming
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-07: `DecisionRequest`'s constructor parameters are PascalCase

- **Flag:** B
- **Lines:** `Minos.DecisionRequest.DecisionRequest(Minos.QuestionSetDefinition! Definition, Minos.DecisionContent State) -> void`
- **Problem:** `DecisionRequest` is not a positional record. It has an explicit constructor and no `Deconstruct`
  (`DecisionRequest.cs:18`). The PascalCase parameter names `Definition` and `State` are a left-over of a positional
  form, and they break the .NET rule that parameters are camelCase. They show in IntelliSense and in named arguments,
  and in exception `ParamName` (`nameof(State)`, line 21). The type is the one every custom stage, fake and mock
  builds (`pipeline.md:21-24`, `testing-your-code.md:104-140`). Renaming later breaks named-argument callers, so it is
  now or never.
- **Proposal:** `public DecisionRequest(QuestionSetDefinition definition, DecisionContent state)`. The `<param>` tags
  and the `ArgumentException` parameter name become `state`.
- **Checklist area:** Naming
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-08: `DecisionContent.IsString` is undocumented and duplicates `TryGetString`

- **Flag:** B
- **Lines:** `Minos.DecisionContent.IsString.get -> bool`
- **Problem:** No docs page, sample or README uses `IsString`. `typed-evaluation.md:331` documents `TryGetString` and
  `TryGetJson` as the way to read content back. Nothing in `src` calls it either. It has no `IsJson` counterpart, and
  it is `false` both for JSON and for uninitialized content, so it cannot tell those apart. On UTF-8 state it parses the
  bytes on every read (`DecisionContent.cs:42`, `IsJsonString` at 295-299). It adds surface without adding a
  capability.
- **Proposal:** Remove it. `TryGetString(out _)` answers the same question. If the maintainer prefers to keep it,
  document it in `typed-evaluation.md` beside `TryGetString` instead.
- **Checklist area:** Documented
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-51: `DecisionCapabilities.Images` and `ModelListing` are Boolean properties named as nouns

- **Flag:** B
- **Lines:**
  `Minos.DecisionCapabilities.Images.get -> bool?`
  `Minos.DecisionCapabilities.Images.set -> void`
  `Minos.DecisionCapabilities.ModelListing.get -> bool?`
  `Minos.DecisionCapabilities.ModelListing.set -> void`
- **Problem:** The .NET design guidelines name a Boolean property with an affirmative phrase, such as `CanSeek`, often with an
  `Is`, `Can`, `Has` or `Supports` prefix. `Images` and `ModelListing` (src/Minos.NET/DecisionCapabilities.cs:71, :77) are
  nouns, so the property reads as if it held images or a listing. The docs have to explain it with "whether"
  (docs/providers.md:302 "`Images` says whether the provider takes images", :305), and the code reads
  `capabilities.Images == true` (docs/providers.md:401-402). The library's own failure message already uses the
  affirmative form: "Custom does not support images." (docs/providers.md:348). The sibling properties `QuestionKinds`,
  `MaxQuestions` and `MaxChoiceOptions` are not Booleans, so they are fine as they are. The 1.0 freeze fixes the name
  permanently, and every protocol package's options take a `DecisionCapabilities`.
- **Proposal:** Rename `Images` to `SupportsImages` and `ModelListing` to `SupportsModelListing`, both still `bool?`.
  Update the XML summaries ("Gets or sets whether the provider accepts images…"), docs/providers.md (the capabilities
  table, :49-52, :302-306, :348, :401-402, :470-486), docs/client-and-errors.md and docs/pipeline.md wherever they name
  the old properties, and the snippet at docs/providers.md:486 (`new DecisionCapabilities { SupportsImages = true }`).
  Leave the MIN206 message as it is.
- **Checklist area:** Naming
- **Ruling:** Approved, maintainer, 2026-10-13

### CORE-09: Generator-only surface is undocumented, and `AnswerSlots` is neither hidden nor fully documented

- **Flag:** N
- **Lines:**
  `Minos.AnswerSlots`
  `Minos.AnswerSlots.Noul(int index) -> Minos.Noul`
  `Minos.AnswerSlots.Choice<T>(int index, Minos.DecisionOptionSet<T>! options) -> Minos.Choice<T>`
  `Minos.AnswerSlots.Score<T>(int index, Minos.DecisionOptionSet<T>! options) -> Minos.Score<T>`
  `Minos.AnswerSlots.Count.get -> int`
  `Minos.DecisionOptionSet<T>` (and its three abstract members)
- **Problem:** Both types must stay public, because generated code in the user's assembly calls them
  (`SourceEmitter.cs:206-231`). No docs page, sample or README names either one, though.
  `DecisionOptionSet<T>` is marked `[EditorBrowsable(Never)]` and documented as infrastructure
  (`DecisionOptionSet.cs:8-12`). `AnswerSlots` is not, so it shows in IntelliSense as if it were application API.
  Its three read methods have no `<exception>` tags, although they throw `ArgumentOutOfRangeException` for a bad index,
  `InvalidOperationException` for a question of another kind, `ArgumentNullException` for null `options`, and
  `ArgumentException` for an option count that does not match (`AnswerSlots.cs:65-87`).
- **Proposal:** Add `[EditorBrowsable(EditorBrowsableState.Never)]` to `AnswerSlots`, and the remark "Infrastructure
  for the code the `[Questions]` source generator emits; application code does not use it." Add the four `<exception>`
  tags to `Noul`, `Choice<T>` and `Score<T>`. In `typed-evaluation.md`, under "What the package ships", add one
  sentence: the generated type implements `IQuestionSet<TSelf>`, and its `Create(AnswerSlots)` and
  `DecisionOptionSet<T>` subclasses are generator plumbing that application code does not call.
- **Checklist area:** Documented

### CORE-10: The definition factories and `OptionDefinition` omit the exceptions they throw

- **Flag:** N
- **Lines:**
  `static Minos.QuestionDefinition.Noul(string! key, Minos.DecisionContent instructions, Minos.DecisionContent? whenTrue = null, Minos.DecisionContent? whenFalse = null) -> Minos.QuestionDefinition!`
  `static Minos.QuestionDefinition.Choice(string! key, Minos.DecisionContent instructions, params System.ReadOnlySpan<Minos.OptionDefinition!> options) -> Minos.QuestionDefinition!`
  `static Minos.QuestionDefinition.Score(string! key, Minos.DecisionContent instructions, params System.ReadOnlySpan<Minos.Criterion!> levels) -> Minos.QuestionDefinition!`
  `Minos.OptionDefinition.OptionDefinition(string! key, Minos.Criterion? criterion) -> void`
- **Problem:** `QuestionDefinition.Noul` has no `<exception>` at all. `Choice` and `Score` document only their
  option and level checks. All three throw `ArgumentNullException` for a null `key` and `ArgumentException` for an
  empty one (`CheckKey`, `QuestionDefinition.cs:107-111`), and `ArgumentException` for uninitialized `instructions`,
  `whenTrue` or `whenFalse` (`QuestionDefinition.cs:113-127`). The `OptionDefinition` constructor throws the same pair
  for `key` (`OptionDefinition.cs:11`) and documents neither. These are the documented raw-definition path
  (`samples/Minos.NET.Samples.ProviderSwitch/TicketQuestions.cs:12-19`).
- **Proposal:** Add to each factory: `<exception cref="ArgumentNullException"><paramref name="key"/> is null.</exception>`
  and `<exception cref="ArgumentException"><paramref name="key"/> is empty, or <paramref name="instructions"/> is
  uninitialized.</exception>`. For `Noul`, add "or `whenTrue` or `whenFalse` is uninitialized" and merge the existing
  option and level text into the same `ArgumentException` tag. Add the `key` pair to the `OptionDefinition`
  constructor.
- **Checklist area:** XML docs

### CORE-11: Provider-neutral types carry one provider's wording

- **Flag:** N
- **Lines:**
  `Minos.DecisionUsage`
  `Minos.DecisionContent`
  `Minos.QuestionsAttribute`
- **Problem:** These core types serve both the SystemOne and OpenAI protocols, but their summaries describe one
  provider:
  - `DecisionUsage`: "Only input tokens are billed." (`DecisionUsage.cs:3`). That is TypeSafe's billing, and wrong for
    OpenAI and OpenRouter, whose `Cost` the same type reports.
  - `DecisionContent`: "A value the Jev API accepts" (`DecisionContent.cs:11`).
  - `QuestionsAttribute`: the generator "turns into a `/v1/systemone` `questions` object"
    (`QuestionsAttribute.cs:5-6`). The generator now emits a provider-neutral `QuestionSetDefinition`
    (`SourceEmitter.cs:124`), which the OpenAI protocol sends as a `questions` array to `v1/decisions`
    (`providers.md:36`).
- **Proposal:**
  - `DecisionUsage`: "Token usage, and the cost where the provider reports one, for one request."
  - `DecisionContent`: "A value a provider accepts as either plain text or structured JSON (an object or array), such
    as a request state, a question's instructions or a criterion."
  - `QuestionsAttribute`: "…properties the Minos.NET source generator turns into a provider-neutral
    `QuestionSetDefinition` and a typed answer reader."
- **Checklist area:** XML docs

### CORE-12: `DecisionResponse`'s public constructor cannot set `Id`, `Provider` or `IsCached`

- **Flag:** N
- **Lines:**
  `Minos.DecisionResponse.DecisionResponse(Minos.QuestionSetDefinition! definition, System.Collections.Generic.IReadOnlyList<Minos.QuestionAnswer>! answers, string? model = null, Minos.DecisionUsage? usage = null) -> void`
  `Minos.DecisionResponse.Id.get -> string?`
  `Minos.DecisionResponse.IsCached.get -> bool`
- **Problem:** The public constructor sets only definition, answers, model and usage (`DecisionResponse.cs:24`). `Id`,
  `Provider` and `IsCached` can be set only through the internal constructor and `AsCached()`
  (`DecisionResponse.cs:82-104`, `153-154`), which `Minos.NET.Caching` reaches through `InternalsVisibleTo`
  (`Minos.NET.csproj:53`). Custom stages are a documented extension point (`pipeline.md:265-292`). A third-party cache
  stage therefore cannot mark a hit as `IsCached`, so `minos.cache.hit` and the cached-spend exclusion
  (`observability.md:349`) silently miss it. A stage or a hand-written `IDecisionClient` that rebuilds a response also
  loses `Id` and `Provider`. This is additive, so it does not block the freeze.
- **Proposal:** Make `Id`, `Provider` (renamed `UpstreamProvider` under CORE-04) and `IsCached` `{ get; init; }`, so a
  stage writes `new DecisionResponse(definition, answers, model, usage) { Id = …, IsCached = true }`. Or file it as a
  feature for 1.x. The init form is preferred now, because it costs nothing.
- **Checklist area:** Microsoft.Extensions.AI
- **Merge note:** This also covers the `IsCached` half of CORE-58, without a 1.x feature.

### CORE-52: `DecisionClientBuilder` is unsealed, but nothing says it is designed for inheritance

- **Flag:** N
- **Lines:** `Minos.DecisionClientBuilder`
- **Problem:** `DecisionClientBuilder` is `public class` (src/Minos.NET/Pipeline/DecisionClientBuilder.cs:10). It is
  neither abstract nor documented as an extension point, which the checklist requires of an unsealed class. Its members
  are not virtual. It cannot be sealed, because `Minos.NET.DependencyInjection`'s `DecisionClientServiceBuilder` derives
  from it (src/Minos.NET.DependencyInjection/DecisionClientServiceBuilder.cs:10), and docs/pipeline.md:359-362 documents
  that derivation. So the class is designed for inheritance, but its XML docs do not say so or what a derived builder
  may add. Microsoft.Extensions.AI's `ChatClientBuilder` is sealed, so the difference needs stating.
- **Proposal:** Keep the class unsealed and add to its `<remarks>`: "Registration packages derive from this class to add
  what a registration knows, such as `DecisionClientServiceBuilder.Name`. A derived builder adds members only: `Use` and
  the `Use…` extensions return the base `DecisionClientBuilder`, and `Build` composes the stages the same way."
- **Checklist area:** Sealing

### CORE-53: The pipeline types' constructors are public but no page uses or mentions them

- **Flag:** N
- **Lines:**
  `Minos.DecisionClientBuilder.DecisionClientBuilder(Minos.IDecisionClient! innerClient) -> void`
  `Minos.DecisionClientBuilder.DecisionClientBuilder(System.Func<System.IServiceProvider!, Minos.IDecisionClient!>! innerClientFactory) -> void`
  `Minos.LoggingDecisionClient.LoggingDecisionClient(Minos.IDecisionClient! innerClient, Microsoft.Extensions.Logging.ILogger! logger) -> void`
  `Minos.OpenTelemetryDecisionClient.OpenTelemetryDecisionClient(Minos.IDecisionClient! innerClient) -> void`
  `Minos.RetryingDecisionClient.RetryingDecisionClient(Minos.IDecisionClient! innerClient, Minos.DecisionRetryOptions? options = null, Microsoft.Extensions.Logging.ILogger? logger = null, System.TimeProvider? timeProvider = null) -> void`
- **Problem:** No docs page, sample or the README contains `new DecisionClientBuilder`, `new LoggingDecisionClient`,
  `new OpenTelemetryDecisionClient` or `new RetryingDecisionClient`. The docs use only `AsBuilder()` and the `Use…`
  extensions (docs/pipeline.md:88-124). The stage classes themselves are documented (docs/pipeline.md:63-67, :333;
  docs/observability.md:35-36), but their constructors are not. One undocumented difference matters to a user who finds
  them: `new RetryingDecisionClient(inner)` starts from the library defaults (RetryingDecisionClient.cs:35), while
  `UseRetries()` starts from the inner client's own retry settings (RetryingDecisionClientBuilderExtensions.cs:19). So
  wrapping a `SystemOneClient` configured with `MaxRetries = 5` by hand silently retries twice.

### OAI-01: The two providers name their client family with different schemes

- **Flag:** B, ruled with S1-01

### CACHE-10: A disposed caching or rate-limiting stage still answers instead of throwing `ObjectDisposedException`

- **Flag:** B
- **Lines:**
  - `override Minos.Caching.CachingDecisionClient.EvaluateAsync(Minos.DecisionRequest! request, System.Threading.CancellationToken cancellationToken = default(System.Threading.CancellationToken)) -> System.Threading.Tasks.ValueTask<ZeroAlloc.Results.Result<Minos.DecisionResponse!, Minos.DecisionError!>>`

- **Problem:** The client docs promise "A call started after `Dispose` throws `ObjectDisposedException`, because calling a disposed client is a mistake in the calling code" (docs/client-and-errors.md:82-83; also `DecisionErrorKind.Disposed`, src/Minos.NET/DecisionErrorKind.cs:66-69). The core stages keep that promise because they always call the inner client, which throws. These two stages are the only ones that answer without calling the inner client, and neither tracks disposal: `CachingDecisionClient.EvaluateAsync` returns an in-process hit before anything else (CachingDecisionClient.cs:86-90), and `RateLimitingDecisionClient` returns a `RateLimited` failure for a rejected lease (RateLimitingDecisionClient.cs:58-66) or waits on the limiter's queue. - **Proposal:** In both stages, keep a `volatile bool _disposed`, set it in an override of `Dispose(bool)` before `base.Dispose(disposing)` (as `RetryingDecisionClient` does, src/Minos.NET/Pipeline/RetryingDecisionClient.cs:47-50), and start `EvaluateAsync` with `ObjectDisposedException.ThrowIf(_disposed, this);` after the null check. Add `<exception cref="ObjectDisposedException">` to each `EvaluateAsync` (replacing the bare `<inheritdoc />` or adding to it), and a test per stage that a call after `Dispose` throws even on a warm cache or with an exhausted limiter.

- **Ruling:** Approved, maintainer, 2026-10-13
