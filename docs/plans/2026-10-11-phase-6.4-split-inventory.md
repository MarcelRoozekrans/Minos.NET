### 2c. Things that should not go through IVT, or that need a decision

- **Nothing needs to become public for bridging.** Every crossing works through IVT; the spike in 7.3 proves the generator-produced cases.
- `DecisionError` with `Failures` for `Unsupported`: an internal ctor through IVT is enough for S1. Third-party protocol packages, which have no IVT, could not build such errors. That would need a public ctor, which is new public API and so the maintainer's call; it should not block 6.4.
- `DecisionClientServiceBuilder.HttpClient` is non-null public (DI DecisionClientServiceBuilder.cs:22), but a factory registration has no named `HttpClient`. Making it `IHttpClientBuilder?` breaks the public API. The other option is a builder type per registration kind, but the class is `sealed`. **This needs a maintainer decision.**

## 6. Telemetry naming

- **Provider name.** `DecisionTelemetry.ProviderOf(settings.Provider)` (Telemetry/DecisionTelemetry.cs:113) produces it from the constants `TypeSafe = "typesafe"` (:62) and `OpenRouter = "openrouter"` (:65). It is called at DecisionClient.cs:202 into `_providerName` and put in `DecisionClientMetadata` (DecisionClient.cs:214).
  - The core stages read it through `GetService<DecisionClientMetadata>()` (OpenTelemetryDecisionClient.cs:28-29, LoggingDecisionClient.cs:29-30).
  - The raw calls pass it to the S1 proxy (DecisionClient.cs:352, :379).
  - **After the split S1 owns the mapping** (`typesafe/openrouter/cloudflare/vllm-sr/custom`), and core only carries the string in `DecisionClientMetadata`.
- **Inconsistency to fix in the move.** The raw-evaluate log uses `ProviderName(_provider)` (DecisionClient.cs:436, :454-455), which logs `"TypeSafe"`/`"OpenRouter"` (`nameof`). - **ListModels gate.** `if (_provider == DecisionProvider.OpenRouter)` (DecisionClient.cs:369) becomes the `ModelListing` capability.
- **ActivitySource and Meter `"Minos"`.**
  - The name constant `DecisionTelemetry.SourceName` (:11) stays in **core**; S1 uses it via IVT in `[Instrument(SourceName)]`.
  - The instances are **per generated proxy**: each `*Instrumented` class has its own `static ActivitySource _activitySource = new("Minos", "<informational version>")` and `static Meter _meter = new("Minos", …)`. - **Logger category.** `"Minos.DecisionClient"` is core-owned (DecisionLog.cs:18) because core pipeline extensions use it. Keep it unless the maintainer renames it.

## 7. Risks and gotchas

1. **Same-named internal types across assemblies: CS0436, which is an error here.** With IVT, an S1 internal type whose fully qualified name matches one in core gets CS0436 in S1 and CS0433 (ambiguous) in any test or benchmark project that gets IVT from both. Reproduced: linking `DecisionLimits.cs` into an IVT'd assembly gives `error CS0436`. Consequences:
   - S1's logging partial must not be `Minos.DecisionLog`; use for example `Minos.SystemOne.SystemOneLog`.
   - Do not link `DiagnosticIds.cs`, `DecisionLimits.cs` or `SnakeCase.cs` into S1.
   - `RawJson` and `RetrySettings` must exist once, in core.
   - Put S1 internals in `Minos.SystemOne.*` namespaces, not `Minos.Transport` or `Minos.Telemetry`.
2. **Generated code moves with its source.**
   - The ZeroAlloc.Rest `DecisionApiClient` (from `IDecisionApi`), the ZeroAlloc.Telemetry `DecisionOperationsInstrumented` (from `IDecisionOperations`) and the STJ `DecisionJsonContext.*.g.cs` are generated in S1 once their sources move.
   - In core stay `DecisionEvaluationInstrumented`, `QuestionSpecValidator`/`QuestionSetSpecValidator` (ZeroAlloc.Validation) and `DecisionLog`'s `[LoggerMessage]` output.
   - The DI configuration-binder interceptor (`file` class, `InterceptsLocation` into DecisionServiceCollectionExtensions.cs:182) disappears from DI and regenerates in S1.
   - Today's stale `bin/Debug` DLL (built 2026-10-10) still contains pre-6.3 types (`DisposalGuardDecisionApi`, `LoggingDecisionApi`, `*ResilienceProxy`). Rebuild before comparing.
3. **The generators work across the IVT boundary (verified by the spike):**
   - ZeroAlloc.Telemetry emits `_result.Error?.ErrorType` against core's internal `DecisionError.ErrorType`, and accepts `[Instrument(SourceName)]` and tag constants from core's internal `DecisionTelemetry` via `using static`.
   - The STJ generator emits `new global::Minos.Serialization.DecisionContentConverter()` (internal, core).
   - `[LoggerMessage]` works in a separately named class.
   - The build is clean under the repo's analyzers (TreatWarningsAsErrors).
   - **The spike did not cover the AOT/trim view.** The aot-surface job should be the gate for that.
4. **S1 needs its own ZeroAlloc.Telemetry reference.** Core references it with `PrivateAssets="analyzers;build;buildtransitive"`, so the generator does not flow to S1 and `IDecisionOperations` would silently produce no proxy, which is a compile error at `new DecisionOperationsInstrumented`. S1's nuspec must then exclude Build and Analyzers in the same way, and a pack test must prove it.
5. **IVT fan-out.**
   - Core: add `Minos.NET.SystemOne`; keep `Minos.NET.Tests` and `Minos.NET.Benchmarks`.
   - S1: `Minos.NET.Tests` (or the new S1 test project), `Minos.NET.Benchmarks` (ParseBenchmarks and QuestionSetBenchmarks need internal `SystemOneProtocol`/`SystemOneAnswers`).
   - DI: add IVT to `Minos.NET.SystemOne` (it has none today).
   - Phase 6.5 will add `Minos.NET.OpenAI` to core and DI.
6. **Logging event ids.** 1001-1006 share the category `"Minos.DecisionClient"`. After the split, 1004 and 1005 are declared in S1 and the rest in core, and no compiler check stops a reuse. Add a test that collects the `[LoggerMessage]` ids from both assemblies and asserts they are unique. The AotSmoke `LoggingChecks.cs:25` asserts id 1003 and the category.
7. **`DecisionError` for capability failures.** The existing internal ctor forces `InvalidQuestions` (DecisionError.cs:28-32). The capability check (`Unsupported` + `Failures`) needs a new core ctor.
8. **Protocol slot hard-coding.** `QuestionSetDefinition._protocolData = new object?[1]` (:13) assumes exactly one protocol. Phase 6.5 needs it widened; the slot numbers should be owned by the protocol packages.
9. **Doc crefs to moving types in core** become CS1574 errors (list in 2b).
10. **Path-reading tests break silently or loudly:** ObservabilityNamesTests.cs:69 (`IDecisionOperations.cs` path), ProtocolBoundaryTests.cs:30 (scans only core), and the Docs `NativeAotTests`/`GettingStartedTests` csproj reads.
11. **Many core tests depend on SystemOneProtocol** to build responses (section 5). The plan should decide whether `Minos.NET.Tests` keeps referencing S1 (simplest, preserves the AOT and allocation tests unchanged) or gains a core-only response factory.
12. **Raw `IDecisionApi` routes are TypeSafe-shaped.** `[Post("v1/systemone")]`, `[Get("v1/models")]` and the `X-TypeSafe-Retry-Count` header (IDecisionApi.cs:18-23, :44-48) are fixed at compile time. Cloudflare's account path and `Custom.Path` need the raw call to go through `{**path}`, as `SendAsync` does.
13. **The DI builder shape** (`DecisionClientServiceBuilder.HttpClient` non-null, `sealed`) conflicts with a factory registration that has no HttpClient. This needs a maintainer decision (2c).
14. **Release-please.** The change is breaking and multi-package, so use the nested `BEGIN_COMMIT_OVERRIDE`. Bodies must not contain nested parentheses, for example `typeof(X)` inside parentheses.
15. **Minor findings to fix in the same change:**
    - The `ProtocolBoundaryTests.cs:24` allow-list entry names the deleted `Telemetry/ResponseFields.cs`.
    - `Serialization/DecisionJson.cs` is test-only (RequestSerializationTests.cs:130,212-214).
    - The AotSmoke `AllocationChecks.cs:82,113` and `ClientBenchmarks.cs:12` comments call `DecisionJsonContext`, `TypedEvaluation` and `RawJson` "internal" with the old location.
