## CI-runnable local server (GitHub-hosted ubuntu, CPU only, ~7 GB RAM)

No concrete command could be fully verified. Candidates, best first:

1. **ollajev with a small model.** `pip install ollajev` (Python must be >=3.12 and <3.13, so pin it with `actions/setup-python`), then `ollajev serve` (127.0.0.1:8000). It supports all three kinds and has CPU mode via `OLLAJEV_DEVICE=cpu`. Apache-2.0. Small models listed: Julia-1 (0.6 GB, PyTorch CPU), laya family (0.7 to 0.9 GB), decider-0.8b (1.5 GB), the default vega-08b-public-intents (1.8 GB). Sizes are from https://pypi.org/project/ollajev/. How to choose a model non-interactively (CLI flag or env var) was NOT verified, nor was the actual RAM use. PyTorch CPU wheels are large but fit a ~14 GB disk, presumably. The model licences must be checked per model (e.g. d1-omni is restricted).
2. **jevos.** Smallest (~630 MB) but noul only, so it is useless for testing Choice and Score except as a 422 source. It is also useful as a negative-path test for unsupported kinds. Run command: not documented. Only a Dockerfile build from the repo exists (no published image). The licence is conflicting (MIT per two aggregators, none stated in the repo page).
3. **vllm-sr with Decision-1.0-Kai-0.6B or Lex (Apache-2.0, 0.6B).** Supports all three kinds, and a reviewer verified the CPU Docker image. But the image name, port and release status are NOT verified. A candidate command is `vllm-sr decision serve vllm-sr/Decision-1.0-Kai-0.6B` after the install script, which would need to be tried in a throwaway workflow. Note the 1,024-token limit.

Recommendation: ollajev (Apache-2.0, multi-kind, port 8000) is the only option with a documented pip install plus a documented default port plus all three kinds. Validate it in a scratch workflow before relying on it. As a fallback for pure unit tests, stub the server in-process.

## Unverified list

- TypeSafe: GET /v1/models, questions per request, max state size, image support (Cloudflare's sheet claims text-only, 32k), the error body schema.
- OpenRouter: the score kind, limits, errors, and images.
- Cloudflare: any /v1/systemone path or gateway (the evidence says there is none); whether Clef accepts the `{input:{...}}` wrapper; the Clef (27B) context window and image limits from a primary page; the pricing conflict ($0.038 vs $0.09/M); the error shapes.
- vllm-sr: the default host and port, the Docker image name and release status, server-side auth enforcement, images, GET /v1/models, and whether the 2.0 wire format differs.
- jevos: the licence conflict, `docker run` command, RAM, and the 422 body. Two different repo URLs appear (mc9max/jevos and feder-cr/jev).
- ollajev: the non-interactive model selection, the RAM at runtime, the exact `/v1/models` response shape, and the default model's licence.
- llama.cpp-Jev: the path, port and licence. A claim that upstream llama-server added /v1/systemone (daily.dev blog) was not confirmed from a primary source.
- LitJev, WaterSheep, joyfox/Qwen3.5-0.8B-JEV: not found at all.
- All benchmark and latency claims are vendor-reported only.
