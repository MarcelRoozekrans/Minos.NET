All planned items are implemented. The branch departs from the spec as approved before implementation in three places. Each change was recorded in the spec and the plan when it was made:

1. **Rate limiting is in its own package.** `System.Threading.RateLimiting` is not in the base shared framework, so putting the stage in core would have added a package dependency. The maintainer chose this before implementation started.
2. **The recommended stage order is telemetry, caching, retries, rate limiting, then the transport.** The first draft of the spec contradicted itself on this point. The controller ruled on it during Task 3, in commit 59eb693.
3. **HybridCache was replaced** by an in-process `IMemoryCache` and an optional `IDistributedCache`. HybridCache 10.0.0 and 10.10.0 both produce IL2026, IL3053 and IL2104 in every app that calls `AddHybridCache()`; see dotnet/extensions#5624. The maintainer made this choice after Task 7's AOT publish failed, in commits 5dcf7c6 and ddb423d.

The final whole-branch review found a Critical bug: the cache key ignored the client's default model. The fix is in 5f2e473 and has two tests; reverting the fix makes both fail. One related case needs a change to a public contract, so it is filed as #175 for the Phase 7.2 API review instead of being fixed here. Until then, the docs explain how to work around it.
