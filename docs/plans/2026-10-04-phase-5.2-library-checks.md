# Phase 5.2 library checks

Checked on 2026-10-04. Each library must pass three checks to be a benchmark client: a licence that allows use as a
benchmark dependency, a custom base URL, and a single-attempt setting. A library that fails is recorded and left out.
Nothing is patched. All three .NET libraries pass.

- **JevSharp** has no base-URL option. A custom endpoint is the only way to point it at the mock. The endpoint is
  `http://127.0.0.1:5005/v1/systemone`, the protocol is `JevProtocol.TypeSafe`, and a model string is required. Custom

- **Jev.Net** defaults to two retries, `RetryPolicy.None` disables them. It needs an API key, so it gets a dummy key.

## Transport

Every .NET client that accepts an `HttpClient` or a handler gets the same transport in the benchmark: one long-lived
`SocketsHttpHandler` per client, with `PooledConnectionLifetime` set to 2 minutes, `AutomaticDecompression` off and the
default `MaxConnectionsPerServer`. All three community clients accept an `HttpClient`, so all five .NET clients run on
it, and none keeps its own default. The harness's `BenchmarkTransport` builds it, and a test checks that no client sends
`Accept-Encoding`.

| | Accepts | Its own default, unused in the benchmark |
|---|---|---|
| ZeroAlloc.Jev | `new JevClient(httpClient, options)` | a client it creates and owns |
| JevSharp | `new JevClient(options, httpClient, logger)` | a `SocketsHttpHandler` it creates, with redirects off |
| TypeSafe.AI.Sdk | `new TypeSafeClient(httpClient, options)`; not disposed by the SDK | `new HttpClientHandler()` |
| Jev.Net | `TypeSafeClientOptions.HttpClient`, with `DisposeHttpClient = false` | `SocketsHttpHandler` with `AllowAutoRedirect = false`, `AutomaticDecompression = All` and `PooledConnectionLifetime` of 2 minutes |

### Jev.Net's throughput

Jev.Net led every client in the first smoke runs, at 28.7k calls/s against the raw baseline's 22.2k behind WireMock, and
it beat ZeroAlloc.Jev again in the first Kestrel smoke run, at 71.2k against 67.1k. The measurements below show that
this lead came from the 1 s smoke phase, not from Jev.Net's transport or its connection use.

10 s runs at 16 workers against the Kestrel mock, measured on 2026-10-04 with a 2 s warm-up, the shared transport and
every request counted:

| Client | Calls/s |
|---|---|
| ZeroAlloc.Jev | 113,214 |
| raw `HttpClient` | 107,456 |
| Jev.Net, shared transport | 65,684 |
| Jev.Net, its own default handler | 63,134 |
| TypeSafe.AI.Sdk | 62,752 |
| JevSharp | 49,931 |

- **The handler:** Jev.Net on its own default handler and on the shared transport differ by 4 %, within run-to-run
  noise. Its default turns on decompression, but the mock sends no compressed body, so the setting has no effect here.
- **Connections:** the mock held 16 established connections during every client's run, plus 1 for the harness's count
  reads. No client opened more connections than it had workers.
- **HTTP version:** every client speaks HTTP/1.1. Kestrel serves HTTP/2 over plain HTTP only with prior knowledge, and
  no client asks for it.
- **Request shape:** Jev.Net serializes the request into a `byte[]` and sends it as a `ByteArrayContent` with a
  `Content-Length`. It reads the whole response with `HttpCompletionOption.ResponseContentRead` and
  `ReadAsByteArrayAsync`, then decodes it. Nothing in that path explains a lead over ZeroAlloc.Jev or the raw
  baseline, and the 10 s runs show none.
- **The 1 s phase:** a 1 s phase spends much of its time in tiered JIT compilation and warm-up. It ranks clients by how
  fast they warm up, not by their steady-state cost: the raw client measured 75k/s in a 1 s smoke phase and 107k/s over
  10 s. Only full-length runs rank the clients.

## Official SDKs

| | JS | Python |
|---|---|---|
| Package | `@typesafe-ai/sdk` 0.6.0, Node 20 or later | `typesafe-sdk` 0.7.2, Python 3.10 or later |
| Licence | MIT | MIT |
| Base URL | `baseURL` in the constructor config | `base_url=` |
| Single attempt | `retry: { maxRetries: 0 }` in the constructor config | `retry=RetryPolicy(max_retries=0)` |

The JS constructor is `new TypeSafeClient({ apiKey, baseURL, retry: { maxRetries: 0 } })`. In `client.ts` the config's
`retry` is a partial policy, merged over `DEFAULT_RETRY_POLICY` by `resolveRetryPolicy`. The default is
`maxRetries: 2`, set in `retry.ts`. Each attempt is retried while `req.retry.maxRetries - attempt` is above zero, so
`0` gives exactly one attempt. Calls go to `POST /v1/systemone` on `baseURL`.
