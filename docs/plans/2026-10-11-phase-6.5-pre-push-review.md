## Code quality

| Rule | Result |
|---|---|
| 1. Security | No findings. The OpenAI key is read only from the options or `OPENAI_API_KEY`, the settings class is not a record and its `ToString` masks the key. `DecisionImage` accepts inline data only: remote URLs and file ids are rejected, so the client never fetches a URL on a caller's behalf. The data URL is written raw only after its text is restricted to a known media type and base64. |
| 2. YAGNI | No findings. There is no `OpenAICapabilities`, as ruling 1 decided; model listing is not implemented, and the client reports `ModelListing` false rather than pretending. |
| 3. Debug and temporary code | None in `src` or `samples`: no `Console.Write`, `Debugger`, `TODO`, `FIXME` or `HACK` added. |
| 4. Dead code | The moved SystemOne files, `Capabilities.cs`, `RequestStates.cs`, `StateWriter.cs` and `SystemOneCapabilities.cs`, are deleted, not left behind. |
| 5. Error handling | A refusal is `Refused` with status 200 and one `QuestionFailure` per refused key, per ruling 8. Malformed bodies are `InvalidResponse` through `JsonException`, never an unhandled throw. MIN204 and MIN205 merge with the capability failures into one `Unsupported` error, capability failures first, and the transport test pins the order. `OpenAIRequestWriter` disposes the pooled body when writing throws. |
| 6. Naming | Follows the plan: `OpenAI`-prefixed public types in `Minos.OpenAI`, `OpenAIServiceCollectionExtensions` in `Microsoft.Extensions.DependencyInjection`, internals in `Minos.OpenAI.*`, and the provider name `openai`. |
| 7. Test coverage | The new `Minos.NET.OpenAI.Tests` has 137 tests over the request writer, the answer and response readers, errors, the MIN204 and MIN205 checks, settings and the client. WireMock tests in `Integration.Tests`, DI and configuration tests, docs tests for the provider differences, pack tests for the new package, AOT smoke checks and gates, and image tests for both protocols cover the rest. |
