Changes on top of the plan, each recorded as a ruling:

- The loop class is `ShadowReplayLoop` and not `ShadowReplay`, because a type named like its namespace trips MA0049.
- The app deletes an existing records file before a run, because `JsonlDecisionRecordSink` appends.
- It refuses a dataset with more items than the daily cap of 400, with exit 2. Otherwise each item past the cap would wait 65 s for a shadow that never comes.
- The replay runs with `dotnet run --no-build` after a separate build step. `dotnet run` forwards SIGTERM to the app; this was checked twice on SDK 10.0.403, and the app flushed and exited 130.
- An internal `RunAsync` overload takes a test hook, the candidate timeout and the shadow wait. The sample has InternalsVisibleTo for its tests only.
- `docs/samples.md`, `samples/README.md` and the root README count six samples. They exempt the shadow replay from recordings and offline mode.

There is no change under `src/`, and no verdict wording in code or docs.
